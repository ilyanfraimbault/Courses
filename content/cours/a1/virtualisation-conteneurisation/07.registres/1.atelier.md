::rappel{titre="Les commandes de l'atelier" icone="i-lucide-terminal"}
| Commande | Ce qu'elle fait |
|---|---|
| `docker pull ubuntu:jammy` | télécharge l'image `ubuntu` au tag `jammy`, depuis Docker Hub |
| `docker pull docker.io/ubuntu:jammy` | la **même** commande : `docker.io` est le registre par défaut |
| `docker pull registry.hub.docker.com/library/ubuntu:jammy` | la même image, rangée localement sous un **autre** nom de dépôt |
| `docker pull mysql/mysql-server` | une image **non officielle** : espace de nommage `mysql`, dépôt `mysql-server` |
| `docker rmi ubuntu:jammy` | supprime une image — tag compris, faute de quoi Docker cherche `latest` |
| `docker login -u <identifiant>` | s'authentifie auprès de Docker Hub |

Le nom complet d'une image : **registre** / **espace de nommage** / **image** : **tag** — par exemple `registry.hub.docker.com/library/ubuntu:jammy`.
::

## 1. Docker Hub, le registre par défaut

Dans sa configuration par défaut, le client Docker récupère ses images sur **Docker Hub**. Trois mots à distinguer :

- un **registre** stocke des images de conteneurs. On y récupère des images, et l'on peut y déposer les siennes, si l'on a les droits nécessaires ;
- un **dépôt**, dans un registre, est une collection d'une ou plusieurs images ;
- chaque image d'un dépôt est stockée sous un **tag**. Le tag désigne en général une **version** de l'image, mais aussi ses **déclinaisons** : un dépôt MySQL peut porter des images basées sur Alpine et d'autres sur Debian, chacune sous son tag.

Récupérons l'image Ubuntu au tag `jammy` :

```text
$ docker pull docker.io/ubuntu:jammy
jammy: Pulling from library/ubuntu
3153aa388d02: Pull complete
Digest: sha256:0bced47fffa3361afa981854fcabcd4577cd43cebbb808cea2b1f33a3dd7f508
Status: Downloaded newer image for ubuntu:jammy
docker.io/library/ubuntu:jammy
```

Cette commande est **exactement la même** que `docker pull ubuntu:jammy` : `docker.io` est le nom de domaine de Docker Hub, et Docker le sous-entend. Ce nom a changé plusieurs fois au fil des années — les anciens fonctionnent toujours —, et `docker.io` est celui qu'on recommande aujourd'hui.

Si le téléchargement se solde par un `Error response from daemon`, pas d'inquiétude : il suffit de relancer la commande.

## 2. Le nom complet d'une image

Récupérons la même image Ubuntu en passant par un **autre** nom de domaine de Docker Hub, `registry.hub.docker.com` :

```text
$ docker pull registry.hub.docker.com/library/ubuntu:jammy
$ docker image ls
REPOSITORY                               TAG     IMAGE ID       ...   SIZE
ubuntu                                   jammy   5a81c4b8502e   ...   77.8MB
registry.hub.docker.com/library/ubuntu   jammy   5a81c4b8502e   ...   77.8MB
```

La colonne `IMAGE ID` montre **la même empreinte** : c'est la même image. Mais la colonne `REPOSITORY` dit qu'elles ne viennent pas du même dépôt — pour lancer un conteneur avec la seconde, il faut l'écrire en entier :

```text
$ docker run -dit registry.hub.docker.com/library/ubuntu:jammy
```

Le nom se lit ainsi :

| Morceau | Ici | Rôle |
|---|---|---|
| l'adresse du registre | `registry.hub.docker.com` | où l'image est stockée |
| `/` puis le dépôt | `library` | l'espace des images officielles |
| `/` puis l'image | `ubuntu` | |
| `:` puis le tag | `jammy` | la version |

Pour supprimer l'image venue de `docker.io`, qui s'affiche simplement `ubuntu`, il faut **préciser le tag** : sans lui, Docker chercherait `ubuntu:latest`, qui n'existe pas ici.

```text
$ docker rmi ubuntu:jammy
Untagged: ubuntu:jammy
```

Une image **non officielle** porte un espace de nommage avant son nom de dépôt :

```text
$ docker pull mysql/mysql-server
Using default tag: latest
...
docker.io/mysql/mysql-server:latest
```

- l'espace de nommage (*namespace*) est `mysql`, le dépôt `mysql-server`, et faute de tag, c'est `latest` ;
- dans `dolibarr/dolibarr:21`, l'espace de nommage est `dolibarr`, le dépôt `dolibarr`, le tag `21`.

Vos propres images sur Docker Hub suivront ce format : **votre identifiant Docker** / **le nom du dépôt** : **un tag**.

Attention à la sécurité : une image non marquée comme officielle n'a été vérifiée par personne, et même les images officielles portent des vulnérabilités que leur fournisseur corrigera un jour. Dans le doute, on construit ses propres images, avec circonspection.

::exemple{id="rg-ex-nom" titre="Décomposer un nom d'image" pour="Savoir quoi écrire pour viser une image précise"}
`docker.io/mysql/mysql-server:latest`, la dernière ligne du téléchargement ci-dessus, se décompose en :

- `docker.io` — le registre, Docker Hub ;
- `mysql` — l'espace de nommage, celui de l'éditeur ;
- `mysql-server` — le dépôt ;
- `latest` — le tag, pris par défaut.

À l'inverse, `ubuntu:jammy` n'a pas d'espace de nommage écrit : c'est une image officielle, rangée dans `library`.
::

## 3. Les autres registres et l'authentification

Docker Hub n'est pas le seul registre de conteneurs. On en trouve d'autres, par exemple :

- Amazon Elastic Container Registry ;
- Red Hat Quay ;
- Google Artifact Registry.

Les applications professionnelles utilisent souvent **leur propre registre**, privé : il faut alors **se connecter** pour y accéder. Mettre en place un registre privé pour Docker n'a rien de compliqué.

On s'authentifie avec `docker login`. Docker Hub étant le registre par défaut, inutile de le nommer : il suffit de donner son identifiant avec `-u`, et le mot de passe est demandé.

```text
$ docker login -u kikinovak
Password: *********
...
Login Succeeded
```

::extrait-cours{id="rg-hub" titre="Docker Hub, le registre par défaut" source="/cours/a1/virtualisation-conteneurisation/registres/atelier#_1-docker-hub-le-registre-par-défaut"}
- Un **registre** stocke des images ; un **dépôt** y rassemble les images d'une application ; chaque image y porte un **tag** — une version ou une déclinaison.
- Sans registre, Docker utilise **Docker Hub**, `docker.io` : `docker pull ubuntu:jammy` et `docker pull docker.io/ubuntu:jammy` sont la même commande.
- Sans tag, Docker prend `latest` : `docker pull postgres` ; une version précise : `docker pull postgres:13.22`.
::

::extrait-cours{id="rg-nom" titre="Le nom complet d'une image" source="/cours/a1/virtualisation-conteneurisation/registres/atelier#_2-le-nom-complet-dune-image"}
`registre/dépôt/image:tag` — par exemple `registry.hub.docker.com/library/ubuntu:jammy`.

- `library` est l'espace des images **officielles**, qu'on n'écrit pas sur Docker Hub.
- Une image **non officielle** porte un espace de nommage : `mysql/mysql-server`, `dolibarr/dolibarr:21`, `elestio/glpi`.
- Pour supprimer une image dont le tag n'est pas `latest`, on l'écrit : `docker rmi ubuntu:jammy`.
- Ses propres images : `identifiant/dépôt:tag`.
::

Autres registres : Amazon ECR, Red Hat Quay, Google Artifact Registry, ou un registre **privé**.

```bash
docker login -u kikinovak
```

Docker Hub étant le registre par défaut, on ne le nomme pas ; le mot de passe est demandé.
