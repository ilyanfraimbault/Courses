## 1. Alpine Linux, une base ultra-légère

**Alpine Linux** est une distribution conçue pour servir de base aux conteneurs : son image pèse moins de 10 Mo. C'est un excellent point de départ pour une image légère.

```text
$ docker pull alpine
Using default tag: latest
latest: Pulling from library/alpine
Status: Downloaded newer image for alpine:latest
docker.io/library/alpine:latest
$ docker images
REPOSITORY   TAG       IMAGE ID       CREATED      SIZE
alpine       latest    706db57fb206   7 days ago   8.32MB
```

L'objectif de l'atelier : y compiler le code source de **CMatrix**, l'économiseur d'écran aux caractères qui défilent façon *Matrix*.

## 2. Préparer le Dockerfile

Le `Dockerfile` est la **recette** de l'image : un fichier texte qui contient toutes les instructions nécessaires pour la construire. On lui fait un répertoire de travail :

```text
$ mkdir -v cmatrix
mkdir: created directory 'cmatrix'
$ cd cmatrix/
$ vim Dockerfile
```

L'instruction `FROM` donne l'image de base pour toutes les instructions qui suivent :

```dockerfile
FROM alpine
```

Pour les métadonnées, la bonne pratique est l'instruction `LABEL`, avec les clés **standard** de l'Open Container Initiative — l'auteur de l'image, puis une description succincte :

```dockerfile
LABEL org.opencontainers.image.authors="Nicolas Kovacs"
LABEL org.opencontainers.image.description="Container image for CMatrix"
```

## 3. Un premier jet et un conteneur

L'image ne fait encore rien, mais rien n'empêche d'en construire un premier jet :

```text
$ docker build -t kikinovak/cmatrix .
$ docker images
REPOSITORY          TAG       IMAGE ID       CREATED      SIZE
alpine              latest    706db57fb206   7 days ago   8.32MB
kikinovak/cmatrix   latest    6ffa90735c23   7 days ago   8.32MB
```

Les deux images ont **la même taille** : on n'a ajouté que des métadonnées.

On démarre ensuite un conteneur basé sur cette image, pour y compiler CMatrix à la main, **par tentative et échec** :

```text
$ docker run --rm -it kikinovak/cmatrix sh
/ #
```

- `--rm` supprime le conteneur dès qu'il s'arrête ;
- `-it` donne un shell interactif ;
- `sh` : Alpine est plus exigeante qu'une Debian ou une Ubuntu — au départ, pas même de shell Bash, et la plupart des outils habituels sont absents.

## 4. Compiler CMatrix pas à pas

Dans le conteneur, on avance à tâtons. C'est tout à fait normal de rencontrer une succession d'obstacles : chacun dit ce qui manque.

**Récupérer le code source.** `git` n'est pas installé :

```text
/ # git clone https://github.com/abishekvashok/cmatrix
sh: git: not found
```

Alpine installe ses paquets avec **APK** (*Alpine Package Keeper*) :

```text
/ # apk update
/ # apk add git
/ # git clone https://github.com/abishekvashok/cmatrix
Cloning into 'cmatrix'...
/ # cd cmatrix/
```

**Préparer la compilation.** Chaque obstacle se lève en installant ce qui manque :

| On lance | Le shell répond | On installe |
|---|---|---|
| `autoreconf -i` | `autoreconf: not found` | `apk add autoconf` |
| `autoreconf -i` | `Can't exec "aclocal"` | `apk add automake` |
| `./configure LDFLAGS="-static"` | `no acceptable C compiler found` | `apk add alpine-sdk` |

`autoreconf -i` finit par afficher un gloubi-boulga d'avertissements — inquiétant à première vue. Pour en avoir le cœur net, on affiche le **code retour** de la dernière commande : `0` veut dire qu'elle a réussi.

```text
/cmatrix # echo $?
0
```

`LDFLAGS="-static"` demande un **binaire statique**, qui contient toutes les dépendances nécessaires à son exécution. Sous Alpine, les compilateurs viennent du méta-paquet `alpine-sdk` (*Software Development Kit*) — et la taille des paquets installés grimpe : on passe de quelques mégaoctets à près de 300.

**Les deux détails.** `./configure` passe enfin, mais signale deux manques : deux répertoires de polices, et la bibliothèque NCurses.

```text
/cmatrix # mkdir -pv /usr/lib/kbd/consolefonts
/cmatrix # mkdir -pv /usr/share/consolefonts
/cmatrix # apk add ncurses-dev ncurses-static
```

Au passage, `apk` installe `ncurses-terminfo-base` : ce paquet sera une **dépendance d'exécution** de CMatrix, on en reparlera.

**Compiler.** On relance `./configure LDFLAGS="-static"`, puis :

```text
/cmatrix # make
...
gcc  -g -O2  -static -o cmatrix cmatrix.o  -lncurses  -lncurses
/cmatrix # ls -lh ./cmatrix
-rwxr-xr-x    1 root     root      777.9K Oct 18 13:39 ./cmatrix
/cmatrix # ./cmatrix
```

Les caractères défilent ; **Q** quitte CMatrix.

::exemple{id="cc-ex-obstacle" titre="Lire un obstacle" pour="Savoir quoi installer quand une commande échoue dans un conteneur minimal"}
```text
/ # git clone https://github.com/abishekvashok/cmatrix
sh: git: not found
```

Le shell ne trouve pas `git` : il manque le **programme**, pas le dépôt. Sous Alpine, le paquet porte le nom de la commande — `apk add git`, après un `apk update` qui rafraîchit la liste des paquets. Même lecture pour `autoreconf: not found`, sauf que la commande `autoreconf` vient du paquet `autoconf` : il faut parfois chercher le nom du paquet.
::

## 5. Enregistrer les étapes

CMatrix est compilé. Pour retrouver la procédure, il suffit d'afficher l'**historique** du shell :

```text
/cmatrix # history
   0 git clone https://github.com/abishekvashok/cmatrix
   1 apk update
   2 apk add git
   3 git clone https://github.com/abishekvashok/cmatrix
   4 cd cmatrix/
   ...
  17 apk add ncurses-dev ncurses-static
  18 ./configure LDFLAGS="-static"
  19 make
  20 ls -lh ./cmatrix
  21 ./cmatrix
  22 history
```

On copie cet historique dans le presse-papier, puis on quitte le conteneur. **Gare à la suppression** : il a été lancé avec `--rm`, donc l'arrêt le supprime — tout ce qu'on y a installé et compilé part au paradis des octets. Il ne reste que l'historique copié, qu'on colle tel quel à la suite des trois premières instructions du `Dockerfile`. Le transformer en `Dockerfile` propre et efficace, c'est l'atelier suivant.

FROM alpine

::extrait-cours{id="cc-premier-jet" titre="Un premier jet et un conteneur" source="/cours/a1/virtualisation-conteneurisation/cmatrix-compilation/atelier#_3-un-premier-jet-et-un-conteneur"}

docker build -t kikinovak/cmatrix .

Avec seulement `FROM` et `LABEL`, l'image pèse autant qu'Alpine. `--rm` supprime le conteneur à l'arrêt ; `sh` parce qu'Alpine n'a pas Bash.

::extrait-cours{id="cc-compiler" titre="Compiler CMatrix pas à pas" source="/cours/a1/virtualisation-conteneurisation/cmatrix-compilation/atelier#_4-compiler-cmatrix-pas-à-pas"}
```bash
apk update
apk add git
git clone https://github.com/abishekvashok/cmatrix
cd cmatrix/
apk add autoconf automake       # autoreconf, puis aclocal
autoreconf -i
echo $?                         # 0 : succès
apk add alpine-sdk              # les compilateurs
mkdir -pv /usr/lib/kbd/consolefonts
mkdir -pv /usr/share/consolefonts
apk add ncurses-dev ncurses-static
./configure LDFLAGS="-static"   # un binaire statique
make
./cmatrix                       # Q pour quitter
```

`history` affiche les commandes tapées dans le shell : on les copie avant de quitter, car un conteneur lancé avec `--rm` est **supprimé à l'arrêt**, avec tout ce qu'on y a installé. L'historique, collé à la suite de `FROM` et `LABEL`, sera la matière première du `Dockerfile`.
