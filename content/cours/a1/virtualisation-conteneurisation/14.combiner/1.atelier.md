::rappel{titre="Les commandes de l'atelier" icone="i-lucide-boxes"}
| Commande ou option | Ce qu'elle fait |
|---|---|
| `docker network create blog-wordpress` | crée le réseau commun aux trois conteneurs |
| `--network blog-wordpress` | branche un conteneur sur ce réseau |
| `--name mariadb` | nomme le conteneur — c'est par ce nom que les autres le joignent |
| `-h mariadb` | fixe le nom d'hôte du conteneur |
| `-e CLE=valeur` | passe une variable d'environnement (une option par variable) |
| `-v blog-db-volume:/var/lib/mysql` | monte un volume nommé, créé au besoin |
| `-p 8080:80` | publie un port du conteneur sur l'hôte |
| `docker stop mariadb phpmyadmin wordpress` | arrête les trois d'un coup ; `start` et `rm` de même |
| `docker pull mariadb` | récupère la dernière version d'une image |

| Image | Variables |
|---|---|
| `mariadb` | `MYSQL_RANDOM_ROOT_PASSWORD`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD` |
| `phpmyadmin` | `PMA_HOST` |
| `wordpress` | `WORDPRESS_DB_HOST`, `WORDPRESS_DB_USER`, `WORDPRESS_DB_NAME`, `WORDPRESS_DB_PASSWORD` |
::

On revient sur l'installation de WordPress, cette fois avec trois conteneurs aux images toutes faites : **MariaDB** pour la base, **PHPMyAdmin** pour l'administrer depuis un navigateur, et **WordPress**. Monter un tel ensemble à la main a surtout une vertu pédagogique : en pratique, on le décrit avec `docker compose` — c'est l'atelier suivant.

## 1. Un réseau et une base MariaDB

Les trois conteneurs communiqueront par un réseau Docker à eux :

```text
$ docker network create blog-wordpress
```

On lance ensuite MariaDB, un peu autrement que dans l'atelier sur les réseaux :

```text
$ docker run -d --name mariadb \
  -h mariadb \
  --network blog-wordpress \
  -e MYSQL_RANDOM_ROOT_PASSWORD=1 \
  -e MYSQL_DATABASE=wp \
  -e MYSQL_USER=wpuser \
  -e MYSQL_PASSWORD=motdepasse \
  -v blog-db-volume:/var/lib/mysql \
  mariadb
```

- Au lancement, MariaDB crée une base vide `wp` et un utilisateur `wpuser` qui y a accès — l'image initialise la base dès qu'on lui passe `MYSQL_DATABASE`, `MYSQL_USER` et `MYSQL_PASSWORD`. PHPMyAdmin et WordPress utiliseront ce compte.
- Personne n'a besoin du mot de passe `root` : `MYSQL_RANDOM_ROOT_PASSWORD=1` en fait tirer un au hasard.
- `-h mariadb` donne au conteneur son **nom d'hôte**.
- `-v blog-db-volume:/var/lib/mysql` monte un volume nommé `blog-db-volume`, que Docker crée s'il n'existe pas : les données de la base survivent au conteneur.
- Un mot de passe « bidon » écrit en clair n'est pas idéal pour la sécurité ; on s'en contente ici.
- Les `\` en fin de ligne prolongent la commande sur la suivante : c'est **une seule** commande, découpée pour se lire.

## 2. PHPMyAdmin

PHPMyAdmin, l'interface web d'administration de MariaDB, se lance sur le même réseau :

```text
$ docker run -d --name phpmyadmin \
  -h phpmyadmin \
  --network blog-wordpress \
  -p 8080:80 \
  -e PMA_HOST=mariadb \
  phpmyadmin
```

- `--network` le met en relation avec les autres conteneurs du réseau `blog-wordpress`.
- `-p 8080:80` publie son interface web sur le port 8080 de l'hôte.
- `PMA_HOST` donne le **nom d'hôte du serveur MariaDB** sur le réseau. Les réseaux Docker résolvent les noms en interne : un conteneur se joint par le nom donné avec `--name`.

À l'adresse `http://localhost:8080`, on se connecte avec `wpuser` et `motdepasse`, et l'on peut interroger ou créer les tables de la base `wp`.

## 3. WordPress

Dernière brique :

```text
$ docker run -d --name wordpress \
  -h wordpress \
  --network blog-wordpress \
  -v blog-wp-volume:/var/www/html/wp-content \
  -p 80:80 \
  -e WORDPRESS_DB_HOST=mariadb \
  -e WORDPRESS_DB_USER=wpuser \
  -e WORDPRESS_DB_NAME=wp \
  -e WORDPRESS_DB_PASSWORD=motdepasse \
  wordpress
```

- `--network` relie ce conteneur au réseau `blog-wordpress`.
- L'installateur s'affiche sur le port 80 de l'hôte, à `http://localhost`.
- Le volume `blog-wp-volume`, monté sur `/var/www/html/wp-content`, garde les données du blog : images téléversées, extensions…
- Les quatre variables `WORDPRESS_DB_…` permettent la connexion à la base ; comme pour PHPMyAdmin, l'hôte de la base est le **nom** donné à MariaDB avec `--name`.

Il ne reste qu'à choisir la langue du blog et à définir son administrateur. Comparée à une installation manuelle — installer et configurer un à un tous les composants —, la procédure est bien plus rapide.

## 4. Arrêter, redémarrer, mettre à jour

On n'a pas toujours besoin des trois conteneurs. `docker stop` et `docker start` les prennent tous à la fois :

```text
$ docker stop mariadb phpmyadmin wordpress
$ docker start mariadb phpmyadmin wordpress
```

Quand une nouvelle version des images paraît, on **remplace** les conteneurs. On les arrête et on les supprime, on récupère les images à jour, puis on relance :

```text
$ docker stop mariadb phpmyadmin wordpress
$ docker rm mariadb phpmyadmin wordpress
$ docker pull mariadb
$ docker pull phpmyadmin/phpmyadmin
$ docker pull wordpress
```

Les données, elles, sont dans les volumes : supprimer les conteneurs ne les touche pas.

- **MariaDB** n'a plus à être initialisé : la base existe déjà dans `blog-db-volume`. Il se relance sans ses variables :

  ```text
  $ docker run -d --name mariadb \
    -h mariadb \
    --network blog-wordpress \
    -v blog-db-volume:/var/lib/mysql \
    mariadb
  ```

- **PHPMyAdmin** se relance exactement comme au premier jour.
- **WordPress** aussi, variables `WORDPRESS_DB_…` comprises. Son fichier de configuration `wp-config.php` n'est **pas** rangé sous `wp-content`, dans les données persistantes : il est régénéré à chaque lancement, et il a besoin de ces variables pour l'être.

  -h web \
  --network blognet \
  -v webvol:/var/www/html/wp-content \
  -p 9000:80 \
  -e WORDPRESS_DB_HOST=db \
  -e WORDPRESS_DB_USER=bloguser \

Le blog s'ouvre à `http://localhost:9000`, PHPMyAdmin à `http://localhost:9090`.

::extrait-cours{id="co-mariadb" titre="Un réseau et une base MariaDB" source="/cours/a1/virtualisation-conteneurisation/combiner/atelier#_1-un-réseau-et-une-base-mariadb"}
```bash
docker network create blog-wordpress
docker run -d --name mariadb \
  -h mariadb \
  --network blog-wordpress \
  -e MYSQL_RANDOM_ROOT_PASSWORD=1 \
  -e MYSQL_DATABASE=wp \
  -e MYSQL_USER=wpuser \
  -e MYSQL_PASSWORD=motdepasse \
  -v blog-db-volume:/var/lib/mysql \
  mariadb
```

- `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD` : la base et le compte créés au lancement.
- `MYSQL_RANDOM_ROOT_PASSWORD=1` : un mot de passe `root` tiré au hasard, dont personne n'a besoin.
- `-h` : le nom d'hôte ; `-v nom:chemin` : un volume nommé, créé au besoin.
::

::extrait-cours{id="co-phpmyadmin" titre="PHPMyAdmin" source="/cours/a1/virtualisation-conteneurisation/combiner/atelier#_2-phpmyadmin"}
```bash
docker run -d --name phpmyadmin \
  -h phpmyadmin \
  --network blog-wordpress \
  -p 8080:80 \
  -e PMA_HOST=mariadb \
  phpmyadmin
```

`PMA_HOST` : le **nom** du serveur MariaDB sur le réseau — celui donné par `--name`, que le réseau résout.
::

::extrait-cours{id="co-wordpress" titre="WordPress" source="/cours/a1/virtualisation-conteneurisation/combiner/atelier#_3-wordpress"}
```bash
docker run -d --name wordpress \
  -h wordpress \
  --network blog-wordpress \
  -v blog-wp-volume:/var/www/html/wp-content \
  -p 80:80 \
  -e WORDPRESS_DB_HOST=mariadb \
  -e WORDPRESS_DB_USER=wpuser \
  -e WORDPRESS_DB_NAME=wp \
  -e WORDPRESS_DB_PASSWORD=motdepasse \
  wordpress
```

Le volume garde `wp-content` (images, extensions) ; les variables `WORDPRESS_DB_…` donnent l'hôte, l'utilisateur, la base et le mot de passe.
::

::extrait-cours{id="co-maj" titre="Arrêter, redémarrer, mettre à jour" source="/cours/a1/virtualisation-conteneurisation/combiner/atelier#_4-arrêter-redémarrer-mettre-à-jour"}
```bash
docker stop mariadb phpmyadmin wordpress
docker start mariadb phpmyadmin wordpress
docker rm mariadb phpmyadmin wordpress
docker pull mariadb
```

Mettre à jour, c'est remplacer les conteneurs : arrêter, supprimer, tirer les images neuves, relancer. Les volumes gardent les données. MariaDB se relance **sans** ses variables (la base existe) ; WordPress **avec**, car `wp-config.php` est régénéré à chaque lancement.
::
