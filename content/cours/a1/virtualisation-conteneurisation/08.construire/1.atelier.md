## 1. Les instructions d'un Dockerfile

Un `Dockerfile` est la recette d'une image : un fichier texte, qu'on nomme de préférence `Dockerfile`, dont chaque ligne est une **instruction**. Voici celles qu'on y rencontre :

| Instruction | Rôle |
|---|---|
| `FROM` | l'image de départ, sur laquelle on se base |
| `CMD` | la commande exécutée au lancement ; ou l'argument par défaut d'`ENTRYPOINT` |
| `RUN` | exécute une commande qui contribue à **construire** l'image |
| `EXPOSE` | ouvre un ou plusieurs ports du réseau |
| `VOLUME` | crée un point de montage |
| `COPY` | ajoute un fichier dans l'image |
| `LABEL` | ajoute des métadonnées, en paires clé/valeur |
| `ENV` | définit une variable d'environnement |
| `ENTRYPOINT` | l'exécutable lancé au démarrage du conteneur ; `CMD` lui passe ses options |

`RUN` agit **une fois**, quand on construit l'image ; `CMD` et `ENTRYPOINT` agissent à **chaque** démarrage d'un conteneur.

## 2. ENTRYPOINT et CMD

Un `Dockerfile` qui illustre la différence subtile entre les deux :

```dockerfile
FROM rockylinux:8
LABEL maintainer="Microlinux <info@microlinux.fr>"
ENTRYPOINT ["/usr/bin/ping"]
CMD ["www.docker.com"]
```

- `ENTRYPOINT` fait exécuter `/usr/bin/ping` au démarrage du conteneur ;
- `CMD` fournit `www.docker.com` comme **argument** à `ENTRYPOINT` ;
- au final, le conteneur exécute `/usr/bin/ping www.docker.com`.

Les deux instructions s'écrivent ici en **tableau JSON** : des crochets, et chaque élément entre guillemets doubles.

La valeur de `CMD` n'est qu'une valeur **par défaut** : ce qu'on écrit après l'image, dans `docker run`, la remplace.

```text
$ docker run kikinovak/dockerping
PING d1syzps6kort6n.cloudfront.net (52.222.174.72) 56(84) bytes of data.
$ docker run kikinovak/dockerping google.fr
PING google.fr (142.250.74.227) 56(84) bytes of data.
```

`ENTRYPOINT` reste `ping` ; seul l'argument change. **Ctrl + C** arrête le ping.

::exemple{id="bd-ex-entrypoint" titre="Ce que lance vraiment le conteneur" pour="Prévoir la commande exécutée à partir d'ENTRYPOINT, CMD et docker run"}
Avec `ENTRYPOINT ["/usr/bin/ping"]` et `CMD ["www.docker.com"]` :

| On lance | Le conteneur exécute |
|---|---|
| `docker run kikinovak/dockerping` | `/usr/bin/ping www.docker.com` |
| `docker run kikinovak/dockerping google.fr` | `/usr/bin/ping google.fr` |

On colle `ENTRYPOINT` devant ; on prend `CMD`, sauf si `docker run` donne autre chose après l'image.
::

## 3. Construire et publier une image

La commande `docker build` construit l'image :

```text
$ docker build -t kikinovak/dockerping:latest .
```

- `-t` donne un **nom** et un **tag** à l'image ;
- le nom suit le format **identifiant Docker** / **nom du dépôt** : **tag** ; sans tag, `latest` est présumé ;
- le point `.` dit à `docker build` où trouver le `Dockerfile` : dans le **répertoire courant**.

```text
$ docker image ls
REPOSITORY             TAG       IMAGE ID       CREATED         SIZE
kikinovak/dockerping   latest    b06be6abe1c9   6 minutes ago   197MB
rockylinux             8         4e97feadb276   5 weeks ago     197MB
```

Deux images : Docker a d'abord téléchargé l'image de base `rockylinux:8`, celle de l'instruction `FROM`, puis exécuté les instructions du `Dockerfile` pour créer `kikinovak/dockerping`.

Pour la publier sur Docker Hub, on s'authentifie, puis on la pousse :

```text
$ docker login -u kikinovak
$ docker push kikinovak/dockerping
Using default tag: latest
The push refers to repository [docker.io/kikinovak/dockerping]
b9674b668e06: Mounted from library/rockylinux
latest: digest: sha256:8fd30a6170de239ec761b42cc3a7b91412c0... size: 529
```

La couche de Rocky Linux est déjà sur Docker Hub (`Mounted from library/rockylinux`) : seul ce qu'on a ajouté est envoyé.

## 4. Ajouter un logiciel à l'image

Dans `dockerping`, la commande `ping` était déjà dans l'image de base. Ce n'est pas toujours le cas — sous Debian, elle manque :

```text
$ docker run -it --name debianping debian:latest
root@c098cce01e95:/# ping docker.com
bash: ping: command not found
root@c098cce01e95:/# apt update
root@c098cce01e95:/# apt install iputils-ping
root@c098cce01e95:/# ping docker.com
PING docker.com (141.193.213.20) 56(84) bytes of data.
```

Ce qu'on vient de faire à la main, le `Dockerfile` le fait à la construction :

```dockerfile
FROM debian:latest
LABEL maintainer="Microlinux <info@microlinux.fr>"
RUN apt-get update \
    && apt-get install -y iputils-ping \
    && apt-get clean
ENTRYPOINT ["/usr/bin/ping"]
CMD ["www.docker.com"]
```

- Debian a deux gestionnaires de paquets : `apt`, plutôt pour un usage interactif, et `apt-get`, plutôt pour les scripts ;
- les commandes `apt-get` sont regroupées en **une seule** instruction `RUN` par `&&` : une seule couche au-dessus de l'image de base. Plusieurs `RUN` marcheraient, mais chacune ajouterait une couche ;
- `-y` répond oui d'avance : à la construction, personne n'est là pour taper « o » ;
- l'antislash `\` en fin de ligne ne sert qu'à la lisibilité ;
- `apt-get clean` supprime les paquets téléchargés, et réduit la taille de l'image.

```text
$ docker build -t kikinovak/debianping .
$ docker run kikinovak/debianping
$ docker push kikinovak/debianping
```

:::exo-question{label="1." cours="bd-build"}
Connecte-toi à Docker Hub.

::commande
---
attendues:
  - docker login -u etudiant42
---
::

#indice
`docker login`, l'option du nom d'utilisateur.

#solution
```bash
docker login -u etudiant42
```
:::

:::exo-question{label="2." cours="bd-build"}
Donne à `nettools:latest` le nom `etudiant42/nettools:latest`, puis publie-la — deux commandes, une par ligne.

::commande
---
attendues:
  - |-
    docker tag nettools:latest etudiant42/nettools:latest
    docker push etudiant42/nettools:latest
---
::

#indice
`docker tag` prend l'image source puis le nouveau nom ; `docker push` prend le nouveau nom.

#solution
```bash
docker tag nettools:latest etudiant42/nettools:latest
docker push etudiant42/nettools:latest
```

`docker tag nettools etudiant42/nettools` revient au même : `latest` est sous-entendu.
:::

:::exo-question{label="3." cours="bd-build"}
Fais de même pour `rockyvim:8`, en gardant son tag.

::commande
---
attendues:
  - |-
    docker tag rockyvim:8 etudiant42/rockyvim:8
    docker push etudiant42/rockyvim:8
---
::

#indice
Cette fois, le tag n'est pas `latest` : il faut l'écrire des deux côtés.

#solution
```bash
docker tag rockyvim:8 etudiant42/rockyvim:8
docker push etudiant42/rockyvim:8
```
:::

::extrait-cours{id="bd-instructions" titre="Les instructions d'un Dockerfile" source="/cours/a1/virtualisation-conteneurisation/construire/atelier#_1-les-instructions-dun-dockerfile"}
`FROM` (image de départ), `RUN` (une commande à la **construction**), `CMD` (la commande par défaut au démarrage), `ENTRYPOINT` (l'exécutable lancé au démarrage), `EXPOSE` (un port), `VOLUME` (un point de montage), `COPY` (un fichier), `LABEL` (des métadonnées clé/valeur), `ENV` (une variable d'environnement).

```dockerfile
FROM rockylinux:8
LABEL maintainer="Microlinux <info@microlinux.fr>"
EXPOSE 80
```
::

::extrait-cours{id="bd-entrypoint" titre="ENTRYPOINT et CMD" source="/cours/a1/virtualisation-conteneurisation/construire/atelier#_2-entrypoint-et-cmd"}
```dockerfile
ENTRYPOINT ["/usr/bin/ping"]
CMD ["www.docker.com"]
```

Le conteneur exécute `/usr/bin/ping www.docker.com`. Ce qu'on écrit après l'image dans `docker run` **remplace `CMD`** : `docker run kikinovak/dockerping google.fr` exécute `/usr/bin/ping google.fr`. Seul, `CMD ["/bin/bash"]` donne la commande par défaut.
::

::extrait-cours{id="bd-build" titre="Construire et publier une image" source="/cours/a1/virtualisation-conteneurisation/construire/atelier#_3-construire-et-publier-une-image"}
```bash
docker build -t kikinovak/dockerping:latest .   # le point : le Dockerfile du répertoire courant
docker login -u kikinovak
docker push kikinovak/dockerping
```

Le nom : identifiant Docker / dépôt : tag (`latest` par défaut). Une image locale se renomme pour Docker Hub avec `docker tag source identifiant/dépôt:tag`.

::extrait-cours{id="bd-logiciel" titre="Ajouter un logiciel à l'image" source="/cours/a1/virtualisation-conteneurisation/construire/atelier#_4-ajouter-un-logiciel-à-limage"}
Installé à la main dans un conteneur (`apt update`, `apt install iputils-ping`), un logiciel ne vit que dans ce conteneur. Dans l'image :

```dockerfile
RUN apt-get update \
    && apt-get install -y iputils-ping \
    && apt-get clean
```

Une seule instruction `RUN` (une seule couche), `apt-get` pour les scripts, `-y` pour ne rien demander, `apt-get clean` pour alléger l'image. Sous Rocky Linux : `dnf install -y`.
