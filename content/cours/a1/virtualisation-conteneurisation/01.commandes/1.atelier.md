::rappel{titre="Les commandes de l'atelier" icone="i-lucide-terminal"}
| Commande | Ce qu'elle fait |
|---|---|
| `docker run -dit alpine` | lance un conteneur Alpine en arrière-plan, entrée standard ouverte et terminal attaché |
| `docker ps` | liste les conteneurs **en cours d'exécution** |
| `docker ps -a` | liste **aussi** les conteneurs arrêtés |
| `docker stop <id ou nom>` | arrête un conteneur |
| `docker start <id ou nom>` | relance un conteneur arrêté |
| `docker images` ou `docker image ls` | liste les images téléchargées |
| `docker inspect <id ou nom>` | affiche tout le détail d'un conteneur |
| `docker --help`, `docker image --help` | l'aide en ligne, générale ou d'une sous-commande |

Un conteneur se désigne au choix par son **ID complet** (douze caractères dans `docker ps`), par un **début d'ID** qui suffit à lever l'ambiguïté, ou par son **nom**.
::

## 1. Lancer un conteneur

La commande `docker run` démarre un conteneur à partir d'une **image**. Lançons un conteneur Alpine Linux :

```text
$ docker run -dit alpine
Unable to find image 'alpine:latest' locally
latest: Pulling from library/alpine
31e352740f53: Pull complete
Digest: sha256:82d1e9d7ed48a7523bdebc18cf6290bdb97b82302a8a9c27d4fe885949ea94d1
Status: Downloaded newer image for alpine:latest
ee69d5c92d4dff5e752e8c0070afe6e85f8ef5fc0df2fbbdefc8ffe51e63c320
```

- Les deux premières lignes disent que Docker **n'a pas l'image** sur la machine : il la télécharge depuis le dépôt d'images par défaut, **Docker Hub**. Faute de tag, il prend `latest`.
- Une fois l'image récupérée, il démarre un conteneur qui l'utilise.
- La dernière ligne est l'**identifiant** (l'ID) du conteneur. C'est le signe qu'il a démarré : sans ID, il y a eu un problème.

Les trois options, qu'on groupe derrière un seul tiret :

- `-d` (*detach*) fait tourner le conteneur **en arrière-plan** — Docker affiche alors son ID et rend la main ;
- `-i` (*interactive*) garde l'**entrée standard** ouverte, même quand on n'est pas attaché au conteneur ;
- `-t` (*terminal*) lui attribue un **terminal**, indispensable pour interagir avec un shell.

`docker run -dit alpine`, `docker run -it -d alpine` et `docker run -i -t -d alpine` sont **la même commande** : l'ordre des options ne compte pas. Ce qui compte, c'est qu'elles soient placées **avant** l'image.

::exemple{id="cb-ex-run" titre="Lire la réponse de docker run" pour="Savoir, d'un coup d'œil, si le conteneur a démarré et si l'image a été téléchargée"}
On lance un deuxième conteneur Alpine, juste après le premier :

```text
$ docker run -dit alpine
6b238bee1856b02fec058d82dfc631d48e368993f36b4f33cb8fa7e3f2925222
```

Cette fois, **pas de téléchargement** : l'image `alpine:latest` est déjà sur la machine. Docker démarre directement un nouveau conteneur, distinct du premier — un autre ID. Une image sert autant de conteneurs qu'on veut.
::

## 2. Lister les conteneurs

La commande `docker ps` vérifie que le conteneur tourne :

```text
$ docker ps
CONTAINER ID  IMAGE   COMMAND    CREATED        STATUS        PORTS  NAMES
57c00f853a75  alpine  "/bin/sh"  3 minutes ago  Up 2 minutes         hardcore_mccarthy
```

| Colonne | Exemple | Ce qu'elle dit |
|---|---|---|
| `CONTAINER ID` | `57c00f853a75` | l'ID, abrégé à douze caractères |
| `IMAGE` | `alpine` | l'image dont le conteneur est issu |
| `COMMAND` | `"/bin/sh"` | la commande avec laquelle il a démarré |
| `CREATED` | `3 minutes ago` | sa date de création |
| `STATUS` | `Up 2 minutes` | depuis quand il tourne |
| `PORTS` | | ses ports (atelier « Exposer un conteneur ») |
| `NAMES` | `hardcore_mccarthy` | son nom, lisible par un humain — tiré au hasard par Docker |

`docker ps` n'affiche **que** les conteneurs en cours d'exécution. Pour voir aussi ceux qui sont **arrêtés**, on ajoute `-a` (*all*) : `docker ps -a`.

::exemple{id="cb-ex-ps" titre="Le conteneur qui disparaît de docker ps" pour="Ne pas croire supprimé un conteneur qui est seulement arrêté"}
```text
$ docker stop hardcore_mccarthy
hardcore_mccarthy
$ docker ps
CONTAINER ID   IMAGE     COMMAND   ...  NAMES
$ docker ps -a
CONTAINER ID   IMAGE     COMMAND     ...  NAMES
57c00f853a75   alpine    "/bin/sh"   ...  hardcore_mccarthy
```

Après l'arrêt, `docker ps` est vide, mais le conteneur existe toujours : `docker ps -a` le montre. On pourra le relancer.
::

## 3. Arrêter et relancer un conteneur

On arrête un conteneur avec `docker stop`, on le relance avec `docker start`. Les deux prennent le conteneur à viser, désigné de trois façons :

```text
$ docker stop 57c00f853a75
57c00f853a75
$ docker start 57c0
57c0
$ docker stop hardcore_mccarthy
hardcore_mccarthy
```

- par l'**ID** affiché dans `docker ps` ;
- par un **début d'ID** : il suffit de taper assez de caractères pour lever l'ambiguïté entre les conteneurs présents — trois ou quatre en pratique ;
- par le **nom** lisible, que la touche **Tab** complète automatiquement.

Docker répond en répétant ce qu'on lui a donné : c'est le signe que l'opération a réussi.

## 4. Pourquoi détacher un conteneur

Voici comment il ne faut **pas** lancer un conteneur :

```text
$ docker run debian
$ docker ps
CONTAINER ID   IMAGE   COMMAND   ...  NAMES
```

Le conteneur a démarré, puis s'est **arrêté aussitôt** : Docker traite le logiciel du conteneur comme un processus, et le conteneur vit tant que ce processus vit. Le shell de Debian, sans terminal ni entrée standard, n'a rien à faire et se termine. D'où les options `-d`, `-i` et `-t`, qui le gardent en vie en arrière-plan.

Certains conteneurs sont **faits** pour s'arrêter tout de suite : ils accomplissent une seule tâche, puis rendent la main. C'est le cas de l'image `hello-world`, qu'on lance pour vérifier que Docker fonctionne :

```text
$ docker run hello-world
Unable to find image 'hello-world:latest' locally
latest: Pulling from library/hello-world
Status: Downloaded newer image for hello-world:latest

Hello from Docker!
This message shows that your installation appears to be working correctly.
```

::::exercice{titre="Au terminal — détacher ou non" theme="Ce qui garde un conteneur en vie"}

#a
Vraie

#b

#indice
Un conteneur vit tant que son processus principal vit. Que fait un shell qui n'a ni terminal ni entrée standard ?

#solution
**Fausse.** Le conteneur démarre, son shell se termine aussitôt faute de terminal et d'entrée, et le conteneur s'arrête avec lui : `docker ps` ne le montre pas, `docker ps -a` le montre arrêté (`Exited`). Pour qu'il reste en vie, on le lance avec `-dit`.
:::

#solution
```bash

```

Le conteneur s'exécute **au premier plan**, affiche son message, puis s'arrête : il n'a qu'une tâche, et l'a accomplie.

## 5. Lister les images locales

Les images téléchargées par Docker se listent avec `docker images` — ou, ce qui revient au même, `docker image ls` :

```text
$ docker images
REPOSITORY    TAG     IMAGE ID      CREATED       SIZE
ubuntu        latest  2b4cba85892a  6 days ago    72.8MB
debian        latest  d40157244907  9 days ago    124MB
alpine        latest  c059bfaa849c  3 months ago  5.59MB
hello-world   latest  feb5d9fea6a5  5 months ago  13.3kB
```

Ne pas confondre : `docker ps` liste les **conteneurs**, `docker images` les **images** dont ils sont issus. Une image Alpine de 5,59 Mo peut servir à cent conteneurs.

## 6. Inspecter un conteneur

`docker inspect` affiche **tout** ce que Docker sait d'un conteneur — son image, sa configuration, son réseau, ses montages —, au format JSON. La sortie est longue : on la fait défiler avec `less`.

```text
$ docker run -dit alpine
6b238bee1856b02fec058d82dfc631d48e368993f36b4f33cb8fa7e3f2925222
$ docker ps
CONTAINER ID  IMAGE   COMMAND    CREATED        ...  NAMES
6b238bee1856  alpine  "/bin/sh"  5 seconds ago  ...  wizardly_chatelet
$ docker inspect 6b23 | less
```

Le tube `|` envoie la sortie de `docker inspect` à `less`, qui l'affiche page par page (**q** pour quitter). On apprendra plus tard à n'en extraire que ce qui nous intéresse.

## 7. L'aide en ligne

Toutes les commandes Docker ont leur aide, à trois niveaux :

```text
$ docker --help | less          # l'aide générale : la liste des sous-commandes
$ docker image --help           # l'aide d'une sous-commande : image, network, volume…
$ docker image prune --help     # l'aide d'une sous-commande de sous-commande
```

C'est dans l'aide qu'on trouve, par exemple, que `docker rmi` accepte `-f` pour forcer une suppression. Le jour où une option échappe, `--help` la retrouve.

::extrait-cours{id="cb-run" titre="Lancer un conteneur" source="/cours/a1/virtualisation-conteneurisation/commandes/atelier#_1-lancer-un-conteneur"}
```bash
docker run -dit alpine
```

- Si l'image n'est pas sur la machine, Docker la **télécharge** depuis Docker Hub ; sans tag, il prend `latest` — et échoue si l'image n'a pas de tag `latest` (préciser alors `image:tag`, comme `rockylinux:9`).
- `-d` : en arrière-plan ; `-i` : entrée standard ouverte ; `-t` : un terminal.
- Les options se groupent et s'ordonnent librement, mais se placent **avant** l'image.
- La dernière ligne de la réponse est l'**ID** du conteneur : sans ID, le lancement a échoué.
::

::extrait-cours{id="cb-ps" titre="Lister les conteneurs" source="/cours/a1/virtualisation-conteneurisation/commandes/atelier#_2-lister-les-conteneurs"}
- `docker ps` : les conteneurs **en cours d'exécution** seulement.
- `docker ps -a` : **tous** les conteneurs, y compris les arrêtés (`STATUS` à `Exited`).

Colonnes : `CONTAINER ID` (douze caractères), `IMAGE`, `COMMAND`, `CREATED`, `STATUS`, `PORTS`, `NAMES` (le nom lisible, tiré au hasard si on n'en donne pas).
::

::extrait-cours{id="cb-stop-start" titre="Arrêter et relancer un conteneur" source="/cours/a1/virtualisation-conteneurisation/commandes/atelier#_3-arrêter-et-relancer-un-conteneur"}
```bash
docker stop 57c00f853a75        # par l'ID
docker start 57c0               # par un début d'ID qui lève l'ambiguïté
docker stop hardcore_mccarthy   # par le nom (complété par Tab)
```

Plusieurs conteneurs à la suite : `docker stop nom1 nom2`. Docker répond en répétant ce qu'on lui a donné.
::

::extrait-cours{id="cb-detacher" titre="Pourquoi détacher un conteneur" source="/cours/a1/virtualisation-conteneurisation/commandes/atelier#_4-pourquoi-détacher-un-conteneur"}
Un conteneur vit **tant que son processus principal vit**.

- `docker run debian` : le shell n'a ni terminal ni entrée, il se termine, le conteneur s'arrête aussitôt.
- `docker run -dit debian` : le conteneur reste en vie, en arrière-plan.
- `docker run -it alpine` : on est connecté au shell du conteneur (invite `/ #`) ; `exit` le termine, et le conteneur s'arrête.
- `docker run hello-world` : une tâche unique, puis l'arrêt — c'est voulu.
::

::extrait-cours{id="cb-images" titre="Lister les images locales" source="/cours/a1/virtualisation-conteneurisation/commandes/atelier#_5-lister-les-images-locales"}
```bash
docker images
docker image ls     # la même chose
```

Colonnes : `REPOSITORY`, `TAG`, `IMAGE ID`, `CREATED`, `SIZE`. `docker ps` liste les **conteneurs**, `docker images` les **images**.
