| Commande | Ce qu'elle fait |
|---|---|
| `docker run -dit debian` | lance un conteneur qui reste en vie, en arrière-plan |
| `docker run -dit --name web debian` | lui donne un nom choisi |
| `docker ps -l` | affiche le dernier conteneur créé, quel que soit son état |
| `docker stop web` | arrête le conteneur |
| `docker rm web` | supprime un conteneur arrêté |
| `docker run -dit --restart always debian` | le relance automatiquement (plantage, redémarrage de l'hôte) |
| `docker kill web` | force l'arrêt |
| `docker system prune` | supprime d'un coup les conteneurs arrêtés (et le reste inutilisé) |
| `docker run --rm hello-world` | supprime le conteneur dès qu'il s'arrête |
| `docker logs -tf web` | la sortie du conteneur, horodatée (`-t`) et suivie en direct (`-f`) |

## 1. Garder un conteneur en vie

Un conteneur qui démarre puis s'arrête aussitôt : c'est la surprise de tout débutant. Docker traite le logiciel du conteneur comme **un processus système** ; quand ce processus s'arrête, Docker arrête le conteneur.

L'exécution **au premier plan**, par défaut, convient à un conteneur qui accomplit une tâche unique — télécharger un fichier, le traiter, enregistrer le résultat. Mais un conteneur est en général censé **fournir un service permanent** : on le lance alors détaché.

```text
$ docker run -dit debian
3d631b930885d7e1d135b348bf34c69e002aa9d455f7f438cbcbd4dcff9dbbe8
```

- `-d` détache le conteneur — on dit aussi qu'on le **démonise** : un démon (*daemon*) est un programme qui tourne en arrière-plan, hors du contrôle direct d'un utilisateur ;
- `-i` et `-t` lui donnent un shell interactif, pour pouvoir y accéder ;
- les trois options vont généralement ensemble : `-dit`.

## 2. Donner un nom à un conteneur

Désigner un conteneur par son empreinte `3e03c8cff364` ou par un nom tiré au hasard n'est pas commode. Comme le DNS évite de retenir des adresses IP, l'option `--name` donne au conteneur un **nom parlant** :

```text
$ docker run -dit --name web debian
3e03c8cff364c8a4e3e543c99f1f5ad243fd8877fe4fa2dc80a44cf4c4f2ad24
$ docker ps
CONTAINER ID   IMAGE   ...  STATUS        ...  NAMES
3e03c8cff364   debian  ...  Up 2 seconds  ...  web
c4494c0904c9   debian  ...  Up 3 minutes  ...  fervent_mendel
```

`fervent_mendel` a été nommé au hasard par Docker ; `web`, c'est nous.

Pour retrouver le **dernier** conteneur créé — qu'il tourne encore ou non — on utilise `-l` (*latest*) :

```text
$ docker ps -l
CONTAINER ID   IMAGE     COMMAND   CREATED          ...  NAMES
a50d0ce4292a   debian    "bash"    19 seconds ago   ...  conteneur_trois
```

Un nom est **unique** : tant qu'un conteneur `web` existe, même arrêté, Docker refuse d'en lancer un autre du même nom.

```text
$ docker run -dit --name web debian
docker: Error response from daemon: Conflict.
```

## 3. Arrêter, supprimer, relancer

`docker stop` arrête un conteneur ; `docker ps` ne le montre plus, `docker ps -a` le montre avec le statut `Exited`. `docker start` le relance. `docker rm` le **supprime** pour de bon — et son nom redevient libre.

```text
$ docker stop web
web
$ docker ps -a
CONTAINER ID   ...  STATUS                       ...  NAMES
b47080056050   ...  Exited (137) 4 seconds ago        web
a50d0ce4292a   ...  Up 7 minutes                      conteneur_trois
$ docker start web
web
$ docker stop web
web
$ docker rm web
web
```

::exemple{id="ex-ex-cycle" titre="Arrêter puis supprimer" pour="Libérer un nom ou faire place nette"}
On ne supprime pas un conteneur qui tourne : on l'arrête d'abord.

```text
$ docker stop web
web
$ docker rm web
web
$ docker ps -a
```

`docker ps -a` ne montre plus `web` : il a disparu, et `docker run --name web …` redevient possible.
::

## 4. Redémarrer automatiquement

Si la machine qui fait tourner Docker redémarre, ou si un conteneur plante, on veut souvent qu'il **reparte tout seul**, sans intervention humaine. C'est l'option `--restart` :

```text
$ docker run -dit --restart always --name conteneur_quatre debian
497d59bd57d53ab987a511b7834db3dec43d75cf115d13a78212628319df7439
```

On vérifie la politique de redémarrage en inspectant le conteneur, et en filtrant la sortie avec `grep` :

```text
$ docker inspect conteneur_quatre | grep -A 3 RestartPolicy
  "RestartPolicy": {
    "Name": "always",
    "MaximumRetryCount": 0
  },
```

`-A 3` demande à `grep` d'afficher la ligne trouvée **et les trois suivantes** (voir `man grep`). Toutes les options de `docker run` — elles sont nombreuses — se lisent avec `docker run --help | less`.

## 5. Forcer l'arrêt

Il arrive qu'un conteneur résiste à `docker stop`. Docker affiche alors un avertissement qui permet en général de régler le problème ; sinon, `docker kill` **force** l'arrêt :

```text
$ docker kill tender_ellis
tender_ellis
```

Mise en garde : `docker kill` n'arrête pas le conteneur **proprement**, comme le fait `docker stop`. Rarement, le conteneur peut s'en trouver dans un état qui l'empêche de redémarrer. En règle générale, peu importe : les conteneurs sont conçus pour être **jetables**.

#solution

## 6. Faire le ménage

Supprimer les conteneurs arrêtés un par un avec `docker rm` devient vite fastidieux. `docker system prune` les supprime **d'un coup**, avec les réseaux inutilisés, les images en suspens et le cache de construction :

```text
$ docker system prune
WARNING! This will remove:
- all stopped containers
- all networks not used by at least one container
- all dangling images
- all dangling build cache

Are you sure you want to continue? [y/N] y
Deleted Containers:
4ee29e393a22d286e2a70de462c585cf40fdc27706f275da1fe94b8236ab6aa3
…
```

Mieux encore, on peut faire le ménage **à mesure** : avec `--rm`, Docker supprime le conteneur dès que son processus principal se termine.

```text
$ docker run --rm hello-world

Hello from Docker!
This message shows that your installation appears to be working correctly.
$ docker ps -a
```

Aucune trace du conteneur : il s'est lancé, a affiché son message, s'est arrêté, et Docker l'a supprimé. Utiliser `--rm` au quotidien évite d'encombrer le système.

## 7. Afficher les logs d'un conteneur

Lancé au premier plan, `hello-world` affiche sa sortie dans la console. Lancé **en arrière-plan**, il l'affiche… nulle part. `docker logs` la retrouve :

```text
$ docker run -dit hello-world
b9a9ba3116ec8f6341f313d5133885e28bd2535d341777ae2da...
$ docker logs b9a9

Hello from Docker!
This message shows that your installation appears to be working correctly.
```

Deux options, à retrouver dans `docker logs --help` :

- `-t` ajoute l'**horodatage** de chaque ligne, utile pour déboguer ;
- `-f` (*follow*) suit la sortie **en temps réel**, comme `tail -f` sous Linux.

Elles se combinent : `docker logs -tf 8b5c`.

```text
$ docker logs -t b9a9
2023-06-29T06:52:24.949346103Z Hello from Docker!
2023-06-29T06:52:24.949370149Z This message shows that your installation appears to be working correctly.
```

::extrait-cours{id="ex-concepts" titre="Garder un conteneur en vie" source="/cours/a1/virtualisation-conteneurisation/execution/atelier#_1-garder-un-conteneur-en-vie"}
Docker traite le logiciel du conteneur comme un **processus** : quand il s'arrête, le conteneur s'arrête.

- Au premier plan (par défaut) : pour une tâche unique, comme `hello-world`.
- Pour un service permanent : `docker run -dit debian`. `-d` démonise (arrière-plan), `-i` et `-t` donnent un shell interactif.
::

::extrait-cours{id="ex-nom" titre="Donner un nom à un conteneur" source="/cours/a1/virtualisation-conteneurisation/execution/atelier#_2-donner-un-nom-à-un-conteneur"}
```bash
docker run -dit --name web debian
docker ps -l      # le dernier conteneur créé, arrêté ou non
```

Un nom est unique : tant qu'un conteneur `web` existe, même arrêté, un second `--name web` provoque un `Conflict`.
::

::extrait-cours{id="ex-cycle" titre="Arrêter, supprimer, relancer" source="/cours/a1/virtualisation-conteneurisation/execution/atelier#_3-arrêter-supprimer-relancer"}
```bash
docker stop web    # arrêté : visible seulement dans docker ps -a (Exited)
docker start web   # relancé
docker rm web      # supprimé pour de bon ; le nom est libre
```

On arrête un conteneur avant de le supprimer.
::

::extrait-cours{id="ex-restart" titre="Redémarrer automatiquement" source="/cours/a1/virtualisation-conteneurisation/execution/atelier#_4-redémarrer-automatiquement"}
```bash
docker run -dit --restart always --name conteneur_quatre debian
docker inspect conteneur_quatre | grep -A 3 RestartPolicy
docker run --help | less
```

`--restart always` relance le conteneur après un plantage ou un redémarrage de l'hôte. `grep -A 3` affiche la ligne trouvée et les trois suivantes.
::

::extrait-cours{id="ex-kill" titre="Forcer l'arrêt" source="/cours/a1/virtualisation-conteneurisation/execution/atelier#_5-forcer-larrêt"}
```bash
docker kill tender_ellis
```

Quand `docker stop` échoue. L'arrêt n'est pas propre : rarement, le conteneur ne pourra plus redémarrer — sans gravité pour un conteneur jetable.
::

::extrait-cours{id="ex-menage" titre="Faire le ménage" source="/cours/a1/virtualisation-conteneurisation/execution/atelier#_6-faire-le-ménage"}
```bash
docker system prune          # conteneurs arrêtés, réseaux inutilisés, images en suspens, cache
docker run --rm hello-world  # le conteneur est supprimé dès qu'il s'arrête
```
