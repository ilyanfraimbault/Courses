::rappel{titre="Les commandes de l'atelier" icone="i-lucide-terminal"}
| Commande | Ce qu'elle fait |
|---|---|
| `docker login -u kikinovak` | s'identifie sur Docker Hub, pour pouvoir y publier |
| `docker buildx create --name buildx-multi-arch` | crée une configuration de construction, un *constructeur* |
| `docker buildx use buildx-multi-arch` | choisit ce constructeur pour les constructions suivantes |
| `docker buildx build --platform linux/amd64,linux/arm64/v8 -t kikinovak/cmatrix . --push` | construit une image par plateforme et les publie |
| `docker system prune` | supprime ce que la construction a laissé derrière elle |

Les plateformes s'écrivent `système/architecture[/variante]` : `linux/amd64` (Intel et AMD), `linux/arm64/v8` (Mac Silicon), `linux/s390x` (mainframes IBM S/390).

## 1. De build à buildx

Jusqu'ici, l'image se construisait avec `docker build` :

```text
$ ls
Dockerfile
$ docker build -t kikinovak/cmatrix .
```

L'image obtenue ne vaut que pour l'architecture de la machine qui l'a construite : un PC Intel produit une image `linux/amd64`, qu'un Mac Silicon ou un Raspberry Pi ne sait pas exécuter. La fonctionnalité **`buildx`** de Docker construit une **série d'images, une par plateforme**, et les publie ensemble sur Docker Hub sous un seul nom.

Trois préparatifs :

```text
$ docker login -u kikinovak
Authenticating with existing credentials...
Login Succeeded
$ docker buildx create --name buildx-multi-arch
buildx-multi-arch
$ docker buildx use buildx-multi-arch
```

- `docker login` : les images seront **poussées** sur Docker Hub, il faut donc s'y identifier ;
- `docker buildx create` met en place une configuration de construction — un *constructeur* — qu'on nomme avec `--name` ;
- `docker buildx use` la désigne pour les constructions qui suivent.

Sur Docker Hub, la page de l'image `alpine` (onglet *Tags*, tag `latest`, menu *OS/ARCH*) montre qu'elle existe pour **huit architectures** : c'est ce qui permet de construire CMatrix, basé sur Alpine, pour chacune d'elles.

## 2. CMatrix pour PC et Mac Silicon

Construisons une image pour les processeurs Intel et AMD (`linux/amd64`) et pour les Mac Silicon (`linux/arm64/v8`), et publions-la directement sur Docker Hub :

```text
$ docker buildx build --no-cache --platform linux/amd64,linux/arm64/v8 \
  -t kikinovak/cmatrix . --push
```

- `--platform` prend la **liste** des plateformes visées, séparées par des virgules, sans espace ;
- `--no-cache` reconstruit tout, sans réutiliser les couches déjà construites ;
- `-t` nomme l'image, et le point `.` désigne le répertoire du `Dockerfile`, comme pour `docker build` ;
- `--push` publie le résultat sur Docker Hub.

Les deux images se construisent **en parallèle**. Chacune va plus vite sur la machine dont c'est l'architecture native : sur un PC Intel, l'image `linux/amd64` est bien plus rapide à construire que l'image `linux/arm64/v8` — et l'inverse sur un Mac Apple.

## 3. CMatrix pour S/390

Rien n'oblige à s'en tenir à deux architectures. Ajoutons celle des mainframes IBM, S/390 :

```text
$ docker buildx build --no-cache --platform \
  linux/amd64,linux/arm64/v8,linux/s390x -t kikinovak/cmatrix . --push
```

Sur Docker Hub, l'image `kikinovak/cmatrix` existe désormais pour **trois** architectures, sous un seul nom : chaque machine qui la télécharge reçoit la variante qui lui correspond.

## 4. Faire le ménage

Pour construire toutes ces images, Docker a créé sous le capot des conteneurs et laissé un cache de construction. `docker system prune` supprime tout ce qui ne sert plus :

```text
$ docker system prune
WARNING! This will remove:
  - all stopped containers
  - all networks not used by at least one container
  - all dangling images
  - unused build cache

Are you sure you want to continue? [y/N] y
…
Total reclaimed space: 293.2MB
```

::::exercice{titre="Au terminal — le ménage" theme="docker system prune"}
Les trois images sont publiées ; la machine garde les restes de leur construction.

:::exo-question{label="1." cours="mp-menage"}
Supprime les conteneurs arrêtés, les réseaux inutilisés, les images en suspens et le cache de construction inutilisé, en une commande.

::commande
---
attendues:
  - docker system prune
sortie: |
  WARNING! This will remove:
    - all stopped containers
    - all networks not used by at least one container
    - all dangling images
    - unused build cache

  Are you sure you want to continue? [y/N]
---
::

#indice
La sous-commande `system`, et celle qui *élague*.

#solution
```bash
docker system prune
```

Docker demande confirmation avant de supprimer : répondre `y`.
:::

```bash
docker buildx build --no-cache --platform linux/amd64,linux/arm64/v8 \
  -t kikinovak/cmatrix . --push
```

- `--no-cache` : tout reconstruire ;
- `-t` : le nom, `.` : le répertoire du `Dockerfile` ;
