::rappel{titre="Les commandes de l'atelier" icone="i-lucide-terminal"}
| Commande | Ce qu'elle fait |
|---|---|
| `docker run --name mon_nginx -d -p 8080:80 nginx` | publie le port 80 du conteneur sur le port 8080 de l'hôte |
| `docker ps` | la colonne `PORTS` montre la redirection : `0.0.0.0:8080->80/tcp` |
| `curl http://localhost:8080` | interroge le serveur web du conteneur depuis l'hôte |
| `docker logs mon_nginx` | les requêtes reçues par le serveur |
| `docker run … -v $PWD/pagesweb:/usr/share/nginx/html:ro nginx` | partage un dossier de l'hôte avec le conteneur, en lecture seule |

Dans `-p 8080:80`, le premier port est celui de l'**hôte** (le monde extérieur), le second celui du **conteneur** (le monde intérieur). Dans `-v hôte:conteneur:ro`, même ordre : l'hôte d'abord.
::

## 1. Publier un port

Avant de lancer une image, on lit sa documentation : sur **Docker Hub**, la page de l'image officielle (*Official build*) a une section *How to use this image* qui donne les options utiles de `docker run`. Mieux vaut s'en tenir aux **images officielles**, pour être à l'abri des logiciels malveillants.

Pour Nginx, la section *Exposing external port* donne l'exemple qu'on adapte :

```text
$ docker run --name mon_nginx -d -p 8080:80 nginx
```

L'option `-p 8080:80` ouvre le port TCP **8080 de l'hôte** et redirige le trafic, dans les deux sens, vers le port TCP **80 du conteneur**. Le port 8080 représente le monde extérieur ; le port 80, le monde intérieur du conteneur.

::exemple{id="xp-ex-ports" titre="Lire -p hôte:conteneur" pour="Ne jamais inverser les deux ports"}
Un serveur web écoute dans son conteneur sur le port **80**, le port standard du HTTP. On veut l'atteindre sur le port **9900** de l'hôte :

```text
-p 9900:80
```

D'abord le port de l'hôte, celui qu'on tape dans le navigateur ; ensuite celui du conteneur, celui qu'écoute le logiciel. `-p 80:9900` enverrait le trafic du port 80 de l'hôte vers un port 9900 du conteneur, où personne n'écoute.
::

## 2. Vérifier la redirection et les accès

`docker ps` montre la redirection dans sa colonne `PORTS` :

```text
$ docker ps
CONTAINER ID   IMAGE  ...  PORTS                  NAMES
a92710efd101   nginx  ...  0.0.0.0:8080->80/tcp   mon_nginx
```

`0.0.0.0:8080` signifie que **toutes** les adresses IP locales de l'hôte servent sur le port 8080, renvoyé vers le port 80 du conteneur. On interroge le serveur depuis l'hôte avec `curl` :

```text
$ curl http://localhost:8080
<!DOCTYPE html>
<html>
<head>
<title>Welcome to nginx!</title>
…
```

Un navigateur sur l'hôte affiche la même page à `http://localhost:8080` ; depuis une autre machine du réseau, on passe par le nom ou l'adresse IP de l'hôte : `http://192.168.2.4:8080`. Chaque requête laisse une trace dans les journaux du serveur :

```text
$ docker logs mon_nginx
192.168.2.2 - - [30/Jun/2023:06:05:10 +0000] "GET / HTTP/1.1" 200 615 "-" "Mozilla/5.0 (X11; Linux x86_64; rv:102.0) Gecko/20100101 Firefox/102.0" "-"
```

La première colonne est l'adresse du **poste client**.

## 3. Partager des données avec l'hôte

Remplaçons la page par défaut de Nginx par la nôtre. On prépare un dossier sur l'hôte :

```text
$ mkdir -v ~/pagesweb
mkdir: création du répertoire '/home/kikinovak/pagesweb'
$ echo '<h1>Le site web de Nico</h1>' > ~/pagesweb/index.html
```

Puis on lance Nginx avec une option de plus, `-v` :

```text
$ docker run --name autre_nginx -d -p 8080:80 \
  -v $PWD/pagesweb:/usr/share/nginx/html:ro nginx
6b456addfb69fb9fe5acdec3dd4e5e7fbad0808edaac0ac28293979b036e4c0d
```

- `$PWD` est la variable Bash qui donne le répertoire de travail (*present working directory*) — ici le répertoire personnel, où se trouve `pagesweb`.
- `-v` crée un **volume** de partage de fichiers : le chemin sur l'hôte, deux-points, le chemin dans le conteneur, et — après un second deux-points — des options.
- `ro` (*read only*) monte le volume en **lecture seule** dans le conteneur : on modifie les fichiers depuis l'hôte, le conteneur ne peut que les lire.

Le dossier `/home/kikinovak/pagesweb` de l'hôte est ainsi disponible dans `/usr/share/nginx/html`, là où Nginx cherche ses pages :

```text
$ curl http://localhost:8080
<h1>Le site web de Nico</h1>
```

On fait ensuite le ménage : `docker stop autre_nginx` puis `docker system prune`. Les volumes ont leur propre atelier, plus loin.
