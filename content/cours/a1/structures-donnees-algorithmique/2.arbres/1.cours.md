::rappel{titre="La boîte à outils du chapitre"}
- Un **arbre** est fait de **nœuds** reliés par des **arêtes**, sans cycle ; chaque nœud a **un seul parent**, sauf la **racine**.
- **Degré** d'un nœud : son nombre de fils. **Feuille** : nœud sans fils. **Niveau** : nombre d'arêtes jusqu'à la racine. **Hauteur** : le niveau maximal.
- **Arbre binaire** : chaque nœud a **au plus** deux fils, `noeud_gauche` et `noeud_droit`.
- Parcours **préfixé** : le nœud, puis ses fils. **Postfixé** : les fils, puis le nœud. **Infixé** : le fils gauche, le nœud, le fils droit.
- Parcours **en profondeur** : avec une **pile** (ou la récursion). Parcours **en largeur** : avec une **file**, niveau par niveau.
- **Arbre complet** de $n$ nœuds : un nœud est à au plus $\log_2(n)$ liens de la racine.
- **Arbre binaire de recherche** : à gauche les valeurs plus petites, à droite les plus grandes ; la recherche est **logarithmique**, l'affichage trié **linéaire** (parcours infixé).
- Rangé dans un **tableau**, les fils du nœud $i$ sont aux cases $2i$ et $2i+1$.
::

## 1. Un arbre

Un **arbre** est une structure de données contenant des **nœuds** connectés par des **arêtes**.

- Un nœud peut posséder **plusieurs nœuds fils**.
- Chaque nœud possède **exactement un nœud parent**, sauf le nœud le plus haut, appelé **racine**, qui ne possède que des fils.
- Les arêtes ne forment **pas de cycle**.

```text
            0
          ↙   ↘
        1       4
       ↙ ↘    ↙ ↓ ↘
      2   3  5  6  7
```

Ici, 0 est la racine ; 1 et 4 sont ses fils ; 4 a trois fils, 5, 6 et 7.

::exemple{id="ar-ex-aretes" titre="Compter les arêtes d'un arbre" pour="Tirer une conséquence de « un seul parent par nœud »"}
Chaque nœud **sauf la racine** a exactement un parent, donc exactement une arête qui monte vers lui. Un arbre de $n$ nœuds a donc **$n - 1$ arêtes**.

Dans l'arbre ci-dessus, 8 nœuds et 7 arêtes : $0 \to 1$, $0 \to 4$, $1 \to 2$, $1 \to 3$, $4 \to 5$, $4 \to 6$, $4 \to 7$. Ajouter une arête de plus, par exemple $3 \to 4$, donnerait à 4 un second parent : ce ne serait plus un arbre.
::

:::qcm{titre="Contrôle express — un arbre" icone="i-lucide-circle-check-big" compact}

::

## 2. Le vocabulaire

```text
          A
        ↙   ↘
      B       C
     ↙ ↘      ↓
    E   F     D
```

- Le **degré** d'un nœud est son nombre de fils : ici, `B` est de degré 2, `C` de degré 1.
- Une **feuille** est un nœud qui n'a pas de fils : `E`, `F` et `D`.
- Le **niveau** d'un nœud est le nombre d'arêtes qui le séparent de la racine : `D` est de niveau 2, la racine `A` de niveau 0.
- La **hauteur** d'un arbre est son niveau maximal : ici, 2.

::exemple{id="ar-ex-vocabulaire" titre="Tout lire sur un arbre" pour="Appliquer les quatre définitions à la suite"}
Sur l'arbre de la section 1 (racine 0) :

| Notion | Valeur |
|---|---|
| Degré de 4 | 3 (fils 5, 6, 7) |
| Degré de 1 | 2 |
| Feuilles | 2, 3, 5, 6, 7 |
| Niveau de 6 | 2 ($0 \to 4 \to 6$) |
| Hauteur | 2 |

Attention au niveau : on compte les **arêtes**, pas les nœuds. La racine est au niveau 0.
::

## 3. Implémenter un arbre, l'arbre binaire

On peut implémenter les nœuds d'un arbre en utilisant **une liste des nœuds fils** :

```c
struct Noeud {
  char valeur;          // le contenu du nœud
  struct Noeud* fils;   // les fils du nœud
  int nombre_fils;      // combien il y en a
};
```

La diapo ne garde que le pointeur `fils` : il faut aussi savoir **combien** de fils il désigne, d'où `nombre_fils` ajouté ici.

Un **arbre binaire** est un arbre dans lequel le degré **maximal** de chaque nœud est 2 — un nœud peut avoir 0, 1 ou 2 fils. **Tout arbre peut se ramener à une représentation binaire** : le cours le montre en réorganisant les mêmes nœuds pour qu'aucun n'ait plus de deux fils.

```text
   Arbre quelconque          Mêmes nœuds, arbre binaire
          A                            A
       ↙  ↓  ↘                       ↙   ↘
      B   F   C                     B     C
      ↓       ↓                    ↙ ↘    ↓
      E       D                   E   F   D
```

On implémente un arbre binaire avec **deux pointeurs** vers les deux fils de chaque nœud ; un fils absent vaut `NULL`.

```c
struct Noeud {
  int valeur;                  // la valeur contenue dans le nœud
  struct Noeud* noeud_gauche;  // le nœud gauche
  struct Noeud* noeud_droit;   // le nœud droit
};
```

::exemple{id="ar-ex-construire" titre="Construire un petit arbre binaire en C" pour="Passer du dessin aux pointeurs"}
On construit l'arbre `A → (B → E, K → (L, M))`, avec une fonction qui crée une feuille :

```c
struct Noeud* creer(char v) {
  struct Noeud* n = malloc(sizeof(struct Noeud));
  n->valeur = v;
  n->noeud_gauche = NULL;   // pas de fils pour l'instant
  n->noeud_droit = NULL;
  return n;
}

struct Noeud* a = creer('A');
a->noeud_gauche = creer('B');
a->noeud_gauche->noeud_gauche = creer('E');
a->noeud_droit = creer('K');
a->noeud_droit->noeud_gauche = creer('L');
a->noeud_droit->noeud_droit = creer('M');
```

`B` n'a qu'un fils, à gauche : son `noeud_droit` reste `NULL`. C'est l'arbre des parcours de la section suivante.
::

:::qcm{titre="Contrôle express — l'arbre binaire" icone="i-lucide-circle-check-big" compact}

**Les distracteurs :** **a** est le piège du QCM du contrôle (« chaque nœud a deux fils ») : les feuilles n'en ont aucun ; **c** interdit les nœuds à un seul fils, qui existent (`C → D`) ; **d** n'a pas de fondement.
::
:::

## 4. Les parcours récursifs

On peut parcourir tous les nœuds d'un arbre avec une **fonction récursive**. Trois ordres, sur l'arbre `A → (B → E, K → (L, M))` :

```text
          A
        ↙   ↘
      B       K
     ↙       ↙ ↘
    E       L   M
```

**Préfixé** : on parcourt d'abord le nœud **parent**, puis ses fils.

```c
void parcours(struct Noeud* n){
  if (n == NULL) return;
  printf("%c\n", n->valeur);
  parcours(n->noeud_gauche);
  parcours(n->noeud_droit);
}
// affichera A B E K L M
```

**Postfixé** : on parcourt d'abord les nœuds **fils**, puis le parent.

```c
void parcours(struct Noeud* n){
  if (n == NULL) return;
  parcours(n->noeud_gauche);
  parcours(n->noeud_droit);
  printf("%c\n", n->valeur);
}
// affichera E B L M K A
```

**Infixé** : on parcourt le nœud de **gauche**, puis le nœud **père**, puis le nœud de **droite**.

```c
void parcours(struct Noeud* n){
  if (n == NULL) return;
  parcours(n->noeud_gauche);
  printf("%c\n", n->valeur);
  parcours(n->noeud_droit);
}
// affichera E B A L K M
```

::rappel{titre="Ce que la diapo écrit autrement" icone="i-lucide-triangle-alert"}
Les diapos écrivent `parcours(n.noeud_gauche)` : `n` est un **pointeur**, c'est `n->noeud_gauche`. Elles affichent avec `%d` des nœuds dessinés avec des lettres (`%c` pour un `char`). Et elles n'ont **pas de cas d'arrêt** : sans `if (n == NULL) return;`, l'appel sur le fils absent d'une feuille déréférence `NULL`. Le cours suivant ajoute ce test sous la forme `if (n->noeud_gauche) parcours(n->noeud_gauche);`.
::

::exemple{id="ar-ex-parcours" titre="Les trois parcours d'un même arbre" pour="Placer l'affichage avant, entre ou après les deux appels"}
Sur l'arbre `A → (B → (D, E), C → (·, F))` — `C` n'a qu'un fils, à droite :

```text
        A
      ↙   ↘
    B       C
   ↙ ↘        ↘
  D   E        F
```

- **Préfixé** (nœud, gauche, droite) : `A B D E C F`.
- **Postfixé** (gauche, droite, nœud) : `D E B F C A` — la racine sort **en dernier**.
- **Infixé** (gauche, nœud, droite) : `D B E A C F` — la racine est **entre** son sous-arbre gauche et son sous-arbre droit.

Un repère : en préfixé la racine sort **en premier**, en postfixé **en dernier**.
::

:::qcm{titre="Contrôle express — les parcours" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="c" cours="ar-parcours"}
Quel est le parcours **postfixé** de l'arbre `A → (B → (D, E), C → (·, F))` ?

#a

#b
`D B E A C F`

#c
`D E B F C A`

#d
`F C E D B A`

#indice
En postfixé, un nœud ne sort qu'après tout son sous-arbre gauche puis tout son sous-arbre droit : la racine sort en dernier.

#solution
Sous-arbre gauche de `A` en postfixé : `D E B` ; sous-arbre droit : `F C` ; puis `A`. Total : **`D E B F C A`**. **c** est juste.

**Les distracteurs :** **a** est le préfixé ; **b** l'infixé ; **d** est le préfixé lu à l'envers, qui n'est pas le postfixé (il visite la droite avant la gauche).
::

::qcm-question{label="2." bonne="a" cours="ar-parcours"}

::

## 5. En profondeur, en largeur

Dans les trois fonctions précédentes, on parcourt d'abord une branche **jusqu'au dernier niveau** avant de parcourir les autres nœuds de plus haut niveau : on parle de **parcours en profondeur**. Lorsqu'on parcourt **tous les nœuds du même niveau** avant de parcourir ceux du niveau suivant, on parle de **parcours en largeur**.

**En profondeur, sans récursion** : on utilise une **pile**. On empile la racine ; tant que la pile n'est pas vide, on dépile un nœud, on l'affiche et on empile ses fils.

```c
void parcours_profondeur(struct Noeud* racine){
  Pile* p = creer_pile();
  empiler(p, racine);
  while (taille(p)){
    struct Noeud* suivant = depiler(p);
    printf("%c\n", suivant->valeur);
    if (suivant->noeud_droit) empiler(p, suivant->noeud_droit);
    if (suivant->noeud_gauche) empiler(p, suivant->noeud_gauche);
  }
}
// affichera A B E K L M
```

**En largeur** : on remplace la pile par une **file**.

```c
void parcours_largeur(struct Noeud* racine){
  File* f = creer_file();
  enfiler(f, racine);
  while (taille(f)){
    struct Noeud* suivant = defiler(f);
    printf("%c\n", suivant->valeur);
    if (suivant->noeud_gauche) enfiler(f, suivant->noeud_gauche);
    if (suivant->noeud_droit) enfiler(f, suivant->noeud_droit);
  }
}
// affichera A B K E L M
```

::rappel{titre="Ce que la diapo écrit autrement" icone="i-lucide-triangle-alert"}
La diapo de la pile empile le fils **gauche puis le droit** : le droit, empilé en dernier, sort le premier, et le parcours affiche **`A K M L B E`** — un parcours en profondeur, mais qui explore la droite d'abord. Pour retrouver l'ordre préfixé `A B E K L M`, on empile le **droit d'abord**, comme ci-dessus (et comme le fait le cours 3). Les diapos ne créent pas non plus la pile (`Pile* p;` reste non initialisé), testent la fin par `suivant->noeud_gauche != suivant` au lieu de tester les fils absents, et la seconde écrit `suivant>noeud_gauche` pour `suivant->noeud_gauche`.
::

**Les usages.** Un parcours en profondeur sert à calculer le résultat d'un arbre représentant une **expression**, à **chercher une valeur** dans un arbre, ou dans certains algorithmes de type « brute-force ». Un parcours en largeur sert à trouver les nœuds **à une distance donnée** d'un nœud dans un graphe, à trouver le nœud **le plus proche de la racine** qui répond à un critère, ou à simuler l'avancée d'une information ou d'une épidémie.

::exemple{id="ar-ex-largeur" titre="Dérouler la file d'un parcours en largeur" pour="Voir pourquoi la file donne les niveaux dans l'ordre"}
Sur `A → (B → E, K → (L, M))` :

| Défile | Affiche | File après (on enfile à droite) |
|---|---|---|
| | | A |
| A | A | B K |
| B | B | K E |
| K | K | E L M |
| E | E | L M |
| L | L | M |
| M | M | (vide) |

Les fils de `B` et de `K` arrivent **derrière** tout le niveau 1 : la file rend les nœuds niveau par niveau, `A B K E L M`. Avec une pile, les fils empilés passeraient **devant**, et l'on descendrait d'abord dans une branche.
::

## 6. L'arbre complet

On parle d'**arbre binaire complet** lorsque :

- **tous les niveaux sont remplis** (les nœuds ont deux fils), **sauf le dernier** ;
- pour les nœuds du dernier niveau qui n'ont qu'un seul fils, ce fils est **à gauche**.

Pour un arbre complet de taille $n$, le nombre de liens qui séparent un nœud de la racine est alors **au maximum $\log_2(n)$**.

::exemple{id="ar-ex-complet" titre="La hauteur d'un arbre complet" pour="Calculer la hauteur d'après le nombre de nœuds"}
Un arbre complet a 1 nœud au niveau 0, 2 au niveau 1, 4 au niveau 2, …, $2^k$ au niveau $k$. De hauteur $h$, il a donc entre $2^h$ nœuds (un seul au dernier niveau) et $2^{h+1} - 1$ (tous remplis).

Pour **57 nœuds** : $2^5 = 32 \le 57 < 64 = 2^6$, donc la hauteur est **5** — c'est la question 9 du contrôle d'exemple. Pour 100 nœuds : $2^6 = 64 \le 100 < 128$, hauteur 6. La hauteur est la partie entière de $\log_2(n)$.
::

:::qcm{titre="Contrôle express — l'arbre complet" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="c" cours="ar-complet"}
Quelle est la hauteur d'un arbre binaire complet de **100** nœuds ?

#a
$7$

#b
$5$

#c
$6$

#d
$50$

#indice
Encadre 100 entre deux puissances de 2 consécutives.

#solution
$2^6 = 64 \le 100 < 128 = 2^7$ : les niveaux 0 à 5 sont pleins (63 nœuds), les 37 autres sont au niveau 6. La hauteur est **6** : **c**.

**Les distracteurs :** **a** prend la puissance supérieure ; **b** oublie le dernier niveau, partiellement rempli ; **d** divise par 2 au lieu de prendre un logarithme.
::

::qcm-question{label="2." bonne="a" cours="ar-complet"}
Un arbre binaire dont le dernier niveau contient un nœud qui n'a qu'un fils, placé **à droite**, est-il complet ?

#a
Non : un fils unique du dernier niveau doit être à gauche.

#b
Oui, si tous les niveaux précédents sont remplis.

#c
Oui : seul le nombre de nœuds compte.

#d
Non, car un arbre complet n'a que des nœuds à deux fils.

#indice
Relis la seconde condition de la définition.

#solution
La définition impose que le fils unique d'un nœud soit **à gauche** : avec un fils unique à droite, l'arbre n'est pas complet. **a** est juste.

**Les distracteurs :** **b** et **c** oublient la seconde condition ; **d** : le dernier niveau peut contenir des nœuds à un fils, et les feuilles n'en ont aucun.
::
:::

## 7. L'arbre binaire de recherche

On parle d'**arbre binaire de recherche** (ou **ABR**) lorsque :

- l'arbre est **complet** ;
- les valeurs de chaque nœud respectent la relation d'ordre suivante avec ses sous-arbres :

$$
\text{valeur max du sous-arbre gauche} < \text{valeur du père} < \text{valeur min du sous-arbre droit}
$$

Tout est **plus petit à gauche**, tout est **plus grand à droite** — à chaque nœud.

::rappel{titre="Ce que la diapo écrit autrement" icone="i-lucide-triangle-alert"}
La diapo écrit « val **min** sous-arbre gauche < val père » : c'est la valeur **maximale** du sous-arbre gauche qui doit rester sous le père — sinon `5 → (gauche 1 → (·, 9))` serait un ABR, alors qu'on ne retrouverait jamais le 9 en descendant.

Et la condition « l'arbre est complet » est **la définition de ce cours** (le corrigé du contrôle d'exemple la compte juste) : elle garantit la recherche en $\log_2(n)$. Ailleurs, on appelle souvent ABR tout arbre qui respecte l'ordre, équilibré ou non — c'est d'ailleurs ce que construit le TP, qui insère « sans préserver l'équilibre ».
::

- La **recherche** d'une clé dans un ABR de taille $n$ nécessite au maximum $\log_2(n)$ opérations : on parle de **complexité logarithmique**. À chaque nœud, on compare et l'on descend d'un seul côté.
- L'**affichage des données triées** s'effectue en temps **linéaire**, $O(n)$ : c'est le parcours **infixé**.

Rechercher un élément dans un arbre de **dix milliards** d'éléments ne demande alors qu'une poignée d'opérations — le cours dit « au maximum une centaine », et le calcul donne même 34, car $2^{33} < 10^{10} < 2^{34}$.

::exemple{id="ar-ex-recherche" titre="Chercher une clé dans un ABR" pour="Descendre d'un seul côté à chaque comparaison"}
```text
          50
        ↙    ↘
      30      70
     ↙  ↘    ↙  ↘
   20   40  60   80
```

On cherche **60** : $60 > 50$, à droite ; $60 < 70$, à gauche ; trouvé. **Trois comparaisons**, pour un arbre de 7 nœuds.

On cherche **45** : $45 < 50$, à gauche ; $45 > 30$, à droite ; $45 > 40$, à droite… il n'y a pas de fils : **45 est absent**, après trois comparaisons. On ne visite jamais l'autre moitié de l'arbre.

Et le parcours infixé affiche `20 30 40 50 60 70 80` : **trié**.
::

:::qcm{titre="Contrôle express — l'ABR" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="d" cours="ar-abr"}

#c

#solution

**Les distracteurs :** **a** est le cas d'une table de hachage sans collision ; **b** celui d'une liste ; **c** ne correspond à aucune recherche du cours.
::

::

## 8. Insérer, supprimer, rééquilibrer

Lorsqu'on insère ou supprime un élément, on doit s'assurer de **toujours respecter les propriétés** de l'arbre binaire de recherche — l'ordre, et, dans la définition du cours, la complétude.

```text
   Avant                 Après insertion de G, rééquilibré
        C                            D
      ↙   ↘                       ↙     ↘
     B     E                     B       F
    ↙     ↙ ↘                   ↙ ↘     ↙ ↘
   A     D   F                 A   C   E   G
```

Inséré à sa place d'ordre, `G` irait à droite de `F`, au niveau 3 : l'arbre ne serait plus complet. Il faut le **rééquilibrer** — ici, `D` devient la racine.

Il existe de **nombreux algorithmes** assurant l'équilibrage de l'arbre lors de l'insertion ou de la suppression d'un élément. La plupart permettent d'effectuer ces opérations en temps **logarithmique**, $O(\log(n))$ ; dans certains cas, le **coût amorti** de ces opérations peut être constant, $O(1)$.

::rappel{titre="Ce que la diapo écrit autrement" icone="i-lucide-triangle-alert"}
La diapo écrit « en temps **linéaire** ($O(\log(n))$) » : $O(\log n)$ est un temps **logarithmique**. C'est tout l'intérêt de l'équilibrage : un temps linéaire ne ferait pas mieux qu'une liste.
::

::exemple{id="ar-ex-insertion" titre="Insérer sans rééquilibrer" pour="Trouver la place d'une nouvelle valeur, et voir l'arbre se déséquilibrer"}
Pour insérer une valeur **sans** rééquilibrer — ce que fait le TP —, on descend comme pour une recherche, et l'on accroche la valeur là où l'on tombe sur un fils absent.

Dans l'arbre `50 → (30 → (20, 40), 70 → (60, 80))`, insérer **35** : $35 < 50$, gauche ; $35 > 30$, droite ; $35 < 40$, gauche : `35` devient le fils gauche de `40`.

Mais insérer **1, 2, 3, 4, 5** dans cet ordre dans un arbre vide donne une seule branche, chaque valeur à droite de la précédente : une **liste**, de hauteur 4, où la recherche redevient linéaire. C'est pour éviter ce cas qu'on rééquilibre.
::

:::qcm{titre="Contrôle express — l'insertion" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="a" cours="ar-equilibrage"}

#a

#b
Fils gauche de 60

#c
Fils droit de 30, à la place de 40

#d
Fils gauche de 50

#indice
Descends comme pour une recherche de 45, jusqu'à un fils absent.

#solution
$45 < 50$ : à gauche ; $45 > 30$ : à droite, vers 40 ; $45 > 40$ : à droite — fils absent, `45` devient le **fils droit de 40**. **a** est juste.

**Les distracteurs :** **b** part à droite de la racine alors que $45 < 50$ ; **c** et **d** déplaceraient des nœuds existants : une insertion sans rééquilibrage ne fait qu'ajouter une feuille.
::

::qcm-question{label="2." bonne="c" cours="ar-equilibrage"}

#d

**Les distracteurs :** **a** et **b** supposent un arbre équilibré ; **d** compte les nœuds au lieu des arêtes.
::
:::

## 9. Les limites des pointeurs, l'arbre dans un tableau

L'implémentation d'un arbre par pointeurs entraîne **les mêmes ralentissements que la liste chaînée** :

- enregistrer un pointeur avec chaque élément **augmente la mémoire utilisée** ;
- les données sont éparpillées dans la mémoire et **difficiles à cacher** ;
- ce dernier point rend aussi **les prédictions difficiles** ;
- chaque insertion demande une allocation, ce qui **augmente le nombre d'appels système**.

Bien que l'ABR offre de meilleures performances **asymptotiques**, il est parfois plus rapide d'utiliser un **tableau** pour de petits jeux de données. Pour ces raisons, l'implémentation par pointeurs est **rarement utilisée** quand la performance est importante. Le cours présente quelques variantes qui atténuent ces problèmes.

**Tentative I — l'implémentation par tableau.** Si l'on n'est pas intéressé par l'ordre des éléments, il peut être préférable d'utiliser un tableau : on calcule la position d'un nœud d'après celle de son parent. **Les fils du nœud d'indice $i$ sont rangés aux positions $2i$ et $2i+1$** (la case 0 n'est pas utilisée).

```text
          A                 indice : 0   1   2   3   4   5   6   7
        ↙   ↘               valeur : ·   A   B   K   E   ·   D   O
      B       K
     ↙       ↙ ↘
    E       D   O
```

- **Avantages** : pas de pointeur à enregistrer, donc une empreinte mémoire faible si les éléments le sont aussi (`char`, `int`, `float`) ; l'insertion ne nécessite que très rarement un appel système ; les nœuds d'un même niveau sont **proches dans la mémoire**.
- **Désavantages** : on réserve de la place pour plus d'éléments que nécessaire (plus encore si l'arbre n'est pas équilibré) ; si l'insertion d'un élément rajoute un niveau, il peut être nécessaire de réallouer et de recopier : **insertion en $O(n)$**.

::exemple{id="ar-ex-tableau" titre="Se déplacer dans l'arbre rangé en tableau" pour="Calculer les cases des fils et du parent"}
Dans le tableau ci-dessus :

- `B` est en case 2 : ses fils sont en cases $2 \times 2 = 4$ (`E`) et $2 \times 2 + 1 = 5$ (vide : `B` n'a pas de fils droit) ;
- `K` est en case 3 : ses fils sont en cases 6 (`D`) et 7 (`O`) ;
- le parent de la case $i$ est en case $i / 2$ (division entière) : le parent de `O` (case 7) est en case 3, `K`.

Aucun pointeur : la structure de l'arbre est **dans les indices**. Mais la case 5 est réservée pour rien — un arbre déséquilibré en laisserait beaucoup.
::

:::qcm{titre="Contrôle express — l'arbre dans un tableau" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="d" cours="ar-tableau"}
Un arbre binaire est rangé dans un tableau, les fils de la case $i$ en $2i$ et $2i+1$. Un nœud est en case **6**. Où sont ses fils, et son parent ?

#a
Fils en 7 et 8, parent en 5

#b
Fils en 12 et 14, parent en 2

#c
Fils en 13 et 14, parent en 4

#d
Fils en 12 et 13, parent en 3

#indice
Applique $2i$ et $2i+1$ ; pour le parent, l'opération inverse est une division entière par 2.

#solution
Fils : $2 \times 6 = 12$ et $2 \times 6 + 1 = 13$. Parent : $6 / 2 = 3$ (et en effet, les fils de 3 sont 6 et 7). **d** est juste.

**Les distracteurs :** **a** prend les cases voisines ; **b** calcule $2i$ et $2i+2$ ; **c** décale d'une case, comme si les indices commençaient à 0.
::
:::

## 10. La rope

Une **rope** est comme une liste déroulée, mais elle enregistre ses nœuds dans un **arbre binaire équilibré**, pour un accès indexé rapide :

- les **feuilles** contiennent des vecteurs (des morceaux du texte) ;
- les **nœuds internes** contiennent le **nombre total de caractères dans leur sous-arbre de gauche**.

```text
                 6
              ↙     ↘
            5         3
          ↙   ↘     ↙   ↘
     "Bonjo"  "u"  "r à"  " tous"
```

Le texte est `Bonjour à tous`. Le 6 de la racine compte les caractères de `Bonjo` et `u` ; le 5, ceux de `Bonjo` ; le 3, ceux de `r à` (le `r`, l'espace, le `à`).

- L'**insertion**, la **suppression** et l'**accès arbitraires** deviennent $O(\log(n))$ plutôt que $O(n)$.
- L'usage de vecteurs comme feuilles améliore la **localité**, la **prédictibilité** et l'**empreinte mémoire**.
- Elle est très utilisée dans les outils de **manipulation de texte en temps réel** (les IDE, par exemple).

::exemple{id="ar-ex-rope" titre="Trouver le caractère d'indice 8" pour="Descendre dans une rope en comparant l'indice aux nombres des nœuds"}
On cherche le caractère d'indice 8 (en partant de 0) de `Bonjour à tous`.

1. Racine 6 : $8 \ge 6$, le caractère n'est pas dans les 6 premiers : à **droite**, en retirant 6 : on cherche l'indice $8 - 6 = 2$.
2. Nœud 3 : $2 < 3$ : à **gauche**, indice 2.
3. Feuille `r à` : l'indice 2 est le `à`.

Deux comparaisons au lieu de parcourir huit caractères : la hauteur de l'arbre, $O(\log n)$. Vérification : `B o n j o u r ␣ à` — le `à` est bien le neuvième caractère, d'indice 8.
::

:::qcm{titre="Contrôle express — la rope" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="b" cours="ar-rope"}
Le texte `Bonjour à tous` est rangé dans cette rope :

```text
                 6
              ↙     ↘
            5         3
          ↙   ↘     ↙   ↘
     "Bonjo"  "u"  "r à"  " tous"
```

Dans quelle feuille se trouve le caractère d'indice **5** (en partant de 0) ?

#a
`Bonjo`

#b
`u`

#c
`r à`

#d
` tous`

#indice
Racine 6 : $5 < 6$, à gauche. Puis compare 5 au nombre du nœud suivant.

#solution
Racine 6 : $5 < 6$, à gauche. Nœud 5 : $5 \ge 5$, à droite, indice $5 - 5 = 0$. Feuille `u`, indice 0 : c'est le `u` de `Bonjour`. **b** est juste.

**Les distracteurs :** **a** oublie que `Bonjo` ne contient que les indices 0 à 4 ; **c** et **d** partent à droite de la racine alors que $5 < 6$.
::
:::

## 11. L'arbre B, et les arbres réels

**Alternative — l'arbre B.** Chaque nœud peut avoir jusqu'à **B fils**, et contient donc jusqu'à **B − 1 éléments**. La hauteur d'un arbre B complet est de $\log_B(n)$.

```text
                  [ F   L ]
              ↙       ↓       ↘
         [B D]      [H J]      [N]
        ↙  ↓  ↘    ↙  ↓  ↘    ↙   ↘
       A   C   E  G   I   K  M     O
```

Ici $B = 3$ : chaque nœud a au plus 3 fils et 2 éléments. Entre deux éléments d'un nœud, le fils contient les valeurs comprises entre eux : entre `F` et `L`, le fils du milieu contient `H`, `I`, `J`, `K`.

- **Avantages** : améliore la **localité**, la **prédictibilité** et l'**empreinte mémoire** ; **réduit le nombre d'appels système** moyens pour l'insertion et la suppression.
- **Désavantages** : plus **difficile à implémenter** ; effectue **plus d'opérations en moyenne** ; peut demander de trouver une valeur de B optimale selon le cas d'usage.

*Sur une architecture moderne, l'arbre B est presque toujours une solution plus rapide qu'un arbre binaire de recherche.*

**Exemples réels d'arbres.**

- Le **noyau Linux** utilise des **arbres binaires** pour ordonnancer les processus et suivre les régions mémoire allouées.
- Les **bases de données** PostgreSQL, MySQL, SQLite, Oracle, MongoDB et DynamoDB utilisent un **arbre B** pour enregistrer les index.
- Les systèmes de fichiers **NTFS, ext4 et APFS** utilisent un **arbre B** pour minimiser le nombre d'accès arbitraires au disque.
- **Google Maps et Apple Maps** utilisent des **arbres B** pour accélérer la recherche d'éléments proches entre eux.
- Langages : `std::map` en C++, `TreeMap` en Java et `SortedDictionary` en C# utilisent un **arbre binaire** ; `BTreeMap` en Rust utilise un **arbre B**.

::exemple{id="ar-ex-arbre-b" titre="La hauteur d'un arbre B" pour="Comparer la hauteur d'un arbre B à celle d'un ABR"}
Un million de clés, $n = 10^6$ :

- dans un ABR complet, hauteur $\log_2(10^6) \approx 19{,}9$ : une vingtaine de nœuds visités, chacun ailleurs dans la mémoire ;
- dans un arbre B avec $B = 100$, hauteur $\log_{100}(10^6) = 3$, car $100^3 = 10^6$ : **trois nœuds** visités.

Dans chaque nœud de l'arbre B, on parcourt jusqu'à 99 éléments **rangés à la suite** — plus d'opérations, mais en mémoire contiguë. C'est pourquoi les bases de données et les systèmes de fichiers, où chaque accès à un nouveau nœud peut coûter une lecture sur le disque, l'utilisent.
::

:::qcm{titre="Contrôle express — l'arbre B" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="c" cours="ar-arbre-b"}
Un arbre B complet avec $B = 1000$ contient un milliard de clés. Quelle est sa hauteur ?

#a
$30$

#b
$1000$

#c
$3$

#d
$9$

#indice
La hauteur vaut $\log_B(n)$ : à quelle puissance faut-il élever 1000 pour obtenir $10^9$ ?

#solution
$1000^3 = 10^9$ : $\log_{1000}(10^9) = 3$. **c** est juste — un ABR complet en aurait une trentaine ($2^{30} \approx 10^9$).

**Les distracteurs :** **a** est la hauteur d'un ABR ; **b** confond la hauteur et le nombre de fils ; **d** compte les chiffres de $10^9$.
::

::qcm-question{label="2." bonne="a" cours="ar-arbre-b"}

#b

#c

#d

#indice

#solution

**Les distracteurs :** **b** et **c** surestiment ; **d** n'a pas de rapport.
::
:::

::extrait-cours{id="ar-arbre" titre="Un arbre" source="/cours/a1/structures-donnees-algorithmique/arbres/cours#_1-un-arbre"}
Un **arbre** est fait de **nœuds** connectés par des **arêtes**. Un nœud peut avoir plusieurs fils ; chaque nœud a **exactement un parent**, sauf la **racine**, qui n'a que des fils. Les arêtes ne forment pas de cycle. Conséquence : un arbre de $n$ nœuds a $n - 1$ arêtes.
::

::extrait-cours{id="ar-vocabulaire" titre="Degré, feuille, niveau, hauteur" source="/cours/a1/structures-donnees-algorithmique/arbres/cours#_2-le-vocabulaire"}
Le **degré** d'un nœud est son nombre de fils. Une **feuille** n'a pas de fils. Le **niveau** d'un nœud est le nombre d'**arêtes** qui le séparent de la racine (la racine est au niveau 0). La **hauteur** d'un arbre est son niveau maximal.
::

::extrait-cours{id="ar-binaire" titre="L'arbre binaire" source="/cours/a1/structures-donnees-algorithmique/arbres/cours#_3-implémenter-un-arbre-larbre-binaire"}
Un **arbre binaire** est un arbre dont le degré **maximal** est 2 : chaque nœud a 0, 1 ou 2 fils. Tout arbre peut se ramener à une représentation binaire. On l'implémente avec deux pointeurs par nœud, `noeud_gauche` et `noeud_droit`, qui valent `NULL` quand le fils est absent.
::

::extrait-cours{id="ar-parcours" titre="Les parcours récursifs" source="/cours/a1/structures-donnees-algorithmique/arbres/cours#_4-les-parcours-récursifs"}
**Préfixé** : afficher le nœud, puis parcourir le fils gauche, puis le droit (la racine sort en premier). **Postfixé** : gauche, droit, puis le nœud (la racine sort en dernier). **Infixé** : gauche, le nœud, puis droit. La fonction s'arrête sur un fils absent : `if (n == NULL) return;`.
::

::extrait-cours{id="ar-largeur" titre="En profondeur, en largeur" source="/cours/a1/structures-donnees-algorithmique/arbres/cours#_5-en-profondeur-en-largeur"}
Un parcours **en profondeur** descend une branche jusqu'au bout avant les autres : récursion, ou **pile** (empiler le fils droit puis le gauche pour l'ordre préfixé). Un parcours **en largeur** visite les nœuds niveau par niveau : on remplace la pile par une **file**. Profondeur : évaluer une expression, chercher une valeur ; largeur : le nœud le plus proche de la racine qui répond à un critère, les nœuds à une distance donnée.
::

::extrait-cours{id="ar-complet" titre="L'arbre complet" source="/cours/a1/structures-donnees-algorithmique/arbres/cours#_6-larbre-complet"}
Un arbre binaire est **complet** quand tous ses niveaux sont remplis sauf le dernier, et qu'un fils unique au dernier niveau est **à gauche**. Un nœud est alors à au plus $\log_2(n)$ liens de la racine : la hauteur est le plus grand $h$ tel que $2^h \le n$ (5 pour 57 nœuds, car $32 \le 57 < 64$).
::

::extrait-cours{id="ar-abr" titre="L'arbre binaire de recherche" source="/cours/a1/structures-donnees-algorithmique/arbres/cours#_7-larbre-binaire-de-recherche"}
Dans ce cours, un **ABR** est un arbre **complet** où, à chaque nœud, max du sous-arbre gauche < valeur du père < min du sous-arbre droit. La **recherche** compare et descend d'un seul côté : au plus $\log_2(n)$ opérations, complexité **logarithmique**. Le parcours **infixé** affiche les valeurs triées, en temps **linéaire**.
::

::extrait-cours{id="ar-equilibrage" titre="Insérer et rééquilibrer" source="/cours/a1/structures-donnees-algorithmique/arbres/cours#_8-insérer-supprimer-rééquilibrer"}
Pour insérer, on descend comme pour une recherche et l'on accroche la valeur au premier fils absent. Sans rééquilibrage, des insertions dans l'ordre croissant donnent une seule branche, où la recherche devient linéaire. Les algorithmes d'équilibrage gardent les propriétés de l'ABR et font l'insertion et la suppression en $O(\log n)$, parfois en coût amorti constant.
::

::extrait-cours{id="ar-tableau" titre="L'arbre rangé dans un tableau" source="/cours/a1/structures-donnees-algorithmique/arbres/cours#_9-les-limites-des-pointeurs-larbre-dans-un-tableau"}
Les pointeurs coûtent de la mémoire, éparpillent les nœuds (cache, prédiction) et multiplient les allocations. Rangé dans un tableau, le nœud de la case $i$ a ses fils en $2i$ et $2i+1$, et son parent en $i / 2$ : pas de pointeur, nœuds d'un niveau voisins en mémoire ; mais des cases réservées pour rien, et une insertion en $O(n)$ quand il faut ajouter un niveau.
::

::extrait-cours{id="ar-rope" titre="La rope" source="/cours/a1/structures-donnees-algorithmique/arbres/cours#_10-la-rope"}
Une **rope** range les morceaux d'un texte (des vecteurs) dans les **feuilles** d'un arbre binaire équilibré ; chaque nœud interne contient le **nombre de caractères de son sous-arbre gauche**. Pour l'indice $i$ : si $i$ est inférieur au nombre du nœud, à gauche ; sinon à droite, en retirant ce nombre. Accès, insertion et suppression en $O(\log n)$.

Dans un **arbre B**, chaque nœud a jusqu'à **B fils** et **B − 1 éléments** ; la hauteur d'un arbre B complet est $\log_B(n)$. Meilleure localité, moins d'appels système ; plus difficile à implémenter, plus d'opérations en moyenne. Presque toujours plus rapide qu'un ABR sur une machine moderne : bases de données, systèmes de fichiers, `BTreeMap` en Rust.
