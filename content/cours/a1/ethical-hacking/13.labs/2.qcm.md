Un QCM d'un seul bloc, en anglais comme l'examen, qui ne porte que sur les **gestes** des cinq labs — pas sur une machine en particulier. On répond à **tout**, puis on clique sur **Corriger** : chaque question dit alors si elle est juste, et s'ouvrent sous elle l'**indice**, la **solution** et le **cours** visé. Une seule bonne réponse par question. À l'examen, une réponse fausse **ou absente** retire un point : on répond toujours.

::qcm-question{label="1." bonne="b" cours="lab-demarche"}
Each lab is a single isolated machine. Which Nmap command makes sure a service hidden on a non-standard port — such as SSH moved to 22222 — is not missed?

#a
`nmap -F <ip>`

#b
`nmap -p- <ip>`

#c
`nmap --top-ports 100 <ip>`

#d
`nmap -sn <ip>`

#indice
Un scan par défaut ne regarde qu'une petite partie des 65 535 ports. Lequel les couvre tous ?

#solution
`-p-` scanne **tous les ports, de 1 à 65 535**. C'est le réflexe des labs : RickdiculouslyEasy déplace SSH très loin du port 22, et seul un scan complet le trouve.

**Les distracteurs :** **a** (`-F`) se limite aux 100 ports les plus courants ; **c** à 100 ports ; **d** (`-sn`) ne scanne **aucun** port, il se contente de voir si l'hôte est vivant.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="2." bonne="c" cours="lab-demarche"}
Before attacking a Vulnhub lab, which statement is correct?

#a
Scanning leaves no trace, so there is no need for authorization

#b
You may pivot to any other host you can reach on the network

#c
The scope is limited to the single machine provided, under the lab's authorization

#d
Only exploitation needs authorization, not reconnaissance

#indice
Qu'est-ce qu'un lab t'autorise à attaquer, et jusqu'où ?

#solution
Un lab définit un **périmètre** (*scope*) : la seule machine fournie, et c'est elle seule que l'autorisation couvre. Chaque paquet laisse une trace ; on ne sort jamais du cadre défini.

**Les distracteurs :** **a** est faux, tout scan se journalise et se fait sous autorisation ; **b** sortirait du périmètre ; **d** — la reconnaissance envoie déjà des paquets à la cible, elle est dans le périmètre comme le reste.

Réponse : $\boxed{\text{c}}$
::

::qcm-question{label="3." bonne="a" cours="lab-demarche"}
Applied to each lab, what is the correct order of a penetration test's phases?

#a
Reconnaissance → enumeration → exploitation → privilege escalation → reporting

#b
Exploitation → reconnaissance → enumeration → reporting → privilege escalation

#c
Enumeration → exploitation → reconnaissance → reporting → privilege escalation

#d
Reporting → reconnaissance → exploitation → enumeration → privilege escalation

#indice
On ne peut exploiter que ce qu'on a d'abord trouvé, et élever ses privilèges qu'une fois entré.

#solution
L'ordre est **reconnaissance → énumération → exploitation → élévation de privilèges → rapport** : on cartographie, on détaille chaque service, on obtient un premier accès, on passe root, puis on rend compte.

**Les distracteurs :** **b**, **c** et **d** mettent l'exploitation ou le rapport avant d'avoir rien trouvé, ce qui n'a pas de sens.

Réponse : $\boxed{\text{a}}$
::

::qcm-question{label="4." bonne="d" cours="lab1-ports"}
A default Nmap scan of RickdiculouslyEasy finds a web server but no SSH. A full scan then reveals SSH on port 22222. Why did the default scan miss it?

#a
SSH was filtered by a firewall

#b
SSH does not answer to a SYN scan

#c
The host was down during the first scan

#d
Nmap only scans the 1,000 most common ports unless told otherwise

#indice
Rien n'empêchait Nmap de voir ce port — il ne l'a simplement pas regardé.

#solution
Sans option de ports, Nmap ne scanne que les **1 000 ports les plus courants**. Le port 22222 n'en fait pas partie : il faut `-p-` pour le voir. C'est pourquoi on lance toujours un scan complet sur une machine de lab.

**Les distracteurs :** **a** et **b** donneraient un port **filtered** ou muet, pas un port ignoré ; **c** est exclu puisque le web a bien répondu.

Réponse : $\boxed{\text{d}}$
::

::qcm-question{label="5." bonne="b" cours="lab1-ports"}
During enumeration you read the target's `/robots.txt`. Why is this file useful to an attacker?

#a
It stores the site's administrator password

#b
It lists paths the owner hid from search engines — often sensitive directories

#c
It prevents your scanner from reaching the listed paths

#d
It contains the server's software version

#indice
À quoi sert ce fichier pour un moteur de recherche, et que trahit-il du coup ?

#solution
`robots.txt` dit aux moteurs quels chemins **ne pas indexer**. Pour un attaquant, c'est une liste toute faite de **répertoires que le propriétaire préfère cacher** — un dossier de mots de passe, un `/cgi-bin/` — donc les premiers à visiter.

**Les distracteurs :** **a** et **d** lui prêtent un contenu qu'il n'a pas ; **c** est l'inverse — c'est une **consigne** aux robots polis, elle n'interdit matériellement rien.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="6." bonne="c" cours="lab1-cmdi"}
A CGI script passes your input straight to the system shell. Which input runs *your own* command alongside the intended one?

#a
`8.8.8.8`

#b
`8.8.8.8/24`

#c
`8.8.8.8; id`

#d
`8.8.8.8 -c 1`

#indice
Quel caractère, dans un shell, sépare deux commandes sur la même ligne ?

#solution
C'est une **command injection** : le `;` termine la commande prévue et en enchaîne une seconde, la tienne. `|`, `&&`, les accents graves ou `$(...)` font de même. La parade : ne jamais concaténer une entrée dans un appel système, valider en liste blanche.

**Les distracteurs :** **a** est une entrée normale ; **b** et **d** restent des arguments passés à la commande d'origine, sans en lancer de nouvelle.

Réponse : $\boxed{\text{c}}$
::

::qcm-question{label="7." bonne="b" cours="lab2-cms"}
VulnCMS hosts a WordPress site. Which tool enumerates its plugins, themes, users and vulnerable versions?

#a
`enum4linux-ng`

#b
`wpscan`

#c
`whatweb`

#d
`netdiscover`

#indice
Son nom dit le logiciel qu'il cible.

#solution
**`wpscan`** est le scanner dédié à WordPress : il énumère extensions, thèmes, utilisateurs et versions vulnérables (`wpscan --url <url> --enumerate`).

**Les distracteurs :** **c** (`whatweb`) **reconnaît** le CMS mais n'énumère ni extensions ni utilisateurs ; **a** interroge SMB sur Windows ; **d** découvre des hôtes par ARP.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="8." bonne="d" cours="lab2-cms"}
You have identified a CMS and its exact version. What is the fastest way, from the command line, to find a matching public exploit?

#a
`hydra`

#b
`gobuster`

#c
`sqlmap`

#d
`searchsploit <cms> <version>`

#indice
Quel outil interroge en local la base Exploit-DB par mots-clés ?

#solution
**`searchsploit`** cherche dans une copie locale d'**Exploit-DB** : avec le nom du logiciel et sa version, il renvoie les exploits publics prêts à l'emploi. Identifier précisément **logiciel et version** est ce qui mène à l'exploit.

**Les distracteurs :** **a** fait de la force brute d'identifiants ; **b** énumère des répertoires web ; **c** automatise l'injection SQL — aucun ne cherche un exploit par version.

Réponse : $\boxed{\text{d}}$
::

::qcm-question{label="9." bonne="a" cours="lab3-sqli"}
On the Pentester Lab box, which single character appended to `?id=1` most simply reveals a SQL injection by breaking the query?

#a
A single quote `'`

#b
A hash `#`

#c
A dot `.`

#d
A slash `/`

#indice
Qu'est-ce qui, dans une requête SQL, délimite une chaîne de caractères ?

#solution
L'**apostrophe** `'` ferme une chaîne SQL : injectée dans `?id=1'`, elle déséquilibre la requête et provoque une **erreur SQL**, le premier signe d'une injection.

**Les distracteurs :** **b** est un commentaire **une fois** la requête déjà manipulée, pas un révélateur ; **c** et **d** passent le plus souvent sans rien casser.

Réponse : $\boxed{\text{a}}$
::

::qcm-question{label="10." bonne="c" cours="lab3-sqli"}
In a UNION-based SQL injection, which clause do you use first to find how many columns the query returns?

#a
`GROUP BY`

#b
`LIMIT`

#c
`ORDER BY`

#d
`HAVING`

#indice
On incrémente un numéro de colonne jusqu'à ce que la requête casse : la dernière valeur qui passe donne le compte.

#solution
`ORDER BY 1`, `ORDER BY 2`… trie par la n-ième colonne ; dès que le numéro dépasse le nombre réel de colonnes, la requête échoue. La dernière valeur acceptée **donne le nombre de colonnes**, qu'il faut connaître pour construire le `UNION SELECT`.

**Les distracteurs :** **a**, **b** et **d** ne révèlent pas le nombre de colonnes de cette façon.

Réponse : $\boxed{\text{c}}$
::

::qcm-question{label="11." bonne="a" cours="lab3-sqli"}
With a working UNION injection, how do you list the database's table names?

#a
`UNION SELECT table_name FROM information_schema.tables`

#b
`SHOW TABLES` typed into the URL

#c
`UNION SELECT * FROM users`

#d
`SELECT version()`

#indice
Quelle base, présente dans tout SGBD, décrit les autres bases — leurs tables et leurs colonnes ?

#solution
`information_schema` est le **catalogue** du SGBD : sa table `tables` liste toutes les tables. `UNION SELECT table_name FROM information_schema.tables` les affiche, de quoi repérer ensuite la table des utilisateurs.

**Les distracteurs :** **b** n'est pas injectable dans un `UNION` au milieu d'une requête ; **c** suppose déjà **connu** le nom `users`, justement ce qu'on cherche ; **d** ne donne que la version du serveur.

Réponse : $\boxed{\text{a}}$
::

::qcm-question{label="12." bonne="b" cours="lab3-sqli"}
The admin panel lets you upload an image but only checks the `Content-Type` header. How do you get a PHP webshell served?

#a
Rename the shell to `shell.jpg` and leave it as an image

#b
Send the `.php` file while declaring `Content-Type: image/jpeg`

#c
Compress the shell into a `.zip` archive

#d
It cannot be done; the check is unbypassable

#indice
Le filtre croit le navigateur sur parole. Que se passe-t-il si le navigateur ment ?

#solution
Le contrôle ne lit que l'en-tête `Content-Type` **annoncé**, pas le vrai contenu. On envoie donc le fichier `.php` en déclarant `Content-Type: image/jpeg` (via Burp) : le filtre est trompé, le fichier est servi en PHP, et l'appeler exécute du code — le **shell**.

**Les distracteurs :** **a** — un `.jpg` n'est pas exécuté comme du PHP ; **c** — une archive n'est pas servie comme du code ; **d** est faux, c'est exactement la faille du lab.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="13." bonne="d" cours="lab4-pentest"}
On Basic Pentesting, the FTP banner reads `ProFTPD 1.3.3c`. What is the quickest path to a root shell?

#a
Brute-force the FTP login with Hydra

#b
Upload a webshell over FTP

#c
Run a UDP scan of the host

#d
Use the known 1.3.3c backdoor (Metasploit `proftpd_133c_backdoor`)

#indice
Cette version précise est tristement célèbre : cherche-la dans Exploit-DB.

#solution
**ProFTPD 1.3.3c** embarque une **backdoor** connue : `searchsploit proftpd` la trouve, et le module Metasploit `exploit/unix/ftp/proftpd_133c_backdoor` donne directement un shell **root**. Lire la version d'un service et la chercher dans Exploit-DB est le premier réflexe.

**Les distracteurs :** **a** et **b** sont bien plus longs et incertains ; **c** ne mène à aucun accès.

Réponse : $\boxed{\text{d}}$
::

::qcm-question{label="14." bonne="b" cours="lab4-pentest"}
What first tells you a running service is likely exploitable, before you search Exploit-DB?

#a
The port number alone

#b
The service name and its exact version, from `nmap -sV`

#c
The server's MAC address

#d
The total number of open ports

#indice
Un exploit public vise un logiciel **et** un numéro de version précis.

#solution
Un exploit se cherche par **logiciel et version** : c'est `-sV` (détection de versions) qui les donne, par des sondes applicatives. Sans la version, `searchsploit` n'a rien à interroger.

**Les distracteurs :** **a** suggère un service mais pas sa version ; **c** désigne au mieux le constructeur de la carte ; **d** ne dit rien de l'exploitabilité.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="15." bonne="c" cours="lab4-pentest"}
A default Apache page sits on port 80. Which command reveals the hidden `/secret/` directory that hosts a WordPress blog?

#a
`nmap -sV <ip>`

#b
`enum4linux-ng <ip>`

#c
`gobuster dir -u http://<ip> -w <wordlist>`

#d
`curl -I http://<ip>`

#indice
Il faut deviner des noms de répertoires à partir d'une liste de mots.

#solution
`gobuster dir` (ou `dirb`, `feroxbuster`) **force les répertoires** : il demande au serveur chaque nom d'une liste et garde ceux qui répondent, révélant `/secret/` qui n'est lié nulle part.

**Les distracteurs :** **a** détecte les versions de services, pas les chemins web ; **b** énumère SMB ; **d** ne lit que les en-têtes de la page d'accueil.

Réponse : $\boxed{\text{c}}$
::

::qcm-question{label="16." bonne="b" cours="lab5-rapport"}
In the pentest report for lab 5, what does a risk matrix rank each vulnerability by?

#a
Its CVE number

#b
Its likelihood and its impact

#c
The time it took to exploit

#d
The port it was found on

#indice
Deux axes : la chance qu'une faille soit exploitée, et ce qu'elle coûte si elle l'est.

#solution
Une **matrice de risque** croise la **probabilité** (*likelihood*) et l'**impact** de chaque faille : leur produit donne la criticité, donc l'**ordre** dans lequel corriger. C'est ce qui fait la valeur du rapport pour le client.

**Les distracteurs :** **a**, **c** et **d** sont des détails qui ne disent rien de la gravité ni de la priorité.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="17." bonne="a" cours="lab5-rapport"}
On FunBox you find a password-protected `.zip` left on a service. What do you do?

#a
Crack it offline with `fcrackzip` or `zip2john` + `john`

#b
Ignore it; encrypted archives cannot be opened

#c
Upload it back to the server to unlock it

#d
Report it immediately as unexploitable

#indice
Un mot de passe d'archive se devine hors ligne, sans rien demander au serveur.

#solution
Une archive protégée se **casse hors ligne** : `fcrackzip -u -D -p <liste>`, ou `zip2john` suivi de `john`, essaie une liste de mots de passe. Le mot de passe trouvé, et souvent les identifiants qu'il protège, se **réutilisent** ensuite sur SSH, FTP ou un panneau web.

**Les distracteurs :** **b** et **d** abandonnent une piste exploitable ; **c** n'a aucun sens.

Réponse : $\boxed{\text{a}}$
::

::qcm-question{label="18." bonne="c" cours="lab-privesc"}
You get a shell as a low-privileged user. Which command first checks for an easy path to root?

#a
`uname -a`

#b
`cat /etc/shadow`

#c
`sudo -l`

#d
`ls -la /root`

#indice
Quelle commande dit ce que l'utilisateur a le droit de lancer **en tant que root** ?

#solution
`sudo -l` liste les commandes que l'utilisateur peut lancer en root, souvent **sans mot de passe** (`NOPASSWD`) — un binaire détournable via **GTFOBins** mène alors droit au root. C'est le tout premier réflexe d'élévation de privilèges.

**Les distracteurs :** **b** et **d** demandent **déjà** les droits root pour être lus ; **a** ne sert qu'à chercher un exploit de noyau, une piste plus lourde.

Réponse : $\boxed{\text{c}}$
::

::qcm-question{label="19." bonne="a" cours="lab-privesc"}
Which command lists SUID binaries, a classic road to privilege escalation?

#a
`find / -perm -4000 -type f 2>/dev/null`

#b
`chmod +s /bin/bash`

#c
`ls -l /usr/bin`

#d
`sudo find / -name flag`

#indice
Le bit SUID vaut 4000 dans les permissions ; on cherche les fichiers qui le portent.

#solution
`find / -perm -4000 -type f` parcourt tout le système à la recherche des fichiers portant le bit **SUID** : ils s'exécutent avec les droits de leur **propriétaire** (souvent root), ce qui peut livrer un shell root. `2>/dev/null` masque les erreurs de permission.

**Les distracteurs :** **b** *pose* le bit SUID sur bash — ce qu'on ne peut faire **qu'une fois déjà root** ; **c** ne montre que `/usr/bin` sans filtrer les SUID ; **d** suppose les droits root et ne cherche pas de SUID.

Réponse : $\boxed{\text{a}}$
::

::extrait-cours{id="lab-demarche" titre="La démarche d'un lab et le rapport" source="/cours/a1/ethical-hacking/labs/cours#_1-la-démarche-des-cinq-labs"}
Chaque lab rejoue les **cinq phases** du pentest : reconnaissance / scan (`nmap -sC -sV -p-`, sans oublier `-p-` pour les ports non standard), énumération service par service, exploitation, **élévation de privilèges**, puis rapport. Préalable : l'**autorisation** et le **périmètre** — la seule machine fournie. Pour les labs 4 et 5, le livrable est un **rapport** dans `Pentest_Report_Template.docx`, l'élève en pentester, l'enseignant en client.
::

::extrait-cours{id="lab1-ports" titre="Énumérer large" source="/cours/a1/ethical-hacking/labs/cours#_2-énumérer-tous-les-ports"}
Un scan par défaut ne couvre que les **1 000 ports courants** : seul `nmap -p-` voit un service déplacé (un SSH sur 22222). La phase d'énumération rapporte souvent, sans aucune exploitation : un **FTP anonyme** (`anonymous`, mot de passe vide), les chemins sensibles listés dans **`robots.txt`** (`/cgi-bin/`, un dossier de mots de passe), un flag ou un identifiant dans les **commentaires HTML** d'une page.
::

::extrait-cours{id="lab1-cmdi" titre="L'injection de commande" source="/cours/a1/ethical-hacking/labs/cours#_3-linjection-de-commande"}
Quand une application passe une entrée telle quelle au **shell** du système, un **métacaractère** y glisse sa propre commande : `8.8.8.8; id`, `| cat /etc/passwd`, `&& whoami`, les accents graves ou `$(...)`. C'est une **command injection**. Défense : ne jamais concaténer une entrée dans un appel système, valider en **liste blanche**.
::

::extrait-cours{id="lab2-cms" titre="Reconnaître et énumérer un CMS" source="/cours/a1/ethical-hacking/labs/cours#_4-reconnaître-et-énumérer-un-cms"}
Face à un **CMS** (WordPress, Joomla, Drupal), prendre l'empreinte (`whatweb`, `robots.txt`, chemins comme `/wp-login.php` ou `/administrator/`), puis énumérer avec l'outil dédié — **`wpscan`** pour WordPress (extensions, thèmes, utilisateurs, versions vulnérables), `joomscan`, `droopescan`. Le logiciel **et sa version** connus, `searchsploit <cms> <version>` donne l'exploit public correspondant.
::

::extrait-cours{id="lab3-sqli" titre="De l'injection SQL au shell" source="/cours/a1/ethical-hacking/labs/cours#_5-de-linjection-sql-au-shell"}
Le chemin : une **apostrophe** `'` sur `?id=1` casse la requête (détection) ; `ORDER BY` donne le **nombre de colonnes**, puis `UNION SELECT` lit la base via `information_schema.tables` jusqu'à la table des utilisateurs ; les **hachages MD5** extraits se craquent (`hashcat`/`john`) ; on se connecte au panneau d'administration ; son **upload d'image**, qui ne vérifie que le `Content-Type` annoncé, accepte un **webshell PHP** déclaré `image/jpeg` — d'où l'exécution de code. Défense : requêtes **préparées**, validation du **contenu** d'un fichier.
::

::extrait-cours{id="lab4-pentest" titre="Backdoor de service et énumération web" source="/cours/a1/ethical-hacking/labs/cours#_6-backdoor-de-service-et-énumération-web"}
Deux chemins. Par la **version** : une bannière `ProFTPD 1.3.3c` trahit une **backdoor** connue — module Metasploit `proftpd_133c_backdoor`, shell root direct ; le réflexe est de lire la version (`nmap -sV`) et de la chercher dans Exploit-DB. Par le **web** : `gobuster dir` révèle un répertoire caché (`/secret/`) hébergeant un WordPress ; `wpscan` l'énumère, puis `hydra -l <user> -P <liste> <ip> ssh` force un identifiant pour ouvrir SSH.
::

::extrait-cours{id="lab5-rapport" titre="La reconnaissance et le rapport de pentest" source="/cours/a1/ethical-hacking/labs/cours#_7-la-reconnaissance-et-le-rapport-de-pentest"}
FunBox CTF, second lab noté : dérouler la démarche complète et rendre un **rapport**. Reconnaissance d'abord — une archive protégée se **craque** hors ligne (`fcrackzip`, `zip2john` + `john`), des identifiants trouvés se **réutilisent** ailleurs. Le rapport (`Pentest_Report_Template.docx`) contient la démarche et le périmètre, les **vulnérabilités** décrites et reproduites, des **remédiations**, et une **matrice de risque** qui croise **probabilité** et **impact** pour prioriser les corrections.
::

::extrait-cours{id="lab-privesc" titre="L'élévation de privilèges" source="/cours/a1/ethical-hacking/labs/cours#_8-lélévation-de-privilèges"}
Le dénominateur des cinq labs : d'un utilisateur simple à **root**. Les pistes, de la plus simple à la plus technique : `sudo -l` (une commande en root, souvent `NOPASSWD`, détournable via **GTFOBins**), `find / -perm -4000 -type f` (binaires **SUID**), `/etc/crontab` (tâche root lançant un script modifiable), `uname -a` (exploit de **noyau**), et les mots de passe réutilisables laissés dans les fichiers. **LinPEAS** / **WinPEAS** automatisent la recherche.
::
