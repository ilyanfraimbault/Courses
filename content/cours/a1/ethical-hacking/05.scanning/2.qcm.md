Un QCM d'un seul bloc, en anglais comme l'examen : on répond à **tout**, puis on clique sur **Corriger**. Chaque question dit alors si elle est juste, et s'ouvrent sous elle l'**indice**, la **solution** et le **cours** visé. Une seule bonne réponse par question. À l'examen, une réponse fausse **ou absente** retire un point : on répond toujours, et l'on s'entraîne ici à savoir justifier chaque réponse.

:::qcm{titre="QCM — Scanning et énumération" theme="Découverte d'hôtes, états de ports, déroulé d'un scan, bannières, énumération et scanners" duree="15 min" icone="i-lucide-circle-check-big"}

::qcm-question{label="1." bonne="b" cours="scan-q-definition"}
During an authorized penetration test, you send packets to the target network to find live hosts, open ports and vulnerable services. Which phase are you in?

#a
Passive reconnaissance

#b
Scanning and enumeration

#c
Exploitation

#d
Post-exploitation

#indice
Tu envoies des paquets à la cible, mais tu n'attaques encore rien.

#solution
Envoyer des paquets à la cible pour en lire les réponses, c'est la phase **active** de scanning, qui poursuit justement trois objectifs : hôtes actifs, ports et services, vulnérabilités.

**Les distracteurs :** **a** n'envoie rien à la cible, elle se contente de sources publiques ; **c** exploite les failles trouvées, ce qui vient après ; **d** commence une fois l'accès obtenu.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="2." bonne="c" cours="scan-q-decouverte"}
The target network's firewall drops all ICMP traffic. Which command can still discover the hosts that run web servers?

#a
`nmap -sn -PE 10.0.0.0/24`

#b
`nmap -sn -PP 10.0.0.0/24`

#c
`nmap -sn -PS80,443 10.0.0.0/24`

#d
`nmap -sn -PM 10.0.0.0/24`

#indice
Trois de ces sondes sont des requêtes ICMP. Laquelle parle TCP ?

#solution
`-PS80,443` envoie un **SYN** vers les ports 80 et 443. Un serveur web répond par un SYN-ACK (un port fermé, par un RST) : l'une comme l'autre réponse prouve que l'hôte est actif, sans le moindre paquet ICMP.

**Les distracteurs :** **a** (echo), **b** (timestamp) et **d** (address mask) envoient trois sortes de requêtes ICMP, toutes jetées par le pare-feu.

Réponse : $\boxed{\text{c}}$
::

::qcm-question{label="3." bonne="a" cours="scan-q-decouverte"}
In `nmap -sn -PS80,443 -PE -PU53 192.168.1.0/24`, what does `-PU53` add?

#a
A UDP ping to port 53, the DNS port

#b
A TCP SYN ping to port 53, the DNS port

#c
A UDP port scan of port 53 on every live host

#d
An ICMP echo request carrying 53 bytes of data

#indice
Dans `-PS`, `-PE` et `-PU`, le `P` veut dire *ping* ; la lettre suivante dit la sonde.

#solution
`-PU` est le **ping UDP** : un datagramme vers le port 53 (DNS). Une réponse UDP, ou un ICMP port unreachable, prouve que l'hôte est actif. Ajouté à `-PS80,443` et `-PE`, il élargit la découverte en environnement durci.

**Les distracteurs :** **b** s'écrirait `-PS53` ; **c** est exclu par `-sn`, qui ne scanne aucun port ; **d** confond avec `-PE`, qui ne prend aucun numéro.

Réponse : $\boxed{\text{a}}$
::

::qcm-question{label="4." bonne="d" cours="scan-q-etats"}
During a SYN scan, port 22 answers the SYN with a SYN-ACK. What happens next, and how is the port reported?

#a
Nmap completes the handshake with an ACK; the port is open

#b
Nmap sends nothing more; the port is filtered

#c
Nmap sends a FIN; the port is closed

#d
The scanning host sends a RST instead of an ACK; the port is open

#indice
Le scan SYN est dit *half-open* : la poignée de main n'est jamais terminée.

#solution
Un SYN-ACK signifie qu'un service écoute : le port est **open**. Le scan SYN n'achève jamais la poignée de main : au lieu de l'ACK, la machine qui scanne répond par un **RST**, qui coupe la connexion avant qu'elle ne s'établisse.

**Les distracteurs :** **a** décrit le scan connect (`-sT`), qui termine la poignée de main ; **b** confond avec l'absence de réponse, qui donnerait filtered ; **c** — un port qui répond SYN-ACK n'est pas fermé, seul un RST de la cible l'aurait dit.

Réponse : $\boxed{\text{d}}$
::

::qcm-question{label="5." bonne="a" cours="scan-q-etats"}
During a SYN scan, port 139 gives no response at all, even after retransmissions. What state does Nmap report?

#a
filtered

#b
closed

#c
open|filtered

#d
unfiltered

#indice
Qui, sur le chemin, a pu faire disparaître la sonde sans rien répondre ?

#solution
Le silence d'un port TCP, malgré les retransmissions, veut dire qu'un pare-feu jette la sonde : Nmap le classe **filtered**.

**Les distracteurs :** **b** demanderait un RST ; **c** est la lecture du silence en **UDP** (et dans les scans NULL, FIN et Xmas), pas dans un scan SYN ; **d** n'apparaît qu'avec le scan ACK.

Réponse : $\boxed{\text{a}}$
::

::qcm-question{label="6." bonne="b" cours="scan-q-etats"}
During a UDP scan, port 161 returns an ICMP port unreachable error (type 3, code 3). How does Nmap classify the port?

#a
filtered

#b
closed

#c
open|filtered

#d
open

#indice
En UDP, c'est la seule réponse qui tranche sans ambiguïté.

#solution
L'ICMP **port unreachable** (type 3, code 3) est la façon dont une pile IP dit « personne n'écoute ici » en UDP : le port est **closed**.

**Les distracteurs :** **a** correspond aux **autres** codes ICMP unreachable (0, 1, 2, 9, 10, 13) ; **c** correspond à l'absence de réponse ; **d** demanderait une réponse UDP venue du port.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="7." bonne="c" cours="scan-q-etats"}
A UDP scan reports port 53 as open|filtered. Which Nmap option helps decide whether it is really open?

#a
`-Pn`, to skip host discovery

#b
`-sA`, to map the firewall rules

#c
`-sV`, to send service-specific probes

#d
`--top-ports 1000`, to scan more ports

#indice
Un service UDP ouvert se tait devant une sonde vide. Que faudrait-il lui envoyer pour qu'il réponde ?

#solution
La détection de versions envoie à chaque port des **sondes propres au service** — une vraie requête DNS sur le port 53, par exemple. Un service ouvert y répond, et le port passe à **open**.

**Les distracteurs :** **a** concerne la découverte d'hôtes, pas l'état d'un port ; **b** est un scan TCP, qui ne trouve d'ailleurs jamais de port ouvert ; **d** élargit la liste des ports sans lever l'ambiguïté.

Réponse : $\boxed{\text{c}}$
::

::qcm-question{label="8." bonne="d" cours="scan-q-deroule"}
What does `nmap -sS -sV -T4 --top-ports 1000 -iL hosts.gnmap -oA ports` do?

#a
It discovers the live hosts of a subnet without scanning their ports

#b
It scans all 65,535 TCP and UDP ports of a single host

#c
It runs the NSE vulnerability scripts on the hosts listed in a file

#d
It SYN-scans the top 1,000 ports of the listed hosts and detects versions

#indice
Décompose : `-sS`, `-sV`, `--top-ports 1000`, `-iL`.

#solution
`-sS` : scan SYN ; `-sV` : versions des services ; `-T4` : rythme rapide ; `--top-ports 1000` : les 1 000 ports les plus courants ; `-iL hosts.gnmap` : les cibles lues dans le fichier de l'étape de découverte ; `-oA ports` : les résultats dans les trois formats. C'est le scan rapide, l'étape « largeur » du déroulé.

**Les distracteurs :** **a** est l'étape de découverte (`-sn`) ; **b** le scan complet (`-sS -sU -p-`) ; **c** la vérification des vulnérabilités (`--script=vuln,vulners`).

Réponse : $\boxed{\text{d}}$
::

::qcm-question{label="9." bonne="b" cours="scan-q-deroule"}
Why is `nmap -sS -sU -p- -sV -O -T4 10.10.0.5` kept for a few key hosts and run in the background?

#a
Because `-O` only works on one host at a time

#b
Because scanning every TCP and UDP port is very slow

#c
Because `-sU` cannot be combined with a list of targets

#d
Because `-T4` must never be used on a whole subnet

#indice
Combien de ports ce scan vise-t-il, et quel protocole est réputé lent ?

#solution
`-p-` porte le scan à 65 535 ports **par protocole**, et `-sU` y ajoute l'UDP, très lent : un port UDP ouvert se tait, et les systèmes limitent le débit de leurs messages ICMP d'erreur. On réserve donc ce scan complet aux machines intéressantes, en arrière-plan.

**Les distracteurs :** **a**, **c** et **d** inventent des restrictions : `-O` s'applique à plusieurs hôtes, `-sU` accepte une liste de cibles, `-T4` sert aussi sur un sous-réseau.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="10." bonne="a" cours="scan-q-bannieres"}
Which command grabs the raw banner of the SSH service on 10.1.1.5 without resolving names?

#a
`nc -nv 10.1.1.5 22`

#b
`curl -I http://10.1.1.5`

#c
`openssl s_client -connect 10.1.1.5:443`

#d
`whatweb http://10.1.1.5`

#indice
SSH écoute sur le port 22. Quel outil ouvre une simple connexion TCP et affiche ce que le service envoie ?

#solution
`nc` (netcat) ouvre une connexion TCP brute vers le port 22 ; le serveur SSH envoie aussitôt sa bannière, du type `SSH-2.0-OpenSSH_8.9p1 Ubuntu`. `-n` évite la résolution DNS, `-v` rend la sortie verbeuse.

**Les distracteurs :** **b** lit les en-têtes d'un serveur **web** ; **c** ouvre une session **TLS** sur le port 443 ; **d** prend l'empreinte des technologies d'un site web.

Réponse : $\boxed{\text{a}}$
::

::qcm-question{label="11." bonne="d" cours="scan-q-bannieres"}
Which command displays only the HTTP response headers of a web server, such as `Server: nginx/1.18.0 (Ubuntu)`?

#a
`nc -nv 10.1.1.5 22`

#b
`enum4linux-ng 10.1.1.5`

#c
`netdiscover -r 10.1.1.0/24`

#d
`curl -I http://10.1.1.5`

#indice
Une seule de ces commandes parle HTTP.

#solution
`curl -I` envoie une requête **HEAD** et n'affiche que les **en-têtes** de la réponse, dont `Server`, qui trahit souvent le logiciel et sa version.

**Les distracteurs :** **a** lit la bannière SSH ; **b** énumère SMB ; **c** découvre des hôtes par ARP.

Réponse : $\boxed{\text{d}}$
::

::qcm-question{label="12." bonne="c" cours="scan-q-bannieres"}
Why is `nmap -sV` more reliable than a raw banner grab to identify a service version?

#a
It completes the TCP handshake, unlike netcat

#b
It reads the service's configuration files on the target

#c
It sends application probes and matches the answers against a signature database

#d
It identifies the service from the MAC address of the target

#indice
Une bannière se modifie ou se masque ; la manière dont un service répond à des requêtes précises, beaucoup moins.

#solution
`-sV` ne se fie pas à ce qu'annonce le service : il lui envoie des **sondes applicatives** et compare les réponses à une base de signatures (`nmap-service-probes`). Il reconnaît ainsi un service sans bannière, ou dont la bannière ment.

**Les distracteurs :** **a** est faux, netcat aussi établit une connexion complète ; **b** — un scan réseau n'a pas accès aux fichiers de la cible ; **d** — une adresse MAC désigne au mieux le constructeur de la carte, et elle ne franchit pas les routeurs.

Réponse : $\boxed{\text{c}}$
::

::qcm-question{label="14." bonne="d" cours="scan-q-enumeration"}
On a Linux host, which command lists the TCP and UDP ports in listening state, with the processes behind them?

#a
`sudo -l`

#b
`find / -perm -4000`

#c
`uname -a`

#d
`ss -tulpn`

#indice

::extrait-cours{id="scan-q-definition" titre="Le scanning, phase active" source="/cours/a1/ethical-hacking/scanning/cours#_1-quest-ce-que-le-scanning"}
Le **scanning** est la phase **active** qui suit la reconnaissance : il envoie des paquets directement à la cible et analyse ses réponses. Trois objectifs : les **hôtes actifs**, les **ports ouverts et les services**, les **vulnérabilités**.

Méthode : host discovery → port scan → service / version → OS fingerprint → vuln scan → enumeration → document. Viennent ensuite l'exploitation, puis la post-exploitation. Chaque paquet laisse des traces : jamais sans autorisation écrite.
::

::extrait-cours{id="scan-q-decouverte" titre="Les sondes de découverte d'hôtes" source="/cours/a1/ethical-hacking/scanning/cours#_2-la-découverte-dhôtes"}
`nmap -sn` : ping sweep, sans scan de ports. Les sondes se choisissent avec `-P…`, port collé à l'option :

- `-PS80,443` : ping **TCP SYN** (port 80 par défaut) — passe quand l'ICMP est filtré ;
- `-PE`, `-PP`, `-PM` : requêtes **ICMP** echo, timestamp et address mask ;
- `-PU53` : ping **UDP** vers le port 53.

`nmap -sn -PS80,443 -PE -PU53 192.168.1.0/24` combine les trois familles, pour la meilleure couverture en environnement durci. Sur le réseau local, l'ARP (`netdiscover`) ne se filtre pas.
::

::extrait-cours{id="scan-q-etats" titre="La table des états de ports" source="/cours/a1/ethical-hacking/scanning/cours#_3-les-états-de-ports"}
**Scan SYN** : SYN-ACK → **open** (la machine qui scanne répond RST au lieu d'ACK : la poignée de main n'est jamais terminée) ; RST → **closed** ; aucune réponse ou ICMP unreachable → **filtered**.

**Scan UDP** : réponse UDP → open ; ICMP port unreachable (type 3, code 3) → **closed** ; autres ICMP unreachable (codes 0, 1, 2, 9, 10, 13) → filtered ; aucune réponse → **open|filtered**. `-sV`, qui envoie de vraies requêtes de service, aide à trancher.

*Unfiltered* n'apparaît qu'avec le scan ACK.
::

::extrait-cours{id="scan-q-deroule" titre="Le déroulé d'un scan" source="/cours/a1/ethical-hacking/scanning/cours#_4-le-déroulé-dun-scan"}
1. Découverte : `nmap -sn -PS80,443 -PE 10.10.0.0/24 -oA hosts`.
2. Scan rapide des hôtes actifs : `nmap -sS -sV -T4 --top-ports 1000 -iL hosts.gnmap -oA ports` — SYN, versions, rythme rapide, 1 000 ports courants, cibles lues dans un fichier.
3. Scan complet des machines clés, en arrière-plan : `nmap -sS -sU -p- -sV -O -T4 10.10.0.5 -oA full_10_10_0_5` — tous les ports TCP et UDP, très lent à cause de l'UDP.
4. Vulnérabilités : `nmap -sV --script=vuln,vulners -p 22,80,443,445 10.10.0.5 -oA vuln_check`.

Chaque étape nourrit la suivante et s'enregistre avec `-oA`.
::

::extrait-cours{id="scan-q-bannieres" titre="Le banner grabbing" source="/cours/a1/ethical-hacking/scanning/cours#_5-banner-grabbing-et-énumération"}
- `nc -nv 10.1.1.5 22` : connexion TCP brute, la bannière SSH s'affiche (`-n` sans DNS, `-v` verbeux).
- `curl -I http://10.1.1.5` : requête HEAD, les seuls en-têtes HTTP, dont `Server`.
- `openssl s_client -connect 10.1.1.5:443` : les détails de la session TLS.
- `whatweb` : les technologies d'un site web.
- `nmap -sV` : des sondes applicatives comparées à une base de signatures — plus fiable qu'une bannière, qui peut être masquée ou falsifiée.
::

::extrait-cours{id="scan-q-enumeration" titre="L'énumération" source="/cours/a1/ethical-hacking/scanning/cours#_5-banner-grabbing-et-énumération"}
**SMB (Windows)** : `enum4linux-ng` (Python 3 : utilisateurs, partages, système, politique de mots de passe), `crackmapexec smb hôte --users` ou sur tout un sous-réseau, `nmap -p445 --script=smb-enum-users,smb-enum-shares`.

**Linux, en local** : `sudo -l` (droits sudo), `find / -perm -4000` (fichiers SUID), `ss -tulpn` (ports TCP et UDP en écoute, avec leurs processus), `uname -a` (noyau). LinPEAS / WinPEAS automatisent cette énumération.
::

::extrait-cours{id="scan-q-scanners" titre="Choisir un scanner de vulnérabilités" source="/cours/a1/ethical-hacking/scanning/cours#_6-les-scanners-de-vulnérabilités"}
- **Nmap NSE** (`--script=vuln`, `vulners`) : intégré, vérifications ciblées.
- **Nuclei** : modèles communautaires (plus de 10 000), le plus rapide pour vérifier des CVE à grande échelle — `nuclei -u https://target.com -t cves/`.
- **OpenVAS / Greenbone** : complet, interface web (Greenbone Security Assistant), scans planifiés, authentifiés et de conformité ; plus lent.
- **Nikto** : serveurs web (fichiers dangereux, logiciels obsolètes) — `nikto -h http://target.com` ; rapide et bruyant.
::
