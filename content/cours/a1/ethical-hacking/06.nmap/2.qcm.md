Deux blocs, en anglais comme l'examen, où l'enseignant a annoncé des questions sur les options de Nmap. Dans chaque bloc, on répond à **tout**, puis on clique sur **Corriger** : chaque question dit alors si elle est juste, et s'ouvrent sous elle l'**indice**, la **solution** et le **cours** visé. Une seule bonne réponse par question. À l'examen, une réponse fausse **ou absente** retire un point : on répond toujours, et l'on s'entraîne ici à savoir justifier chaque réponse. Les options de Nmap sont sensibles à la casse : `-sn` n'est pas `-sN`, ni `-f` `-F`.

::qcm-question{label="1." bonne="d" cours="nm-q-ports"}
You need to scan all 65,535 TCP ports of 10.1.1.1. Which command should you use?

#a
`nmap -p 65535 10.1.1.1`

#b
`nmap -F 10.1.1.1`

#c
`nmap -p 1-1024 10.1.1.1`

#d
`nmap -p- 10.1.1.1`

#indice
Une plage dont on omet le début et la fin va de 1 à 65 535.

#solution
`-p-` est une plage sans bornes : Nmap la complète de **1 à 65 535**, soit tous les ports. C'est exhaustif, mais bien plus long que le scan par défaut des 1 000 ports les plus courants.

**Les distracteurs :** **a** ne scanne que le seul port 65535 ; **b** est le mode rapide, limité aux 100 ports les plus courants ; **c** ne couvre que les 1 024 premiers ports.

Réponse : $\boxed{\text{d}}$
::

::qcm-question{label="2." bonne="b" cours="nm-q-ports"}
Which command scans only ports 22, 80 and 443?

#a
`nmap -p 22-443 10.1.1.1`

#b
`nmap -p 22,80,443 10.1.1.1`

#c
`nmap --top-ports 3 10.1.1.1`

#d
`nmap --exclude 22,80,443 10.1.1.1`

#indice
Virgule ou tiret : l'un énumère, l'autre couvre tout un intervalle.

#solution
Les virgules énumèrent des ports précis : `-p 22,80,443` en scanne trois, et rien d'autre.

**Les distracteurs :** **a** couvre toute la plage de 22 à 443, soit 422 ports ; **c** prend les trois ports les plus fréquents de `nmap-services` — 80, 23 et 443, pas le 22 ; **d** — `--exclude` retire des **hôtes** de la liste des cibles, pas des ports.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="3." bonne="a" cours="nm-q-cibles"}
You must scan 10.1.1.0/24 but leave out the production server 10.1.1.5. Which command should you use?

#a
`nmap 10.1.1.0/24 --exclude 10.1.1.5`

#b
`nmap 10.1.1.0/24 -Pn 10.1.1.5`

#c
`nmap -iL 10.1.1.5 10.1.1.0/24`

#d
`nmap 10.1.1.0/24 --exclude-ports 10.1.1.5`

#indice
Une option retire des cibles, une autre retire des ports.

#solution
`--exclude` retire de la liste des cibles les hôtes qu'on lui donne, séparés par des virgules : les autres adresses de la plage sont scannées, pas `10.1.1.5`.

**Les distracteurs :** **b** — `-Pn` saute la découverte d'hôtes, et `10.1.1.5` devient une cible de plus ; **c** — `-iL` attend un **fichier** de cibles ; **d** — `--exclude-ports` retire des **ports**, pas des hôtes.

Réponse : $\boxed{\text{a}}$
::

::qcm-question{label="4." bonne="c" cours="nm-q-decouverte"}
A Windows server does not answer pings, but you know it runs services. Which option makes Nmap scan its ports anyway?

#a
`-sn`

#b
`-PE`

#c
`-Pn`

#d
`-sA`

#indice
Il faut dire à Nmap de ne pas attendre de réponse à la découverte d'hôtes.

#solution
`-Pn` (*no ping*) saute la découverte d'hôtes : Nmap considère la cible comme active et passe directement au scan de ports. C'est ce que Nmap suggère lui-même quand un hôte semble éteint (*try -Pn*), et c'est indispensable contre un pare-feu qui bloque le ping, comme celui de Windows par défaut.

**Les distracteurs :** **a** fait l'inverse, découverte seule et aucun scan de ports ; **b** envoie justement un ICMP echo, le ping qui reste sans réponse ; **d** est un scan ACK, qui cartographie un pare-feu sans jamais trouver de port ouvert.

Réponse : $\boxed{\text{c}}$
::

::qcm-question{label="5." bonne="b" cours="nm-q-decouverte"}
What does `nmap -sn 192.168.1.0/24` do?

#a
It skips host discovery and treats every address as up

#b
It discovers which hosts are up, without scanning their ports

#c
It sends TCP packets with no flag set to every port

#d
It scans every port of every host as quietly as possible

#indice
Attention à la casse : `-sn` et `-sN` ne sont pas la même option.

#solution
`-sn` (*no port scan*, anciennement `-sP`) s'arrête après la découverte d'hôtes : c'est le **ping sweep**, qui liste les machines actives.

**Les distracteurs :** **a** décrit `-Pn` ; **c** décrit le scan NULL, `-sN` avec un N majuscule ; **d** ne correspond à aucune option — et un scan de tous les ports n'a rien de discret.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="6." bonne="a" cours="nm-q-decouverte"}
Which host discovery option sends ICMP timestamp requests?

#a
`-PP`

#b
`-PE`

#c
`-PM`

#d
`-PS`

#indice
Echo, timestamp, address mask : trois options ICMP, trois lettres différentes.

#solution
`-PP` envoie des requêtes ICMP **timestamp** : utile quand l'echo classique est filtré, mais pas les autres types ICMP.

**Les distracteurs :** **b** envoie un ICMP **echo**, le ping ordinaire ; **c** une requête ICMP **address mask** ; **d** un ping **TCP SYN**.

Réponse : $\boxed{\text{a}}$
::

::qcm-question{label="7." bonne="d" cours="nm-q-scans"}
You do not have root privileges. Which command performs a TCP connect scan of 10.1.1.1?

#a
`nmap -sS 10.1.1.1`

#b
`nmap -sA 10.1.1.1`

#c
`nmap -sU 10.1.1.1`

#d
`nmap -sT 10.1.1.1`

#indice
Le scan qui ne forge aucun paquet : il demande au système d'ouvrir une vraie connexion TCP.

#solution
`-sT` demande au système d'ouvrir une vraie connexion avec l'appel `connect()` : aucun paquet forgé, donc **aucun privilège** requis. C'est d'ailleurs le scan par défaut d'un simple utilisateur.

**Les distracteurs :** **a** (SYN), **b** (ACK) et **c** (UDP) forgent leurs paquets et demandent root : sans lui, Nmap refuse de les lancer.

Réponse : $\boxed{\text{d}}$
::

::qcm-question{label="8." bonne="c" cours="nm-q-scans"}
Which command performs a TCP SYN scan of the ports of 10.1.1.1?

#a
`sudo nmap -sn -PS 10.1.1.1`

#b
`nmap -sT 10.1.1.1`

#c
`sudo nmap -sS 10.1.1.1`

#d
`sudo nmap -sA 10.1.1.1`

#indice
Dans une option de Nmap, un « P » désigne une sonde de découverte d'hôtes, un « s » un type de scan.

#solution
`-sS` est le scan **SYN** ; il forge ses paquets, d'où `sudo`. En root, c'est aussi le scan par défaut.

**Les distracteurs :** **a** — `-PS` est un **ping** TCP SYN, une sonde de découverte, et `-sn` interdit tout scan de ports ; **b** est le scan connect ; **d** le scan ACK.

Réponse : $\boxed{\text{c}}$
::

::qcm-question{label="9." bonne="b" cours="nm-q-scans"}
Why is the SYN scan called half-open?

#a
It only scans half of the 65,535 ports

#b
It never completes the TCP three-way handshake

#c
It only sends half of the TCP header

#d
It waits for half of the usual timeout

#indice
Compte les étapes de la poignée de main TCP qu'il accomplit.

#solution
Le scan SYN envoie le SYN, reçoit le SYN-ACK… et répond par un **RST** au lieu de l'ACK : la connexion n'est jamais établie, elle reste **à moitié ouverte**. L'application ne voit donc aucune connexion à journaliser.

**Les distracteurs :** **a**, **c** et **d** prennent *half* au pied de la lettre : la moitié qui manque est celle de la poignée de main.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="10." bonne="a" cours="nm-q-scans"}
Which scan type does Nmap use by default when it runs with root privileges?

#a
The TCP SYN scan (`-sS`)

#b
The TCP connect scan (`-sT`)

#c
The UDP scan (`-sU`)

#d
The ACK scan (`-sA`)

#indice
Le défaut dépend des privilèges ; avec root, Nmap peut forger ses paquets.

#solution
Avec le droit de forger des paquets, Nmap choisit le scan **SYN**, rapide et discret. Sans ce droit, il se rabat sur le scan connect.

**Les distracteurs :** **b** est le défaut **sans** root ; **c** ne se lance que si on le demande ; **d** sert à cartographier un pare-feu, jamais par défaut.

Réponse : $\boxed{\text{a}}$
::

::qcm-question{label="11." bonne="c" cours="nm-q-udp"}
You want to know whether a host runs DNS, DHCP or SNMP services. Which scan type must you include?

#a
`-sS`

#b
`-sA`

#c
`-sU`

#d
`-sX`

#indice
Ports 53, 67/68 et 161 : quel protocole de transport ?

#solution
DNS (53), DHCP (67/68) et SNMP (161) fonctionnent en **UDP** : seul `-sU` les voit. C'est pourquoi le scan UDP ne doit jamais être oublié, malgré sa lenteur ; il s'ajoute à un scan TCP (`-sS -sU`).

**Les distracteurs :** **a**, **b** et **d** sont des scans **TCP** (SYN, ACK, Xmas) : ils ne voient aucun service UDP.

Réponse : $\boxed{\text{c}}$
::

::qcm-question{label="12." bonne="d" cours="nm-q-furtifs"}
What is the ACK scan (`-sA`) mainly used for?

#a
Finding open ports faster than a SYN scan

#b
Detecting the version of each service

#c
Fingerprinting the target's operating system

#d
Mapping firewall rules by telling filtered from unfiltered ports

#indice
Ouvert ou fermé, un port joignable répond pareil à un ACK isolé.

#solution
Un ACK isolé reçoit un RST que le port soit ouvert ou fermé : le scan ACK ne trouve donc **jamais** de port ouvert. Il distingue **unfiltered** (un RST revient) de **filtered** (rien ne revient), ce qui cartographie les règles du pare-feu — et dit s'il est à états.

**Les distracteurs :** **a** — il ne détecte aucun port ouvert ; **b** est le rôle de `-sV` ; **c** celui de `-O`.

Réponse : $\boxed{\text{d}}$
::

::qcm-question{label="13." bonne="b" cours="nm-q-furtifs"}
Which scan sends TCP packets with no flag set at all?

#a
The FIN scan (`-sF`)

#b
The NULL scan (`-sN`)

#c
The Xmas scan (`-sX`)

#d
The ACK scan (`-sA`)

#indice
*Null*, comme zéro drapeau.

#solution
Le scan **NULL** envoie un en-tête TCP sans aucun drapeau levé.

**Les distracteurs :** **a** ne lève que FIN ; **c** lève FIN, PSH et URG ; **d** ne lève qu'ACK.

Réponse : $\boxed{\text{b}}$
::

::qcm-question{label="14." bonne="a" cours="nm-q-furtifs"}
You run a FIN scan (`-sF`) against a Windows server. What should you expect?

#a
All ports appear closed, because Windows sends a RST whatever the port state

#b
All ports appear open|filtered, because Windows silently drops FIN packets

#c
Open ports answer with a SYN-ACK, closed ports with a RST

#d
The scan reveals which ports the Windows firewall filters

#indice
La règle de la RFC 793 suppose qu'un port ouvert reste muet. Windows la respecte-t-il ?

#solution
Windows, comme de nombreux équipements Cisco, répond **RST** à ces sondes, que le port soit ouvert ou fermé : tout paraît **closed**, et le scan ne dit rien. Les scans NULL, FIN et Xmas sont inutiles contre Windows.

**Les distracteurs :** **b** — Windows ne se tait pas, il répond RST ; seuls un port ouvert sur une pile conforme à la RFC 793, ou un pare-feu qui jette la sonde, donneraient open|filtered ; **c** — un SYN-ACK ne répond qu'à un SYN ; **d** est le rôle du scan ACK.

Réponse : $\boxed{\text{a}}$
::

::qcm-question{label="15." bonne="c" cours="nm-q-furtifs"}
During a NULL, FIN or Xmas scan of an RFC 793-compliant host, a port gives no response. How is it classified?

#a
closed

#b
filtered

#c
open|filtered

#d
unfiltered

#indice
Un port ouvert ignore la sonde ; un pare-feu qui la jette aussi.

#solution
Sur une pile conforme à la RFC 793, un port **ouvert** ignore la sonde, mais un pare-feu qui la jette produit le même silence : Nmap ne peut pas trancher, d'où **open|filtered**. Un RST, lui, aurait dit closed.

**Les distracteurs :** **a** demanderait un RST ; **b** correspond à un ICMP unreachable ; **d** n'est produit que par le scan ACK.

Réponse : $\boxed{\text{c}}$
::

::qcm-question{label="1." bonne="d" cours="nm-q-versions"}
Which option detects the name and version of the software listening on open ports?

#a
`-O`

#b
`-sC`

#c
`-sS`

#d
`-sV`

#indice
V comme version.

#solution
`-sV` envoie des sondes applicatives à chaque port ouvert et identifie le logiciel et sa version — l'option que les diapos jugent la plus importante, parce qu'elle permet de chercher les CVE exactes.

**Les distracteurs :** **a** détecte le **système d'exploitation** ; **b** lance les scripts par défaut ; **c** est le scan SYN, qui dit seulement si un port est ouvert.

Réponse : $\boxed{\text{d}}$

::qcm-question{label="2." bonne="a" cours="nm-q-systeme"}
Which option fingerprints the operating system, and what does it need to be reliable?

#a
`-O`, run as root, with at least one open and one closed port

#b
`-sV`, run as any user, with at least one filtered port

#c
`-O`, run without root, against filtered ports only

#d
`-sU`, run as root, with a single open UDP port

#indice
Pour comparer les réactions d'une pile TCP/IP, il faut des ports qui réagissent — et de deux façons différentes.

#solution
`-O` compare les réactions de la pile TCP/IP de la cible à la base `nmap-os-db`. Il forge ses sondes, donc demande **root**, et il lui faut **au moins un port ouvert et un port fermé** pour des réponses fiables à comparer.

**Les distracteurs :** **b** détecte les versions des services, et un port filtré ne répond rien ; **c** — sans root, pas de détection du système, et des ports filtrés ne renvoient rien à comparer ; **d** est le scan UDP.

Réponse : $\boxed{\text{a}}$
::

::qcm-question{label="3." bonne="c" cours="nm-q-systeme"}
Which of the following does `-A` NOT enable?

#a
OS detection (`-O`)

#b
Version detection (`-sV`)

#c
The aggressive timing template (`-T4`)

#d
The default NSE scripts (`-sC`)

#indice
Le mode agressif active des fonctions. Le rythme du scan en est-il une ?

#solution
`-A` active `-O`, `-sV`, `-sC` et `--traceroute`, mais **aucune option de timing** : malgré son nom, il ne règle pas `-T4`, qu'il faut ajouter soi-même.

::qcm-question{label="11." bonne="c" cours="nm-q-sorties"}

::qcm-question{label="15." bonne="b" cours="nm-q-evasion"}
What does the lowercase `-f` option do?

#a
It runs a fast scan of the 100 most common ports

#b
It fragments packets into small chunks to confuse older IDS

#c
It forces the scan of hosts that do not answer pings

#d
It finishes the scan faster by skipping version detection

#indice
La casse compte : `-F` et `-f` sont deux options différentes.

#solution
`-f` **fragmente** les paquets en morceaux de 8 octets après l'en-tête IP (16 avec `-ff`, une taille multiple de 8 avec `--mtu`) : un IDS ancien, qui ne réassemble pas les fragments, ne reconnaît plus le scan.

**Les distracteurs :** **a** est `-F`, en majuscule, le mode rapide ; **c** est `-Pn` ; **d** ne correspond à aucune option.

::qcm-question{label="16." bonne="a" cours="nm-q-evasion"}

::extrait-cours{id="nm-q-cibles" titre="Désigner et exclure des cibles" source="/cours/a1/ethical-hacking/nmap/cours#_2-cibles-ports-et-sorties"}
Une adresse, un CIDR (`10.1.1.0/24`), une plage (`10.1.1.1-50`). `-iL fichier` lit les cibles dans un fichier ; `--exclude 10.1.1.5,10.1.1.6` retire des **hôtes** de la liste ; `--excludefile` fait de même depuis un fichier ; `-6` active l'IPv6.

À ne pas confondre : `--exclude-ports` retire des **ports**, et `-Pn` ne retire rien — il saute la découverte d'hôtes.
::

::extrait-cours{id="nm-q-ports" titre="La syntaxe des ports" source="/cours/a1/ethical-hacking/nmap/cours#_2-cibles-ports-et-sorties"}
Sans option : les **1 000** ports les plus courants. `-p 22` : un port. `-p 22,80,443` : une liste (virgules). `-p 22-443` : une plage (tiret), tous les ports entre les deux. **`-p-` : de 1 à 65 535, tous les ports.** `-F` : les 100 plus courants. `--top-ports N` : les N plus fréquemment ouverts d'après `nmap-services` (les trois premiers en TCP : 80, 23, 443).
::

::extrait-cours{id="nm-q-decouverte" titre="Découverte d'hôtes : -sn, -Pn et les sondes" source="/cours/a1/ethical-hacking/nmap/cours#_2-cibles-ports-et-sorties"}
- `-sn` : **découverte seule**, aucun scan de ports (le ping sweep ; ancien nom `-sP`).
- `-Pn` : **aucune découverte**, la cible est supposée active — contre un hôte qui bloque le ping.
- `-PS` : ping TCP SYN ; `-PE` : ICMP echo ; `-PP` : ICMP timestamp ; `-PM` : ICMP address mask.

`-sN`, avec une majuscule, est le scan NULL : rien à voir avec `-sn`.
::

::extrait-cours{id="nm-q-sorties" titre="Les sorties et l'affichage" source="/cours/a1/ethical-hacking/nmap/cours#_2-cibles-ports-et-sorties"}
`-oN` normal (`.nmap`), `-oX` XML (`.xml`, pour Metasploit et les outils), `-oG` grepable (`.gnmap`, une ligne par hôte), **`-oA base` : les trois d'un coup**.

`-v` / `-vv` : plus de verbosité pendant le scan. `--reason` : la réponse qui décide de chaque état (`syn-ack`, `reset`, `no-response`). `-V` affiche la version de Nmap ; `-sV` détecte les versions des services.
::

::extrait-cours{id="nm-q-scans" titre="SYN et connect, et les privilèges" source="/cours/a1/ethical-hacking/nmap/cours#_3-les-types-de-scans"}
**`-sS`, SYN** : SYN → SYN-ACK (open) puis RST de la machine qui scanne, ou RST (closed). La poignée de main n'est jamais terminée : *half-open*. Paquets forgés : **root**. **Défaut en root.**

**`-sT`, connect** : l'appel `connect()` ouvre une vraie connexion, poignée de main complète, souvent journalisée. **Aucun privilège ; défaut sans root.**

Sans root, Nmap refuse `-sS`, `-sU`, `-sA`, `-sN`, `-sF`, `-sX` et `-O`.
::

::extrait-cours{id="nm-q-udp" titre="Le scan UDP" source="/cours/a1/ethical-hacking/nmap/cours#_3-les-types-de-scans"}
`-sU` est le seul à voir les services UDP : **DNS (53)**, **DHCP (67/68)**, **SNMP (161)**. Réponse UDP → open ; ICMP port unreachable → closed ; rien → open|filtered (`-sV` aide à trancher). Très lent ; il se combine avec un scan TCP : `-sS -sU`.
::

::extrait-cours{id="nm-q-furtifs" titre="ACK, NULL, FIN et Xmas" source="/cours/a1/ethical-hacking/nmap/cours#_3-les-types-de-scans"}
**`-sA`** : RST → unfiltered, rien → filtered ; jamais de port ouvert — il cartographie le pare-feu.

**`-sN`** (aucun drapeau), **`-sF`** (FIN), **`-sX`** (FIN, PSH, URG). Pile conforme à la RFC 793 : RST → **closed**, rien → **open|filtered**, ICMP unreachable → filtered. Windows et de nombreux équipements Cisco répondent RST quel que soit l'état : tout paraît fermé, ces scans y sont inutiles.
::

::extrait-cours{id="nm-q-versions" titre="La détection de versions" source="/cours/a1/ethical-hacking/nmap/cours#_4-versions-système-et-timing"}
`-sV` envoie des sondes applicatives (`nmap-service-probes`) aux ports ouverts et donne le logiciel et sa version exacte : la base de la recherche de CVE. `--version-intensity` va de 0 à 9 (7 par défaut). Sans `-sV`, la colonne SERVICE n'est qu'une supposition tirée du numéro de port.
::

::extrait-cours{id="nm-q-systeme" titre="Le système et le mode agressif" source="/cours/a1/ethical-hacking/nmap/cours#_4-versions-système-et-timing"}
`-O` compare les réactions de la pile TCP/IP à la base `nmap-os-db` ; il demande **root** et au moins **un port ouvert et un port fermé**.

`-A` = `-O` + `-sV` + `-sC` (scripts par défaut) + `--traceroute`. Il n'active **aucun** timing : `-T4` s'ajoute à part.
::

::extrait-cours{id="nm-q-timing" titre="Timing et débit" source="/cours/a1/ethical-hacking/nmap/cours#_4-versions-système-et-timing"}
`-T0` paranoid (5 min entre deux sondes), `-T1` sneaky (15 s), `-T2` polite (0,4 s), `-T3` normal (**défaut**), `-T4` aggressive (labs, CTF), `-T5` insane.

`--min-rate N` : au moins N paquets par seconde ; `--max-rate N` : au plus N ; `--scan-delay 500ms` : une attente entre deux sondes.
::

::extrait-cours{id="nm-q-nse" titre="Sélectionner des scripts NSE" source="/cours/a1/ethical-hacking/nmap/cours#_5-le-moteur-de-scripts-nse"}
Par catégorie (`--script=vuln`), par nom (`--script=http-title,ssl-cert`), par joker (`--script="smb-*"`), par expression (`"default or safe"`). `-sC` = `--script=default`.

Catégories : **auth** (identifiants, ou leur contournement), **brute** (force brute), **default**, **discovery**, **safe**, **version** (avec `-sV`), **vuln** ; et aussi exploit, intrusive, external…

`--script-help nom` : la description d'un script, sans scanner. `--script-updatedb` : reconstruire la base des scripts après en avoir ajouté ou retiré.
::

::extrait-cours{id="nm-q-scripts" titre="Quelques scripts NSE" source="/cours/a1/ethical-hacking/nmap/cours#_5-le-moteur-de-scripts-nse"}
`vulners` : les CVE de chaque version détectée, depuis la base en ligne Vulners — demande `-sV`. `smb-vuln-ms17-010` : EternalBlue. `ssl-enum-ciphers` : les suites de chiffrement TLS acceptées. `ssl-cert` : le certificat. `http-title` / `http-headers` : titre et en-têtes HTTP. `http-waf-detect` : un pare-feu applicatif web. `ssh-auth-methods` : les méthodes d'authentification SSH. `smb-enum-shares` : les partages SMB.
::

::extrait-cours{id="nm-q-deroule" titre="Le déroulé en quatre phases" source="/cours/a1/ethical-hacking/nmap/cours#_6-le-déroulé-en-quatre-phases"}
1. Découverte : `nmap -sn -PE -PS80,443 192.168.1.0/24 -oA hosts_alive`.
2. Largeur : `nmap -sS -sV -T4 --top-ports 1000 -iL hosts_alive.gnmap -oA quick_scan`.
3. Profondeur : `nmap -sS -sU -p- -T4 -sV -O 10.1.1.5 -oA full_10_1_1_5`.
4. Vulnérabilités : `nmap -sV --script=vuln,vulners -p 22,80,443,445 10.1.1.5 -oA vuln_check`.
::

::extrait-cours{id="nm-q-evasion" titre="L'évasion et ses limites" source="/cours/a1/ethical-hacking/nmap/cours#_7-les-techniques-dévasion"}
`-f` : fragments de 8 octets (≠ `-F`, le mode rapide). `-D RND:5,ME` : leurres. `--source-port 53` / `-g 53` : port source DNS. `--scan-delay 500ms` : délai entre sondes. `--spoof-mac Apple` : MAC aléatoire à préfixe Apple, utile sur le réseau local seulement.

Ces options réduisent le bruit sans rendre invisible : un NDR ou un EDR comportemental détecte encore le scan, et l'autorisation écrite reste obligatoire.
::
