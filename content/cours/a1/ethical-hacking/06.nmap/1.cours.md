::rappel{titre="La boîte à outils du chapitre"}
- **Nmap** (*Network Mapper*) : découverte d'hôtes, scan de ports, versions, système, scripts **NSE**. Sans option, il scanne les **1 000 ports TCP les plus courants**.
- Cibles : une adresse, un CIDR, `-iL fichier`, `--exclude`, `-6` pour l'IPv6. Ports : `-p 22,80`, `-p 1-1000`, **`-p-` = les 65 535 ports**, `--top-ports N`, `-F` (100 ports).
- Découverte : `-sn` = ping sweep, **aucun scan de ports** ; `-Pn` = **aucune découverte**, toute cible est supposée active.
- Scans : **`-sS`** SYN, **half-open**, root requis, défaut en root ; **`-sT`** connect, poignée de main complète, défaut sans root ; `-sU` UDP ; `-sA` ACK, pour le pare-feu ; `-sN` / `-sF` / `-sX` NULL, FIN, Xmas, inutiles contre Windows.
- `-sV` versions (`--version-intensity` de 0 à 9), `-O` système, **`-A` = `-sV` + `-O` + scripts par défaut + `--traceroute`**.
- Timing : `-T0` paranoid, `-T1` sneaky, `-T2` polite, **`-T3` normal (défaut)**, `-T4` aggressive, `-T5` insane ; `--min-rate N` paquets par seconde au moins.
- NSE : `--script=` catégorie, nom ou joker ; `-sC` = `--script=default`. Sorties : `-oN`, `-oX`, `-oG`, **`-oA` les trois** ; `-v`, `--reason`.
- Évasion : `-f`, `-D RND:5,ME`, `--source-port 53`, `--scan-delay`, `--spoof-mac` — moins de bruit, jamais l'invisibilité.

## 1. Présentation de Nmap

**Nmap** (**Network Mapper**) est l'outil open source de référence pour la **découverte réseau** et l'**audit de sécurité**. Écrit par Gordon Lyon (« Fyodor ») et sorti en **1997**, il en est à la version **7.9x**. Défenseurs — inventaire d'un parc, contrôle d'un pare-feu — et pentesteurs s'en servent dans le monde entier.

Ses cinq capacités :

| Capacité | Ce qu'elle cherche | Options phares |
|---|---|---|
| **Host discovery** | quelles machines répondent | `-sn`, `-Pn`, `-PS` |
| **Port scanning** | quels ports sont ouverts | `-sS`, `-sT`, `-sU`, `-p` |
| **Service / version detection** | quel logiciel, en quelle version | `-sV` |
| **OS fingerprinting** | quel système d'exploitation | `-O` |
| **NSE scripting** | tout le reste, en scripts | `--script`, `-sC` |

Ses résultats alimentent les autres outils : **Metasploit** (qui charge un fichier XML de Nmap avec `db_import`), **Nuclei**, **OpenVAS**, **Burp**, les outils de rapport.

La syntaxe tient en une ligne : `nmap`, les options dans n'importe quel ordre, puis la ou les cibles — `nmap -sS -p 22,80 10.1.1.1`. **Sans aucune option**, `nmap 10.1.1.1` fait deux choses :

1. une **découverte d'hôte**, pour savoir si la cible répond ;
2. un scan des **1 000 ports TCP les plus courants** — en **SYN** si l'on est root, en **connect** sinon.

**Les privilèges comptent.** Les scans qui forgent leurs propres paquets (**raw packets**) — SYN, UDP, ACK, NULL, FIN, Xmas, détection du système — demandent **root** (`sudo`). Sans ces droits, Nmap se rabat sur le scan connect, qui passe par le système.

Si la cible ne répond pas à la découverte, Nmap s'arrête là et le dit : *Host seems down. If it is really up, but blocking our ping probes, try -Pn*. L'option `-Pn` (section suivante) force le scan.

Enfin, **scanner sans autorisation est illégal** : une autorisation écrite précède tout scan.

::exemple{id="nm-ex-defaut" titre="Le même nmap 10.1.1.1, avec et sans sudo" pour="Savoir ce que fait Nmap quand on ne lui précise rien"}
```
sudo nmap 10.1.1.1
Nmap scan report for 10.1.1.1
Host is up (0.0012s latency).
Not shown: 997 closed tcp ports (reset)
PORT    STATE SERVICE
22/tcp  open  ssh
80/tcp  open  http
443/tcp open  https
```

- En root, la découverte envoie un ICMP echo, un SYN vers 443, un ACK vers 80 et un ICMP timestamp (sur le réseau local, une requête ARP les remplace), puis le scan est un scan **SYN** : les ports fermés ont répondu par un RST, d'où le `(reset)`.
- **997 fermés + 3 ouverts = 1 000 ports** : Nmap ne détaille pas les ports fermés quand ils sont nombreux.
- Sans `sudo`, même commande : la découverte se contente de connexions TCP vers 80 et 443, et le scan devient un scan **connect** — la ligne de résumé dit alors `(conn-refused)`.
::

## 2. Cibles, ports et sorties

**Les cibles.**

| Commande | Ce qui est scanné |
|---|---|
| `nmap 10.0.0.1` | une seule adresse |
| `nmap 192.168.10.0/24` | une plage **CIDR** : les 256 adresses de `192.168.10.0` à `192.168.10.255` |
| `nmap 192.168.10.1-50` | une plage d'adresses |
| `nmap -iL hosts.txt` | les cibles listées dans un **fichier** (*input from list*) |
| `nmap 10.1.1.0/24 --exclude 10.1.1.5` | la plage, **sauf** `10.1.1.5` (plusieurs hôtes : séparés par des virgules ; `--excludefile` pour une liste en fichier) |
| `nmap -6 2001:db8::1` | une adresse **IPv6** — souvent oubliée, alors que les règles de pare-feu ne sont parfois écrites que pour l'IPv4. Sans `-6`, Nmap refuse l'adresse |

**La découverte d'hôtes**, détaillée au chapitre précédent :

| Option | Effet |
|---|---|
| `-sn` | **ping sweep** : découverte seule, **aucun scan de ports** (son ancien nom : `-sP`) |
| `-Pn` | **aucune découverte** : la cible est supposée active, on scanne directement (anciens noms : `-P0`, `-PN`) |
| `-PS80,443` | ping TCP SYN vers les ports donnés (80 par défaut) |
| `-PE` / `-PP` / `-PM` | ping ICMP echo / timestamp / address mask |

Deux paires à ne pas confondre : `-sn` (*no port scan*) et `-sN` (le scan NULL) ; `-sn` (découverte **seule**) et `-Pn` (**pas** de découverte).

**Les ports.**

| Syntaxe | Ports scannés |
|---|---|
| (rien) | les **1 000** ports les plus courants de chaque protocole scanné |
| `-p 22` | le seul port 22 |
| `-p 22,80,443` | une liste |
| `-p 1-1000` | une plage |
| `-p-` | **tous les ports, de 1 à 65 535** — exhaustif, mais lent (le port 0 ne se scanne que demandé explicitement) |
| `-p U:53,T:22,80` | des ports UDP et TCP précisés, avec un scan UDP et un scan TCP |
| `--top-ports N` | les N ports les plus fréquemment ouverts, d'après les statistiques du fichier `nmap-services` — `--top-ports 1000` revient au scan par défaut |
| `-F` | le mode rapide (*fast*) : les **100** ports les plus courants |

**Les sorties.**

| Option | Format | Usage |
|---|---|---|
| `-oN scan.nmap` | **normal** : ce qu'affiche l'écran | lire, archiver |
| `-oX scan.xml` | **XML** | les outils : `db_import` de Metasploit, rapports |
| `-oG scan.gnmap` | **grepable** : une ligne par hôte | `grep`, `awk` — format dit obsolète, mais toujours pratique |
| `-oA scan` | les **trois** d'un coup : `scan.nmap`, `scan.xml`, `scan.gnmap` | **à chaque scan**, c'est la recommandation |
| `-v`, `-vv` | **verbosité** : plus d'informations pendant le scan, chaque port ouvert affiché dès qu'il est trouvé | suivre un long scan |
| `--reason` | la **raison** de chaque état : `syn-ack`, `reset`, `no-response`… | comprendre un état |
| `--open` | n'afficher que les ports ouverts ou peut-être ouverts | alléger la sortie |

Attention à la casse : `-v` (verbosité), `-V` (affiche la version de Nmap et s'arrête) et `-sV` (détection des versions des services) sont trois options différentes.

::exemple{id="nm-ex-commandes" titre="Traduire un besoin en commande" pour="Les questions d'examen du type quelle commande pour…"}
| Besoin | Commande |
|---|---|
| tous les ports TCP de `10.1.1.1` | `nmap -p- 10.1.1.1` |
| les hôtes actifs de `192.168.1.0/24`, sans scanner leurs ports | `nmap -sn 192.168.1.0/24` |
| les ports 22, 80 et 443 des machines de `cibles.txt`, sauf `10.1.1.5` | `nmap -p 22,80,443 -iL cibles.txt --exclude 10.1.1.5` |
| un serveur qui ne répond pas au ping, scanné quand même | `nmap -Pn 10.1.1.1` |
| les 100 ports les plus courants, vite | `nmap -F 10.1.1.1` ou `nmap --top-ports 100 10.1.1.1` |
| garder le résultat pour le rapport et pour Metasploit | ajouter `-oA rapport` |
| comprendre pourquoi un port est dit filtered | ajouter `--reason` |
::

## 3. Les types de scans

| Option | Scan | Principe | Privilèges |
|---|---|---|---|
| `-sS` | **TCP SYN** (**half-open**, **stealth**) | SYN → SYN-ACK (open) ou RST (closed) ; la poignée de main n'est jamais terminée | **root** — et **défaut en root** |
| `-sT` | **TCP connect** | appel système `connect()` : poignée de main **complète** | **aucun** — défaut **sans root** |
| `-sU` | **UDP** | un datagramme vers chaque port | root |
| `-sA` | **ACK** | un segment ACK seul : cartographie les règles du pare-feu | root |
| `-sN` | **NULL** | aucun drapeau levé | root |
| `-sF` | **FIN** | le seul drapeau FIN | root |
| `-sX` | **Xmas** | FIN, PSH et URG : le paquet « s'allume comme un sapin de Noël » | root |

**`-sS`, le scan SYN.** Nmap envoie un SYN. Un **SYN-ACK** dit que le port est **open** ; la machine qui scanne répond alors par un **RST** au lieu de l'ACK, et la connexion ne s'établit jamais — d'où son nom de scan **half-open**, « à moitié ouvert ». Un **RST** dit **closed** ; rien, ou un ICMP unreachable, **filtered**. Il est rapide — des milliers de ports par seconde — et relativement discret : l'application ne voit aucune connexion aboutir, donc ne la journalise pas, même si un IDS ou un pare-feu moderne repère le scan. Il demande **root**, et c'est le scan par défaut quand on l'est.

**`-sT`, le scan connect.** Sans droit de forger des paquets, Nmap demande au système d'ouvrir une vraie connexion avec l'appel `connect()` : la poignée de main est **complète**, puis coupée aussitôt. Plus lent, plus de paquets, et la connexion établie a toutes les chances d'être **journalisée par l'application**. Aucun privilège requis : c'est le scan par défaut d'un simple utilisateur.

**`-sU`, le scan UDP — à ne jamais oublier.** Des services critiques vivent en UDP : **DNS (53)**, **DHCP (67/68)**, **SNMP (161)**. Une réponse UDP dit open ; un ICMP port unreachable, closed ; le silence, **open|filtered**, qu'on lève en ajoutant `-sV`. Il est **très lent** sur de grandes plages : un port ouvert se tait, et les systèmes limitent le débit de leurs messages ICMP d'erreur. Nmap n'accepte qu'**un** type de scan TCP à la fois, mais `-sU` peut s'y ajouter : `-sS -sU`.

**`-sA`, le scan ACK — pour le pare-feu seulement.** Un ACK isolé n'appartient à aucune connexion : qu'il soit ouvert ou fermé, un port joignable répond **RST**, et Nmap le dit **unfiltered** ; sans réponse, ou avec un ICMP unreachable, le port est **filtered**. Le scan ACK ne détecte **jamais** de port ouvert : il sert à cartographier les règles du pare-feu, et à savoir s'il est **à états** (**stateful**) — un pare-feu à états jette un ACK qui ne correspond à aucune connexion connue.

**`-sN`, `-sF`, `-sX` : NULL, FIN et Xmas.** Ils exploitent une règle de la **RFC 793** : un segment qui ne porte ni SYN, ni RST, ni ACK déclenche un **RST** s'il arrive sur un port **fermé**, et il est ignoré sur un port **ouvert**. RST → **closed** ; rien → **open|filtered** ; ICMP unreachable → filtered. Ces scans passent parfois des filtres sans état. Mais **Windows** — comme de nombreux équipements Cisco — répond **RST** quel que soit l'état du port : tous les ports paraissent fermés, et ces scans sont **inutiles contre Windows**.

::exemple{id="nm-ex-paquets" titre="Ce qui circule sur un port ouvert et sur un port fermé" pour="Retrouver l'état d'un port à partir des paquets échangés"}
| Scan | Port **ouvert** | Port **fermé** |
|---|---|---|
| `-sS` | SYN → SYN-ACK → RST : **open** | SYN → RST : **closed** |
| `-sT` | SYN → SYN-ACK → ACK, puis RST : **open** | SYN → RST : **closed** |
| `-sA` | ACK → RST : **unfiltered** | ACK → RST : **unfiltered** |
| `-sN`, `-sF`, `-sX` (pile conforme à la RFC 793) | sonde → rien : **open\|filtered** | sonde → RST : **closed** |
| `-sN`, `-sF`, `-sX` contre Windows | sonde → RST : **closed**, à tort | sonde → RST : **closed** |

Et derrière un pare-feu qui jette tout, chaque sonde reste sans réponse : filtered pour `-sS`, `-sT` et `-sA`, open|filtered pour les trois derniers.
::

::exemple{id="nm-ex-choix-scan" titre="Un besoin, un scan" pour="Choisir le type de scan dans une question de mise en situation"}
- On est root et l'on veut un scan TCP rapide et discret : `-sS` — qu'il est même inutile d'écrire.
- On n'a pas les droits root : `-sT`.
- On cherche un serveur DNS, DHCP ou SNMP : `-sU`, sur les ports 53, 67/68 et 161.
- On veut savoir quels ports le pare-feu filtre, et s'il est à états : `-sA`.
- La cible est un Windows : pas de `-sN`, `-sF` ni `-sX`, tout paraîtrait fermé.
::

## 4. Versions, système et timing

**`-sV`, la détection de versions** — l'option que les diapos jugent la plus importante : elle donne le **logiciel et sa version exacte** (OpenSSH 8.9p1, nginx 1.18.0), seule base solide pour chercher les **CVE** qui les visent. Elle envoie des **sondes applicatives**, tirées de la base `nmap-service-probes`, au lieu de se fier à une bannière. `--version-intensity` règle le nombre de sondes essayées, de **0** (les plus probables seulement) à **9** (toutes) ; **7 par défaut**. Deux raccourcis : `--version-light` vaut 2, `--version-all` vaut 9.

**`-O`, la détection du système** (**OS fingerprinting**). Nmap envoie une série de sondes TCP et UDP et compare les réactions de la pile TCP/IP de la cible à sa base `nmap-os-db`. Il demande **root**, et n'est fiable qu'avec **au moins un port ouvert et un port fermé**.

**`-A`, le mode agressif** : un raccourci pour `-sV` + `-O` + `--script=default` (les scripts par défaut, soit `-sC`) + `--traceroute`. Il n'active que des fonctions, **pas le timing** : `-T4` reste à ajouter soi-même. Ses scripts le rendent bruyant.

| Commande | Effet |
|---|---|
| `nmap -sV 10.1.1.1` | versions des services sur les ports ouverts |
| `nmap -sV --version-intensity 9 10.1.1.1` | toutes les sondes : précision maximale, mais plus lent |
| `nmap -O 10.1.1.1` | système d'exploitation (root ; un port ouvert et un fermé) |
| `nmap -A 10.1.1.1` | `-sV` + `-O` + scripts par défaut + traceroute |

**Le timing.** Six gabarits (**timing templates**), du plus lent au plus rapide :

| Gabarit | Nom | Comportement |
|---|---|---|
| `-T0` | **paranoid** | une sonde à la fois, cinq minutes entre deux : évasion d'IDS |
| `-T1` | **sneaky** | quinze secondes entre deux sondes : évasion d'IDS |
| `-T2` | **polite** | 0,4 seconde entre deux sondes : ménage la bande passante et la cible |
| `-T3` | **normal** | **le défaut** : écrire `-T3` ne change rien |
| `-T4` | **aggressive** | suppose un réseau rapide et fiable : le choix des labs et des CTF |
| `-T5` | **insane** | suppose un réseau extrêmement rapide ; sacrifie de la précision à la vitesse |

Au-delà des gabarits, on règle le débit à la main : `--min-rate 500` envoie **au moins** 500 paquets par seconde, `--max-rate` fixe un plafond.

::exemple{id="nm-ex-version" titre="Ce que -sV ajoute à une sortie" pour="Lire la colonne VERSION et comprendre ce qu'elle change"}
Sans `-sV` :

```
PORT   STATE SERVICE
22/tcp open  ssh
80/tcp open  http
```

Avec `-sV` :

```
PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 8.9p1 Ubuntu 3ubuntu0.1 (Ubuntu Linux; protocol 2.0)
80/tcp open  http    nginx 1.18.0 (Ubuntu)
Service Info: OS: Linux; CPE: cpe:/o:linux:linux_kernel
```

- Sans `-sV`, la colonne SERVICE n'est qu'une **supposition** tirée de la table des ports : un SSH déplacé sur le port 80 s'afficherait « http ».
- Avec `-sV`, on a le logiciel et sa **version exacte**, à confronter aux CVE — et un indice sur le système (Ubuntu), avant même `-O`.
::

## 5. Le moteur de scripts NSE

Le **Nmap Scripting Engine** (NSE) exécute pendant le scan des scripts écrits en **Lua**. Il fait de Nmap bien plus qu'un scanner de ports : découverte, détection de versions, de vulnérabilités, voire exploitation. Nmap 7.9x en livre **plus de 600**, rangés dans `/usr/share/nmap/scripts/` — `ls /usr/share/nmap/scripts/ | wc -l` pour les compter.

Les scripts sont rangés par **catégories**. Les diapos en retiennent sept :

| Catégorie | Les scripts qui… |
|---|---|
| **auth** | traitent des identifiants d'authentification, ou de leur contournement |
| **brute** | devinent des identifiants par **force brute** |
| **default** | forment le jeu par défaut, lancé par `-sC` ou `-A` |
| **discovery** | découvrent davantage sur le réseau : registres, annuaires, SNMP… |
| **safe** | ne sont pas conçus pour planter un service ni saturer le réseau |
| **version** | complètent la détection de versions : lancés seulement avec `-sV`, ils ne se choisissent pas directement |
| **vuln** | cherchent des **vulnérabilités connues** précises, et ne parlent en général que s'ils en trouvent |

La documentation officielle en compte sept autres : **broadcast**, **dos**, **exploit**, **external** (le script envoie des données à un service tiers), **fuzzer**, **intrusive** (risque de planter la cible ou de déclencher des alertes) et **malware**.

**Choisir les scripts :**

| Sélection | Exemple |
|---|---|
| par **catégorie** | `--script=safe`, `--script=vuln`, `--script=default` (= `-sC`) |
| par **nom** | `--script=http-title,ssl-cert` |
| par **joker** | `--script="smb-*"` : tous les scripts dont le nom commence par `smb-` |
| par **expression** | `--script="default or safe"`, `--script="not intrusive"` |

`--script-args` passe des paramètres aux scripts. Deux commandes d'entretien :

- `nmap --script-help ssl-cert` affiche le nom, les catégories et la description d'un script, **sans rien scanner** ;
- `nmap --script-updatedb` met à jour la base des scripts (`script.db`), après en avoir ajouté, retiré ou recatégorisé un.

**Les scripts à connaître :**

| Script | Ce qu'il fait |
|---|---|
| `vulners` | pour chaque version détectée, les **CVE** connues et leur score CVSS, tirées de la base en ligne Vulners — demande `-sV` et un accès Internet |
| `smb-vuln-ms17-010` | vérifie la faille **EternalBlue** (MS17-010, celle de WannaCry) sur SMB, port 445 — il détecte, il n'exploite pas |
| `ssl-enum-ciphers` | liste toutes les **suites de chiffrement** TLS acceptées, chacune notée |
| `ssl-cert` | récupère le **certificat** TLS du serveur |
| `http-title` | le **titre** de la page d'accueil d'un serveur web |
| `http-headers` | les **en-têtes** HTTP renvoyés par le serveur |
| `http-waf-detect` | détecte un pare-feu applicatif web (**WAF**) |
| `ssh-auth-methods` | les **méthodes d'authentification** SSH acceptées : mot de passe, clé publique… |
| `smb-enum-users`, `smb-enum-shares` | les utilisateurs et les partages SMB |

Les diapos disent d'installer `vulners.nse` d'abord : il est en fait livré avec Nmap depuis la version 7.80, sortie en 2019.

`--script=vuln` est **bruyant** : uniquement avec autorisation. Et NSE ne s'arrête pas au scan : les diapos montrent un script qui, muni d'identifiants SMB valides, extrait les empreintes NTLM des mots de passe de tous les comptes locaux. Les scripts ne tournent dans aucun bac à sable : on ne lance que des scripts de confiance, et seulement dans le périmètre autorisé.

::exemple{id="nm-ex-scripts" titre="Composer la sélection de scripts d'un besoin" pour="Écrire la bonne option --script dans une question de mise en situation"}
| Besoin | Commande |
|---|---|
| vérifier EternalBlue sur un serveur Windows | `nmap -p445 --script=smb-vuln-ms17-010 10.1.1.1` |
| inspecter le TLS d'un serveur HTTPS | `nmap -p443 --script=ssl-cert,ssl-enum-ciphers 10.1.1.1` |
| le titre et les en-têtes d'un site | `nmap -p80 --script=http-title,http-headers 10.1.1.1` |
| tous les scripts SMB — intrusifs compris, prudence | `nmap -p445 --script="smb-*" 10.1.1.1` |
| les CVE des versions trouvées | `nmap -sV --script=vulners 10.1.1.1` |
| les scripts par défaut | `nmap -sC 10.1.1.1` |
| savoir ce que fait un script avant de le lancer | `nmap --script-help ssl-enum-ciphers` |
::

## 6. Le déroulé en quatre phases

Les diapos proposent un déroulé réaliste : **découverte → largeur → profondeur → vulnérabilités**. Chaque phase nourrit la suivante, et chaque sortie s'enregistre avec `-oA` pour le rapport.

**Phase 1 — une découverte d'hôtes discrète.**

```bash
nmap -sn -PE -PS80,443 192.168.1.0/24 -oA hosts_alive
```

Ping sweep (`-sn`) par ICMP echo (`-PE`) et SYN vers 80 et 443 (`-PS80,443`) ; les hôtes actifs atterrissent dans `hosts_alive.nmap`, `.xml` et `.gnmap`.

**Phase 2 — la largeur : les 1 000 ports courants des hôtes actifs.**

```bash
nmap -sS -sV -T4 --top-ports 1000 -iL hosts_alive.gnmap -oA quick_scan
```

Scan SYN, versions, rythme rapide, 1 000 ports, cibles lues dans le fichier de la phase 1 (en pratique, on en extrait d'abord la liste des adresses actives).

**Phase 3 — la profondeur : tous les ports des hôtes intéressants**, en arrière-plan.

```bash
nmap -sS -sU -p- -T4 -sV -O --version-intensity 7 10.1.1.5 -oA full_10_1_1_5
```

Tous les ports TCP et UDP, versions et système. `--version-intensity 7` est la valeur par défaut : l'écrire la rend seulement explicite.

**Phase 4 — la vérification ciblée des vulnérabilités.**

```bash
nmap -sV --script=vuln,vulners -p 22,80,443,445 10.1.1.5 -oA vuln_check
```

Les scripts de la catégorie vuln et `vulners`, sur les seuls ports qui comptent.

**La revue rapide** se fait sur le format grepable, qui met un hôte par ligne :

```bash
grep open quick_scan.gnmap | grep -v ignored
```

::exemple{id="nm-ex-revue" titre="Lire la revue rapide d'un fichier .gnmap" pour="Choisir les hôtes de la phase 3 à partir de la phase 2"}
```
Host: 10.1.1.5 ()  Ports: 22/open/tcp//ssh//OpenSSH 8.9p1 Ubuntu/, 80/open/tcp//http//nginx 1.18.0/  Ignored State: closed (998)
Host: 10.1.1.9 ()  Ports: 445/filtered/tcp//microsoft-ds///  Ignored State: closed (999)
```

- Chaque port se lit `port/état/protocole//service//version/`.
- `10.1.1.5` a deux ports ouverts, avec leurs versions : `grep open` le retient, c'est un candidat pour la phase 3.
- `10.1.1.9` n'a qu'un port filtré : `grep open` l'écarte. Un pare-feu protège son port 445 ; on pourra y revenir plus tard, par exemple avec un scan ACK pour cartographier ce filtrage.
::

## 7. Les techniques d'évasion

| Commande | Effet |
|---|---|
| `nmap -f 10.1.1.1` | **fragmente** les paquets en morceaux de 8 octets après l'en-tête IP : trompe les IDS anciens, qui ne réassemblent pas. `-ff` : 16 octets ; `--mtu` : une taille au choix, multiple de 8 |
| `nmap -D RND:5,ME 10.1.1.1` | **leurres** (**decoys**) : la vraie adresse (`ME`) noyée parmi 5 adresses aléatoires usurpées |
| `nmap --source-port 53 10.1.1.1` (ou `-g 53`) | **port source** 53 (DNS) : certains pare-feu laissent passer ce qui ressemble à une réponse DNS |
| `nmap --scan-delay 500ms 10.1.1.1` | un **délai** entre deux sondes : complique la corrélation par l'IDS |
| `nmap --spoof-mac Apple 10.1.1.1` | une adresse **MAC usurpée**, aléatoire avec un préfixe Apple (`0` : entièrement aléatoire) — réseau local seulement |

Les gabarits `-T0` (paranoid) et `-T1` (sneaky) servent le même but : ils sont conçus pour l'évasion d'IDS.

Leurs limites :

- les leurres ne fonctionnent ni avec le scan connect (`-sT`) ni avec la détection de versions, qui passent par de vraies connexions ;
- `--source-port` est sans effet sur `-sT`, `-sV` et les scripts, pour la même raison ;
- une adresse MAC ne voyage pas au-delà du premier routeur : la falsifier n'a de sens que sur le réseau local ;
- surtout, ces options **réduisent le bruit**, elles **ne rendent pas invisible** : un NDR ou un EDR moderne, qui analyse les comportements, détecte encore le scan. Et l'autorisation reste obligatoire.

Côté défense : un pare-feu **à états** ne se laisse pas prendre au port source 53, et un IDS moderne réassemble les fragments avant de les analyser.

::exemple{id="nm-ex-port-source" titre="Le port source 53 face à deux pare-feu" pour="Comprendre pourquoi --source-port fonctionne parfois, et comment s'en protéger"}
Pour laisser revenir les réponses DNS, un administrateur écrit la règle « accepter tout paquet entrant dont le port **source** est 53 ».

- Sur un pare-feu **sans état**, `nmap -sS -g 53 10.1.1.1` passe : chaque sonde semble venir d'un serveur DNS, et la règle l'accepte sans rien vérifier d'autre.
- Sur un pare-feu **à états** (*stateful*), une réponse DNS n'est acceptée que si elle correspond à une requête sortie auparavant : les sondes de Nmap ne correspondent à rien, elles sont jetées.

La parade n'est donc pas de cacher le port 53, mais de filtrer **avec état**.
::

::extrait-cours{id="nm-c-presentation" titre="Nmap en bref" source="/cours/a1/ethical-hacking/nmap/cours#_1-présentation-de-nmap"}
**Nmap** (*Network Mapper*), open source, 1997, version 7.9x : découverte d'hôtes, scan de ports, détection des versions et du système, scripts NSE. Ses sorties alimentent Metasploit (`db_import` d'un fichier XML), Nuclei, OpenVAS, Burp.

Sans option, `nmap cible` découvre l'hôte puis scanne les **1 000 ports TCP les plus courants** : en **SYN** si l'on est root, en **connect** (`connect()`, poignée de main complète) sinon. Les scans en paquets forgés — SYN, UDP, ACK, NULL, FIN, Xmas, détection du système — demandent root.
::

::extrait-cours{id="nm-c-cibles" titre="Désigner les cibles" source="/cours/a1/ethical-hacking/nmap/cours#_2-cibles-ports-et-sorties"}
Une adresse (`10.0.0.1`), un CIDR (`192.168.10.0/24`, 256 adresses), une plage (`192.168.10.1-50`).

- `-iL fichier` : les cibles lues dans un fichier (*input from list*) ;
- `--exclude hôte1,hôte2` : retirer des hôtes ; `--excludefile` : la même chose depuis un fichier ;
- `-iR N` : N cibles tirées au hasard ;
- `-6` : scan IPv6, obligatoire pour une adresse IPv6.
::

::extrait-cours{id="nm-c-ports" titre="Choisir les ports" source="/cours/a1/ethical-hacking/nmap/cours#_2-cibles-ports-et-sorties"}
Par défaut : les **1 000** ports les plus courants. `-p 22` (un port), `-p 22,80,443` (une liste), `-p 1-1000` (une plage), **`-p-` (tous, de 1 à 65 535)**, `-p U:53,T:22` (UDP et TCP précisés).

`--top-ports N` : les N ports les plus fréquemment ouverts d'après `nmap-services`. `-F` : les 100 plus courants.
::

::extrait-cours{id="nm-c-scans" titre="SYN et connect" source="/cours/a1/ethical-hacking/nmap/cours#_3-les-types-de-scans"}
**`-sS`, SYN** (*half-open*, *stealth*) : SYN → SYN-ACK (open) ou RST (closed) ; la machine qui scanne répond RST au SYN-ACK, la poignée de main n'est jamais terminée. Rapide, discret. **Root requis, défaut en root.**

**`-sT`, connect** : l'appel système `connect()` établit une vraie connexion, poignée de main **complète**. Plus lent, journalisé par l'application. **Aucun privilège, défaut sans root.**
::

::extrait-cours{id="nm-c-furtifs" titre="ACK, NULL, FIN et Xmas" source="/cours/a1/ethical-hacking/nmap/cours#_3-les-types-de-scans"}
**`-sA`, ACK** : RST → **unfiltered**, rien → **filtered**. Ne détecte jamais de port ouvert : il cartographie les règles du pare-feu (et dit s'il est à états).

**`-sN` NULL** (aucun drapeau), **`-sF` FIN** (FIN), **`-sX` Xmas** (FIN, PSH, URG). D'après la RFC 793 : RST → closed, rien → **open|filtered**. Windows et de nombreux équipements Cisco répondent RST quel que soit l'état du port : contre eux, tout paraît fermé.
::

::extrait-cours{id="nm-c-versions" titre="Versions, système et mode agressif" source="/cours/a1/ethical-hacking/nmap/cours#_4-versions-système-et-timing"}
**`-sV`** : le logiciel et sa version exacte, par des sondes applicatives — la base de la recherche de CVE. `--version-intensity` de **0 à 9**, **7 par défaut** (`--version-light` = 2, `--version-all` = 9).

**`-O`** : le système, par l'empreinte de la pile TCP/IP ; root, et au moins un port ouvert et un fermé.

**`-A`** = `-sV` + `-O` + scripts par défaut (`-sC`) + `--traceroute`. Il ne règle **pas** le timing.
::

::extrait-cours{id="nm-c-timing" titre="Les gabarits de timing" source="/cours/a1/ethical-hacking/nmap/cours#_4-versions-système-et-timing"}
`-T0` **paranoid** (5 minutes entre deux sondes) et `-T1` **sneaky** (15 secondes) : évasion d'IDS. `-T2` **polite** (0,4 seconde) : ménage le réseau. **`-T3` normal : le défaut.** `-T4` **aggressive** : réseau rapide et fiable, labs et CTF. `-T5` **insane** : le plus rapide, au prix de la précision.

`--min-rate N` : au moins N paquets par seconde ; `--max-rate N` : au plus.
::

::extrait-cours{id="nm-c-nse" titre="Le moteur de scripts NSE" source="/cours/a1/ethical-hacking/nmap/cours#_5-le-moteur-de-scripts-nse"}
Des scripts en **Lua**, plus de 600, dans `/usr/share/nmap/scripts/`. Catégories des diapos : auth, brute, default, discovery, safe, version, vuln.

Sélection par catégorie (`--script=vuln`), par nom (`--script=http-title,ssl-cert`), par joker (`--script="smb-*"`), par expression (`"default or safe"`). **`-sC` = `--script=default`** ; `-A` l'inclut, mais ajoute d'autres fonctions. `--script-help` décrit un script ; `--script-updatedb` met à jour la base des scripts.
::

::extrait-cours{id="nm-c-scripts" titre="Les scripts à connaître" source="/cours/a1/ethical-hacking/nmap/cours#_5-le-moteur-de-scripts-nse"}
`vulners` : les CVE des versions trouvées (demande `-sV`). `smb-vuln-ms17-010` : EternalBlue / WannaCry sur SMB, port 445, détection seule. `ssl-enum-ciphers` : les suites de chiffrement TLS. `ssl-cert` : le certificat. `http-title`, `http-headers` : titre et en-têtes d'un site. `http-waf-detect` : un pare-feu applicatif. `ssh-auth-methods` : les méthodes d'authentification SSH. `smb-enum-users`, `smb-enum-shares` : utilisateurs et partages SMB.
::

::extrait-cours{id="nm-c-deroule" titre="Le déroulé en quatre phases" source="/cours/a1/ethical-hacking/nmap/cours#_6-le-déroulé-en-quatre-phases"}
**Découverte → largeur → profondeur → vulnérabilités** :

1. `nmap -sn -PE -PS80,443 192.168.1.0/24 -oA hosts_alive` ;
2. `nmap -sS -sV -T4 --top-ports 1000 -iL hosts_alive.gnmap -oA quick_scan` ;
3. `nmap -sS -sU -p- -T4 -sV -O 10.1.1.5 -oA full_10_1_1_5`, en arrière-plan ;
4. `nmap -sV --script=vuln,vulners -p 22,80,443,445 10.1.1.5 -oA vuln_check`.

Chaque phase nourrit la suivante (la phase 2 lit le fichier de la phase 1) ; chaque sortie s'enregistre avec `-oA` pour le rapport. Revue rapide : `grep open quick_scan.gnmap`.
::

::extrait-cours{id="nm-c-evasion" titre="Les techniques d'évasion" source="/cours/a1/ethical-hacking/nmap/cours#_7-les-techniques-dévasion"}
- `-f` : fragments de 8 octets (`-ff` : 16 ; `--mtu` : multiple de 8) ;
- `-D RND:5,ME` : la vraie adresse parmi 5 leurres aléatoires ;
- `--source-port 53` / `-g 53` : passer un pare-feu sans état qui fait confiance aux « réponses DNS » ;
- `--scan-delay 500ms` : espacer les sondes ;
- `--spoof-mac Apple` : une MAC usurpée, réseau local seulement ;
- `-T0` / `-T1` : gabarits d'évasion.

Elles réduisent le bruit sans rendre invisible : un NDR ou un EDR comportemental détecte encore le scan.
::
