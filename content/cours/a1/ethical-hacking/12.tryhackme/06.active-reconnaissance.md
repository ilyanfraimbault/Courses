Room **I-06** du TD : [Active Reconnaissance](https://tryhackme.com/room/activerecon), environ 1 h, la suite de la précédente. Cette fois on entre en contact avec la cible, avec des outils simples : le navigateur et ses outils de développement (Tasks 1-2), `ping` (Task 3), `traceroute` (Task 4), `telnet` (Task 5) et `nc` (Task 6), que la dernière tâche assemble en un petit scanner fait main. Les questions de la room qui portent sur une notion sont reprises en QCM ; celles qui demandent ce qu'affiche la machine du lab — les adresses d'un traceroute, la version d'un serveur — sont remplacées par des questions sur le fonctionnement et les options des outils. Énoncés et propositions en anglais, comme à l'examen ; sous chaque question, l'**Indice**, la **Solution** et le **Cours**, un rappel en français.

:::exercice{titre="Tasks 1-2 — Introduction and Web Browser" theme="Ce qui rend une reconnaissance active, et le navigateur comme outil"}

::exo-question{label="1." bonne="b" cours="thm-ar-actif"}
Why can browsing the target's website be a discreet form of active reconnaissance?

#a
Browsers never leave any trace in the web server's logs.

#b
The connection is logged, but it blends in with hundreds of legitimate visitors.

#c
The browser hides the client's IP address from the server by default.

#d
Web traffic does not count as a direct connection to the target.

#indice
Toute connexion laisse une trace ; la question est de savoir si elle se remarque.

#solution
Toute reconnaissance active commence par une **connexion directe** à la cible, qui peut être journalisée : adresse IP du client, heure, durée. Mais un navigateur parmi des centaines de visiteurs légitimes n'éveille aucun soupçon — de quoi ne pas alerter l'équipe bleue.

**a** et **c** sont faux : le serveur journalise l'adresse IP de chaque visiteur ; **d** — se connecter au serveur web est bien une connexion directe, c'est même ce qui rend la démarche active.

Réponse : $\boxed{\text{b}}$
::

::exo-question{label="2." bonne="c" cours="thm-ar-actif"}
By default, on which TCP ports does a browser connect for HTTP and for HTTPS?

#a
8080 for HTTP and 8443 for HTTPS

#b
443 for HTTP and 80 for HTTPS

#c
80 for HTTP and 443 for HTTPS

#d
21 for HTTP and 22 for HTTPS

#indice
Ce sont les deux ports les plus célèbres du Web ; reste à ne pas les intervertir.

#solution
Sans port précisé dans l'URL, le navigateur se connecte au port **TCP 80** en HTTP et au port **TCP 443** en HTTPS ; un autre port s'écrit après le nom, comme dans `https://127.0.0.1:8834`.

**a** sont des ports alternatifs courants, pas ceux par défaut ; **b** intervertit les deux ; **d** sont les ports de FTP et de SSH.

Réponse : $\boxed{\text{c}}$
::
:::

:::exercice{titre="Task 3 — Ping" theme="Les messages ICMP de ping, ses options et ses limites"}

::exo-question{label="1." bonne="a" cours="thm-ar-ping"}
Which ICMP message types does ping use?

#a
Echo request (type 8), answered by echo reply (type 0)

#b
Echo request (type 0), answered by echo reply (type 8)

#c
Destination unreachable (type 3), answered by time exceeded (type 11)

#d
Echo request (type 8), answered by time exceeded (type 11)

#indice
Ce sont les deux messages ICMP les plus connus ; reste à se souvenir de leurs numéros de type.

#solution
`ping` envoie un **ICMP echo request** (type 8) ; une cible joignable répond par un **ICMP echo reply** (type 0), sauf si un pare-feu bloque l'échange.

**b** intervertit les deux numéros ; **c** sont des messages d'erreur — le type 3 annonce une destination injoignable, le type 11 un TTL épuisé ; **d** — le type 11 est la réponse que provoque `traceroute`, pas celle de `ping`.

Réponse : $\boxed{\text{a}}$
::

::exo-question{label="2." bonne="d" cours="thm-ar-ping"}
Which option of the Linux ping command sets the size of the data carried by the ICMP echo request?

#a
`-c`

#b
`-n`

#c
`-t`

#d
`-s`

#indice
Ce n'est ni le nombre de paquets, ni la durée de vie du paquet.

#solution
`-s` fixe la taille des données (*packet size*) de chaque echo request — 56 octets par défaut sous Linux.

**a** fixe le nombre de paquets envoyés (`ping -c 10`) ; **b** joue ce rôle sous Windows (`ping -n 10`), alors que sous Linux il affiche les adresses sans les traduire en noms ; **c** règle le TTL sous Linux, et fait tourner `ping` sans fin sous Windows.

Réponse : $\boxed{\text{d}}$
::

::exo-question{label="3." bonne="b" cours="thm-ar-ping"}
What is the size of the ICMP header, in bytes?

#a
20

#b
8

#c
16

#d
64

#indice
Il est plus petit que l'en-tête IP, qui en compte au moins 20.

#solution
L'**en-tête ICMP** fait **8 octets** : type, code, somme de contrôle, puis 4 octets qui portent, pour un echo, l'identifiant et le numéro de séquence.

**a** est la taille minimale de l'en-tête IP ; **d** est la taille habituelle d'un paquet ICMP de `ping` sous Linux — 56 octets de données plus les 8 de l'en-tête ; **c** ne correspond à rien.

Réponse : $\boxed{\text{b}}$
::

::exo-question{label="4." bonne="a" cours="thm-ar-ping"}
By default, the Microsoft Windows Firewall blocks ping.

#a
True

#b
False

#indice
La room cite ce cas parmi les raisons de ne recevoir aucune réponse à un ping.

#solution
Vrai : le pare-feu de Windows bloque le ping par défaut. D'où la leçon de la room : l'absence de réponse ne prouve pas qu'un hôte est éteint — il peut être en train de démarrer, débranché, ou derrière un pare-feu qui filtre l'ICMP.

Réponse : $\boxed{\text{a}}$
::
:::

:::exercice{titre="Task 4 — Traceroute" theme="Découvrir les routeurs du chemin grâce au TTL"}

::exo-question{label="1." bonne="c" cours="thm-ar-traceroute"}
How does traceroute discover the routers between your system and a target?

#a
It asks each router for its routing table using SNMP.

#b
It reads the path recorded by the target's DNS server.

#c
It sends packets with an increasing TTL and collects the ICMP Time-to-Live exceeded replies.

#d
It sends echo requests of increasing size until a router fragments them.

#indice
Chaque routeur décrémente un champ de l'en-tête IP, et jette le paquet quand ce champ tombe à zéro.

#solution
**traceroute** envoie des paquets de **TTL** 1, puis 2, puis 3… Chaque routeur décrémente le TTL ; celui qui le fait tomber à 0 jette le paquet et renvoie un message **ICMP Time-to-Live exceeded**, qui révèle son adresse. Le TTL compte donc des **sauts**, pas des secondes.

**a** — les routeurs ne livrent pas leur table à qui la demande ; **b** — le DNS ne garde aucune trace du chemin ; **d** décrit la recherche de la taille maximale des paquets (MTU), pas celle du chemin.

Réponse : $\boxed{\text{c}}$
::

::exo-question{label="2." bonne="d" cours="thm-ar-traceroute"}
By default, what does traceroute send on Linux?

#a
TCP SYN packets to port 80

#b
ICMP echo requests, like Windows tracert

#c
ARP requests to each router

#d
UDP datagrams

#indice
Sous Linux, l'option `-I` de la commande du cours change justement ce comportement par défaut.

#solution
Sous Linux, `traceroute` envoie par défaut des **datagrammes UDP**, dans des paquets IP au TTL croissant.

**b** est le comportement de `tracert` sous Windows, et celui de `traceroute -I` sous Linux, la commande des diapos ; **a** s'obtient avec l'option `-T` ; **c** — ARP ne franchit pas les routeurs, il ne sert que sur le réseau local.

Réponse : $\boxed{\text{d}}$
::
:::

:::exercice{titre="Tasks 5-6 — Telnet and Netcat" theme="Se connecter à un service pour lire sa bannière, écouter sur un port"}

::exo-question{label="1." bonne="a" cours="thm-ar-banniere"}
Why is the TELNET protocol (default TCP port 23) considered insecure for remote administration?

#a
It sends all data, usernames and passwords included, in cleartext.

#b
It runs over UDP, so commands can be lost on the way.

#c
It can only connect to web servers on port 80.

#d
It requires root privileges on the client machine.

#indice
Pense à ce que verrait quelqu'un qui écoute le réseau pendant ta connexion.

#solution
**TELNET** (*Teletype Network*, 1969) envoie **tout en clair**, identifiants et mots de passe compris : quiconque écoute le canal peut les voler. Son remplaçant sûr est **SSH**.

**b** — TELNET repose sur TCP ; **c** — le client `telnet` se connecte à n'importe quel service TCP, ce qui en fait justement un outil de reconnaissance ; **d** — aucun privilège n'est nécessaire pour se connecter.

Réponse : $\boxed{\text{a}}$
::

::exo-question{label="2." bonne="c" cours="thm-ar-banniere"}
A pentester runs `telnet MACHINE_IP 80`, then types `GET / HTTP/1.1` followed by a Host header. What is the goal?

#a
Logging in to the server's administration shell

#b
Scanning every open port of the machine

#c
Grabbing the web server's banner: its name and version

#d
Requesting a DNS zone transfer from the server

#indice
Le client `telnet` ne parle aucun protocole par lui-même : c'est toi qui tapes la requête HTTP.

#solution
Le client `telnet` repose sur TCP et peut se connecter à **n'importe quel service** : en tapant une requête HTTP à la main, on lit la réponse du serveur web, dont l'en-tête `Server` donne le nom et la version. C'est de la **capture de bannière** (*banner grabbing*).

**a** — le port 80 sert des pages, pas un shell ; **b** — une connexion ne vise qu'un port, balayer tous les ports est le travail d'un scanner ; **d** — un transfert de zone se demande à un serveur DNS, sur le port 53.

Réponse : $\boxed{\text{c}}$
::

::exo-question{label="3." bonne="d" cours="thm-ar-netcat"}
In the command `nc -vnlp 1234`, what does the `-n` option do?

#a
It keeps listening after the client disconnects.

#b
It switches netcat to UDP.

#c
It puts netcat in listen mode.

#d
It disables DNS resolution: numeric addresses only.

#indice
Les autres lettres de la commande : `-v` pour le détail, `-l` pour écouter, `-p` pour le port. Reste celle-ci.

#solution
`-n` : adresses **numériques seulement**, sans résolution de noms par le DNS — ni requête inutile, ni avertissement. La commande équivaut à `nc -v -l -n -p 1234` : sortie détaillée, en écoute, sans DNS, sur le port 1234.

**a** est le rôle de `-k` ; **b** celui de `-u` ; **c** celui de `-l`.

Réponse : $\boxed{\text{d}}$
::

::exo-question{label="4." bonne="b" cours="thm-ar-netcat"}
A regular user runs `nc -lvnp 80` and the command fails, while `nc -lvnp 4444` works. Why?

#a
Port 80 is reserved for telnet, which netcat cannot replace.

#b
Listening on a port below 1024 requires root privileges.

#c
The `-n` option forbids listening on well-known ports.

#d
Netcat needs the `-u` option to listen on port 80.

#indice
Les deux commandes ne diffèrent que par le numéro de port : qu'est-ce qui distingue 80 de 4444 ?

#solution
Écouter sur un port **inférieur à 1024**, un port « privilégié », demande les droits **root** ; la room le rappelle pour `nc`. Un utilisateur ordinaire peut écouter sur 4444.

**a** — le port 80 est celui de HTTP, et netcat écoute sur n'importe quel port avec les bons droits ; **c** — `-n` ne fait que désactiver la résolution DNS ; **d** — `-u` passe en UDP, ce qui ne change rien à la règle des ports privilégiés.

Réponse : $\boxed{\text{b}}$
::
:::

::extrait-cours{id="thm-ar-actif" titre="La reconnaissance active et le navigateur" source="/cours/a1/ethical-hacking/reconnaissance/cours#_7-osint-visuel-et-reconnaissance-active"}
La reconnaissance **active** commence avec les connexions directes à la cible. Chacune peut laisser une trace dans ses journaux — adresse IP du client, heure, durée. Mais toutes ne sont pas suspectes : un navigateur connecté au serveur web, parmi des centaines de visiteurs légitimes, passe inaperçu. L'équipe rouge s'en sert pour ne pas alerter l'équipe bleue.

Le **navigateur** se connecte par défaut au port **TCP 80** en HTTP et **TCP 443** en HTTPS ; un autre port s'écrit dans l'URL (`https://127.0.0.1:8834`). Ses **outils de développement** (*Developer Tools*, Ctrl+Maj+I) montrent le code, les fichiers et les requêtes de la page. Trois extensions utiles : **FoxyProxy** (changer de proxy, par exemple pour Burp Suite), **User-Agent Switcher and Manager** (se faire passer pour un autre système ou un autre navigateur), **Wappalyzer** (identifier les technologies du site).
::

::extrait-cours{id="thm-ar-ping" titre="ping et ICMP" source="/cours/a1/ethical-hacking/scanning/cours#_2-la-découverte-dhôtes"}
`ping` vérifie qu'un hôte est en ligne. Il envoie un **ICMP echo request** (type 8) ; une cible joignable répond par un **ICMP echo reply** (type 0). L'**en-tête ICMP** fait 8 octets.

| Rôle | Linux | Windows |
| --- | --- | --- |
| nombre de paquets | `-c 10` | `-n 10` |
| taille des données | `-s 64` | `-l 64` |

Pas de réponse ne veut pas dire hôte éteint : la machine peut être en train de démarrer, débranchée, un équipement du chemin peut être en panne, ou un **pare-feu** filtrer l'ICMP — celui de **Windows bloque le ping par défaut**. C'est pourquoi `nmap -sn` ne se contente pas de l'ICMP pour découvrir les hôtes.
::

::extrait-cours{id="thm-ar-traceroute" titre="traceroute et le TTL" source="/cours/a1/ethical-hacking/reconnaissance/cours#_6-whois-dns-et-traceroute"}
`traceroute` (Linux, macOS) ou `tracert` (Windows) affiche les routeurs (*hops*) qu'un paquet traverse jusqu'à la cible, et donc leur nombre. Le chemin peut changer d'une fois sur l'autre — beaucoup de routeurs suivent des protocoles de routage dynamique —, et certains routeurs ne répondent pas.

Le principe repose sur le **TTL** (*Time To Live*) de l'en-tête IP, qui compte en fait des **sauts** : chaque routeur le décrémente, et celui qui le fait tomber à 0 jette le paquet et renvoie un **ICMP Time-to-Live exceeded**, qui révèle son adresse. `traceroute` envoie donc des paquets de TTL 1, 2, 3… Sous Linux, ce sont par défaut des **datagrammes UDP** ; `traceroute -I` envoie des echo requests ICMP, comme `tracert`, et `-T` des segments TCP SYN.
::

::extrait-cours{id="thm-ar-banniere" titre="telnet et la capture de bannière" source="/cours/a1/ethical-hacking/scanning/cours#_5-banner-grabbing-et-énumération"}
**TELNET** (*Teletype Network*), conçu en 1969, sert à administrer une machine à distance en ligne de commande, sur le port **TCP 23**. Il envoie **tout en clair**, identifiants et mots de passe compris : son remplaçant sûr est **SSH**.

Le client `telnet`, lui, reste utile : il repose sur TCP et peut se connecter à **n'importe quel service** pour en lire la **bannière** (*banner grabbing*). Avec `telnet MACHINE_IP 80`, on tape une requête HTTP à la main — `GET / HTTP/1.1`, puis un en-tête `Host` — et la réponse du serveur web donne son nom et sa version. `nc` et `curl -I` rendent le même service.
::

::extrait-cours{id="thm-ar-netcat" titre="Netcat" source="/cours/a1/ethical-hacking/scanning/cours#_5-banner-grabbing-et-énumération"}
**Netcat** (`nc`) fonctionne en TCP comme en UDP, en **client** — `nc MACHINE_IP 21` se connecte au service et affiche sa bannière — ou en **serveur** qui écoute sur un port choisi.

| Option | Rôle |
| --- | --- |
| `-l` | mode écoute (*listen*) |
| `-p` | le port, juste avant son numéro |
| `-n` | adresses numériques seulement, sans résolution DNS |
| `-v`, `-vv` | sortie détaillée, très détaillée |
| `-k` | continuer d'écouter après la déconnexion du client |
| `-u` | UDP au lieu de TCP |

`nc -vnlp 1234` équivaut à `nc -v -l -n -p 1234`. Écouter sur un port **inférieur à 1024** demande les droits **root**.
::
