Room **I-02** du TD : [Offensive Security Intro](https://tryhackme.com/room/offensivesecurityintro), environ 30 min. Trois tâches : ce qu'est la sécurité offensive (Task 1), un premier « piratage » encadré — trouver avec Gobuster une page cachée du site d'une fausse banque, FakeBank (Task 2) —, et les métiers offensifs (Task 3). Seules les notions sont reprises : ce qui distingue l'attaque autorisée de l'autre, l'outil et ses options, ce que dit sa sortie, ce qu'un hacker éthique fait de sa trouvaille ; le mot que le lab fait recopier à la fin est écarté. Énoncés et propositions en anglais, comme à l'examen ; sous chaque question, l'**Indice**, la **Solution** et le **Cours**, un rappel en français.

:::exercice{titre="Task 1 — What is Offensive Security?" theme="Sécurité offensive et défensive, et le cadre légal"}

::exo-question{label="1." bonne="a" cours="thm-off-offensive"}
Which of the following options better represents the process where you simulate a hacker's actions to find vulnerabilities in a system?

#a
Offensive security

#b
Defensive security

#c
Digital forensics

#d
Threat intelligence

#indice
Pour déjouer un pirate, dit la room, il faut penser comme lui.

#solution
Simuler les actions d'un pirate — s'introduire dans un système, exploiter un bogue, trouver une faille — pour la faire corriger avant les criminels, c'est la **sécurité offensive** (*offensive security*).

**b** protège, détecte et répond, sans attaquer ; **c** enquête après coup sur les traces d'une attaque ; **d** recueille des informations sur les adversaires pour mieux s'en défendre.

Réponse : $\boxed{\text{a}}$
::

::exo-question{label="2." bonne="c" cours="thm-off-offensive"}
Why does an organization pay ethical hackers to attack its own systems?

#a
To monitor its employees' activity on the network

#b
To investigate a breach after it has happened

#c
To find vulnerabilities and fix them before criminals exploit them

#d
To block malicious IP addresses in real time

#indice
Ce que cherche l'organisation, c'est un coup d'avance sur les vrais attaquants.

#solution
Le hacker éthique attaque **avec autorisation** pour trouver les failles et recommander leurs correctifs **avant** qu'un criminel ne les découvre.

**a** relève de la surveillance, pas du test d'intrusion ; **b** est le travail de l'investigation numérique (**DFIR**), une fois l'incident survenu ; **d** est le quotidien défensif d'un SOC.

Réponse : $\boxed{\text{c}}$
::

::exo-question{label="3." bonne="b" cours="thm-off-cadre"}
Probing a company's website for hidden pages without its permission is acceptable, as long as you report what you find.

#a
True

#b
False

#indice
Qu'est-ce qui sépare un hacker éthique d'un pirate, avant même le premier outil lancé ?

#solution
Faux : sans **autorisation écrite** préalable — un périmètre et des règles d'engagement signés —, sonder un site est illégal, même avec l'intention de signaler la faille ensuite. C'est la conduite d'un *gray hat*, pas celle d'un hacker éthique. La room le rappelle : exploiter une telle faille sans autorisation expose à de lourdes conséquences juridiques.

Réponse : $\boxed{\text{b}}$
::
:::

:::exercice{titre="Task 2 — Hacking your first machine" theme="Trouver une page cachée avec Gobuster, lire sa sortie, signaler la faille"}

::exo-question{label="1." bonne="d" cours="thm-off-gobuster"}
What is Gobuster used for in this room?

#a
Scanning a host for open TCP ports

#b
Cracking password hashes offline

#c
Intercepting and modifying HTTP requests

#d
Brute-forcing a website's hidden pages with a wordlist

#indice
La banque a laissé en ligne une page d'administration vers laquelle aucun lien ne mène : comment la trouver sans connaître son nom ?

#solution
**Gobuster** essaie un à un les noms d'une liste de mots (*wordlist*) sur le serveur web et signale ceux qui existent : c'est une **énumération par force brute** des répertoires et des fichiers.

**a** est le rôle de nmap ; **b** celui de hashcat ou de John the Ripper ; **c** celui d'un proxy comme Burp Suite.

Réponse : $\boxed{\text{d}}$
::

::exo-question{label="2." bonne="b" cours="thm-off-gobuster"}
In the command `gobuster -u http://fakebank.thm -w wordlist.txt dir`, what does `-w` specify?

#a
The target URL

#b
The wordlist of names to try

#c
The number of concurrent threads

#d
The file where the results are saved

#indice
Pour deviner des pages, il faut bien une source de noms à essayer.

#solution
`-w` donne la **liste de mots** (*wordlist*) que Gobuster essaie un à un, ici `wordlist.txt`.

**a** est le rôle de `-u`, qui reçoit `http://fakebank.thm` ; **c** se règle avec `-t` ; **d** avec `-o`.

Réponse : $\boxed{\text{b}}$
::

::exo-question{label="3." bonne="a" cours="thm-off-gobuster"}
In the command `gobuster -u http://fakebank.thm -w wordlist.txt dir`, what does `dir` select?

#a
The directory and file brute-forcing mode

#b
The DNS subdomain brute-forcing mode

#c
The virtual host brute-forcing mode

#d
The local folder where the report is saved

#indice
Gobuster sait chercher plusieurs sortes de choses, et un mot-clé dit laquelle.

#solution
`dir` choisit le mode **répertoires et fichiers** : Gobuster ajoute chaque mot de la liste à l'URL et regarde la réponse du serveur.

**b** est le mode `dns`, qui devine des sous-domaines ; **c** le mode `vhost`, qui devine des hôtes virtuels ; **d** — le mode ne désigne pas un dossier, la sortie se règle avec `-o`. La forme courante aujourd'hui écrit le mode en premier : `gobuster dir -u … -w …`.

Réponse : $\boxed{\text{a}}$
::

::exo-question{label="4." bonne="c" cours="thm-off-gobuster"}
Gobuster returns `/images (Status: 301)` and `/bank-transfer (Status: 200)`. What does status 200 tell you about /bank-transfer?

#a
The page redirects to another location.

#b
Access to the page is forbidden.

#c
The page exists and was served successfully.

#d
The page does not exist on the server.

#indice
Compare avec `/images`, qui renvoie 301 : laquelle des deux pages le serveur sert-il directement ?

#solution
**200 OK** : la page existe et le serveur l'a renvoyée — c'est la page de virement cachée.

**a** correspond au code 301 (*Moved Permanently*), celui de `/images` ; **b** au code 403 (*Forbidden*) ; **d** au code 404 (*Not Found*), que Gobuster n'affiche pas par défaut.

Réponse : $\boxed{\text{c}}$
::

::exo-question{label="5." bonne="d" cours="thm-off-cadre"}
During an authorized test, you discover that the hidden /bank-transfer page lets anyone move money between accounts. What should you do as an ethical hacker?

#a
Exploit it further in production to measure how much money can be moved

#b
Publish it on social media so that customers can protect themselves

#c
Keep it to yourself in case you need it in a later engagement

#d
Report it to the organization with evidence so that it can be fixed

#indice
Dans un test d'intrusion, le vrai livrable n'est pas la faille : c'est ce qu'on en remet au client.

#solution
Le hacker éthique **signale** la faille au client, preuves à l'appui et avec une recommandation de correction : c'est la phase de **rapport** (*reporting*), le livrable du test.

**a** sort du périmètre et cause un dommage réel ; **b** expose la faille avant son correctif et met les clients en danger ; **c** revient à garder une porte d'entrée pour soi, ce que ferait un pirate.

Réponse : $\boxed{\text{d}}$
::

::extrait-cours{id="thm-off-offensive" titre="Sécurité offensive et défensive" source="/cours/a1/ethical-hacking/introduction/cours#_7-les-types-de-hackers"}
La room part d'une idée : pour déjouer un pirate, il faut penser comme lui. La **sécurité offensive** (*offensive security*) consiste à s'introduire dans des systèmes, exploiter des bogues et trouver des failles dans des applications — le tout **avec autorisation**, pour recommander des correctifs avant que des criminels ne les découvrent. C'est le métier du **hacker éthique** (*white hat*).

La **sécurité défensive** (*defensive security*) en est le pendant : protéger les réseaux et les systèmes de l'organisation, détecter les intrusions, enquêter sur une machine compromise, surveiller l'infrastructure. On parle d'**équipe rouge** (*red team*) pour l'attaque et d'**équipe bleue** (*blue team*) pour la défense.
::

::extrait-cours{id="thm-off-cadre" titre="Autorisation et rapport" source="/cours/a1/ethical-hacking/introduction/cours#_9-les-phases-dun-test-dintrusion"}
Ce qui sépare le hacker éthique du pirate, ce ne sont pas les outils : c'est l'**autorisation écrite**, obtenue avant tout test actif. Les **règles d'engagement** (*rules of engagement*) fixent le périmètre, le calendrier, les techniques permises et les contacts d'urgence. Sonder un site sans permission est illégal, même avec de bonnes intentions — c'est la conduite du *gray hat*.

La trouvaille ne s'exploite pas : elle se **signale**. Le test se termine par le **rapport** (*reporting*) — constats, preuves, scores CVSS et recommandations de correction —, le livrable que le client reçoit réellement. Exploiter une faille sans autorisation, comme la page de virement de FakeBank, expose à de lourdes conséquences juridiques.
::

::extrait-cours{id="thm-off-gobuster" titre="Gobuster et les codes HTTP" source="/cours/a1/ethical-hacking/introduction/cours#_9-les-phases-dun-test-dintrusion"}
Une entreprise laisse souvent en ligne des pages qu'aucun lien ne mentionne — une console d'administration, une page de virement. **Gobuster** les débusque par **force brute** : il essaie un à un les noms d'une **liste de mots** (*wordlist*) et signale ceux qui existent.

```bash
gobuster -u http://fakebank.thm -w wordlist.txt dir
```

- `-u` : l'URL de la cible ; `-w` : la liste de mots ;
- `dir` : le mode **répertoires et fichiers** — les autres modes sont `dns` pour les sous-domaines et `vhost` pour les hôtes virtuels ;
- la forme courante aujourd'hui écrit le mode en premier : `gobuster dir -u … -w …`.

La sortie se lit avec les **codes de statut HTTP** : **200** (*OK*), la page existe — `/bank-transfer` ; **301** (*Moved Permanently*), une redirection — `/images` ; **403** (*Forbidden*), la page existe mais l'accès est refusé ; **404** (*Not Found*), elle n'existe pas.
::

::extrait-cours{id="thm-off-metiers" titre="Les métiers offensifs" source="/cours/a1/ethical-hacking/introduction/cours#_7-les-types-de-hackers"}
La room conseille de choisir un domaine et de s'y exercer un peu chaque jour, puis présente trois métiers :

- le **testeur d'intrusion** (*penetration tester*) teste des produits technologiques — une application, un réseau, un site — pour y trouver des failles exploitables ;
- le **red teamer** joue l'**adversaire** : il attaque l'organisation tout entière comme le ferait un ennemi, et lui rend compte de ce point de vue ;
- l'**ingénieur sécurité** (*security engineer*) conçoit, surveille et maintient les contrôles de sécurité, les réseaux et les systèmes qui préviennent les attaques.

Tous travaillent avec autorisation : ce sont des *white hats*, à l'opposé des *black hats* qui attaquent pour le profit, le sabotage ou l'espionnage.
::
