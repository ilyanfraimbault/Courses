Room **I-07** du TD : [DNS in Detail](https://tryhackme.com/room/dnsindetail), environ 30 min, celle que cite le cours sur le DNS et les transferts de zone. Elle explique ce qu'est le DNS (Task 1), la hiérarchie des noms de domaine (Task 2), les principaux types d'enregistrements (Task 3) et le chemin d'une requête, du cache local au serveur faisant autorité (Task 4), avant un exercice pratique avec `nslookup` (Task 5). Les questions de notion de la room sont reprises en QCM ; celles de l'exercice pratique, dont les réponses dépendent du domaine fictif du lab, sont remplacées par des questions sur les mêmes enregistrements. Énoncés et propositions en anglais, comme à l'examen ; sous chaque question, l'**Indice**, la **Solution** et le **Cours**, un rappel en français.

:::exercice{titre="Tasks 1-2 — What is DNS? and Domain Hierarchy" theme="Le rôle du DNS et la hiérarchie des noms de domaine"}

::exo-question{label="1." bonne="c" cours="thm-dns-hierarchie"}
What does DNS stand for?

#a
Domain Name Server

#b
Dynamic Network Service

#c
Domain Name System

#d
Digital Naming Standard

#indice
Il s'agit de tout un système réparti dans le monde, pas d'une seule machine.

#solution
**DNS** veut dire **Domain Name System** : le système qui traduit un nom de domaine en adresse IP, pour qu'on n'ait pas à retenir des suites de chiffres.

**a** est la confusion classique : un *serveur* DNS n'est qu'une pièce du système ; **b** et **d** n'existent pas.

Réponse : $\boxed{\text{c}}$
::

::exo-question{label="2." bonne="d" cours="thm-dns-hierarchie"}
In the name admin.tryhackme.com, which part is the second-level domain?

#a
admin

#b
com

#c
admin.tryhackme

#d
tryhackme

#indice
Un nom se lit de droite à gauche : la racine, puis le premier niveau, puis…

#solution
De droite à gauche : `com` est le **domaine de premier niveau** (**TLD**, *Top-Level Domain*), `tryhackme` le **domaine de second niveau** (*Second-Level Domain*), `admin` un **sous-domaine**.

**a** est le sous-domaine ; **b** le TLD ; **c** réunit un sous-domaine et un domaine de second niveau, ce n'est pas un niveau de la hiérarchie.

Réponse : $\boxed{\text{d}}$
::

::exo-question{label="3." bonne="b" cours="thm-dns-hierarchie"}
What type of TLD is .co.uk?

#a
A gTLD (generic top-level domain)

#b
A ccTLD (country code top-level domain)

#c
A new gTLD, such as .online

#d
An infrastructure TLD, such as .arpa

#indice
Le `uk` final désigne un pays.

#solution
`.co.uk` est un **ccTLD** (*country code TLD*), lié à un pays — le Royaume-Uni —, comme `.fr` ou `.ca`.

**a** désigne les domaines à vocation générale, comme `.com` (commercial), `.org` ou `.edu` ; **c** est la vague récente de gTLD (`.online`, `.club`, `.website`), génériques eux aussi ; **d** est réservé à l'infrastructure d'Internet, notamment à la résolution inverse.

Réponse : $\boxed{\text{b}}$
::

::exo-question{label="4." bonne="a" cours="thm-dns-hierarchie"}
Which length limits apply to domain names, according to the room?

#a
63 characters per label, 253 characters for the whole name

#b
253 characters per label, 63 characters for the whole name

#c
32 characters per label, 128 characters for the whole name

#d
63 characters per label, with no limit for the whole name

#indice
Une étiquette est forcément plus courte que le nom complet, qui en enchaîne plusieurs.

#solution
Un domaine de second niveau ou un sous-domaine compte au plus **63 caractères** — lettres a-z, chiffres 0-9 et tirets —, et le nom complet au plus **253 caractères**. On peut enchaîner autant de sous-domaines qu'on veut dans cette limite.

**b** intervertit les deux nombres ; **c** invente des limites ; **d** oublie la limite du nom complet.

Réponse : $\boxed{\text{a}}$
::
:::

:::exercice{titre="Task 3 — Record Types" theme="A, AAAA, CNAME et MX, et la priorité des serveurs de courrier"}

::exo-question{label="1." bonne="d" cours="thm-dns-mx"}
What type of record would be used to advise where to send email?

#a
TXT

#b
CNAME

#c
PTR

#d
MX

#indice
Ce type porte une priorité, pour ordonner plusieurs serveurs de courrier.

#solution
L'enregistrement **MX** (*Mail Exchange*) désigne le ou les serveurs qui reçoivent le courrier du domaine.

**a** contient du texte libre — dont la politique SPF, qui dit qui a le droit d'**envoyer** du courrier au nom du domaine, pas où lui écrire ; **b** fait d'un nom l'alias d'un autre ; **c** sert à la résolution inverse, d'une adresse IP vers un nom.

Réponse : $\boxed{\text{d}}$
::

::exo-question{label="2." bonne="b" cours="thm-dns-mx"}
A domain has two MX records, with priorities 10 and 30. Which mail server do clients try first?

#a
The one with priority 30, the higher number

#b
The one with priority 10, the lower number

#c
Either one, picked at random each time

#d
Both at once, to deliver the message faster

#indice
Le second serveur sert de secours : lequel des deux nombres désigne le serveur principal ?

#solution
La **priorité** d'un MX fixe l'ordre dans lequel essayer les serveurs : la **plus petite valeur passe en premier** — ici 10 —, les autres servent de secours si le principal ne répond pas.

**a** inverse la règle ; **c** ne vaut que pour deux MX de même priorité, entre lesquels la charge se répartit ; **d** — un message n'est remis qu'une fois, à un seul serveur.

Réponse : $\boxed{\text{b}}$
::

What type of record handles IPv6 addresses?

#a
A

PTR

#c
AAAA

#d
SRV

#indice

Looking up store.tryhackme.com returns another domain name, shops.shopify.com, which must itself be resolved to get an IP address. Which record type is this?

#b

#c

#d

Le nom renvoie vers un autre nom, comme un alias.

:::exercice{titre="Task 4 — Making A Request" theme="Le chemin d'une requête DNS, le cache et le TTL"}

::exo-question{label="1." bonne="b" cours="thm-dns-requete"}
What field specifies how long a DNS record should be cached?

#a
The serial number

#b
The TTL (Time To Live)

#c
The priority

#d
The class

#indice
C'est une durée de vie, comptée en secondes.

#solution
Le **TTL** (*Time To Live*) donne, en **secondes**, la durée pendant laquelle une réponse peut être gardée en cache avant d'être redemandée. Rien à voir avec le TTL d'un paquet IP, qui compte des routeurs : même nom, autre champ.

**a** est le numéro de version de la zone, dans l'enregistrement SOA ; **c** ordonne les serveurs MX ; **d** (`IN`, pour Internet) dit à quelle famille de réseaux l'enregistrement s'applique.

Réponse : $\boxed{\text{b}}$
::

::exo-question{label="2." bonne="d" cours="thm-dns-requete"}
What type of DNS server is usually provided by your ISP?

#a
An authoritative server

#b
A root server

#c
A TLD server

#d
A recursive server

#indice
C'est le serveur qui fait les démarches à ta place, de la racine jusqu'à la réponse.

#solution
Le **serveur récursif** (*recursive DNS server*), en général fourni par le fournisseur d'accès — on peut en choisir un autre —, reçoit les requêtes des clients, répond depuis son cache s'il le peut, et sinon interroge la hiérarchie pour eux.

**a** détient les enregistrements d'un domaine ; **b** oriente vers le bon serveur de TLD ; **c** indique quels serveurs font autorité pour un domaine.

::

::exo-question{label="3." bonne="c" cours="thm-dns-requete"}
What type of server holds all the records for a domain, and is where any update to them is made?

#a
A recursive server

#b
A root server

#c
An authoritative server

#d
A TLD server

#indice
C'est la source de vérité du domaine ; les autres ne font que relayer la question ou garder une copie en cache.

#solution
Le **serveur faisant autorité** (*authoritative server*, aussi appelé serveur de noms du domaine) stocke les enregistrements DNS du domaine, et c'est là qu'on les modifie.

::exo-question{label="4." bonne="a" cours="thm-dns-requete"}
No cache holds the answer yet. In which order are the steps of a request for www.tryhackme.com taken?

#a
Local cache, recursive server, root server, TLD server, authoritative server

#b
Local cache, root server, recursive server, authoritative server, TLD server

#c
Recursive server, TLD server, root server, authoritative server, local cache

#d
Local cache, authoritative server, TLD server, root server, recursive server

#indice
On part de sa propre machine, puis on descend la hiérarchie des noms en la lisant de droite à gauche.

#solution
Le poste regarde d'abord son **cache local**, puis interroge son **serveur récursif** ; celui-ci demande à un **serveur racine** où trouver le serveur du TLD `.com`, le **serveur de TLD** lui indique les serveurs **faisant autorité** pour `tryhackme.com`, et ceux-ci donnent la réponse. Le récursif la garde en cache le temps du TTL et la renvoie au client.

**b** fait passer la racine avant le récursif, alors que le poste ne parle qu'à ce dernier ; **c** parcourt la hiérarchie à l'envers ; **d** commence par le serveur faisant autorité, que personne ne sait encore trouver.

Réponse : $\boxed{\text{a}}$
::

::extrait-cours{id="thm-dns-hierarchie" titre="Le DNS et la hiérarchie des domaines" source="/cours/a1/ethical-hacking/dns-zone-transfer/cours#_1-la-résolution-dns"}
Le **DNS** (*Domain Name System*) permet de joindre un appareil par un nom plutôt que par son adresse IP. Un nom se lit **de droite à gauche** :

- la **racine** (*root*), notée par un point final qu'on n'écrit pas ;
- le **domaine de premier niveau** (**TLD**, *Top-Level Domain*) : les **gTLD**, génériques (`.com` pour commercial, `.org`, `.edu`, `.gov`, et les récents `.online`, `.club`…), ou les **ccTLD**, liés à un pays (`.fr`, `.ca`, `.co.uk`) ;
- le **domaine de second niveau** (*Second-Level Domain*) : `tryhackme` dans `tryhackme.com` ;
- les **sous-domaines**, à gauche : `admin` dans `admin.tryhackme.com`.

Une étiquette — domaine de second niveau ou sous-domaine — compte au plus **63 caractères** (lettres a-z, chiffres 0-9, tirets) ; le nom complet, au plus **253**. On peut enchaîner autant de sous-domaines qu'on veut dans cette limite.
::

::extrait-cours{id="thm-dns-types" titre="Les types d'enregistrements" source="/cours/a1/ethical-hacking/dns-zone-transfer/cours#_2-les-types-denregistrements"}
- **A** : associe un nom à une adresse **IPv4**.
- **AAAA** : à une adresse **IPv6**.
- **CNAME** (*Canonical Name*) : fait du nom l'**alias** d'un autre nom, que le client doit à son tour résoudre — `store.tryhackme.com` renvoie vers `shops.shopify.com`.
- **MX** (*Mail Exchange*) : les serveurs qui reçoivent le courrier du domaine, avec leur priorité.
- **TXT** : du texte libre — la liste des serveurs autorisés à envoyer du courrier pour le domaine (SPF), contre le spam et l'usurpation, ou un jeton qui prouve la propriété du domaine à un service tiers.

Le cours en ajoute d'autres : **PTR** pour la résolution inverse (d'une adresse vers un nom), **NS** pour la délégation d'une zone à ses serveurs, **SOA** pour l'en-tête de la zone, **SRV** pour localiser un service.
::

::extrait-cours{id="thm-dns-mx" titre="Les enregistrements MX et leur priorité" source="/cours/a1/ethical-hacking/dns-zone-transfer/cours#_4-ce-que-révèlent-les-enregistrements-mail"}
Un enregistrement **MX** (*Mail Exchange*) dit **où envoyer le courrier** d'un domaine : `dig MX example.com +short` répond par exemple `10 mail.example.com.`. Chaque MX porte une **priorité** : les serveurs s'essaient de la **plus petite valeur à la plus grande** — 10 avant 30 —, les suivants servant de secours si le premier ne répond pas.

Les MX disent aussi quel fournisseur de messagerie le domaine utilise : Google Workspace, Microsoft 365 ou un serveur maison. Ne pas les confondre avec les enregistrements **TXT** de SPF, DKIM et DMARC : ceux-là disent qui a le droit d'**envoyer** du courrier au nom du domaine.
::

::extrait-cours{id="thm-dns-requete" titre="Le chemin d'une requête DNS" source="/cours/a1/ethical-hacking/dns-zone-transfer/cours#_1-la-résolution-dns"}
1. Le poste consulte son **cache local** ; s'il n'y trouve rien, il interroge son **serveur DNS récursif** (*recursive DNS server*), en général fourni par le fournisseur d'accès.
2. Le récursif consulte son propre cache ; sinon, il demande à un **serveur racine** (*root server*), qui l'oriente vers le serveur du bon TLD.
3. Le **serveur de TLD** indique les serveurs **faisant autorité** pour le domaine — souvent plusieurs, par sécurité.
4. Le **serveur faisant autorité** (*authoritative server*) détient les enregistrements du domaine — c'est là qu'on les modifie — et donne la réponse.

Le récursif garde la réponse en cache pendant son **TTL** (*Time To Live*), exprimé en **secondes**, puis la renvoie au client. Rien à voir avec le TTL d'un paquet IP, qui compte des routeurs.
::
