::::exercice{titre="Palier 1 — Structures et unions dans la mémoire" theme="Copie de structure, octets de compensation, champ pointeur, union qui écrase" badge="★★☆☆☆" icone="i-lucide-memory-stick" entete="introduction"}
Une structure range ses champs **dans l'ordre**, avec de la compensation si l'alignement l'exige ; une union met **tous** ses champs au même endroit.

:::exo-question{label="1." cours="s-c-structures"}
Avec `char` sur 1 octet :

```c
struct Point { char x; char y; };

struct Point p = {.x = 3, .y = 4};
struct Point q = p;
q.x = 10;
p.y = p.x + q.x;
```

::tableau-memoire
---
titre: Après la dernière ligne
cases:
  - variable: p.x
    adresse: '0xff150'
    attendu: '3'
  - variable: p.y
    adresse: '0xff151'
    attendu: '13'
  - variable: q.x
    adresse: '0xff152'
    attendu: '10'
  - variable: q.y
    adresse: '0xff153'
    attendu: '4'
---
::

#indice
`q = p` copie les deux champs dans les octets de `q`. Après, `p` et `q` sont-elles liées ?

#solution
- `q = p` : `q` vaut $(3, 4)$, dans ses propres octets ;
- `q.x = 10` ne touche que `q` ;
- `p.y = p.x + q.x` $= 3 + 10 = 13$.

Mémoire : `p` = $\boxed{(3, 13)}$, `q` = $\boxed{(10, 4)}$.
:::

:::exo-question{label="2." cours="s-c-alignement"}
Avec `int` sur 4 octets d'alignement $4$ et `char` d'alignement $1$, la structure commençant à `0xff80` :

```c
struct CharInt { char a; int b; };
struct CharInt s = {.a = 5, .b = 6};
```

::tableau-memoire
---
titre: La structure s
cases:
  - variable: s.a
    adresse: '0xff80'
    attendu: '5'
  - variable: compensation
    adresse: '0xff81'
    octets: 3
    attendu: ['??', '?']
  - variable: s.b
    adresse: '0xff84'
    octets: 4
    attendu: '6'
---
::

#indice
`b` doit commencer à une adresse multiple de 4. Quelle est la première après `a` ?

#solution
`a` occupe `0xff80`. `b` ne peut pas commencer à `0xff81`, qui n'est pas un multiple de 4 : il commence à `0xff84`. Les trois octets `0xff81` à `0xff83` sont de la **compensation**, jamais écrits : `??`.

Mémoire : `a` = $\boxed{5}$, compensation `??`, `b` = $\boxed{6}$ sur 4 octets.
:::

:::exo-question{label="3." cours="s-c-pointeurs"}
Avec `int` sur 2 octets et un pointeur sur 4, sans alignement :

```c
struct User { int age; char* name; };

char nom[4] = "ann";
struct User u = {.age = 28, .name = nom};
u.age++;
```

::tableau-memoire
---
titre: Après la dernière ligne
cases:
  - variable: nom[0]
    adresse: '0xff150'
    attendu: ["'a'", 'a', '97']
  - variable: nom[1]
    adresse: '0xff151'
    attendu: ["'n'", 'n', '110']
  - variable: nom[2]
    adresse: '0xff152'
    attendu: ["'n'", 'n', '110']
  - variable: nom[3]
    adresse: '0xff153'
    attendu: '0'
  - variable: u.age
    adresse: '0xff154'
    octets: 2
    attendu: '29'
  - variable: u.name
    adresse: '0xff156'
    octets: 4
    attendu: '0xff150'
---
::

#indice
Le champ `name` est un pointeur : contient-il les lettres, ou une adresse ? Et un tableau, utilisé comme valeur, vaut l'adresse de sa première case.

#solution
- `nom` occupe `0xff150` à `0xff153` : `'a'`, `'n'`, `'n'`, $0$ ;
- `u` commence à `0xff154` : `age` (2 octets), puis `name` (4 octets) ;
- `name` reçoit `nom`, c'est-à-dire l'**adresse** `0xff150` — les lettres ne sont pas copiées dans la structure ;
- `u.age++` : $29$.

Mémoire : `u.age` = $\boxed{29}$, `u.name` = $\boxed{\texttt{0xff150}}$.
:::

:::exo-question{label="4." cours="s-c-unions"}
```c
union Valeur { char octet; char lettres[2]; };

union Valeur v;
v.lettres[0] = 'a';
v.lettres[1] = 'b';
v.octet = 'z';
```

::tableau-memoire
---
titre: L'union v, après la dernière ligne
cases:
  - variable: octet / lettres[0]
    adresse: '0xff150'
    attendu: ["'z'", 'z', '122']
  - variable: lettres[1]
    adresse: '0xff151'
    attendu: ["'b'", 'b', '98']
---
::

#indice
Tous les champs d'une union commencent à la même adresse. Quels octets `octet` partage-t-il avec `lettres` ?

#solution
L'union fait 2 octets, la taille de son plus grand champ. `octet` et `lettres[0]` sont **le même octet**, `0xff150` : `v.octet = 'z'` écrase le `'a'`. `lettres[1]` n'est pas touché.

Mémoire : **`'z'`**, **`'b'`**. Un `printf("%c", v.lettres[0])` afficherait `z`.
:::

::::exercice{titre="Palier 2 — Ce qu'affiche le programme" theme="Structure copiée ou pointée, enum à valeurs mêlées" badge="★★☆☆☆" icone="i-lucide-terminal" entete="introduction"}
Une structure passée à une fonction est **copiée**, comme un `int` ; pour la modifier, il faut son **adresse**.

:::exo-question{label="5." cours="s-c-pointeurs"}
```c
struct User { int age; char* name; };

void vieillir(struct User u) { u.age++; }
void vieillir_p(struct User* u) { u->age++; }

int main() {
    struct User u = {.age = 20, .name = "ann"};
    vieillir(u);
    printf("%d\n", u.age);
    vieillir_p(&u);
    printf("%d\n", u.age);
}
```

::champs-reponse
---
champs:
  - libelle: Ligne 1
    attendu: '20'
  - libelle: Ligne 2
    attendu: '21'
---
::

#indice
Laquelle des deux fonctions reçoit une copie de la structure ?

#solution
`vieillir` reçoit une **copie** de `u` et vieillit la copie : `u.age` reste $20$. `vieillir_p` reçoit l'**adresse** de `u` et écrit dans l'original : $21$. Sortie : **`20`** puis **`21`**.
:::

:::exo-question{label="6." cours="s-c-enums"}
```c
typedef enum { LUNDI, MARDI, MERCREDI = 10, JEUDI } jour;
printf("%d %d %d\n", MARDI, MERCREDI, JEUDI);
```

::champs-reponse
---
champs:
  - libelle: Ligne affichée
    attendu: '1 10 11'
---
::

#indice
Sans valeur précisée, une constante vaut la précédente plus 1.

#solution
`LUNDI` $= 0$, `MARDI` $= 1$, `MERCREDI` $= 10$, `JEUDI` $= 11$. Sortie : **`1 10 11`**.
:::

:::exo-question{label="7." cours="s-c-pointeurs"}
```c
struct Point { int x; int y; };

int main() {
    struct Point t[3] = {{1, 2}, {3, 4}, {5, 6}};
    struct Point* p = &t[1];
    p->x = p->y + t[2].x;
    p++;
    p->y = 0;
    printf("%d %d %d\n", t[1].x, t[2].x, t[2].y);
}
```

::champs-reponse
---
champs:
  - libelle: Ligne affichée
    attendu: '9 5 0'
---
::

#indice
`p` pointe d'abord vers `t[1]`. Vers quelle case pointe-t-il après `p++` ?

#solution
- `p->x = p->y + t[2].x` : `t[1].x` reçoit $4 + 5 = 9$ ;
- `p++` avance d'**une structure** : `p` pointe vers `t[2]` ;
- `p->y = 0` : `t[2].y` vaut $0$.

Sortie : **`9 5 0`**. L'arithmétique de pointeurs avance de la taille du type pointé, ici une `struct Point` entière.
:::

::::exercice{titre="Palier 3 — Les tailles" theme="Taille d'une structure avec compensation, d'une union, choix de l'ordre des champs" badge="★★★☆☆" icone="i-lucide-ruler" entete="introduction"}
Les conventions de la diapo : `int` sur 4 octets d'alignement $4$, `char` sur 1 octet d'alignement $1$. Place les champs un à un, en partant de l'octet $0$.

:::exo-question{label="8." cours="s-c-alignement" bonne="b"}
Combien d'octets occupe `struct S1 { char a; int b; char c; };`, sachant que la taille totale d'une structure est arrondie au multiple de son plus grand alignement ?

#a
$6$

#b
$12$

#c
$9$

#d
$8$

#indice
Place `a`, puis `b` à un multiple de 4, puis `c` ; enfin arrondis la taille au multiple de 4.

#solution
`a` à l'octet $0$ ; compensation de $1$ à $3$ ; `b` de $4$ à $7$ ; `c` à $8$. Cela fait $9$ octets, arrondis au multiple de $4$ : $\boxed{12}$ — c'est ce qu'affiche `sizeof` sur un PC.

**Les distracteurs :** **a** additionne les champs sans compensation ; **c** oublie l'arrondi final ; **d** est la taille de la même structure bien ordonnée (question suivante).
:::

:::exo-question{label="9." cours="s-c-alignement" bonne="d"}
Quel ordre des mêmes trois champs donne la **plus petite** structure ?

#a
`char a; int b; char c;`

#b
`char c; int b; char a;`

#c
L'ordre ne change rien à la taille.

#d
`int b; char a; char c;`

#indice
Calcule la taille de chacun. Quel ordre évite de laisser des trous **avant** l'`int` ?

#solution
Avec `int b; char a; char c;` : `b` de $0$ à $3$, `a` à $4$, `c` à $5$ ; $6$ octets arrondis à $\boxed{8}$. Réponse **d**.

**Les distracteurs :** **a** et **b** donnent $12$ — chaque `char` isolé devant un `int` coûte de la compensation ; **c** ignore l'alignement. (`char a; char c; int b;`, absent des propositions, donnerait aussi $8$.) La règle : ranger les champs **du plus aligné au moins aligné**.
:::

:::exo-question{label="10." cours="s-c-unions" bonne="a"}
Avec `int` et `float` sur 4 octets, combien d'octets réserve `union Mesure { int entier; float reel; char texte[8]; } m[3];` ?

#a
$24$

#b
$48$

#c
$8$

#d
$16$

#indice
D'abord la taille d'**une** union, puis celle d'un tableau de trois.

#solution
Une union a la taille de son plus grand champ, `texte` : $8$ octets. Le tableau en contient trois : $3 \times 8 = \boxed{24}$.

**Les distracteurs :** **b** additionne les champs comme pour une structure, $16$, puis multiplie par 3 ; **c** oublie qu'il y a trois unions ; **d** est la taille d'**une** union calculée comme une structure.
:::

::::exercice{titre="Palier 4 — Écrire des fonctions sur des structures" theme="Point et flèche, copie et pointeur, tableau de structures, malloc, enum" badge="★★★★☆" icone="i-lucide-code-xml" entete="introduction"}
Les types de ce palier :

```c
typedef struct Point { int x; int y; } Point;
typedef struct Etudiant { char nom[20]; float note; } Etudiant;
enum couleur { ROUGE, VERT, BLEU };
```

Pour chaque fonction : **reçoit-elle une structure (copie) ou un pointeur (pour modifier, ou pour éviter de copier)** ? Écris un `main` qui l'appelle, compile et teste.

:::exo-question{label="11." cours="s-c-structures" code="c"}
Écrire une fonction `distance_carre` qui reçoit deux `Point` et renvoie le carré de leur distance, $(x_a - x_b)^2 + (y_a - y_b)^2$.

#indice
La fonction ne modifie rien : elle peut recevoir des copies. Un point pour accéder aux champs.

#solution
```c
int distance_carre(Point a, Point b) {
    int dx = a.x - b.x;
    int dy = a.y - b.y;
    return dx * dx + dy * dy;
}
```

Avec $a = (1, 2)$ et $b = (4, 6)$ : $3^2 + 4^2 = 25$.
:::

:::exo-question{label="12." cours="s-c-pointeurs" code="c"}
Écrire une fonction `translater` qui déplace un `Point` de l'appelant de `dx` horizontalement et `dy` verticalement, appelée par `translater(&p, 3, -1);`.

#indice
Pour modifier le point de l'appelant, la fonction reçoit son adresse — et utilise donc la flèche.

#solution
```c
void translater(Point* p, int dx, int dy) {
    p->x += dx;
    p->y += dy;
}
```

Avec `p` $= (1, 2)$, `translater(&p, 3, -1)` donne $(4, 1)$. Avec `void translater(Point p, …)`, la fonction déplacerait une copie.
:::

:::exo-question{label="13." cours="s-c-pointeurs" code="c"}
Écrire une fonction `moyenne` qui reçoit un tableau d'`Etudiant` et sa taille, et renvoie la moyenne des notes.

#indice
`t[i]` est une structure : son champ `note` s'écrit `t[i].note`. La somme et le résultat sont à virgule.

#solution
```c
float moyenne(Etudiant t[], int n) {
    float s = 0;
    for (int i = 0; i < n; i++) {
        s += t[i].note;
    }
    return s / n;
}
```

Avec `Etudiant t[3] = {{"Ana", 12.5}, {"Bob", 15}, {"Cyl", 9.5}};`, la moyenne vaut $37 / 3 \approx 12{,}33$. `s` est un `float` : la division n'est pas entière.
:::

:::exo-question{label="14." cours="s-c-pointeurs" code="c"}
Écrire une fonction `meilleur` qui reçoit un tableau d'`Etudiant` et sa taille, et renvoie un **pointeur** vers l'étudiant qui a la meilleure note.

#indice
Comme un maximum, mais on garde l'**adresse** de la meilleure case, `&t[i]`, au lieu de sa note.

#solution
```c
Etudiant* meilleur(Etudiant t[], int n) {
    Etudiant* m = &t[0];
    for (int i = 1; i < n; i++) {
        if (t[i].note > m->note) {
            m = &t[i];
        }
    }
    return m;
}
```

`m` est un pointeur : `m->note`. Avec le tableau précédent, `meilleur(t, 3)->nom` vaut `"Bob"`. Renvoyer `&t[i]` est sûr : le tableau appartient à l'appelant, il existe encore après le `return`.
:::

:::exo-question{label="15." cours="s-c-pointeurs" code="c"}
Écrire une fonction `cree_point` qui reçoit deux entiers et renvoie un pointeur vers un **nouveau** `Point` réservé sur le tas.

#indice
`malloc(sizeof(Point))`, puis la flèche pour remplir. Qui fera le `free` ?

#solution
```c
Point* cree_point(int x, int y) {
    Point* p = malloc(sizeof(Point));
    p->x = x;
    p->y = y;
    return p;
}
```

Dans `main` :

```c
Point* p = cree_point(2, 5);
printf("%d %d\n", p->x, p->y);   // 2 5
free(p);
```

Un `Point` déclaré dans la fonction serait libéré au `return` ; celui du tas survit, et l'appelant le libère.
:::

::extrait-cours{id="s-c-alignement" titre="L'alignement" source="/cours/a1/mise-a-niveau-c/types-personnalises/cours#_4-structure-et-mémoire-lalignement"}
Champs dans l'ordre de déclaration ; chacun commence à un multiple de son alignement (`int` : 4, `char` : 1), avec des **octets de compensation** si besoin ; la taille totale est arrondie au multiple du plus grand alignement. Ranger les champs du plus aligné au moins aligné.
::

::extrait-cours{id="s-c-pointeurs" titre="Pointeurs vers une structure" source="/cours/a1/mise-a-niveau-c/types-personnalises/cours#_2-pointeurs-malloc-et-tableaux-de-structures"}
`p->x` équivaut à `(*p).x`. Point pour une structure, flèche pour un pointeur. Pour modifier une structure dans une fonction, passer son adresse. `malloc(sizeof(struct Point))` en réserve une sur le tas. `p++` avance d'une structure entière.
::

::extrait-cours{id="s-c-unions" titre="Les unions" source="/cours/a1/mise-a-niveau-c/types-personnalises/cours#_5-les-unions"}
Tous les champs d'une union commencent à la **même adresse** : écrire dans l'un écrase les autres. Taille : celle du **plus grand** champ.
::

::extrait-cours{id="s-c-enums" titre="Les enums" source="/cours/a1/mise-a-niveau-c/types-personnalises/cours#_6-les-enums"}
`enum nom { A, B, C = 10, D };` : la première constante vaut $0$, chaque constante sans valeur vaut **la précédente plus 1** — ici `D` = 11.
::
