::rappel{titre="La boîte à outils du chapitre"}
- On **compile** un fichier `.c` en binaire avec `gcc main.c -o main.out`, puis on lance `./main.out`.
- Une **variable** = un nom + un type. Le type fixe **la place réservée** dans la mémoire et **les opérations** permises : `int` (entier), `char` (entier sur 1 octet, ou caractère), `float` (nombre à virgule).
- Une variable déclarée sans valeur contient **n'importe quoi** (`??`) : ce qui traînait dans ses octets.
- Un caractère entre apostrophes **est un nombre** : son code dans la table ASCII. **Inutile de connaître les codes** : il suffit de savoir que les chiffres, les minuscules et les majuscules se suivent, ce qui permet de calculer `'a' + 2`, `ch - '0'` ou `c - 'a' + 'A'`.
- `/` entre deux entiers **tronque** ($7/2$ vaut $3$) ; `%` donne le reste.
- `&`, `|`, `^`, `~`, `<<`, `>>` travaillent **bit à bit**.
- `printf("%d %f %c\n", entier, flottant, caractere);` — et `scanf("%d", &entier);` avec un `&`.
- En C, une condition est un entier : **$0$ est faux, tout le reste est vrai**. Les comparaisons renvoient $1$ ou $0$.
- `c++` renvoie l'**ancienne** valeur, `++c` la **nouvelle** ; `c = b` renvoie la valeur affectée.
::

::rappel{titre="Les conventions des tableaux mémoire" icone="i-lucide-memory-stick"}
Le cours dessine la mémoire comme un tableau d'octets, et ce site fait pareil. Sauf mention contraire, on y prend les **tailles des exemples du professeur** :

| Type | Octets |
|---|---|
| `char` | 1 |
| `int` | 2 |
| `float` | 4 |
| un pointeur (chapitre 4) | 4 |

et les variables sont **rangées dans l'ordre où elles sont déclarées**, à la suite les unes des autres. Une case réservée mais jamais écrite se note `??`.

Ce sont des simplifications : sur un PC d'aujourd'hui, un `int` occupe 4 octets et un pointeur 8, et le compilateur range les variables comme il veut (chapitre 2). Le raisonnement, lui, reste le même.
::

## 1. Le C et la compilation

Le C est le langage qu'on choisit quand on veut **maximiser la vitesse** d'exécution, **minimiser la mémoire** utilisée et **contrôler** précisément les instructions exécutées. On le retrouve dans les systèmes d'exploitation, les drivers, les navigateurs, les microcontrôleurs, les jeux vidéo — et dans les interpréteurs de la plupart des autres langages (Python, Java, C#, bash…). Revers de la médaille : près de 70 % des failles de sécurité critiques recensées par Google en 2018 venaient de programmes écrits en C.

Le professeur compare un même petit programme (demander un nombre, afficher deux de ses facteurs) dans trois langages :

| Langage | Temps d'exécution | Appels système | Mémoire utilisée | Disque |
|---|---|---|---|---|
| C | 8 ms | 52 | 2,5 Mo | 24 Ko |
| Java | 86 ms | 185 | 623 Mo | 124 000 Ko |
| Python | 1 400 ms | 670 | 13 Mo | 6 000 Ko |

Ce contrôle a un prix : en C, on se demande en permanence **quelles instructions** sont exécutées, **combien de mémoire** est utilisée, **quels appels système** sont faits, et **comment les données sont rangées** dans la mémoire.

Un programme C ne s'exécute pas tel quel : il est **traduit en binaire** par un programme appelé **compilateur**. Cette traduction s'appelle la **compilation**. Le compilateur du cours est `gcc` : on lui donne le fichier `.c` à compiler, puis, après `-o`, le nom du binaire à créer.

```bash
gcc main.c -o main.out
./main.out
```

::exemple{id="b-ex-compiler" titre="Compiler puis lancer" pour="Le cycle de chaque TP"}
On a écrit `bonjour.c`. Pour obtenir un exécutable nommé `bonjour` :

```bash
gcc bonjour.c -o bonjour
```

`gcc` lit `bonjour.c` et écrit le fichier binaire `bonjour`. On le lance avec `./bonjour`. Modifier `bonjour.c` ne change **rien** au binaire tant qu'on n'a pas recompilé.
::

:::qcm{titre="Contrôle express — la compilation" icone="i-lucide-circle-check-big" compact}

## 2. Variables et types

En C, une **variable** est définie par **un nom** et **un type**. Elle associe ce nom à un **emplacement dans la mémoire**, dont on peut changer la valeur pendant l'exécution.

Le C oblige à donner le type de **chaque** variable. Le type dit deux choses :

- **la quantité de mémoire** qui lui est réservée ;
- **les opérations** qu'on peut lui appliquer.

Les trois types de la première séance :

| Nom | Ce qu'il représente | Mémoire | Valeurs |
|---|---|---|---|
| `int` | un nombre entier | au moins 2 octets | sur 2 octets : $[-32\,768 ; 32\,767]$ |
| `char` | un nombre entier (ou un caractère) | 1 octet (8 bits) | $[-128 ; 127]$ |
| `float` | un réel (nombre à virgule) | 4 octets en pratique | environ $\pm 3{,}4 \times 10^{38}$ |

::rappel{titre="Écart avec la diapo" icone="i-lucide-triangle-alert"}
La diapo donne $[-65\,536 ; 65\,535]$ pour un `int` sur 2 octets. Or 2 octets, c'est 16 bits, soit $2^{16} = 65\,536$ valeurs **en tout** : de $-2^{15} = -32\,768$ à $2^{15}-1 = 32\,767$. C'est la même logique que pour le `char` : 8 bits, $2^8 = 256$ valeurs, de $-128$ à $127$.
::

On **déclare** une variable en écrivant son type puis son nom, et on peut lui donner une valeur dans la foulée :

```c
int b;           // un entier nommé b, sans valeur
char c;          // un char nommé c
int age = 52;    // déclaré et initialisé
```

Ensuite, on change sa valeur par une **affectation** :

```c
int a = 5;
a = a - 1;   // a contient maintenant 4
```

::exemple{id="b-ex-declarer" titre="Choisir le type" pour="Chaque fois qu'on déclare une variable"}
Un nombre d'élèves : `int nb_eleves = 31;`. Une moyenne : `float moyenne = 12.5;`. Une lettre de groupe : `char groupe = 'B';`.

`a = a - 1` ne se lit pas comme une équation : on **calcule** `a - 1` avec la valeur actuelle, puis on **range** le résultat dans `a`.
::

::

## 3. Les variables dans la mémoire

Chaque déclaration **réserve** des octets dans la mémoire ; chaque affectation **écrit** dans ces octets. Une variable déclarée sans valeur occupe déjà sa place, mais ce qu'elle contient est **indéterminé** : ce qui traînait là avant. On le note `??`.

::exemple{id="b-ex-memoire" titre="Dérouler un programme dans la mémoire" pour="La méthode de tous les tableaux mémoire du cours"}
Le programme du cours, avec `int` sur 2 octets, `char` sur 1, `float` sur 4 :

```c
int a = 5;
int b;
char c = 10;
float f = -1.8;
b = a + c;
```

Ligne par ligne :

1. `int a = 5;` réserve les octets 1 et 2 et y écrit $5$ ;
2. `int b;` réserve les octets 3 et 4, **sans rien y écrire** : `??` ;
3. `char c = 10;` réserve l'octet 5 et y écrit $10$ ;
4. `float f = -1.8;` réserve les octets 6 à 9 et y écrit $-1{,}8$ ;
5. `b = a + c;` **ne réserve rien** : il lit $5$ et $10$, et écrit $15$ dans les octets de `b`.

| Variable | Valeur | Octets |
|---|---|---|
| `a` | 5 | 1–2 |
| `b` | ~~??~~ → 15 | 3–4 |
| `c` | 10 | 5 |
| `f` | −1.8 | 6–9 |
::

## 4. Les caractères et la table ASCII

Le type `char` sert aussi à représenter un **caractère** — une lettre, un chiffre, un symbole. On l'écrit entre **apostrophes** :

```c
char a = 'i';
char b = '$';
char c = '*';
```

La **table ASCII** associe un nombre à chaque caractère usuel, sur 7 bits (128 positions). Quand on écrit un caractère dans un programme, c'est **ce nombre** qui est rangé dans la mémoire.

::rappel{titre="Pas besoin d'apprendre la table" icone="i-lucide-info"}
Le contrôle ne demande aucun code par cœur. Ce qu'il faut savoir, c'est que **les chiffres `'0'` … `'9'`, les minuscules `'a'` … `'z'` et les majuscules `'A'` … `'Z'` se suivent**. On calcule donc **en décalant**, sans jamais écrire un code :

- `'a' + 4` est la lettre 4 crans après `'a'` : `'e'` ;
- `ch - '0'` donne la valeur d'un chiffre écrit en caractère : `'7' - '0'` vaut $7$ ;
- `c - 'a' + 'A'` donne la majuscule d'une minuscule `c` : la même distance depuis `'A'` que depuis `'a'`.

(Pour information seulement : `'0'` vaut $48$, `'A'` $65$, `'a'` $97$. Quand une diapo montre un code, elle le donne.)
::

::exemple{id="b-ex-ascii" titre="Quatre char dans la mémoire" pour="Passer du caractère au nombre et retour"}
```c
char a = 56;
char b = '8';
char c = 'a' + 4;
char d = 'e';
```

| Variable | Valeur | Octet |
|---|---|---|
| `a` | 56 | 1 |
| `b` | 56 | 2 |
| `c` | 101 | 3 |
| `d` | 101 | 4 |

`a` et `b` contiennent **le même nombre** : $56$ est le code du caractère `'8'` (la diapo le donne). Attention : `'8'` n'est pas l'entier $8$. De même, `c` et `d` sont identiques : `'a' + 4` est la lettre 4 crans plus loin, `'e'`.
::

:::qcm{titre="Contrôle express — la table ASCII" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="c" cours="b-c-ascii"}

#a

#b

#indice

#solution
`'a'` + 1 → `'b'`, + 2 → `'c'`, + 3 → `'d'`. `x` contient **`'d'`**.

**Les distracteurs :** **a** compte `'a'` comme premier cran ; **b** en compte un de trop ; **d** oublie que `'a'` est lui-même un nombre auquel on ajoute 3.
::

::qcm-question{label="2." bonne="a" cours="b-c-ascii"}

$7$

#b
$0$

**Les distracteurs :** **b** croit que tous les chiffres se valent ; **c** confond l'entier $7$ avec le caractère `'7'` ; **d** oublie qu'un caractère est un nombre.
::
:::

## 5. Opérations sur les entiers

Le C propose sur les entiers les quatre opérations classiques `+`, `-`, `*`, `/`, et le **reste de la division euclidienne**, ou **modulo**, `%`.

- $1 + 2 * 3 - 4 = 3$ : la multiplication passe avant (section 9) ;
- $18 \% 14 = 4$, car $18 = 1 \times 14 + 4$.

Point crucial : **entre deux entiers, `/` est la division entière**. Le résultat est tronqué, la partie décimale est perdue : `7 / 2` vaut $3$, et `7 % 2` vaut $1$. Pour obtenir $3{,}5$, il faut qu'un des deux soit un `float` : `7 / 2.0`.

::exemple{id="b-ex-division" titre="Division entière et modulo" pour="Tout calcul de moyenne, de parité, de chiffre"}
- `17 / 5` vaut $3$ et `17 % 5` vaut $2$ : $17 = 3 \times 5 + 2$.
- **Parité** : `n % 2` vaut $0$ si `n` est pair, $1$ s'il est impair (pour `n` positif).
- **Dernier chiffre** : `1234 % 10` vaut $4$ ; `1234 / 10` vaut $123$, le nombre sans son dernier chiffre.
::

:::qcm{titre="Contrôle express — division et modulo" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="b" cours="b-c-entiers"}

#b

#c

#d
$6$ et $1$

#indice

#solution
$23 = 5 \times 4 + 3$, donc `n / 4` vaut $5$ et `n % 4` vaut $3$ : $\boxed{5 \text{ et } 3}$.

**Les distracteurs :** **a** oublie que `/` entre deux `int` tronque ; **c** donne la partie décimale au lieu du reste ; **d** arrondit au plus proche au lieu de tronquer.
::

::qcm-question{label="2." bonne="d" cours="b-c-entiers"}

## 6. Opérations bit à bit

Les entiers sont rangés en binaire, et le C sait opérer **sur chaque bit**.

- `&` (ET), `|` (OU), `^` (OU exclusif) appliquent l'opération booléenne **bit par bit** aux deux entiers ;
- `<<` et `>>` **décalent** les bits vers la gauche ou la droite : décaler de $k$ à gauche multiplie par $2^k$, à droite divise (division entière) par $2^k$ ;
- `~` (tilde) est le **complément à 1** : chaque bit est inversé.

Les exemples du professeur, vérifiés :

| Expression | En binaire | Résultat |
|---|---|---|
| `1 \| 2` | `01 \| 10 = 11` | $3$ |
| `31 & 16` | `11111 & 10000 = 10000` | $16$ |
| `5 ^ 30` | `00101 ^ 11110 = 11011` | $27$ |
| `3 << 2` | `11` → `1100` | $12$ |
| `40 >> 3` | `101000` → `101` | $5$ |
| `~7` sur 8 bits | `00000111` → `11111000` | $248$ |

::rappel{titre="Deux écarts avec la diapo" icone="i-lucide-triangle-alert"}
La diapo annonce `1|2 = 0` et `5 ^ 30 = 25`. Le calcul bit à bit, et le programme compilé, donnent **$3$** et **$27$** : un OU ne peut pas faire disparaître des bits à 1, et `00101 ^ 11110` a quatre bits à 1, soit $16 + 8 + 2 + 1$.
::

::exemple{id="b-ex-bits" titre="Poser un ET, un OU, un OU exclusif" pour="Toute opération bit à bit"}
Calculer `12 & 10`, `12 | 10` et `12 ^ 10`. On écrit les deux nombres en binaire, l'un sous l'autre :

```
12 = 1100
10 = 1010
```

- ET (1 si **les deux** bits valent 1) : `1000` $= 8$ ;
- OU (1 si **au moins un** vaut 1) : `1110` $= 14$ ;
- OU exclusif (1 si **exactement un** vaut 1) : `0110` $= 6$.
::

:::qcm{titre="Contrôle express — bit à bit" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="a" cours="b-c-bits"}
Que vaut `6 ^ 3` ?

#a
$5$

#b
$2$

#c
$7$

#d
$216$

#indice
$6$ = `110`, $3$ = `011`. Le OU exclusif met 1 là où les bits **diffèrent**.

#solution
`110 ^ 011 = 101`, soit $\boxed{5}$.

**Les distracteurs :** **b** est `6 & 3` (`010`) ; **c** est `6 | 3` (`111`) ; **d** lit `^` comme une puissance ($6^3$), ce qu'il n'est pas en C.
::

::qcm-question{label="2." bonne="c" cours="b-c-bits"}
Que vaut `5 << 3` ?

#a
$8$

#b
$15$

#c
$40$

#indice

#solution

**Les distracteurs :** **a** donne $2^3$ sans le $5$ ; **b** multiplie par $3$ ; **d** décale dans le mauvais sens et perd tous les bits.
::
:::

## 7. Afficher et lire : printf et scanf

Pour **écrire dans le terminal**, on utilise `printf` (*print format*) : `printf(format, variables);`. Dans le format, chaque `%…` est remplacé, dans l'ordre, par la variable correspondante :

- `%d` pour un `int` ;
- `%f` pour un `float` — affiché **avec six décimales** ;
- `%c` pour un `char`, affiché comme **caractère** de la table ASCII.

```c
int jour = 27;
float temperature = 25.4;
printf("il fait %f le %d\n", temperature, jour);
// il fait 25.400000 le 27
```

Dans la plupart des environnements, le texte n'apparaît pas tant qu'on n'a pas envoyé un **saut de ligne** `"\n"`.

::rappel{titre="Ce qu'affiche vraiment %f" icone="i-lucide-triangle-alert"}
La diapo montre `il fait 25.4 le 27`. Compilé, le programme affiche `il fait 25.400000 le 27` : `%f` écrit toujours six décimales. Pour en garder une seule, on écrit `%.1f`.
::

Pour **lire** ce que tape l'utilisateur, on utilise `scanf` (*scan format*) avec les mêmes formats : `scanf(format, &variable);`. Le `&` devant la variable est **obligatoire** : `scanf` a besoin de savoir **où** écrire (son adresse, chapitre 4).

```c
int age;
float taille;
scanf("%d %f", &age, &taille);
```

Un espace dans le format de `scanf` saute tous les caractères « transparents » — espaces, tabulations, sauts de ligne — jusqu'au prochain caractère visible.

::exemple{id="b-ex-printf" titre="Un char affiché de trois façons" pour="Prédire l'affichage d'un printf"}
```c
char a = 56;
float b = 8.1;
int c = 4;
printf("%c - %f - %d\n", a, b, c);
```

`%c` affiche le caractère de code $56$ — la diapo l'a choisi : c'est `'8'` ; `%f` affiche `8.100000` ; `%d` affiche `4`. Sortie :

```
8 - 8.100000 - 4
```

Le même `a` affiché avec `%d` donnerait `56`.
::

:::qcm{titre="Contrôle express — printf et scanf" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="b" cours="b-c-printf"}
`char x = 'B';` Qu'affiche `printf("%c%c\n", x, x + 1);` ?

#a
`BB`

#b
`BC`

#c
`B1`

#d
`CB`

#indice
Le premier format reçoit le premier argument. `x + 1` est le caractère qui suit `'B'`, et `%c` l'affiche comme un caractère.

#solution
`%c` affiche `B`, puis `x + 1`, la lettre suivante, `C`. Sortie : **`BC`**.

**Les distracteurs :** **a** oublie le `+ 1` ; **c** affiche le `+ 1` au lieu de l'ajouter ; **d** inverse l'ordre des formats.
::

::qcm-question{label="2." bonne="c" cours="b-c-printf"}
Laquelle de ces lignes lit correctement un entier tapé au clavier dans `int n;` ?

#a
`scanf("%d", n);`

#b
`scanf("%f", &n);`

#c
`scanf("%d", &n);`

#d
`printf("%d", &n);`

#indice
Deux choses à vérifier : le format qui correspond au type, et ce que `scanf` doit recevoir pour pouvoir écrire dans `n`.

#solution
Format `%d` pour un `int`, et l'adresse de `n` : **`scanf("%d", &n);`**.

**Les distracteurs :** **a** oublie le `&` — `scanf` reçoit la valeur (indéterminée) de `n` au lieu de son adresse ; **b** lit un `float` dans un `int` ; **d** affiche au lieu de lire.
::
:::

## 8. Les conditions : if et else

L'instruction `if` (« si ») n'exécute un bloc de code **que si une condition est vraie** ; `else` (« sinon »), placé juste après, exécute un autre bloc **si elle était fausse**.

```c
if (age > 17) {
    printf("Tarif : 8€\n");
} else {
    printf("Tarif : 6€\n");
}
```

En C, **une condition est un entier** :

- $0$ veut dire **faux** ;
- **n'importe quelle autre valeur** veut dire **vrai**.

Les comparaisons `>`, `<`, `==`, `>=`, `<=`, `!=` et les opérateurs logiques `&&` (et), `||` (ou), `!` (non) **renvoient $1$ pour vrai, $0$ pour faux**.

Attention à ne pas confondre `==` (comparer) et `=` (affecter).

::exemple{id="b-ex-if" titre="Une condition qui n'est pas une comparaison" pour="Lire if (n % 2), if (x = 0)…"}
```c
int n = 17;
if (n % 2) {
    printf("impair\n");
} else {
    printf("pair\n");
}
```

`n % 2` vaut $1$, qui n'est pas $0$ : c'est **vrai**, le programme affiche `impair`. Pas besoin d'écrire `n % 2 == 1`.

Piège classique : `if (x = 0)` **affecte** $0$ à `x`, puis teste la valeur obtenue, $0$ — la condition est toujours fausse.
::

:::qcm{titre="Contrôle express — les conditions" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="d" cours="b-c-conditions"}
Que vaut l'expression `(5 > 3) + (2 == 2) + (4 < 1)` ?

#a
$0$

#b
Elle ne compile pas : on n'additionne pas des conditions.

#c
$1$

#d
$2$

#indice
Chaque comparaison renvoie un entier, $1$ ou $0$.

#solution
$1 + 1 + 0 = \boxed{2}$.

**Les distracteurs :** **b** — une condition est un entier, elle s'additionne ; **a** et **c** se trompent sur la valeur d'une comparaison vraie.
::

::qcm-question{label="2." bonne="a" cours="b-c-conditions"}
`int x = 5;` Qu'affiche `if (x = 0) printf("A"); else printf("B");` ?

#a
`B`

#b
`A`

#c
`AB`

#d
Rien

#indice
`=` n'est pas `==`. Que vaut l'expression `x = 0` ?

#solution
`x = 0` affecte $0$ à `x` et vaut $0$, donc faux : le programme affiche **`B`** — et `x` vaut désormais $0$.

**Les distracteurs :** **b** lit `=` comme `==` et compare $5$ à $0$… ce qui donnerait d'ailleurs aussi faux ; **c** exécute les deux branches, ce qu'un `if`/`else` ne fait jamais ; **d** oublie le `else`.
::
:::

## 9. Les opérateurs d'affectation

Une affectation est une **expression** : elle change la valeur d'une variable **et renvoie un résultat**, qu'on peut réutiliser.

| Opérateur | Effet | Renvoie |
|---|---|---|
| `c = b` | met la valeur de `b` dans `c` | la nouvelle valeur |
| `c += b` | ajoute `b` à `c` (existe aussi : `-=`, `*=`, `/=`) | la nouvelle valeur |
| `c++` | ajoute 1 à `c` | **l'ancienne** valeur |
| `c--` | enlève 1 à `c` | **l'ancienne** valeur |
| `++c` | ajoute 1 à `c` | **la nouvelle** valeur |
| `--c` | enlève 1 à `c` | **la nouvelle** valeur |

(La diapo écrit « `c--` ajoute 1 » : c'est bien **enlève** 1.)

::exemple{id="b-ex-affectation" titre="Le programme des affectations, case par case" pour="Dérouler des ++, des -- et des affectations imbriquées"}
```c
char a = 5;
char b = (a = 2);
b *= 2;
a = --b + 4;
char c = (b = a) + 1;
```

| Ligne | `a` (octet 1) | `b` (octet 2) | `c` (octet 3) |
|---|---|---|---|
| `char a = 5;` | 5 | | |
| `char b = (a = 2);` | 2 | 2 | |
| `b *= 2;` | 2 | 4 | |
| `a = --b + 4;` | 7 | 3 | |
| `char c = (b = a) + 1;` | 7 | 7 | 8 |

- `(a = 2)` met $2$ dans `a` **et vaut** $2$ : `b` reçoit $2$.
- `--b` fait d'abord passer `b` à $3$, **puis** vaut $3$ : `a` reçoit $3 + 4 = 7$.
- `(b = a)` copie $7$ dans `b` et vaut $7$ : `c` reçoit $8$.
::

:::qcm{titre="Contrôle express — ++ et --" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="c" cours="b-c-affectation"}
`int i = 5; int j = i++ + 2;` Que valent `i` et `j` ensuite ?

#a
`i = 5`, `j = 8`

#b
`i = 6`, `j = 8`

#c
`i = 6`, `j = 7`

#d
`i = 5`, `j = 7`

#indice
`i++` augmente `i`, mais quelle valeur **renvoie**-t-il dans le calcul ?

#solution
`i++` renvoie l'ancienne valeur, $5$, puis `i` passe à $6$ : `j` vaut $5 + 2 = 7$. Donc $\boxed{i = 6,\ j = 7}$.

**Les distracteurs :** **b** confond `i++` et `++i` ; **a** et **d** oublient que `i` a bien été augmenté.
::

::qcm-question{label="2." bonne="b" cours="b-c-affectation"}
`int k = 4; k *= k - 1;` Que vaut `k` ?

#a
$15$

#b
$12$

#c
$3$

#d
$16$

#indice
`k *= expr` équivaut à `k = k * (expr)` : l'expression de droite est calculée entière d'abord.

#solution
`k *= k - 1` équivaut à `k = k * (k - 1)` $= 4 \times 3 = \boxed{12}$.

**Les distracteurs :** **a** calcule `k * k - 1` sans parenthèses ; **c** garde seulement `k - 1` ; **d** calcule `k * k`.
::
:::

## 10. Priorité des opérateurs et programme complet

Quand une expression mélange plusieurs opérateurs, ceux de **plus haute priorité** sont évalués en premier : dans `2 + 3 * 5`, la multiplication passe avant, `2 + (3 * 5)`. Du plus prioritaire au moins prioritaire :

| Rang | Opérateurs |
|---|---|
| 1 | parenthèses `()` |
| 2 | unaires `++` `--` `-` `!` `~` |
| 3 | `*` `/` `%` |
| 4 | `+` `-` |
| 5 | décalages `<<` `>>` |
| 6 | comparaisons `>` `>=` `<` `<=` |
| 7 | égalité `==` `!=` |
| 8 | bit à bit : `&`, puis `^`, puis `\|` |
| 9 | logique : `&&`, puis `\|\|` |
| 10 | affectation `=` `+=` `-=` `*=` `/=` |

Deux pièges : les opérateurs bit à bit passent **après** `==` — `6 & 3 == 3` se lit `6 & (3 == 3)`, soit `6 & 1`, qui vaut $0$ ; et `&&` passe **avant** `||`. Dans le doute, **on met des parenthèses**.

Un programme complet de la première séance a toujours cette forme : la ligne `#include` donne accès à `printf` et `scanf`, et le code se place entre les accolades de `main`.

```c
#include <stdio.h>

int main() {
    printf("C'est la fin !\n");
}
```

(La diapo écrit `#include "stdio.h"` : avec des guillemets, le compilateur cherche d'abord dans le dossier du projet, puis dans les fichiers du système ; les chevrons `<stdio.h>` sont l'écriture habituelle pour la bibliothèque standard.)

::exemple{id="b-ex-priorite" titre="Parenthéser avant de calculer" pour="Toute expression qui mélange plusieurs opérateurs"}
`1 + 2 * 3 - 4` : `*` d'abord, puis `+` et `-` de gauche à droite : $(1 + 6) - 4 = 3$.

`1 || 0 && 0` : `&&` d'abord, `1 || (0 && 0)` $= 1 || 0 = 1$. Lu de gauche à droite sans priorité, on aurait trouvé $(1 || 0) \&\& 0 = 0$.
::

:::qcm{titre="Contrôle express — la priorité" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="d" cours="b-c-priorite"}
Que vaut `10 - 2 * 3 + 1` ?

#a
$25$

#b
$3$

#c
$-6$

#d
$5$

#indice
La multiplication d'abord, puis `-` et `+` de gauche à droite.

#solution
$10 - 6 + 1 = \boxed{5}$.

**Les distracteurs :** **a** calcule de gauche à droite sans priorité, $(10-2) \times 3 + 1$ ; **b** fait la soustraction en dernier, $10 - (6+1)$ ; **c** fait l'addition avant la multiplication, $10 - 2 \times (3 + 1)$ — des parenthèses qui n'existent pas.
::

::qcm-question{label="2." bonne="a" cours="b-c-priorite"}
Que vaut `6 & 3 == 3` ?

#a
$0$

#b
$1$

#c
$2$

#d
$3$

#indice
Dans le tableau, `==` est-il au-dessus ou au-dessous de `&` ?

#solution
`==` passe avant `&` : on calcule `3 == 3`, qui vaut $1$, puis `6 & 1` = `110 & 001` = $\boxed{0}$.

**Les distracteurs :** **c** calcule `6 & 3` d'abord, soit $2$, comme si `&` passait avant `==` ; **b** lit l'expression comme une condition vraie ; **d** ne garde que la valeur de droite.
::
:::

::extrait-cours{id="b-c-compilation" titre="Compiler avec gcc" source="/cours/a1/mise-a-niveau-c/les-bases/cours#_1-le-c-et-la-compilation"}
Le C est **compilé** : un programme, le compilateur, le traduit en binaire avant toute exécution. Avec `gcc` :

```bash
gcc main.c -o main.out   # fichier source, puis -o et le binaire à créer
./main.out               # on lance le binaire
```

Le binaire ne change pas tant qu'on ne recompile pas.
::

::extrait-cours{id="b-c-types" titre="Variables et types" source="/cours/a1/mise-a-niveau-c/les-bases/cours#_2-variables-et-types"}
Une variable = un **nom** + un **type**. Le type fixe la **mémoire réservée** et les **opérations** permises.

- `char` : 1 octet, de $-128$ à $127$ ;
- `int` : au moins 2 octets — sur 2 octets, de $-32\,768$ à $32\,767$ ;
- `float` : un nombre à virgule.

Sur $n$ bits, un entier signé va de $-2^{n-1}$ à $2^{n-1} - 1$.
::

::extrait-cours{id="b-c-memoire" titre="Une variable dans la mémoire" source="/cours/a1/mise-a-niveau-c/les-bases/cours#_3-les-variables-dans-la-mémoire"}
Une **déclaration réserve** des octets (dans le cours : `char` 1, `int` 2, `float` 4), à la suite des précédents. Une **affectation écrit** dans ces octets, sans rien réserver. Une variable déclarée sans valeur contient ce qui traînait là : `??`.
::

::extrait-cours{id="b-c-ascii" titre="La table ASCII" source="/cours/a1/mise-a-niveau-c/les-bases/cours#_4-les-caractères-et-la-table-ascii"}
Un caractère entre apostrophes est **un nombre** :

Pas besoin de connaître les codes : les chiffres, les minuscules et les majuscules **se suivent**. On calcule en décalant :

- `'a' + 4` vaut `'e'` ;
- `ch - '0'` convertit un chiffre écrit en entier ;
- `c - 'a' + 'A'` donne la majuscule de la minuscule `c`.
::

::extrait-cours{id="b-c-entiers" titre="Division entière et modulo" source="/cours/a1/mise-a-niveau-c/les-bases/cours#_5-opérations-sur-les-entiers"}
Entre deux entiers, `/` **tronque** et `%` donne le **reste** : $23 = 5 \times 4 + 3$, donc `23 / 4` vaut $5$ et `23 % 4` vaut $3$. Pour une division à virgule, un des opérandes doit être à virgule **avant** la division : `7 / 2.0` vaut $3{,}5$.
::

::extrait-cours{id="b-c-bits" titre="Les opérateurs bit à bit" source="/cours/a1/mise-a-niveau-c/les-bases/cours#_6-opérations-bit-à-bit"}
On écrit les nombres en binaire, l'un sous l'autre :

- `&` : 1 si les deux bits valent 1 ; `|` : si au moins un ; `^` : si exactement un ;
- `x << k` multiplie par $2^k$, `x >> k` divise (entièrement) par $2^k$ ;
- `~x` inverse tous les bits.

`12 & 10 = 8`, `12 | 10 = 14`, `12 ^ 10 = 6`.
::

::extrait-cours{id="b-c-printf" titre="printf et scanf" source="/cours/a1/mise-a-niveau-c/les-bases/cours#_7-afficher-et-lire-printf-et-scanf"}
`printf(format, valeurs…)` : chaque `%` du format est remplacé, dans l'ordre, par une valeur — `%d` un `int`, `%f` un `float` (six décimales), `%c` le **caractère** de ce code ASCII. Le texte s'affiche au `\n`.

`scanf(format, &variable)` : mêmes formats, et **un `&`** devant chaque variable à remplir.
::

::extrait-cours{id="b-c-conditions" titre="Conditions" source="/cours/a1/mise-a-niveau-c/les-bases/cours#_8-les-conditions-if-et-else"}
`if (condition) { … } else { … }`. Une condition est un entier : **$0$ = faux, tout le reste = vrai**. Comparaisons (`>`, `==`, `!=`…) et logique (`&&`, `||`, `!`) renvoient $1$ ou $0$. `=` affecte, `==` compare.
::

::extrait-cours{id="b-c-affectation" titre="Les opérateurs d'affectation" source="/cours/a1/mise-a-niveau-c/les-bases/cours#_9-les-opérateurs-daffectation"}
Une affectation est une expression qui **renvoie** une valeur :

- `c = b`, `c += b`… renvoient la **nouvelle** valeur de `c` ;
- `c++`, `c--` modifient `c` et renvoient l'**ancienne** ;
- `++c`, `--c` modifient `c` et renvoient la **nouvelle**.

`k *= expr` équivaut à `k = k * (expr)`.
::

::extrait-cours{id="b-c-priorite" titre="La priorité des opérateurs" source="/cours/a1/mise-a-niveau-c/les-bases/cours#_10-priorité-des-opérateurs-et-programme-complet"}
Du plus fort au plus faible : `()` ; unaires `++ -- - ! ~` ; `* / %` ; `+ -` ; `<< >>` ; `< <= > >=` ; `== !=` ; `&`, `^`, `|` ; `&&`, `||` ; affectations. Les opérateurs bit à bit passent **après** `==` : dans le doute, parenthéser.
::
