Trois paliers :

1. **La mémoire d'un appel** — remplir le tableau mémoire à l'instant indiqué. Le contexte d'appel est fourni ; une case réservée mais pas encore écrite se note `??`.
2. **Ce qu'affiche le programme** — taper la sortie.
3. **Écrire des fonctions** — le cœur de la fiche. Pour chacune, avant d'écrire une ligne, réponds à trois questions : **que reçoit-elle** (types des arguments), **que renvoie-t-elle** (type de retour), **sur quel exemple la tester**. Puis écris-la au-dessus d'un `main` qui l'appelle et affiche le résultat, **compile et teste** — y compris sur un cas limite — avant d'ouvrir la solution.

Conventions des tableaux mémoire : `char` 1 octet, `int` 2 octets, contexte d'appel 4 octets, chaque appel placé à la suite de la mémoire de l'appelant.

::::exercice{titre="Palier 1 — La mémoire d'un appel" theme="Contexte d'appel, arguments copiés, valeur renvoyée, variable statique" badge="★★☆☆☆" icone="i-lucide-memory-stick" entete="introduction"}
À chaque appel, la question à se poser : **qu'est-ce qui est réservé à la suite, et qu'est-ce qui est copié dedans ?** Et au `return` : **où va la valeur, et qu'est-ce qui est libéré ?**

:::exo-question{label="1." cours="f-c-memoire"}
```c
int carre(int x) {
    int r = x * x;
    return r;
}

int main() {
    int a = 3;
    int b = carre(a + 1);
}
```

Remplir la mémoire **au moment où `carre` exécute `return r;`**.

::tableau-memoire
---
titre: Pendant l'appel, au moment du return
cases:
  - variable: a (main)
    adresse: Octet 1
    octets: 2
    attendu: '3'
  - variable: b (main)
    adresse: Octet 3
    octets: 2
    attendu: ['??', '?']
  - variable: contexte d'appel
    adresse: Octet 5
    octets: 4
    attendu: '—'
    donnee: true
  - variable: x (carre)
    adresse: Octet 9
    octets: 2
    attendu: '4'
  - variable: r (carre)
    adresse: Octet 11
    octets: 2
    attendu: '16'
---
::

#indice
`b` est réservé par `main`, mais il ne reçoit sa valeur qu'**après** le retour de `carre`. Que reçoit `x` : `a`, ou la valeur de `a + 1` ?

#solution
- `main` réserve `a` (3) et `b`, encore vide : `??` — l'affectation attend la valeur de l'appel ;
- l'appel réserve le contexte d'appel, puis `x`, qui reçoit la **copie** de `a + 1` $= 4$ ;
- `r` reçoit $4 \times 4 = 16$.

Mémoire : `a` = $\boxed{3}$, `b` = $\boxed{??}$, `x` = $\boxed{4}$, `r` = $\boxed{16}$. Juste après le `return`, `b` reçoit $16$ et les octets 5 à 12 sont libérés.
:::

:::exo-question{label="2." cours="f-c-copie"}
```c
void double_val(int n) {
    n = n * 2;
}

int main() {
    int v = 5;
    double_val(v);
    int w = v + 1;
}
```

Remplir la mémoire **juste avant l'accolade fermante de `double_val`**.

::tableau-memoire
---
titre: À la fin de double_val
cases:
  - variable: v (main)
    adresse: Octet 1
    octets: 2
    attendu: '5'
  - variable: contexte d'appel
    adresse: Octet 3
    octets: 4
    attendu: '—'
    donnee: true
  - variable: n (double_val)
    adresse: Octet 7
    octets: 2
    attendu: '10'
---
::

#indice
`n` est-il `v`, ou une copie de `v` ? `w` n'est pas encore déclaré à cet instant.

#solution
`n` reçoit une **copie** de `v`, $5$, et la double : $10$. `v`, dans les octets 1–2, n'a pas bougé : $5$.

Mémoire : `v` = $\boxed{5}$, `n` = $\boxed{10}$. Ensuite, la mémoire de `double_val` est libérée et `w` vaut $5 + 1 = 6$ : le doublement est perdu. Pour que la fonction modifie `v`, il faudra lui passer l'**adresse** de `v` (chapitre 4).
:::

:::exo-question{label="3." cours="f-c-static"}
```c
int compteur() {
    static int n = 0;
    n++;
    return n;
}

int main() {
    int a = compteur();
    int b = compteur();
    int c = compteur() + compteur();
}
```

Remplir les variables de `main` **à la fin du programme**.

::tableau-memoire
---
titre: À la fin de main
cases:
  - variable: a
    adresse: Octet 1
    octets: 2
    attendu: '1'
  - variable: b
    adresse: Octet 3
    octets: 2
    attendu: '2'
  - variable: c
    adresse: Octet 5
    octets: 2
    attendu: '7'
---
::

#indice
Combien d'appels à `compteur` en tout, et que renvoie chacun ? La variable `n` n'est remise à zéro qu'une fois.

#solution
`n` est initialisé à $0$ au premier appel seulement. Les quatre appels renvoient $1$, $2$, $3$, $4$ :

- `a` = $\boxed{1}$ ;
- `b` = $\boxed{2}$ ;
- `c` = $3 + 4 = \boxed{7}$.

Le C ne dit pas lequel des deux appels de la troisième ligne passe en premier — mais la somme est la même.
:::

::::exercice{titre="Palier 2 — Ce qu'affiche le programme" theme="Copie des arguments, appels imbriqués, variable statique" badge="★★☆☆☆" icone="i-lucide-terminal" entete="introduction"}
Un appel imbriqué se calcule **de l'intérieur vers l'extérieur** ; un argument est toujours une **copie** ; une variable `static` **se souvient**.

:::exo-question{label="4." cours="f-c-copie"}
```c
int ajoute(int a) {
    a = 6;
    return a + 5;
}

int main() {
    int b = 5;
    int c = ajoute(b);
    printf("%d %d\n", b, c);
}
```

::champs-reponse
---
champs:
  - libelle: Ligne affichée
    attendu: '5 11'
---
::

#indice
Que reçoit `a` à l'appel, et que devient `b` quand `a` est écrasé ?

#solution
`a` reçoit une copie de `b`, puis est écrasé par $6$ : la fonction renvoie $11$. `b` n'a pas changé. Sortie : **`5 11`**.
:::

:::exo-question{label="5." cours="f-c-fonction"}
```c
int f(int x) {
    return 2 * x + 1;
}

int main() {
    printf("%d\n", f(f(2)));
}
```

::champs-reponse
---
champs:
  - libelle: Ligne affichée
    attendu: '11'
---
::

#indice
Calcule d'abord l'appel intérieur ; sa valeur devient l'argument de l'appel extérieur.

#solution
`f(2)` $= 2 \times 2 + 1 = 5$, puis `f(5)` $= 2 \times 5 + 1 = 11$. Sortie : **`11`**.
:::

:::exo-question{label="6." cours="f-c-static"}
```c
int g(int a) {
    static int s = 10;
    s = s - a;
    return s;
}

int main() {
    printf("%d\n", g(1));
    printf("%d\n", g(2));
}
```

::champs-reponse
---
champs:
  - libelle: Ligne 1
    attendu: '9'
  - libelle: Ligne 2
    attendu: '7'
---
::

#indice
Au second appel, `s` repart-il de $10$ ?

#solution
Premier appel : `s` est initialisé à $10$, puis vaut $10 - 1 = 9$. Second appel : pas de réinitialisation, `s` vaut $9 - 2 = 7$. Sortie : **`9`** puis **`7`**.
:::

::::exercice{titre="Palier 3 — Écrire des fonctions" theme="Maximum, valeur absolue, puissance, factorielle, nombre premier, chaînes et tableaux" badge="★★★☆☆" icone="i-lucide-code-xml" entete="introduction"}
Neuf fonctions, de plus en plus riches. Pour chacune : **que reçoit-elle, que renvoie-t-elle, sur quoi la tester**. Écris un `main` qui l'appelle sur deux ou trois valeurs et affiche les résultats, et ne regarde la solution qu'une fois ton programme compilé et testé.

:::exo-question{label="7." cours="f-c-declaration"}
Écrire une fonction `max2` qui reçoit deux entiers et renvoie le plus grand.

#indice
Un `if` suffit ; et un `return` termine la fonction, ce qui évite le `else`.

#solution
```c
int max2(int a, int b) {
    if (a > b) {
        return a;
    }
    return b;
}
```

Tests : `max2(3, 7)` vaut $7$, `max2(-1, -4)` vaut $-1$, `max2(5, 5)` vaut $5$. Si `a > b`, le premier `return` termine la fonction ; sinon on atteint le second.
:::

:::exo-question{label="8." cours="f-c-declaration"}
Écrire une fonction `valeur_absolue` qui reçoit un entier et renvoie sa valeur absolue.

#indice
Pour un négatif, on renvoie son opposé.

#solution
```c
int valeur_absolue(int x) {
    if (x < 0) {
        return -x;
    }
    return x;
}
```

`valeur_absolue(-8)` vaut $8$, `valeur_absolue(3)` vaut $3$, `valeur_absolue(0)` vaut $0$.
:::

:::exo-question{label="9." cours="f-c-declaration"}
Écrire une fonction `puissance` qui reçoit deux entiers `x` et `n` (avec $n \ge 0$) et renvoie $x^n$, **sans** utiliser `pow`.

#indice
On part de $1$ et on multiplie par `x`, `n` fois. Que doit valoir $x^0$ ?

#solution
```c
int puissance(int x, int n) {
    int r = 1;
    for (int i = 0; i < n; i++) {
        r *= x;
    }
    return r;
}
```

`puissance(2, 10)` vaut $1024$ ; `puissance(5, 0)` vaut $1$ : la boucle ne tourne pas, et l'on renvoie la valeur de départ — d'où le choix de partir de $1$, pas de $0$.
:::

:::exo-question{label="10." cours="f-c-declaration"}
Écrire une fonction `factorielle` qui reçoit un entier $n \ge 0$ et renvoie $n! = 1 \times 2 \times \dots \times n$ (avec $0! = 1$).

#indice
Même structure que la puissance : un résultat qui part de $1$, et une boucle qui multiplie.

#solution
```c
int factorielle(int n) {
    int r = 1;
    for (int i = 2; i <= n; i++) {
        r *= i;
    }
    return r;
}
```

`factorielle(5)` vaut $120$ ; `factorielle(0)` et `factorielle(1)` valent $1$ (la boucle ne tourne pas). Un `int` déborde vite : $13!$ ne tient déjà plus sur 4 octets.
:::

:::exo-question{label="11." cours="f-c-declaration"}
Écrire une fonction `est_premier` qui reçoit un entier et renvoie $1$ s'il est premier, $0$ sinon.

#indice
Un nombre premier est un entier $\ge 2$ qui n'a aucun diviseur entre $2$ et lui-même (exclu). On peut s'arrêter dès qu'on trouve un diviseur — et même ne tester que les `d` tels que `d * d <= n`.

#solution
```c
int est_premier(int n) {
    if (n < 2) {
        return 0;
    }
    for (int d = 2; d * d <= n; d++) {
        if (n % d == 0) {
            return 0;
        }
    }
    return 1;
}
```

- dès qu'un diviseur est trouvé, `return 0` arrête tout ;
- si la boucle se termine sans en trouver, le nombre est premier ;
- si `n` a un diviseur `d`, il en a un $\le \sqrt{n}$, d'où `d * d <= n`. Tester jusqu'à `d < n` est juste aussi, seulement plus lent.

Tests : $1 \to 0$, $2 \to 1$, $9 \to 0$, $17 \to 1$, $25 \to 0$.
:::

:::exo-question{label="12." cours="f-c-declaration"}
Écrire une fonction `longueur` qui reçoit une chaîne et renvoie son nombre de lettres, comme `strlen`.

#indice
Un argument tableau s'écrit `char s[]` (ou `char* s`, comme la déclaration de `strlen` dans la diapo — le chapitre 4 dira pourquoi c'est pareil). Le corps est la boucle de longueur du chapitre 2.

#solution
```c
int longueur(char s[]) {
    int n = 0;
    while (s[n] != 0) {
        n++;
    }
    return n;
}
```

`longueur("Bonjour")` vaut $7$, `longueur("")` vaut $0$.
:::

:::exo-question{label="13." cours="f-c-declaration"}
Écrire une fonction `compte` qui reçoit une chaîne et un caractère, et renvoie le nombre de fois où ce caractère apparaît dans la chaîne.

#indice
Deux arguments, de deux types différents. Un compteur qui part de $0$, un parcours jusqu'au zéro final.

#solution
```c
int compte(char s[], char c) {
    int n = 0;
    for (int i = 0; s[i] != 0; i++) {
        if (s[i] == c) {
            n++;
        }
    }
    return n;
}
```

`compte("banane", 'a')` vaut $2$. Attention aux apostrophes : `'a'` est un caractère, `"a"` une chaîne.
:::

:::exo-question{label="14." cours="f-c-declaration"}
Écrire une fonction `somme` qui reçoit un tableau d'entiers et son nombre d'éléments, et renvoie la somme des éléments.

#indice
Un tableau d'entiers n'a pas de zéro final : la fonction ne peut pas deviner sa taille, il faut la lui passer.

#solution
```c
int somme(int t[], int n) {
    int s = 0;
    for (int i = 0; i < n; i++) {
        s += t[i];
    }
    return s;
}
```

Avec `int t[4] = {3, -1, 7, 2};`, `somme(t, 4)` vaut $11$. `{3, -1, 7, 2}` initialise les quatre cases d'un coup.
:::

:::exo-question{label="15." cours="f-c-declaration"}
Écrire une fonction `nb_chiffres` qui reçoit un entier et renvoie son nombre de chiffres en base 10 : $4512 \to 4$, $-4512 \to 4$, $0 \to 1$.

#indice
Diviser par $10$ enlève le dernier chiffre. Combien de fois peut-on le faire avant d'arriver à un seul chiffre ? Pense aux négatifs et à $0$.

#solution
```c
int nb_chiffres(int n) {
    if (n < 0) {
        n = -n;
    }
    int k = 1;
    while (n >= 10) {
        n = n / 10;
        k++;
    }
    return k;
}
```

- `n` est une **copie** : la rendre positive ne change rien chez l'appelant ;
- partir de `k = 1` et s'arrêter à `n >= 10` donne $1$ pour $0$ — une boucle `while (n > 0)` avec `k = 0` aurait renvoyé $0$ pour $0$.
:::

::extrait-cours{id="f-c-memoire" titre="La mémoire d'un appel" source="/cours/a1/mise-a-niveau-c/fonctions/cours#_5-mémoire-et-fonctions"}
Un appel réserve, **à la suite** de la mémoire de l'appelant : le **contexte d'appel**, puis les **arguments** (copies) et les **variables** de la fonction. Au `return`, la valeur est rangée chez l'appelant et tout cet espace est **libéré**.
::

::extrait-cours{id="f-c-copie" titre="Arguments copiés" source="/cours/a1/mise-a-niveau-c/fonctions/cours#_3-les-arguments-sont-des-copies"}
À l'appel, chaque valeur passée est **copiée** dans l'argument. Modifier l'argument ne modifie jamais la variable de l'appelant.
::

::extrait-cours{id="f-c-static" titre="Variable statique" source="/cours/a1/mise-a-niveau-c/fonctions/cours#_4-les-variables-statiques"}
`static type nom = valeur;` : la variable existe pendant tout le programme, est initialisée **au premier appel seulement**, et garde sa valeur entre les appels.
::

::extrait-cours{id="f-c-fonction" titre="Fonction et appel" source="/cours/a1/mise-a-niveau-c/fonctions/cours#_1-quest-ce-quune-fonction"}
L'appel d'une fonction qui renvoie une valeur est une **expression**. Un appel imbriqué se calcule de l'intérieur : `f(f(2))` calcule `f(2)`, puis `f` de ce résultat.
::

::extrait-cours{id="f-c-declaration" titre="Écrire une fonction" source="/cours/a1/mise-a-niveau-c/fonctions/cours#_2-déclaration-et-définition"}
```c
type_retour nom(type1 arg1, type2 arg2) {
    …
    return valeur;
}
```

Avant d'écrire : que reçoit-elle, que renvoie-t-elle, sur quel exemple la tester. `return` termine la fonction. Un tableau passé en argument s'écrit `int t[]` ; sa taille se passe à part (sauf pour une chaîne, qui a son zéro final).
::
