::rappel{titre="La boîte à outils du chapitre"}
- Une **fonction** associe un nom à un bloc de code ; l'**appeler** exécute ce bloc. `printf` et `scanf` sont des fonctions.
- Un appel qui **renvoie** une valeur est une **expression** : `int n = strlen("bonjour");`.
- On **déclare** une fonction par son type de retour, son nom, et les types et noms de ses arguments : `int add(int a, int b, int c)`. On la **définit** en écrivant son code entre accolades ; `return` renvoie la valeur.
- Les arguments reçoivent une **copie** des valeurs passées : une fonction **ne peut pas modifier** une variable de l'appelant par ses arguments.
- Une variable **`static`** dans une fonction existe pendant tout le programme : initialisée au premier appel, elle **garde sa valeur** entre les appels.
- Chaque appel réserve, **à la suite** de la mémoire de l'appelant, un **contexte d'appel** puis la place des arguments et des variables de la fonction — libérée au retour.
::

## 1. Qu'est-ce qu'une fonction

Une **fonction** associe **un nom à un bloc de code**. On peut ensuite **appeler** la fonction, par son nom, pour exécuter ce bloc — autant de fois qu'on veut, de n'importe où. On en a déjà utilisé deux : `printf` et `scanf`.

Une fonction peut accepter des **arguments** : des valeurs qu'on lui passe entre parenthèses, après son nom, et qu'elle utilise. `printf` reçoit une chaîne de format, puis les valeurs à afficher :

```c
printf("Bonjour %s tu as %d ans\n", nom, age);
```

Une fonction peut aussi **renvoyer une valeur**. L'appel se comporte alors comme une **expression** : il vaut ce que la fonction renvoie, et s'utilise partout où l'on mettrait une valeur.

```c
int longueur_bonjour = strlen("bonjour");    // 7, longueur d'une chaîne
float trois_puissance_quatre = pow(3, 4);    // 81, puissance
```

(`strlen` est fournie par `#include <string.h>`, `pow` par `#include <math.h>`.)

::exemple{id="f-ex-expression" titre="Un appel au milieu d'un calcul" pour="Lire un appel comme une valeur"}
```c
int n = strlen("chat") * 2 + 1;
```

On évalue d'abord l'appel : `strlen("chat")` vaut $4$. L'expression devient `4 * 2 + 1`, et `n` reçoit $9$. Un appel peut même servir d'argument à un autre appel : `printf("%d\n", strlen("chat"));` affiche `4`.
::

## 2. Déclaration et définition

Comme une variable, une fonction doit être **déclarée** avant d'être utilisée. On précise :

- le **type de la valeur renvoyée** ;
- le **nom** de la fonction ;
- les **types et noms des arguments**, entre parenthèses, séparés par des virgules.

```c
int strlen(char* text);          // comme la diapo ; le chapitre 4 expliquera le char*
double pow(double x, double y);  // double : un nombre à virgule, plus précis que float
```

Une fois déclarée, on **définit** son comportement : on écrit son code entre accolades. Le mot-clé **`return`** renvoie une valeur **et termine** la fonction.

```c
int add(int a, int b, int c) {
    return a + b + c;
}
```

Une fonction qui ne renvoie rien a le type de retour **`void`** (« vide ») ; on la quitte par `return;` ou en atteignant l'accolade fermante.

::exemple{id="f-ex-definir" titre="Écrire une fonction de bout en bout" pour="Le squelette de toute fonction à écrire"}
On veut une fonction `moyenne` qui reçoit deux entiers et renvoie leur moyenne à virgule.

1. **Ce qu'elle reçoit** : deux `int`, nommés `a` et `b`.
2. **Ce qu'elle renvoie** : un `float`.
3. **Le calcul** : `(a + b) / 2.0` — le `2.0` évite la division entière.

```c
float moyenne(int a, int b) {
    return (a + b) / 2.0;
}

int main() {
    printf("%f\n", moyenne(12, 15));   // 13.500000
}
```

La fonction est écrite **avant** `main`, qui l'utilise : le compilateur lit le fichier de haut en bas.
::

:::qcm{titre="Contrôle express — déclarer" icone="i-lucide-circle-check-big" compact}

#c

::

```c
int signe(int x) {
    if (x < 0) {

    }

```

$1$

#c
$-1$

## 3. Les arguments sont des copies

Les arguments d'une fonction sont des **variables qui n'existent que dans le code de celle-ci**. Une variable de `main` n'existe que dans `main`, un argument de `triple` que dans `triple` — même s'ils portent le même nom.

```c
int triple(int a) {
    return a + a + a;
}

int main() {
    int b = 5;
    printf("%d\n", triple(b));   // 15
}
```

Lors de l'appel, la **valeur** passée est **copiée** dans l'argument. Modifier l'argument modifie la copie, jamais l'original : **une fonction ne peut pas modifier une variable extérieure par ses arguments**. (Le chapitre 4 montrera comment y arriver, avec un pointeur.)

::exemple{id="f-ex-copie" titre="La fonction ajoute ne touche pas à b" pour="Prédire ce que devient une variable passée à une fonction"}
```c
int ajoute(int a) {
    a = 6;
    return a + 5;
}

int main() {
    int b = 5;
    int c = ajoute(b);
    printf("%d %d\n", b, c);
}
```

À l'appel, $5$ est **copié** dans `a`. La fonction écrase **sa copie** avec $6$ et renvoie $11$. `b` n'a jamais été touché. Sortie : `5 11`.
::

:::qcm{titre="Contrôle express — la copie" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="b" cours="f-c-copie"}
```c
void remise_a_zero(int x) {
    x = 0;
}

int main() {
    int n = 42;
    remise_a_zero(n);
    printf("%d\n", n);
}
```

Qu'affiche ce programme ?

#a
`0`

#b
`42`

#c
Une valeur indéterminée

#d
Rien : le programme ne compile pas.

#indice
`x` est-il `n`, ou une copie de `n` ?

#solution
$42$ est copié dans `x` ; la fonction met **sa copie** à $0$, puis disparaît. `n` vaut toujours **`42`**.

**Les distracteurs :** **a** croit que l'argument est la variable elle-même ; **c** croit que l'appel abîme `n` ; **d** — le code est correct, il ne fait juste pas ce que son nom promet.
::

::qcm-question{label="2." bonne="c" cours="f-c-copie"}
```c
int f(int n) {
    n = n * 2;
    return n + 1;
}
```

Après `int n = 3; int m = f(n);`, que valent `n` et `m` dans `main` ?

#a
`n = 6`, `m = 7`

#b
`n = 3`, `m = 4`

#c
`n = 3`, `m = 7`

#d
`n = 6`, `m = 4`

#indice
Deux variables s'appellent `n` : celle de `main` et l'argument de `f`. Lesquelles change-t-on ?

#solution
L'argument `n` de `f` reçoit une copie, $3$, passe à $6$, et `f` renvoie $7$. Le `n` de `main` reste $3$ : $\boxed{n = 3,\ m = 7}$.

**Les distracteurs :** **a** confond les deux `n` ; **b** renvoie `n + 1` sans le doubler ; **d** mélange les deux erreurs.
::
:::

## 4. Les variables statiques

Une variable déclarée dans une fonction disparaît à la fin de chaque appel. Une variable **statique**, elle, **existe pendant toute la durée du programme** : elle **garde sa valeur** d'un appel à l'autre. On la déclare avec le mot-clé **`static`** devant le type.

Son **initialisation ne s'exécute qu'au premier appel** :

```c
static char c = 'k';   // cette ligne n'est exécutée qu'au premier appel
```

::exemple{id="f-ex-static" titre="Deux appels identiques, deux résultats" pour="Suivre une variable statique d'appel en appel"}
```c
int fonc(int a) {
    static char c = 7;
    c++;
    return a + c;
}

int main() {
    printf("%d\n", fonc(3));
    printf("%d\n", fonc(3));
}
```

| Appel | `c` avant `c++` | `c` après | Renvoie |
|---|---|---|---|
| 1ᵉʳ | 7 (initialisé) | 8 | $3 + 8 = 11$ |
| 2ᵉ | 8 (gardé) | 9 | $3 + 9 = 12$ |

Sortie : `11` puis `12`. Sans `static`, `c` repartirait de $7$ à chaque appel, et les deux lignes afficheraient `11`.
::

:::qcm{titre="Contrôle express — static" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="d" cours="f-c-static"}
```c
int compteur() {
    static int n = 0;
    n++;
    return n;
}
```

Que renvoie le **troisième** appel à `compteur()` ?

#a
$1$

#b
$0$

#c
$4$

#d
$3$

#indice
L'initialisation `n = 0` est-elle refaite à chaque appel ?

#solution
`n` est initialisé à $0$ au premier appel seulement, puis gardé : les appels renvoient $1$, $2$, $\boxed{3}$.

**Les distracteurs :** **a** réinitialise `n` à chaque appel, comme une variable ordinaire ; **b** renvoie la valeur avant le `n++` ; **c** compte un appel de trop.
::

::qcm-question{label="2." bonne="a" cours="f-c-static"}
Quelle phrase décrit une variable `static` déclarée dans une fonction ?

#a
Elle existe pendant tout le programme, et son initialisation n'est exécutée qu'au premier appel.

#b
Elle ne peut jamais changer de valeur.

#c
Elle est partagée avec la fonction `main`, qui peut la lire par son nom.

#d
Elle est réinitialisée à chaque appel, mais plus vite.

#indice
Le cours dit deux choses : sur sa durée de vie, et sur son initialisation.

#solution
**a** : elle vit pendant tout le programme et n'est initialisée qu'une fois, au premier appel.

**Les distracteurs :** **b** confond `static` et constante ; **c** — elle reste invisible hors de sa fonction : seule sa durée de vie change ; **d** est l'inverse de ce qu'elle fait.
::
:::

## 5. Mémoire et fonctions

Quand on appelle une fonction, un espace mémoire est réservé **à la suite** de celui de la fonction courante, **le temps de son exécution**. Il contient :

1. d'abord, le **contexte d'appel** : les informations qui permettront de **reprendre** le programme dans son état d'avant l'appel (où en était l'appelant, où était sa mémoire) ;
2. puis la place des **arguments** et des **variables** de la fonction appelée.

Au `return`, la valeur renvoyée est rangée chez l'appelant, et **tout cet espace est libéré** : un appel suivant réutilisera les mêmes octets.

::exemple{id="f-ex-pile" titre="Un appel, octet par octet" pour="Dessiner la mémoire d'un programme à fonctions"}
Le programme de la diapo, avec `int` sur 2 octets, `char` sur 1, et un contexte d'appel sur 4 :

```c
int fonc(int a) {
    char c = 7;
    return a + c;
}

int main() {
    int b = 5;
    int a = fonc(b + 1);
    affiche(a + 1);
}
```

| Octets | Ce qu'ils contiennent | Valeur |
|---|---|---|
| 1–2 | `b` de `main` | 5 |
| 3–4 | `a` de `main` | ?? puis **13** |
| 5–8 | contexte d'appel de `fonc` | — |
| 9–10 | argument `a` de `fonc` | 6 |
| 11 | `c` de `fonc` | 7 |

- `main` réserve `b` (5) et `a` ;
- l'appel `fonc(b + 1)` réserve, à la suite, le contexte d'appel, puis l'argument `a` de `fonc`, qui reçoit la **copie** $6$ ; puis `c` reçoit $7$ ;
- `return a + c` range $13$ dans le `a` **de `main`** — deux variables `a` cohabitent, chacune dans sa fonction — et libère les octets 5 à 11 ;
- l'appel `affiche(a + 1)` réutilise ces octets : son contexte d'appel prend les octets 5 à 8, et son argument, $14$, les octets 9–10.
::

:::qcm{titre="Contrôle express — la mémoire d'un appel" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="c" cours="f-c-memoire"}
Avec `int` sur 2 octets et un contexte d'appel sur 4, `main` range `b` dans les octets 1–2 et `a` dans les octets 3–4 :

```c
int fonc(int a) {
    char c = 7;
    return a + c;
}

int main() {
    int b = 5;
    int a = fonc(b + 1);
    affiche(a + 1);
}
```

Que contiennent les octets 9–10 pendant l'appel à `affiche(a + 1)` ?

#a
$6$, l'argument de `fonc`

#b
$13$

#c
$14$

#d
Rien : `affiche` réserve sa mémoire ailleurs.

#indice
La mémoire de `fonc` a été libérée au `return`. Où se place le nouvel appel ?

#solution
Le nouvel appel se place **à la suite de `main`**, comme le précédent : son contexte prend les octets 5–8 et son argument, `a + 1` $= \boxed{14}$, les octets 9–10.

**Les distracteurs :** **a** croit que la mémoire de `fonc` est encore réservée ; **b** est la valeur de `a`, pas de l'argument `a + 1` ; **d** — chaque appel se place à la suite de la fonction courante.
::

::qcm-question{label="2." bonne="b" cours="f-c-memoire"}
À quoi sert le **contexte d'appel** réservé au début de chaque appel ?

#a
À stocker la valeur renvoyée par la fonction.

#b
À pouvoir reprendre le programme, dans l'état d'avant l'appel, une fois la fonction terminée.

#c
À garder les variables `static` de la fonction.

#d
À copier toutes les variables de l'appelant.

#indice
Qu'est-ce que le programme doit savoir quand la fonction se termine ?

#solution
Il contient de quoi **reprendre le programme dans son état d'avant l'appel** : où continuer, où se trouve la mémoire de l'appelant. Réponse **b**.

**Les distracteurs :** **a** — la valeur renvoyée est rangée chez l'appelant ; **c** — une variable `static` vit pendant tout le programme, pas dans la mémoire d'un appel ; **d** — l'appelant garde ses variables là où elles sont.
::
:::

::extrait-cours{id="f-c-fonction" titre="Fonction et appel" source="/cours/a1/mise-a-niveau-c/fonctions/cours#_1-quest-ce-quune-fonction"}
Une fonction associe un nom à un bloc de code ; l'appeler l'exécute. Elle peut recevoir des **arguments** et **renvoyer** une valeur : l'appel est alors une **expression** qui vaut cette valeur. `strlen("abc")` vaut $3$ (sans le zéro final), `pow(3, 4)` vaut $81$.
::

::extrait-cours{id="f-c-declaration" titre="Déclarer et définir une fonction" source="/cours/a1/mise-a-niveau-c/fonctions/cours#_2-déclaration-et-définition"}
```c
type_retour nom(type1 arg1, type2 arg2) {
    …
    return valeur;
}
```

`return` renvoie la valeur **et termine** la fonction. `void` : ne renvoie rien. Écrire la fonction avant `main`, qui l'utilise.
::

::extrait-cours{id="f-c-copie" titre="Arguments copiés" source="/cours/a1/mise-a-niveau-c/fonctions/cours#_3-les-arguments-sont-des-copies"}
À l'appel, chaque valeur passée est **copiée** dans l'argument, variable propre à la fonction. Modifier l'argument ne modifie jamais la variable de l'appelant, même si elle porte le même nom.
::

::extrait-cours{id="f-c-static" titre="Variable statique" source="/cours/a1/mise-a-niveau-c/fonctions/cours#_4-les-variables-statiques"}
`static type nom = valeur;` dans une fonction : la variable existe pendant **tout le programme**, l'initialisation n'est faite **qu'au premier appel**, et la valeur est **gardée** d'un appel à l'autre.
::

::extrait-cours{id="f-c-memoire" titre="La mémoire d'un appel" source="/cours/a1/mise-a-niveau-c/fonctions/cours#_5-mémoire-et-fonctions"}
Un appel réserve, **à la suite** de la mémoire de l'appelant : le **contexte d'appel** (de quoi reprendre l'appelant), puis les **arguments** (copies) et les **variables** de la fonction. Au `return`, la valeur est rangée chez l'appelant et tout cet espace est **libéré** — le prochain appel réutilise les mêmes octets.
::
