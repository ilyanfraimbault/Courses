::rappel{titre="La boîte à outils du chapitre"}
- Chaque octet de la mémoire a une **adresse**, notée en hexadécimal : `0xff150`.
- Un **pointeur** est une variable qui contient une adresse : `int* p;` pointe vers un `int`.
- `&x` donne l'**adresse** de `x` ; `*p` donne la **valeur pointée** par `p`, et `*p = 4;` écrit à cette adresse.
- `printf("%p", p);` affiche une adresse.
- Passer `&x` à une fonction lui permet de **modifier** `x`, ou de **renvoyer plusieurs valeurs**.
- `p + 1` avance de **la taille du type pointé** : 2 octets pour un `int*` dans le cours, 1 pour un `char*`.
- Un tableau **est** un pointeur vers sa première case : `t[i]` est traduit en `*(t + i)`.
- Les variables d'une fonction vivent sur la **pile**, libérées à la fin de l'appel. `malloc(n)` réserve $n$ octets sur le **tas**, jusqu'à ce qu'on appelle **`free`**.
- `sizeof(type)` donne la taille d'un type : `malloc(9 * sizeof(float))`.
- Perdre le dernier pointeur vers une zone de `malloc` sans l'avoir libérée : **fuite mémoire**.
::

## 1. Adresses et pointeurs

Dans la mémoire, **chaque octet est identifié par une adresse**, un numéro écrit en hexadécimal. Les tableaux mémoire de ce chapitre portent donc des adresses au lieu de « Octet 1, Octet 2 ».

On peut créer des variables qui **contiennent une adresse** : on les appelle des **pointeurs**. Pour déclarer un pointeur, on ajoute une **étoile** après le type de ce vers quoi il pointe :

```c
int i;        // i est un int
int* iptr;    // iptr est un pointeur vers un int
char* cptr;   // cptr est un pointeur vers un char
```

Pour **récupérer l'adresse** d'une variable, on utilise l'opérateur **`&`** :

```c
int* iptr = &i;   // iptr contient l'adresse de i
```

C'est le `&` qu'on écrivait déjà dans `scanf("%d", &n)` : `scanf` reçoit l'adresse de `n`, pour savoir où écrire.

::exemple{id="p-ex-pointeur" titre="Deux variables et deux pointeurs dans la mémoire" pour="Dessiner un pointeur : il contient une adresse"}
Dans le cours, un `int` occupe 2 octets, un `char` 1, et **un pointeur 4**, quel que soit son type :

```c
int i = 5;
char a = 'a';
int* iptr = &i;
char* aptr = &a;
```

| Variable | Valeur | Adresses |
|---|---|---|
| `i` | 5 | `0xff150` – `0xff151` |
| `a` | 97 | `0xff152` |
| `iptr` | `0xff150` | `0xff153` – `0xff156` |
| `aptr` | `0xff152` | `0xff157` – `0xff15a` |

L'adresse d'une variable sur plusieurs octets est celle de son **premier** octet : `&i` vaut `0xff150`. Un pointeur occupe la même place qu'il pointe vers un `char` ou vers un `int` : il contient toujours une adresse.
::

## 2. Utiliser un pointeur

À partir d'un pointeur, l'opérateur **`*`** (devant le pointeur) accède à la **valeur vers laquelle il pointe** — pour la lire, ou pour y écrire :

```c
int* iptr = &i;   // iptr pointe vers i
int j = *iptr;    // j reçoit la valeur pointée : celle de i
*iptr = 7;        // écrit 7 à l'adresse contenue dans iptr : i vaut 7
```

On affiche une adresse avec le format **`%p`** :

```c
printf("l'adresse de i est %p et sa valeur est %d\n", iptr, *iptr);
```

Attention aux deux sens de l'étoile : **dans une déclaration**, `int* p` dit que `p` est un pointeur ; **dans une expression**, `*p` désigne la valeur pointée.

Un pointeur permet de :

- créer une fonction qui **modifie une variable extérieure** ;
- créer une fonction qui **renvoie plusieurs valeurs** ;
- accéder à de la mémoire **hors de la pile de fonctions** ;
- utiliser des **tableaux de taille dynamique** ;
- **maîtriser précisément** l'usage de la mémoire.

::exemple{id="p-ex-etoile" titre="Lire et écrire à travers un pointeur" pour="Distinguer p, *p et &x"}
```c
int x = 10;
int* p = &x;
*p = *p + 5;
int y = *p * 2;
```

- `p` contient l'adresse de `x` ;
- `*p = *p + 5` lit la valeur pointée ($10$) et écrit $15$ **dans `x`** — sans jamais écrire son nom ;
- `y` reçoit $15 \times 2 = 30$.

Les trois écritures à ne pas confondre : `p` (une adresse), `*p` (la valeur à cette adresse, ici `x`), `&x` (l'adresse de `x`, ici la valeur de `p`).
::

:::qcm{titre="Contrôle express — l'étoile" icone="i-lucide-circle-check-big" compact}


::

::qcm-question{label="2." bonne="d" cours="p-c-etoile"}

## 3. Modifier des variables depuis une fonction

Une fonction reçoit des **copies** (chapitre 3). Mais si on lui passe l'**adresse** d'une variable, elle peut écrire à cette adresse — donc modifier la variable de l'appelant.

```c
void set_to_n(int n, int* a, int* b, int* c) {
    *a = n;   // écrit n à l'adresse vers laquelle pointe a
    *b = n;
    *c = n;
}

int main() {
    int a, b, c;
    set_to_n(5, &a, &b, &c);   // on passe les adresses de a, b et c
    printf("%d, %d, %d\n", a, b, c);   // 5, 5, 5
}
```

Le pointeur est toujours copié — mais la copie d'une adresse **pointe au même endroit**.

C'est aussi le moyen de **renvoyer plusieurs valeurs** : `return` n'en renvoie qu'une, alors la fonction écrit les autres aux adresses qu'on lui donne.

::exemple{id="p-ex-plusieurs" titre="Une fonction qui renvoie quotient et reste" pour="Écrire une fonction à plusieurs résultats"}
```c
void division_avec_reste(int a, int b, int* resultat, int* reste) {
    *resultat = a / b;
    *reste = a % b;
}

int main() {
    int resultat, reste;
    division_avec_reste(35, 8, &resultat, &reste);
    printf("35/8 = %d reste %d\n", resultat, reste);   // 35/8 = 4 reste 3
}
```

`main` réserve `resultat` et `reste` sans valeur, puis passe leurs **adresses**. La fonction écrit $4$ à la première et $3$ à la seconde. La fonction est `void` : ses résultats passent par les pointeurs.
::

## 4. L'arithmétique de pointeurs

**Additionner un nombre à un pointeur le fait avancer dans la mémoire.** Il n'avance pas d'un octet mais de **la taille du type vers lequel il pointe** : ajouter $1$ à un `int*` le déplace d'un `int` — 2 octets avec les conventions du cours, 4 sur un PC ; ajouter $1$ à un `char*` le déplace d'un octet.

En général, `p + k` vaut l'adresse de `p` augmentée de $k \times$ `sizeof(*p)` octets.

::exemple{id="p-ex-arithmetique" titre="Atteindre j à partir de l'adresse de i" pour="Calculer l'adresse de p + k"}
```c
int i = 5;
int j;
int* iptr = &i;
int* jptr = iptr + 1;
*jptr = 4;
```

| Variable | Valeur | Adresses |
|---|---|---|
| `i` | 5 | `0xff150` – `0xff151` |
| `j` | ~~??~~ → **4** | `0xff152` – `0xff153` |
| `iptr` | `0xff150` | `0xff154` – `0xff157` |
| `jptr` | `0xff152` | `0xff158` – `0xff15b` |

`iptr + 1` avance de la taille d'un `int`, 2 octets : `0xff150 + 2 = 0xff152`, qui est justement l'adresse de `j`. `*jptr = 4` écrit donc dans `j`, sans jamais le nommer.

(La diapo écrit « si un int occupe 4 octets, ajouter 1 le déplacera de quatre cases », mais son tableau prend un `int` de 2 octets : c'est la même règle.)
::

:::qcm{titre="Contrôle express — p + k" icone="i-lucide-circle-check-big" compact}

::

## 5. Tableaux et pointeurs

**Un tableau est un pointeur vers son premier élément.** Accéder à l'élément `n` revient à additionner `n` à ce pointeur, puis à prendre la valeur pointée. Le compilateur traduit d'ailleurs l'un en l'autre :

```c
int tab[4];
tab[2] = 0;       // cette ligne
*(tab + 2) = 0;   // est transformée en celle-ci par le compilateur
```

Deux conséquences, déjà rencontrées :

- `scanf("%s", tab)` n'a pas besoin de `&` : `tab` est **déjà** une adresse ;
- une fonction qui reçoit un tableau reçoit en fait **l'adresse de sa première case** : `int longueur(char s[])` et `int longueur(char* s)` sont la même chose — d'où le `char*` de `strlen`. Et une fonction **peut** modifier les cases d'un tableau qu'on lui passe : elle écrit à l'adresse de l'appelant.

À l'inverse, un pointeur s'utilise avec des crochets : si `p` pointe dans un tableau, `p[k]` est `*(p + k)`.

::exemple{id="p-ex-tableau" titre="Un pointeur au milieu d'un tableau" pour="Traduire des crochets en arithmétique, et retour"}
```c
int t[4] = {10, 20, 30, 40};
int* p = t + 1;
*(p + 2) = 7;
p[0] = p[1] + 1;
```

- `p` pointe vers `t[1]` ;
- `*(p + 2)` est la case deux plus loin, `t[3]` : elle reçoit $7$ ;
- `p[0]` est `t[1]`, `p[1]` est `t[2]` : `t[1]` reçoit $30 + 1 = 31$.

Le tableau vaut $\{10, 31, 30, 7\}$.
::

:::qcm{titre="Contrôle express — crochets et étoiles" icone="i-lucide-circle-check-big" compact}

## 6. Pointeurs vers des fonctions

Une fonction aussi a une adresse : celle de la **première instruction** de son code. Le C permet de la ranger dans un **pointeur vers une fonction**, déclaré ainsi :

```c
type_de_retour (*nom_variable)(liste_des_types_des_arguments);

char (*f)(int);   // f pointe vers une fonction qui reçoit un int et renvoie un char
```

On l'appelle ensuite comme la fonction elle-même : `f(3)`. Cela permet de **choisir** une fonction à l'exécution, ou d'en passer une **en argument** à une autre.

::exemple{id="p-ex-fonctions" titre="Un tableau de pointeurs vers des fonctions" pour="Lire une déclaration de pointeur de fonction"}
L'exemple de la diapo :

```c
int stop_at_e(char* str) {
    int i = 0;
    for (int i = 0; str[i] != 'e'; i++);
    return i;
}

char* name = "Alice";
int (*f)(char*) = &strlen;    // l'esperluette est optionnelle
int (*g)(char*) = stop_at_e;
int (*tab[3])(char*) = {f, g, f};
for (int i = 0; i < 3; i++)
    printf("%d\n", tab[i](name));
```

- `f` contient un pointeur vers le code de `strlen` ;
- `g` un pointeur vers le code de `stop_at_e` ;
- `tab` est un **tableau de trois pointeurs vers des fonctions** ;
- la boucle appelle `strlen`, `stop_at_e`, `strlen` sur `"Alice"`.

La diapo annonce `5`, `4`, `5`. **Compilé, le programme affiche `5`, `0`, `5`** : dans `stop_at_e`, le `int i` du `for` déclare une **nouvelle** variable qui masque la première (chapitre 2, section 6). La boucle fait bien avancer *son* `i` jusqu'au `e`, mais `return i` renvoie l'autre, resté à $0$. Il fallait écrire `for (i = 0; …)`, et l'on obtient bien `4`.
::

## 7. La pile d'appels

On parle d'**allocation** quand on **réserve** une partie de la mémoire. Jusqu'ici, on réservait des octets en **déclarant des variables** :

```c
int i;     // des octets sont réservés pour i
char c;    // un octet est réservé pour c
int* ptr;  // des octets sont réservés pour ptr
```

Chaque fonction, quand elle est appelée, réserve **juste assez** de mémoire pour toutes ses variables et ses arguments. Ce calcul est fait **au moment de la compilation** : on parle d'**allocation statique**, et il est difficile de faire varier pendant l'exécution la mémoire qu'occupe une fonction.

Chaque appel alloue sa mémoire **à la suite** de celle de la fonction précédente, avec les informations qui permettent de **reprendre** l'appelant (adresse de la prochaine instruction, adresse de début de la fonction…). Cette partie de la mémoire, qui s'empile et se dépile au fil des appels, s'appelle **la pile** (*stack*).

::exemple{id="p-ex-pile" titre="Lire la pile d'un programme" pour="Savoir quelles fonctions sont en cours à un instant donné"}
```c
void f() { printf(…); }
void h() { f(); }
int main() { h(); }
```

Pendant l'affichage, la pile contient, du bas vers le haut : `main`, `h`, `f`, `printf`, puis les fonctions internes de `printf` (`putchar`, `putc`…). Chacune attend que celle du dessus se termine ; à chaque `return`, le sommet est libéré.
::

:::qcm{titre="Contrôle express — la pile" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="a" cours="p-c-pile"}

#b

#c

#d

#indice
Une fonction peut-elle se terminer avant celle qu'elle a appelée ?

#solution
Chaque fonction attend la fin de celle qu'elle a appelée : c'est **le sommet de la pile** — la dernière appelée — qui se termine en premier, comme une pile d'assiettes. Réponse **a**.

**Les distracteurs :** **b** inverse l'ordre — `main` se termine en dernier ; **c** — `h` attend `f` ; **d** — les retours se font un par un.
::

::qcm-question{label="2." bonne="c" cours="p-c-pile"}

#c

#solution
**À la compilation** : le compilateur connaît les types, donc la taille de chaque variable. C'est pour cela qu'il est difficile de faire varier cette mémoire pendant l'exécution.

**Les distracteurs :** **a** décrit l'allocation dynamique de la section suivante ; **b** — la mémoire d'une fonction n'est réservée que pendant son appel ; **d** — chaque type a sa taille.
::
:::

## 8. Allouer sur la pile, pendant l'exécution

On peut tout de même réserver sur la pile une taille calculée **pendant l'exécution**, de deux façons :

- les **tableaux de taille variable** (*Variable Length Arrays*, VLA) : `char tableau[n];` avec `n` connu seulement à l'exécution — la mémoire n'est réservée **que tant que la variable existe** ;
- la fonction **`alloca(n)`** : la mémoire est réservée **jusqu'à la fin de la fonction**.

```c
int n = rand();
if (n > 0) {
    char tableau[n];            // taille calculée pendant l'exécution
    char* tableau2 = alloca(n); // idem
}   // la mémoire de tableau n'est plus valide à partir d'ici
// celle de tableau2 reste valide jusqu'à la fin de la fonction
```

Ces méthodes ont des **désavantages** :

- le nombre d'instructions exécutées **augmente** ;
- la pile est **limitée** en taille (on la consulte avec `ulimit -a`), et une allocation imprévisible risque fort le **débordement de pile** (*stack overflow*) ;
- la mémoire n'est réservée **qu'un temps**, et le risque de l'utiliser après sa fin de validité augmente.

Pour ces raisons, les tableaux de taille variable sont **interdits ou fortement déconseillés** dans de nombreux projets, le noyau Linux par exemple.

::exemple{id="p-ex-vla" titre="Une adresse qui survit à sa mémoire" pour="Repérer l'usage d'une mémoire qui n'est plus valide"}
```c
char* p;
if (n > 0) {
    char tableau[n];
    p = tableau;
}
p[0] = 'x';   // erreur : tableau n'existe plus
```

`p` contient toujours une adresse, mais la mémoire à cette adresse a été rendue à l'accolade fermante : un autre appel peut l'avoir réutilisée. Le compilateur ne dit rien, et le programme écrit peut-être dans la variable d'un autre.
::

:::qcm{titre="Contrôle express — VLA et alloca" icone="i-lucide-circle-check-big" compact}

#b
Jusqu'à la fin de la fonction qui a appelé `alloca`.

#c

#d

#indice

#solution
**Jusqu'à la fin de la fonction** : c'est ce qui la distingue d'un tableau de taille variable, libéré à la fin de son bloc.

**Les distracteurs :** **a** décrit le VLA ; **c** et **d** décrivent `malloc` et le tas.
::

::qcm-question{label="2." bonne="d" cours="p-c-vla"}

**Les distracteurs :** **a** — ils compilent ; **b** — ils sont sur la pile, pas sur le tas ; **c** — on y écrit comme dans tout tableau.
::

## 9. Allouer sur le tas : malloc et sizeof

On peut réserver de la mémoire dans une **autre zone** du programme : le **tas** (*heap*). La fonction **`malloc`** (fournie par `#include <stdlib.h>`) :

- reçoit en argument le **nombre d'octets** à réserver ;
- renvoie un **pointeur vers le début** de la mémoire réservée ;
- la réserve **jusqu'à la fin du programme** — ou jusqu'à ce qu'on la libère (section 10). Elle survit donc à la fonction qui l'a demandée.

```c
int* a = malloc(8);   // 8 octets pour un tableau d'entiers
a[0] = 5;
a[1] = 4;
printf("%d\n", *(a + 1));   // affiche 4
```

Pour ne pas deviner les tailles, l'opérateur **`sizeof`** prend un type et renvoie le **nombre d'octets** qu'il occupe. On réserve ainsi un tableau de $n$ éléments quelle que soit leur taille :

```c
float* tab = malloc(9 * sizeof(float));   // assez de place pour 9 float
```

::exemple{id="p-ex-malloc" titre="Un tableau dont la taille est lue au clavier" pour="Le schéma type d'un malloc"}
```c
int n;
scanf("%d", &n);
int* t = malloc(n * sizeof(int));
for (int i = 0; i < n; i++) {
    t[i] = i * 10;
}
```

`t` est une variable de `main`, sur la pile : elle ne contient qu'une **adresse**. Les $n$ cases, elles, sont sur le **tas**. On les utilise avec des crochets, exactement comme un tableau — un tableau n'est qu'un pointeur vers sa première case.
::

:::qcm{titre="Contrôle express — malloc" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="c" cours="p-c-malloc"}

#a

#b
`int t = malloc(n * sizeof(int));`

#c
`int* t = malloc(n * sizeof(int));`

#d
`int* t = malloc(sizeof(n));`

#indice
`malloc` compte en **octets** et renvoie une **adresse**.

#solution
**`int* t = malloc(n * sizeof(int));`** : $n$ fois la taille d'un `int`, et le résultat est rangé dans un pointeur.

**Les distracteurs :** **a** réserve $n$ **octets**, pas $n$ entiers ; **b** range une adresse dans un `int` ; **d** réserve la taille de la variable `n`, un seul `int`.
::

::qcm-question{label="2." bonne="a" cours="p-c-malloc"}

#b

#c

#d

**Les distracteurs :** **b** et **c** décrivent la pile ; **d** — un pointeur se renvoie comme n'importe quelle valeur.
::
:::

## 10. Libérer la mémoire : free et la fuite mémoire

Si l'on ne fait rien, la mémoire réservée par `malloc` le reste **jusqu'à la fin de l'exécution**. Quand on ne s'en sert plus, il faut la **libérer à la main** avec **`free`**, en lui donnant le pointeur renvoyé par `malloc`. Tant qu'elle n'est pas libérée, cette mémoire **n'est utilisable nulle part ailleurs**.

```c
float* tab = malloc(9 * sizeof(float));   // on réserve
…
free(tab);                                // on libère
```

Si l'on **perd le pointeur** renvoyé par `malloc` — la variable qui le contenait disparaît, ou on écrit autre chose dedans —, la mémoire reste réservée mais **on ne peut plus la libérer**. C'est une **fuite mémoire**.

```c
if (1) {
    char* tab = malloc(9);   // 9 octets réservés
    …
}   // tab n'existe plus…
int a = 12;
free(??);   // … on ne peut plus libérer la mémoire : on n'a plus le pointeur
```

Un programme qui fuit dans une boucle finit par épuiser la mémoire.

::exemple{id="p-ex-fuite" titre="Une fuite à chaque tour" pour="Repérer le pointeur écrasé"}
```c
char* buf;
for (int i = 0; i < 1000; i++) {
    buf = malloc(100);
    …   // on utilise buf
}
free(buf);
```

À chaque tour, `buf` reçoit une **nouvelle** adresse et perd l'ancienne : les 999 premières zones ne peuvent plus être libérées, et le `free` final n'en libère qu'une. Soit $999 \times 100 = 99\,900$ octets perdus. Il fallait écrire `free(buf);` **à la fin de chaque tour**, dans la boucle.
::

:::qcm{titre="Contrôle express — free" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="d" cours="p-c-free"}
Lequel de ces morceaux de code provoque une **fuite mémoire** ?

#a
`int* p = malloc(8); free(p);`

#b
`int* p = malloc(8); int* q = p; free(q);`

#c
`int t[10]; t[0] = 1;`

#d
`int* p = malloc(8); p = malloc(16); free(p);`

#indice
Cherche une zone réservée par `malloc` dont plus aucune variable ne garde l'adresse.

#solution
En **d**, la seconde affectation écrase la seule copie de l'adresse des 8 premiers octets : ils ne pourront plus jamais être libérés.

**Les autres :** **a** libère ce qu'il a réservé ; **b** libère par une copie du pointeur, qui pointe au même endroit — c'est correct ; **c** n'utilise pas le tas, la mémoire de `t` est libérée avec la fonction.
::

::qcm-question{label="2." bonne="b" cours="p-c-free"}

#b

#d

::
:::

::extrait-cours{id="p-c-pointeurs" titre="Adresse et pointeur" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_1-adresses-et-pointeurs"}
Chaque octet a une **adresse** (`0xff150`) ; celle d'une variable est celle de son premier octet. Un **pointeur** contient une adresse : `int* p;` pointe vers un `int`. `&x` donne l'adresse de `x`. Dans le cours, un pointeur occupe 4 octets, quel que soit le type pointé.
::

::extrait-cours{id="p-c-etoile" titre="L'opérateur *" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_2-utiliser-un-pointeur"}
`*p` est la **valeur pointée** : `int j = *p;` la lit, `*p = 7;` y écrit. `p = q;` change le **pointeur**, pas la valeur. `%p` affiche une adresse. Dans une déclaration, `int* p` dit seulement que `p` est un pointeur.
::

::extrait-cours{id="p-c-fonctions" titre="Modifier une variable depuis une fonction" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_3-modifier-des-variables-depuis-une-fonction"}
On passe l'**adresse** (`f(&x)`), la fonction reçoit un pointeur (`void f(int* p)`) et écrit **à l'adresse** (`*p = …`). C'est aussi la façon de renvoyer plusieurs valeurs : `division_avec_reste(35, 8, &q, &r)`.
::

::extrait-cours{id="p-c-arithmetique" titre="L'arithmétique de pointeurs" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_4-larithmétique-de-pointeurs"}
`p + k` avance de $k \times$ la taille du type pointé : `int*` de 2 octets par unité dans le cours (4 sur un PC), `char*` de 1. Calcul en hexadécimal : `0xff160 + 12 = 0xff16c`.
::

::extrait-cours{id="p-c-tableaux" titre="Tableaux et pointeurs" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_5-tableaux-et-pointeurs"}
Un tableau est un pointeur vers sa première case : `t[i]` est `*(t + i)`, et `p[k]` est `*(p + k)`. Une fonction qui reçoit un tableau reçoit son adresse — `char s[]` et `char* s` sont équivalents — et peut donc en modifier les cases.
::

::extrait-cours{id="p-c-pfonctions" titre="Pointeurs vers des fonctions" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_6-pointeurs-vers-des-fonctions"}
`type_retour (*nom)(types des arguments);` — par exemple `int (*f)(char*) = strlen;` (le `&` est optionnel). On appelle `f(…)` comme la fonction. Les parenthèses autour de `*nom` sont indispensables : `int* f(int)` déclare une fonction qui renvoie un `int*`.
::

::extrait-cours{id="p-c-pile" titre="La pile d'appels" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_7-la-pile-dappels"}
Allocation **statique** : chaque fonction réserve, à l'appel, la place de ses variables et arguments, calculée à la compilation. Les appels s'empilent les uns à la suite des autres (la **pile**, *stack*), avec de quoi reprendre l'appelant ; le dernier appelé se termine le premier.
::

::extrait-cours{id="p-c-vla" titre="Allouer sur la pile à l'exécution" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_8-allouer-sur-la-pile-pendant-lexécution"}
**VLA** `char t[n];` : valide tant que la variable existe. **`alloca(n)`** : valide jusqu'à la fin de la fonction. Désavantages : plus d'instructions, pile limitée (`ulimit -a`) donc risque de **stack overflow**, et risque d'utiliser la mémoire après sa fin de validité. Interdits dans le noyau Linux.
::

::extrait-cours{id="p-c-malloc" titre="malloc et sizeof" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_9-allouer-sur-le-tas-malloc-et-sizeof"}
`malloc(nb_octets)` réserve sur le **tas** et renvoie un pointeur vers le début ; la zone survit à la fonction, jusqu'à la fin du programme ou un `free`. `sizeof(type)` donne la taille d'un type : `int* t = malloc(n * sizeof(int));` puis `t[i]` comme un tableau.
::

::extrait-cours{id="p-c-free" titre="free et la fuite mémoire" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_10-libérer-la-mémoire-free-et-la-fuite-mémoire"}
`free(p)` libère la zone dont `p` (ou une copie) contient l'adresse, renvoyée par `malloc`. Perdre la dernière copie de cette adresse sans l'avoir libérée — variable disparue, pointeur écrasé — c'est une **fuite mémoire** : la zone reste réservée et ne peut plus être libérée.
::
