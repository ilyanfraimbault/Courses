::rappel{titre="Comment se servir de cette fiche" icone="i-lucide-compass"}
Quatre paliers :

1. **Les adresses, case par case** — remplir le tableau mémoire. Un pointeur s'écrit par l'adresse qu'il contient, en hexadécimal (`0xff152`) ; une lettre entre apostrophes (`'B'`), sans connaître son code.
2. **Ce qu'affiche le programme** — taper la sortie.
3. **Fuites et adresses invalides** — repérer la mémoire perdue ou rendue.
4. **Écrire des fonctions** — à pointeurs, puis avec `malloc`. Écris, **compile et teste** avant d'ouvrir la solution. Pour `malloc`, ajoute `#include <stdlib.h>` et n'oublie pas le `free` dans ton `main`.

Les trois questions à se poser devant chaque ligne : **cette expression est-elle une adresse ou une valeur ? `*p` lit ou écrit quelle case ? De combien d'octets avance `p + 1` ?**

Conventions des tableaux mémoire, celles du cours : `char` 1 octet, `int` 2 octets, **pointeur 4 octets**, contexte d'appel 4 octets, variables rangées dans l'ordre de déclaration à partir de `0xff150`. En hexadécimal, après `0xff159` viennent `0xff15a` … `0xff15f`, puis `0xff160`.

::::exercice{titre="Palier 1 — Les adresses, case par case" theme="& et *, pointeur qui change de cible, arithmétique de pointeurs, appel avec des adresses" badge="★★☆☆☆" icone="i-lucide-memory-stick" entete="introduction"}
Commence par placer chaque variable à son adresse — c'est ce qui permet ensuite d'écrire la valeur d'un pointeur. Puis déroule les lignes une à une.

:::exo-question{label="1." cours="p-c-etoile"}
```c
int a = 7;
int b = 2;
int* p = &a;
*p = *p + b;
p = &b;
*p = 10;
```

::tableau-memoire
---
titre: Après la dernière ligne
cases:
  - variable: a
    adresse: '0xff150'
    octets: 2
    attendu: '9'
  - variable: b
    adresse: '0xff152'
    octets: 2
    attendu: '10'
  - variable: p
    adresse: '0xff154'
    octets: 4
    attendu: '0xff152'
---
::

#indice
`*p = …` écrit dans la case pointée ; `p = &b` change la cible sans rien écrire ailleurs. Quelle est l'adresse de `b` ?

#solution
| Ligne | `a` | `b` | `p` |
|---|---|---|---|
| `int a = 7;` | 7 | | |
| `int b = 2;` | 7 | 2 | |
| `int* p = &a;` | 7 | 2 | `0xff150` |
| `*p = *p + b;` | 9 | 2 | `0xff150` |
| `p = &b;` | 9 | 2 | `0xff152` |
| `*p = 10;` | 9 | 10 | `0xff152` |

À la fin : `a` = $\boxed{9}$, `b` = $\boxed{10}$, `p` = $\boxed{\texttt{0xff152}}$.
:::

:::exo-question{label="2." cours="p-c-arithmetique"}
```c
char s[4] = "abc";
char* p = s + 1;
*p = 'B';
p++;
*p = *p + 1;
```

::tableau-memoire
---
titre: Après la dernière ligne
cases:
  - variable: s[0]
    adresse: '0xff150'
    attendu: ["'a'", 'a', '97']
  - variable: s[1]
    adresse: '0xff151'
    attendu: ["'B'", 'B', '66']
  - variable: s[2]
    adresse: '0xff152'
    attendu: ["'d'", 'd', '100']
  - variable: s[3]
    adresse: '0xff153'
    attendu: '0'
  - variable: p
    adresse: '0xff154'
    octets: 4
    attendu: '0xff152'
---
::

#indice
`s` vaut `0xff150`. De combien d'octets avance un `char*` à chaque `+ 1` ou `++` ?

#solution
- `p = s + 1` : `0xff151`, l'adresse de `s[1]` ;
- `*p = 'B'` : `s[1]` vaut `'B'` ;
- `p++` : `p` avance d'**un** octet (un `char`) : `0xff152` ;
- `*p = *p + 1` : `s[2]` passe de `'c'` à la lettre suivante, `'d'`.

La chaîne vaut `"aBd"`, et `p` = $\boxed{\texttt{0xff152}}$.
:::

:::exo-question{label="3." cours="p-c-arithmetique"}
```c
int t[3] = {4, 5, 6};
int* p = t;
*(p + 2) = *p + p[1];
p = p + 1;
*p = 0;
```

::tableau-memoire
---
titre: Après la dernière ligne
cases:
  - variable: t[0]
    adresse: '0xff150'
    octets: 2
    attendu: '4'
  - variable: t[1]
    adresse: '0xff152'
    octets: 2
    attendu: '0'
  - variable: t[2]
    adresse: '0xff154'
    octets: 2
    attendu: '9'
  - variable: p
    adresse: '0xff156'
    octets: 4
    attendu: '0xff152'
---
::

#indice
Ici, chaque case occupe 2 octets : `p + 1` avance de 2. Traduis `*(p + 2)` et `p[1]` en indices de `t`.

#solution
- `p` vaut `t`, soit `0xff150` ;
- `*(p + 2)` est `t[2]`, `*p` est `t[0]`, `p[1]` est `t[1]` : `t[2]` reçoit $4 + 5 = 9$ ;
- `p = p + 1` avance d'un `int`, **2 octets** : `0xff152`, l'adresse de `t[1]` ;
- `*p = 0` écrit dans `t[1]`.

`t` vaut $\{4, 0, 9\}$, et `p` = $\boxed{\texttt{0xff152}}$.
:::

:::exo-question{label="4." cours="p-c-fonctions"}
```c
void echange(int* a, int* b) {
    int t = *a;
    *a = *b;
    *b = t;
}

int main() {
    int x = 3;
    int y = 8;
    echange(&x, &y);
}
```

Remplir la mémoire **juste avant l'accolade fermante d'`echange`**.

::tableau-memoire
---
titre: À la fin d'echange
cases:
  - variable: x (main)
    adresse: '0xff150'
    octets: 2
    attendu: '8'
  - variable: y (main)
    adresse: '0xff152'
    octets: 2
    attendu: '3'
  - variable: contexte d'appel
    adresse: '0xff154'
    octets: 4
    attendu: '—'
    donnee: true
  - variable: a (echange)
    adresse: '0xff158'
    octets: 4
    attendu: '0xff150'
  - variable: b (echange)
    adresse: '0xff15c'
    octets: 4
    attendu: '0xff152'
  - variable: t (echange)
    adresse: '0xff160'
    octets: 2
    attendu: '3'
---
::

#indice
Les arguments `a` et `b` sont des pointeurs : ils reçoivent des **copies des adresses** `&x` et `&y`. Écrire dans `*a`, c'est écrire où ?

#solution
- `a` reçoit `&x` = `0xff150`, `b` reçoit `&y` = `0xff152` ;
- `t` reçoit `*a`, la valeur de `x` : $3$ ;
- `*a = *b` écrit $8$ **dans `x`** ;
- `*b = t` écrit $3$ **dans `y`**.

Les arguments sont toujours des copies — mais des copies d'adresses, qui pointent vers les variables de `main`. Mémoire : `x` = $\boxed{8}$, `y` = $\boxed{3}$, `a` = `0xff150`, `b` = `0xff152`, `t` = $\boxed{3}$.
:::

::::exercice{titre="Palier 2 — Ce qu'affiche le programme" theme="Valeur contre adresse, tableau passé à une fonction, pointeurs de fonctions, malloc" badge="★★★☆☆" icone="i-lucide-terminal" entete="introduction"}
Avant de taper, demande-toi pour chaque argument : **la fonction reçoit-elle une valeur ou une adresse ?** Seule une adresse lui permet de modifier l'original.

:::exo-question{label="5." cours="p-c-fonctions"}
```c
void f(int a, int* b) {
    a = a + 1;
    *b = *b + 1;
}

int main() {
    int x = 1, y = 1;
    f(x, &y);
    printf("%d %d\n", x, y);
}
```

::champs-reponse
---
champs:
  - libelle: Ligne affichée
    attendu: '1 2'
---
::

#indice
`a` reçoit la valeur de `x`, `b` l'adresse de `y`. Laquelle des deux modifications atteint `main` ?

#solution
`a` est une copie de `x` : l'augmenter ne change pas `x`. `b` pointe vers `y` : `*b = *b + 1` augmente `y`. Sortie : **`1 2`**.
:::

:::exo-question{label="6." cours="p-c-tableaux"}
```c
void inc(int t[], int n) {
    for (int i = 0; i < n; i++) {
        t[i]++;
    }
}

int main() {
    int u[3] = {1, 2, 3};
    inc(u, 3);
    inc(u, 2);
    printf("%d %d %d\n", u[0], u[1], u[2]);
}
```

::champs-reponse
---
champs:
  - libelle: Ligne affichée
    attendu: '3 4 4'
---
::

#indice
Que reçoit vraiment `inc` quand on lui passe `u` ? Et le second appel touche-t-il les trois cases ?

#solution
`inc` reçoit l'**adresse** de `u[0]` : elle modifie les cases de `main`. Premier appel : $\{2, 3, 4\}$. Second appel, sur 2 cases seulement : $\{3, 4, 4\}$. Sortie : **`3 4 4`**.
:::

:::exo-question{label="7." cours="p-c-pfonctions"}
Le programme de la diapo, tel qu'il est écrit :

```c
int stop_at_e(char* str) {
    int i = 0;
    for (int i = 0; str[i] != 'e'; i++);
    return i;
}

int main() {
    char* name = "Alice";
    int (*f)(char*) = &strlen;
    int (*g)(char*) = stop_at_e;
    int (*tab[3])(char*) = {f, g, f};
    for (int i = 0; i < 3; i++)
        printf("%d\n", tab[i](name));
}
```

::champs-reponse
---
champs:
  - libelle: Ligne 1
    attendu: '5'
  - libelle: Ligne 2
    attendu: '0'
  - libelle: Ligne 3
    attendu: '5'
---
::

#indice
`tab` appelle `strlen`, puis `stop_at_e`, puis `strlen`. Dans `stop_at_e`, combien de variables s'appellent `i`, et laquelle est renvoyée ?

#solution
- `strlen("Alice")` vaut $5$ ;
- dans `stop_at_e`, le `for` déclare **son propre** `i`, qui avance jusqu'au `e` (indice $4$) puis disparaît ; `return i` renvoie le **premier** `i`, resté à $0$ ;
- `strlen` encore : $5$.

Sortie : **`5`**, **`0`**, **`5`** — et non `5`, `4`, `5` comme l'annonce la diapo. Pour obtenir $4$, il faut `for (i = 0; …)`, sans le `int`.
:::

:::exo-question{label="8." cours="p-c-malloc"}
```c
int* m = malloc(3 * sizeof(int));
m[0] = 1;
*(m + 1) = m[0] + 1;
m[2] = m[1] * 3;
printf("%d %d %d\n", m[0], m[1], m[2]);
free(m);
```

::champs-reponse
---
champs:
  - libelle: Ligne affichée
    attendu: '1 2 6'
---
::

#indice
Une zone de `malloc` s'utilise comme un tableau, avec des crochets ou avec `*(m + k)`.

#solution
`*(m + 1)` est `m[1]` : il reçoit $1 + 1 = 2$ ; `m[2]` reçoit $2 \times 3 = 6$. Sortie : **`1 2 6`**. Le `free` vient **après** le dernier usage.
:::

::::exercice{titre="Palier 3 — Fuites et adresses invalides" theme="Compter la mémoire perdue, renvoyer l'adresse d'une variable de la pile" badge="★★★☆☆" icone="i-lucide-shield-alert" entete="introduction"}
Pour chaque zone réservée, la question à se poser : **qui garde son adresse, et jusqu'à quand cette mémoire est-elle valide ?**

:::exo-question{label="9." cours="p-c-free" bonne="c"}
```c
int* p;
for (int i = 0; i < 10; i++) {
    p = malloc(4);
    *p = i;
}
free(p);
```

Combien d'octets réservés par `malloc` ne pourront jamais être libérés ?

#a
$0$

#b
$40$

#c
$36$

#d
$4$

#indice
Combien de zones sont réservées ? Combien d'adresses restent connues à la fin ?

#solution
Dix zones de 4 octets sont réservées. À chaque tour, `p` reçoit une nouvelle adresse et perd la précédente : seule la dernière est encore connue, et libérée. Les 9 autres sont perdues : $9 \times 4 = \boxed{36}$ octets.

**Les distracteurs :** **a** croit que le `free` final libère tout ; **b** oublie que la dernière zone est bien libérée ; **d** ne compte qu'une zone perdue.

La correction : `free(p);` à la fin de chaque tour, dans la boucle.
:::

:::exo-question{label="10." cours="p-c-pile" bonne="a"}
```c
int* cree_tableau() {
    int t[3] = {1, 2, 3};
    return t;
}
```

Qu'est-ce qui ne va pas dans cette fonction ?

#a
`t` vit sur la pile : sa mémoire est libérée au `return`, et l'appelant reçoit l'adresse d'une zone qui n'est plus valide.

#b
Une fonction ne peut pas renvoyer un pointeur.

#c
Il faut écrire `return &t;`.

#d
Rien : le tableau survit tant que l'appelant garde son adresse.

#indice
Où sont rangées les variables d'une fonction, et que devient leur mémoire au `return` ?

#solution
`t` est une variable de la fonction : elle vit sur la **pile**, libérée au `return`. L'appelant reçoit une adresse **invalide**, que le prochain appel de fonction écrasera. Réponse **a**. (`gcc` le signale d'ailleurs par un avertissement.)

La correction : réserver le tableau sur le **tas**, `int* t = malloc(3 * sizeof(int));`, le remplir, le renvoyer — et laisser l'appelant faire le `free`.

**Les distracteurs :** **b** — renvoyer un pointeur est permis, c'est ce que fait `malloc` ; **c** — `t` est déjà une adresse ; **d** — garder une adresse ne garde pas la mémoire réservée.
:::

::::exercice{titre="Palier 4 — Écrire des fonctions à pointeurs" theme="Échanger, minimum et maximum, copier et dupliquer avec malloc, parcourir par pointeurs" badge="★★★★☆" icone="i-lucide-code-xml" entete="introduction"}
Six fonctions. Pour chacune : **que reçoit-elle** (des valeurs ou des adresses ?), **que renvoie-t-elle** (par `return`, ou par des pointeurs ?), **qui libère** la mémoire qu'elle réserve. Écris un `main` qui l'appelle et affiche le résultat, compile, teste — puis compare.

:::exo-question{label="11." cours="p-c-fonctions"}
Écrire une fonction `echange` qui échange les valeurs de deux variables `int` de l'appelant, appelée par `echange(&x, &y);`.

#indice
Elle reçoit deux adresses. Pour échanger deux cases, il faut une variable temporaire.

#solution
```c
void echange(int* a, int* b) {
    int t = *a;
    *a = *b;
    *b = t;
}
```

Avec `x = 3` et `y = 8`, après `echange(&x, &y)`, `x` vaut $8$ et `y` vaut $3$. Sans pointeurs, `void echange(int a, int b)` échangerait deux copies, et `main` ne verrait rien.
:::

:::exo-question{label="12." cours="p-c-fonctions"}
Écrire une fonction `min_max` qui reçoit un tableau d'entiers et sa taille, et **renvoie à la fois** le minimum et le maximum, appelée par `min_max(t, n, &mn, &mx);`.

#indice
Deux résultats : ils passent par deux pointeurs. Initialise-les avec la première case.

#solution
```c
void min_max(int t[], int n, int* mn, int* mx) {
    *mn = t[0];
    *mx = t[0];
    for (int i = 1; i < n; i++) {
        if (t[i] < *mn) {
            *mn = t[i];
        }
        if (t[i] > *mx) {
            *mx = t[i];
        }
    }
}
```

Avec `{4, -2, 9, 0, 7}`, on obtient `mn` = $-2$ et `mx` = $9$. On lit et on écrit `*mn` et `*mx` comme des variables : ce sont les variables de l'appelant.
:::

:::exo-question{label="13." cours="p-c-malloc"}
Écrire une fonction `copie` qui reçoit un tableau d'entiers et sa taille, et renvoie un **nouveau** tableau, réservé sur le tas, qui contient les mêmes valeurs.

#indice
`malloc` réserve, une boucle recopie, `return` renvoie le pointeur. Pourquoi ne pas déclarer `int c[n];` dans la fonction ?

#solution
```c
int* copie(int t[], int n) {
    int* c = malloc(n * sizeof(int));
    for (int i = 0; i < n; i++) {
        c[i] = t[i];
    }
    return c;
}
```

Dans `main` :

```c
int* c = copie(t, 5);
…
free(c);
```

Un tableau déclaré dans la fonction serait libéré au `return` ; la mémoire du tas, elle, survit — et c'est à l'appelant de la libérer.
:::

:::exo-question{label="14." cours="p-c-malloc"}
Écrire une fonction `duplique` qui reçoit une chaîne et renvoie une **copie** de cette chaîne, réservée sur le tas.

#indice
Calcule d'abord la longueur. Combien d'octets faut-il réserver pour une chaîne de $n$ lettres ? N'oublie pas de copier le zéro final.

#solution
```c
char* duplique(char* s) {
    int n = 0;
    while (s[n] != 0) {
        n++;
    }
    char* d = malloc(n + 1);
    for (int i = 0; i <= n; i++) {
        d[i] = s[i];
    }
    return d;
}
```

- `n + 1` octets : les lettres et le zéro final (un `char` vaut 1 octet, `sizeof(char)` est inutile) ;
- `i <= n` copie aussi `s[n]`, le zéro final — sans lui, la copie ne serait pas une chaîne.

`duplique("chat")` renvoie une nouvelle chaîne `"chat"`, à libérer par l'appelant.
:::

:::exo-question{label="15." cours="p-c-malloc"}
Écrire une fonction `lire_tableau` qui reçoit un entier `n`, lit `n` entiers au clavier, et renvoie un tableau du tas qui les contient.

#indice
`scanf` a besoin de l'adresse de chaque case : `&t[i]`, ou `t + i`.

#solution
```c
int* lire_tableau(int n) {
    int* t = malloc(n * sizeof(int));
    for (int i = 0; i < n; i++) {
        scanf("%d", &t[i]);
    }
    return t;
}
```

`&t[i]` et `t + i` sont la même adresse. Avec l'entrée `7 8 9` et `n = 3`, le tableau vaut $\{7, 8, 9\}$. C'est là tout l'intérêt de `malloc` : la taille n'est connue qu'à l'exécution.
:::

:::exo-question{label="16." cours="p-c-arithmetique"}
Écrire une fonction `somme_ptr` qui reçoit deux pointeurs `debut` et `fin` vers des cases d'un même tableau d'entiers, et renvoie la somme des cases de `debut` (incluse) à `fin` (exclue), **sans utiliser de crochets ni d'indice**.

#indice
Un pointeur `p` part de `debut` et avance case par case avec `p++` ; deux pointeurs se comparent comme des adresses.

#solution
```c
int somme_ptr(int* debut, int* fin) {
    int s = 0;
    for (int* p = debut; p < fin; p++) {
        s += *p;
    }
    return s;
}
```

`p++` avance d'un `int` à chaque tour ; `p < fin` compare deux adresses. Avec `int t[5] = {1, 2, 3, 4, 5};`, `somme_ptr(t, t + 5)` vaut $15$ et `somme_ptr(t + 1, t + 3)` vaut $2 + 3 = 5$.
:::

`*p` est la **valeur pointée** : `*p = 7;` écrit dans la variable dont `p` contient l'adresse. `p = &b;` change la **cible**, sans écrire ailleurs. `&x` est l'adresse de `x`.
::

::extrait-cours{id="p-c-arithmetique" titre="L'arithmétique de pointeurs" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_4-larithmétique-de-pointeurs"}
`p + k` avance de $k \times$ la taille du type pointé : 1 octet pour un `char*`, 2 pour un `int*` dans le cours. `p++` avance d'une case. Deux pointeurs dans un même tableau se comparent comme des adresses.
::

::extrait-cours{id="p-c-fonctions" titre="Modifier une variable depuis une fonction" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_3-modifier-des-variables-depuis-une-fonction"}
On passe l'**adresse** (`f(&x)`), la fonction reçoit un pointeur (`int* p`) et écrit **à l'adresse** (`*p = …`). L'adresse est copiée, mais la copie pointe au même endroit. Plusieurs résultats : plusieurs pointeurs.
::

::extrait-cours{id="p-c-tableaux" titre="Tableaux et pointeurs" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_5-tableaux-et-pointeurs"}
Un tableau est un pointeur vers sa première case : `t[i]` est `*(t + i)`. Une fonction qui reçoit un tableau reçoit son adresse, et modifie les cases de l'appelant.
::

::extrait-cours{id="p-c-pfonctions" titre="Pointeurs vers des fonctions" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_6-pointeurs-vers-des-fonctions"}
`int (*f)(char*) = strlen;` puis `f(name)`. Dans l'exemple de la diapo, `stop_at_e` renvoie $0$ et non $4$ : le `int i` du `for` masque le premier `i`.

`int* t = malloc(n * sizeof(int));` réserve $n$ entiers sur le **tas** et renvoie l'adresse du début. La zone survit à la fonction qui l'a réservée — c'est l'appelant qui la libère. Pour une chaîne de $n$ lettres : `malloc(n + 1)`.
::

::extrait-cours{id="p-c-free" titre="free et la fuite mémoire" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_10-libérer-la-mémoire-free-et-la-fuite-mémoire"}
`free(p)` libère la zone renvoyée par `malloc`. Écraser ou perdre la dernière copie de son adresse avant le `free` : **fuite mémoire**. Dans une boucle qui réserve à chaque tour, libérer à chaque tour.
::

::extrait-cours{id="p-c-pile" titre="La pile d'appels" source="/cours/a1/mise-a-niveau-c/pointeurs-et-allocation/cours#_7-la-pile-dappels"}
Les variables d'une fonction vivent sur la **pile** et sont libérées à la fin de l'appel. Renvoyer leur adresse donne une adresse **invalide** : pour qu'une zone survive à la fonction, la réserver avec `malloc`.
::
