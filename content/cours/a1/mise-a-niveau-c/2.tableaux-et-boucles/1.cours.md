::rappel{titre="La boîte à outils du chapitre"}
- `int t[5];` réserve **5 cases consécutives** du type. Les cases vont de `t[0]` à `t[4]` : l'élément numéro $n$ est `t[n - 1]`.
- Une **chaîne** est un tableau de `char` **terminé par la valeur $0$** (pas le caractère `'0'`, qui vaut $48$). `"oui"` occupe **4** octets.
- `%s` affiche ou lit une chaîne ; avec `scanf`, **pas de `&`** devant le nom du tableau.
- `while (condition) { … }` répète tant que la condition est vraie.
- `for (depart; condition; instruction) { … }` : `depart` une fois, puis tant que `condition` est vraie, le corps **puis** `instruction`.
- Une variable n'existe qu'**entre les accolades** où elle est déclarée ; celle déclarée dans un `for` n'existe que dans ce `for`.
- Écrire ou lire **hors du tableau** ne fait aucune erreur visible : on touche la mémoire d'à côté. C'est le **dépassement de tampon** (*buffer overflow*).
::

## 1. Les tableaux

Un **tableau** est une liste de **taille finie** d'éléments **du même type**. Pour le déclarer, on donne le type des éléments, le nom, et le nombre d'éléments entre crochets :

```c
int notes[5];   // 5 entiers
char tab[4];    // 4 char
```

Les éléments sont rangés **les uns à la suite des autres** dans la mémoire. On accède à chacun par son **indice**, qui commence à **$0$** : le premier est `notes[0]`, le dernier `notes[4]`. L'élément numéro $n$ est donc `notes[n - 1]`.

Un indice peut être n'importe quelle expression entière : `notes[i]`, `notes[2 * k + 1]`.

::exemple{id="t-ex-tableau" titre="Un tableau de char dans la mémoire" pour="Suivre les cases d'un tableau"}
```c
char tab[4];
tab[0] = 1;
tab[1] = 2;
tab[2] = tab[0] + 2;
```

`char tab[4];` réserve les octets 1 à 4, sans rien y écrire. Puis :

| Case | `tab[0]` | `tab[1]` | `tab[2]` | `tab[3]` |
|---|---|---|---|---|
| Octet | 1 | 2 | 3 | 4 |
| Valeur | 1 | 2 | 3 | ?? |

`tab[3]` n'a jamais été écrit : il contient toujours `??`.
::

:::qcm{titre="Contrôle express — les indices" icone="i-lucide-circle-check-big" compact}

`t[11]`

#c

#indice

::

::

## 2. Les chaînes de caractères

En C, une **chaîne de caractères** est un **tableau de `char` qui se termine par la valeur zéro**. Ce zéro final marque la fin du texte : c'est lui qui permet de savoir où la chaîne s'arrête.

::rappel{titre="Attention : zéro, pas « 0 »" icone="i-lucide-triangle-alert"}
Il ne s'agit **pas** du caractère `'0'` (code ASCII $48$) mais de la **valeur** $0$, qu'on peut aussi écrire `'\0'`. Il faut donc **toujours réserver un octet de plus** que le nombre de lettres.
::

Le C permet d'écrire une chaîne entre **guillemets** : `"Bonjour"`. Le compilateur y ajoute le zéro final tout seul : `"Bonjour"` occupe $7 + 1 = 8$ octets.

::exemple{id="t-ex-chaine" titre="Une chaîne dans la mémoire" pour="Lire et modifier les lettres d'une chaîne"}
```c
char tab[4] = "oui";
tab[0]++;
```

| Case | `tab[0]` | `tab[1]` | `tab[2]` | `tab[3]` |
|---|---|---|---|---|
| Après la 1ʳᵉ ligne | 111 (`o`) | 117 (`u`) | 105 (`i`) | 0 |
| Après `tab[0]++` | 112 (`p`) | 117 (`u`) | 105 (`i`) | 0 |

La chaîne vaut désormais `"pui"`. Les quatre octets sont tous utilisés : trois lettres et le zéro.
::

:::qcm{titre="Contrôle express — le zéro final" icone="i-lucide-circle-check-big" compact}

#d
`char nom[10];`

#indice

#solution

**Les distracteurs :** **a** oublie le zéro final — la chaîne ne serait pas terminée ; **c** compte à partir de 0 comme pour un indice ; **d** convient aussi, mais ce n'est pas la plus **petite** taille.
::

::

## 3. Les chaînes avec printf et scanf

`printf` et `scanf` savent traiter une chaîne d'un coup, avec le format **`%s`** : `printf` affiche les caractères **jusqu'au zéro final**, `scanf` écrit ce qu'on tape **et ajoute le zéro**.

::rappel{titre="Pas de & devant un tableau" icone="i-lucide-triangle-alert"}
Pour lire une chaîne avec `scanf`, on **n'écrit pas de `&`** : `scanf("%s", tab);`. Le nom du tableau désigne déjà l'endroit où écrire — le chapitre 4 dira pourquoi : un tableau *est* l'adresse de sa première case.
::

`scanf("%s", …)` s'arrête au premier espace : il lit **un mot**.

::exemple{id="t-ex-scanf-chaine" titre="Lire un mot et le modifier" pour="Combiner %s et l'arithmétique sur les caractères"}
```c
char tab[4];
scanf("%s", tab);
tab[0] -= 32;
printf("%s\n", tab);
```

L'utilisateur tape `oui`. `scanf` écrit `o`, `u`, `i` et le zéro dans les quatre cases. `tab[0] -= 32` passe la lettre en majuscule — l'écart entre une minuscule et sa majuscule est le même pour toutes les lettres, inutile de savoir lequel : `tab[0] = tab[0] - 'a' + 'A'` fait pareil sans aucun nombre. Sortie : `Oui`.
::

:::qcm{titre="Contrôle express — %s" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="a" cours="t-c-printf-chaines"}
`char m[8] = "bonjour"; m[3] = 0;` Qu'affiche `printf("%s\n", m);` ?

#b
`bonjour`

#c
`bon0our`

#d
`bonour`

#indice
`printf` avec `%s` s'arrête au premier octet qui vaut $0$.

#solution
`m[3]` (le `j`) est remplacé par la valeur $0$ : la chaîne s'arrête là. Affiché : **`bon`**. Les lettres `o`, `u`, `r` sont toujours en mémoire, mais `printf` ne les atteint plus.

**Les distracteurs :** **b** ignore la modification ; **c** confond la valeur $0$ avec le caractère `'0'` ; **d** croit que la case est supprimée et le reste recollé.
::

::qcm-question{label="2." bonne="c" cours="t-c-printf-chaines"}

**Les distracteurs :** **a** ajoute un `&` que le cours interdit ; **b** ne lit qu'un seul caractère ; **d** lit un entier.
::

## 4. La boucle while

L'instruction `while` (« tant que ») **répète** un bloc de code **tant qu'une condition est vraie**. La condition est testée **avant chaque tour** : si elle est fausse dès le départ, le bloc ne s'exécute jamais.

```c
while (condition) {
    code
}
```

Il faut que le corps de la boucle **finisse par rendre la condition fausse** — sinon la boucle tourne sans fin.

::exemple{id="t-ex-while" titre="Parcourir une chaîne jusqu'au zéro" pour="Le parcours de chaîne type"}
```c
char tab[4] = "oui";
int i = 0;
while (tab[i] != 0) {
    tab[i]++;
    i++;
}
```

On tient un tableau tour par tour :

| Test | `tab[i] != 0` ? | Après le corps : `tab` | `i` |
|---|---|---|---|
| `i = 0` | `'o'` ≠ 0 : oui | `p`, `u`, `i`, 0 | 1 |
| `i = 1` | `'u'` ≠ 0 : oui | `p`, `v`, `i`, 0 | 2 |
| `i = 2` | `'i'` ≠ 0 : oui | `p`, `v`, `j`, 0 | 3 |
| `i = 3` | $0 \ne 0$ : **non** | on sort | 3 |

La chaîne vaut `"pvj"`, et `i` vaut $3$ — la longueur de la chaîne.
::

:::qcm{titre="Contrôle express — while" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="b" cours="t-c-while"}
`int n = 100, k = 0; while (n > 1) { n = n / 2; k++; }` Que vaut `k` à la fin ?

#a
$7$

#b
$6$

#c
$50$

#d
$5$

#indice
Suis `n` tour par tour, en divisions entières : $100, 50, 25, \dots$

#solution
$100 \to 50 \to 25 \to 12 \to 6 \to 3 \to 1$ : six divisions, donc $\boxed{6}$. Au septième test, $1 > 1$ est faux.

**Les distracteurs :** **a** compte une division de trop, comme si le test était `n >= 1` — la boucle ne finirait d'ailleurs jamais ; **c** est la valeur de `n` après un tour ; **d** en compte une de moins.
::

::qcm-question{label="2." bonne="d" cours="t-c-while"}
`int i = 10; while (i < 5) { i++; }` Combien de fois le corps s'exécute-t-il ?

#a
$5$

#b
$1$

#c
Une infinité

#d
$0$

#indice
Quand la condition est-elle testée pour la première fois ?

#solution
La condition est testée **avant** le premier tour : $10 < 5$ est faux, le corps s'exécute $\boxed{0}$ fois.

**Les distracteurs :** **b** croit que le corps passe une fois avant le test (c'est le `do … while`, hors du cours) ; **a** compte de 5 à 10 ; **c** croit que `i` ne pourra jamais devenir assez petit.
::
:::

## 5. La boucle for

La boucle `for` (« pour ») regroupe sur une ligne les trois morceaux d'une boucle qui compte :

```c
for (depart; condition; instruction) {
    code
}
```

- `depart` est exécuté **une seule fois**, au début ;
- tant que `condition` est vraie, on exécute `code`, **puis** `instruction`.

Elle équivaut donc à :

```c
depart;
while (condition) {
    code
    instruction;
}
```

La forme la plus courante parcourt un tableau : `for (int i = 0; i < 5; i++) { … }`.

::exemple{id="t-ex-for" titre="Une chaîne trop longue pour son tableau" pour="Comprendre pourquoi le zéro final compte"}
L'exemple de la diapo, qui tourne mal exprès :

```c
char tab[4] = "ouais";
for (int i = 0; tab[i] != 0; i++) {
    tab[i]++;
}
```

`"ouais"` demande 6 octets, le tableau n'en a que 4 : seuls `o`, `u`, `a`, `i` y sont copiés, **sans zéro final** (le compilateur prévient d'ailleurs par un avertissement). La boucle transforme `ouai` en `pvbj`, puis, pour `i = 4`, lit `tab[4]` — l'octet **après** le tableau. Ce qu'il contient, personne ne le sait : la boucle peut continuer et modifier la mémoire d'à côté jusqu'à rencontrer un $0$ par hasard. Dans la diapo, elle avance jusqu'à `i = 6` et écrit dans un octet `???`.

C'est la porte ouverte au dépassement de tampon de la section 7.
::

:::qcm{titre="Contrôle express — for" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="a" cours="t-c-for"}
Combien d'étoiles affiche `for (int i = 10; i > 0; i -= 3) printf("*");` ?

#a
$4$

#b
$3$

#c
$10$

#d
$5$

#indice
Liste les valeurs de `i` pour lesquelles la condition est vraie.

#solution
`i` prend les valeurs $10, 7, 4, 1$ — puis $-2$, qui arrête la boucle : $\boxed{4}$ étoiles.

**Les distracteurs :** **b** fait $10/3$ en division entière ; **c** compte de $10$ à $1$ de un en un ; **d** compte aussi le tour à $-2$, où la condition est déjà fausse.
::

::qcm-question{label="2." bonne="c" cours="t-c-for"}
Dans `for (A; B; C) { D }`, dans quel ordre s'exécutent les morceaux pour une boucle qui fait deux tours ?

#a
A, B, C, D, B, C, D, B

#b
A, D, C, B, D, C, B

#c
A, B, D, C, B, D, C, B

#d
A, B, D, B, D, C

#indice
`depart` une fois ; puis, tant que la condition est vraie : le corps, puis l'instruction. Et il faut bien un dernier test pour sortir.

#solution
A, puis à chaque tour B (vrai), D, C, et un dernier B (faux) qui fait sortir : **A, B, D, C, B, D, C, B**.

**Les distracteurs :** **a** exécute l'instruction avant le corps ; **b** saute le premier test ; **d** n'exécute l'instruction qu'une fois, à la fin.
::
:::

## 6. Durée de validité d'une variable

Une variable déclarée **entre deux accolades** n'existe **qu'entre ces deux accolades**. Une variable déclarée **entre les parenthèses d'un `for`** n'existe que **pour ce `for`**.

```c
int a;              // a existe pour toute la suite de main
if (a > 2) {
    int b = 1;      // b n'existe que dans le bloc du if
} else {
    int c = 3;      // c n'existe que dans le bloc du else
}
// ici, ni b ni c n'existent
```

Utiliser une variable hors de son bloc est une **erreur de compilation**. Pour garder la valeur d'un compteur après la boucle, on le déclare **avant** :

```c
int i;
for (i = 0; i < 10; i += 3) { }
printf("%d\n", i);   // affiche 12
```

::exemple{id="t-ex-portee" titre="Une variable masquée" pour="Repérer deux variables qui portent le même nom"}
```c
int i = 0;
for (int i = 0; i < 5; i++) { }
printf("%d\n", i);
```

Le `int i` du `for` déclare une **nouvelle** variable, qui **masque** la première pendant la boucle. Celle qu'on affiche après est l'ancienne, restée à $0$ : le programme affiche `0`. Ce piège revient au chapitre 4, dans un exemple de la diapo.
::

:::qcm{titre="Contrôle express — la portée" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="b" cours="t-c-portee"}
Que se passe-t-il à la compilation de ce code ?

```c
for (int k = 0; k < 3; k++) { }
printf("%d\n", k);
```

#a
Il compile et affiche `3`.

#b
Il ne compile pas : `k` n'existe plus après le `for`.

#c
Il compile et affiche `2`.

#d
Il compile et affiche une valeur indéterminée.

#indice
Où `k` est-il déclaré ?

#solution
`k` est déclaré dans les parenthèses du `for` : il n'existe que pour la boucle. Le `printf` utilise une variable inconnue : **le code ne compile pas**.

**Les distracteurs :** **a** serait juste si `k` était déclaré avant le `for` ; **c** confond la dernière valeur utilisée dans le corps et la valeur de sortie ; **d** suppose que la variable existe encore sans valeur.
::

::qcm-question{label="2." bonne="d" cours="t-c-portee"}
```c
int x = 1;
if (x > 0) {
    int x = 5;
    x++;
}
printf("%d\n", x);
```

Qu'affiche ce programme ?

#a
`6`

#b
`5`

#c
`2`

#d
`1`

#indice
Le `int x = 5;` du bloc crée-t-il une nouvelle variable ou modifie-t-il l'ancienne ?

#solution
Le bloc déclare un **nouveau** `x`, qui masque l'autre : c'est lui qui passe à $6$, puis disparaît à l'accolade fermante. Le `printf` voit le premier `x`, intact : **`1`**.

**Les distracteurs :** **a** croit qu'on a modifié le `x` de dehors ; **b** affiche la valeur initiale du `x` intérieur ; **c** applique le `x++` au `x` extérieur.
::
:::

## 7. Le dépassement de tampon

Écrire ou lire **hors des limites d'un tableau** ne provoque aucune erreur : le C ne vérifie rien, et l'on touche simplement **l'octet d'à côté**, qui appartient peut-être à une autre variable. C'est le **dépassement de tampon** (*buffer overflow*), une famille de failles de sécurité. Pour l'éviter, **il faut toujours contrôler les limites d'un tableau avant d'écrire dedans**.

`scanf`, par exemple, **ne vérifie pas** la taille du tableau avant d'y écrire ce que tape l'utilisateur.

Autre point : dans les exemples du cours, les variables sont rangées dans l'ordre de leur déclaration, pour simplifier. **Ce n'est pas toujours le cas** : le C n'impose aucun ordre, et le compilateur est libre de réorganiser les variables, pour la sécurité ou la performance.

::exemple{id="t-ex-overflow" titre="Un indice non vérifié écrase un code secret" pour="Voir concrètement ce que fait un débordement"}
```c
int main() {
    int code_secu = 24930;
    int modifie = 0;
    char str[4] = "oui";
    printf("Quel char modifier ?\n");
    scanf("%d", &modifie);
    str[modifie] += 1;
    printf("Chaine modifiée: %s\n", str);
}
```

Le compilateur a rangé `str` aux octets 1–4, `code_secu` aux octets 5–6 et `modifie` aux octets 7–8. L'utilisateur tape `3` : `str[3] += 1` change le **zéro final** en $1$. Plus rien n'arrête la chaîne : `printf` continue dans les octets de `code_secu`, dont les deux octets valent $97$ (`a`) et $98$ (`b`) — $24\,930 = 97 \times 256 + 98$. Il affiche quelque chose comme `oui?ab…` : **le code secret a fuité**. Avec `4` ou `5`, l'utilisateur **modifierait** le code.

La correction tient en un test :

```c
scanf("%d", &modifie);
if (modifie >= 0 && modifie < 3) {   // on vérifie que l'indice est dans la chaîne
    str[modifie] += 1;
}
```

(Sur un PC, les octets d'un `int` sont rangés de poids faible en premier : la fuite s'afficherait `ba` plutôt que `ab`. La diapo note aussi $24\,929$ dans la mémoire, coquille pour $24\,930$.)
::

Même quand le tableau se trouve tout au bout des variables, le débordement reste dangereux : la mémoire d'une fonction contient aussi l'**adresse de la prochaine instruction à exécuter**, le début de la mémoire de la fonction en cours, l'adresse de `printf` et `scanf`… Les écraser permet de détourner le programme.

:::qcm{titre="Contrôle express — le dépassement" icone="i-lucide-circle-check-big" compact}

::qcm-question{label="1." bonne="c" cours="t-c-overflow"}

#a

#b
Le programme s'arrête avec un message d'erreur.

#c

#d

#solution

**Les distracteurs :** **a** décrit un comportement prudent que `scanf("%s")` n'a pas ; **b** suppose une vérification qui n'existe pas en C ; **d** confond avec les listes de Python.
::

::qcm-question{label="2." bonne="a" cours="t-c-overflow"}
Un tableau `char str[4]` contient une chaîne de 3 lettres. Quel test protège `str[k] += 1;` ?

#a
`if (k >= 0 && k < 3)`

#b
`if (k <= 4)`

#c
`if (k < 4)`

#d
`if (k > 0 && k <= 3)`

#indice

#solution
Les lettres sont aux indices $0$, $1$, $2$ : **`k >= 0 && k < 3`**. On protège aussi le zéro final, dont la modification ferait fuiter la mémoire d'à côté.

**Les distracteurs :** **b** laisse passer `4`, hors du tableau, et les négatifs ; **c** laisse passer `3` (le zéro final) et les négatifs ; **d** refuse la première lettre et laisse passer le zéro final.
::

::extrait-cours{id="t-c-tableaux" titre="Les tableaux" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_1-les-tableaux"}
`type nom[N];` réserve $N$ cases **consécutives** du type (avec `int` sur 2 octets, `int t[6]` réserve 12 octets). Les indices vont de $0$ à $N - 1$ : l'élément numéro $n$ est `nom[n - 1]`. Une case jamais écrite contient `??`.
::

::extrait-cours{id="t-c-chaines" titre="Les chaînes de caractères" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_2-les-chaînes-de-caractères"}
Une chaîne est un tableau de `char` **terminé par la valeur $0$** (`'\0'`, pas `'0'` qui vaut $48$). `"Alice"` occupe $5 + 1 = 6$ octets : toujours réserver **un octet de plus** que le nombre de lettres.
::

::extrait-cours{id="t-c-printf-chaines" titre="%s dans printf et scanf" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_3-les-chaînes-avec-printf-et-scanf"}
`printf("%s", tab)` affiche jusqu'au premier octet nul. `scanf("%s", tab)` lit un mot, ajoute le zéro final, **sans `&`** devant le tableau — et sans vérifier sa taille.
::

::extrait-cours{id="t-c-while" titre="La boucle while" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_4-la-boucle-while"}
`while (condition) { code }` : la condition est testée **avant chaque tour** — fausse au départ, zéro tour. Le corps doit finir par la rendre fausse. Pour suivre une boucle, tenir un tableau : une ligne par test.
::

::extrait-cours{id="t-c-for" titre="La boucle for" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_5-la-boucle-for"}
`for (depart; condition; instruction) { code }` : `depart` une fois ; puis tant que `condition` est vraie, `code` **puis** `instruction`. Équivaut à `depart; while (condition) { code instruction; }`.
::

::extrait-cours{id="t-c-portee" titre="La durée de validité d'une variable" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_6-durée-de-validité-dune-variable"}
Une variable n'existe qu'entre les accolades où elle est déclarée ; celle déclarée dans les parenthèses d'un `for`, que dans ce `for`. Redéclarer un nom dans un bloc crée une **nouvelle** variable qui masque l'ancienne jusqu'à l'accolade fermante.
::

::extrait-cours{id="t-c-overflow" titre="Le dépassement de tampon" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_7-le-dépassement-de-tampon"}
Lire ou écrire hors d'un tableau ne fait **aucune erreur** : on touche la mémoire voisine (autres variables, adresse de retour…). `scanf("%s")` ne vérifie pas la taille. Toujours **tester les deux bornes** d'un indice avant d'écrire : `if (k >= 0 && k < N)`. Le compilateur range les variables dans l'ordre qu'il veut.
::
