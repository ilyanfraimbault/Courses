::rappel{titre="Comment se servir de cette fiche" icone="i-lucide-compass"}
Quatre paliers, dans l'ordre :

1. **La mémoire, case par case** — remplir le tableau mémoire une fois le programme terminé. Une lettre s'écrit entre apostrophes (`'p'`), sans connaître son code ; le zéro final s'écrit `0` ; une case jamais écrite, `??`.
2. **Ce qu'affiche le programme** — taper la sortie (les espaces ne comptent pas).
3. **Le débordement** — repérer ce qui sort du tableau.
4. **Écrire une boucle** — écris, **compile et teste** avant d'ouvrir la solution.

Pour suivre une boucle, la méthode est toujours la même : **un tableau avec une ligne par tour**, et dans chaque ligne la valeur du test et celle des variables.

Conventions des tableaux mémoire : `char` 1 octet, `int` 2 octets, variables rangées dans l'ordre de déclaration, cases d'un tableau consécutives.
::

::::exercice{titre="Palier 1 — La mémoire, case par case" theme="Cases d'un tableau, chaînes et zéro final, boucles qui écrivent" badge="★☆☆☆☆" icone="i-lucide-memory-stick" entete="introduction"}
Un tableau occupe des cases **consécutives** ; une chaîne s'arrête au **zéro final**. Pour chaque programme, la question à se poser : **quelles cases sont écrites, et lesquelles restent `??`** ?

:::exo-question{label="1." cours="t-c-tableaux"}
```c
char tab[5];
tab[0] = 3;
tab[1] = tab[0] * 2;
tab[3] = tab[1] - 1;
```

::tableau-memoire
---
titre: Après la dernière ligne
cases:
  - variable: tab[0]
    adresse: Octet 1
    attendu: '3'
  - variable: tab[1]
    adresse: Octet 2
    attendu: '6'
  - variable: tab[2]
    adresse: Octet 3
    attendu: ['??', '?']
  - variable: tab[3]
    adresse: Octet 4
    attendu: '5'
  - variable: tab[4]
    adresse: Octet 5
    attendu: ['??', '?']
---
::

#indice
`char tab[5];` réserve cinq octets sans rien y écrire. Repère les indices qu'aucune ligne n'écrit.

#solution
- `tab[0]` reçoit $3$ ;
- `tab[1]` reçoit $3 \times 2 = 6$ ;
- `tab[3]` reçoit $6 - 1 = 5$ ;
- `tab[2]` et `tab[4]` ne sont jamais écrits : **`??`**.

Mémoire finale : $\boxed{3,\ 6,\ ??,\ 5,\ ??}$.
:::

:::exo-question{label="2." cours="t-c-chaines"}
```c
char s[6] = "chat";
s[0] = s[0] - 'a' + 'A';
s[4] = '!';
```

::tableau-memoire
---
titre: Après la dernière ligne
cases:
  - variable: s[0]
    adresse: Octet 1
    attendu: ["'C'", 'C', '67']
  - variable: s[1]
    adresse: Octet 2
    attendu: ["'h'", 'h', '104']
  - variable: s[2]
    adresse: Octet 3
    attendu: ["'a'", 'a', '97']
  - variable: s[3]
    adresse: Octet 4
    attendu: ["'t'", 't', '116']
  - variable: s[4]
    adresse: Octet 5
    attendu: ["'!'", '!', '33']
  - variable: s[5]
    adresse: Octet 6
    attendu: ["'\\0'", '\0', '0']
---
::

#indice
Quand on initialise un tableau avec une chaîne plus courte que lui, que contiennent les cases restantes ?

#solution
`"chat"` remplit `s[0]` à `s[3]` et met le zéro final dans `s[4]`. Quand une chaîne initialise un tableau plus grand, **les cases restantes sont mises à zéro** : `s[5]` vaut $0$ aussi.

- `s[0]` : `'c' - 'a'` vaut $2$, et `'A' + 2` est `'C'` ;
- `s[4]` : l'ancien zéro final est remplacé par `'!'`.

La chaîne reste terminée, grâce à `s[5]` : elle vaut `"Chat!"`. Avec `char s[5]`, plus rien ne l'aurait terminée.

Mémoire : $\boxed{67,\ 104,\ 97,\ 116,\ 33,\ 0}$.
:::

:::exo-question{label="3." cours="t-c-for"}
```c
int t[4];
for (int i = 0; i < 4; i++) {
    t[i] = i * i;
}
```

::tableau-memoire
---
titre: Après la boucle
cases:
  - variable: t[0]
    adresse: Octet 1
    octets: 2
    attendu: '0'
  - variable: t[1]
    adresse: Octet 3
    octets: 2
    attendu: '1'
  - variable: t[2]
    adresse: Octet 5
    octets: 2
    attendu: '4'
  - variable: t[3]
    adresse: Octet 7
    octets: 2
    attendu: '9'
---
::

#indice
Quatre tours, `i` vaut $0$, $1$, $2$, $3$. Chaque case d'un tableau d'`int` occupe deux octets.

#solution
| Tour | `i` | Écrit |
|---|---|---|
| 1 | 0 | `t[0] = 0` |
| 2 | 1 | `t[1] = 1` |
| 3 | 2 | `t[2] = 4` |
| 4 | 3 | `t[3] = 9` |

Puis `i = 4` : $4 < 4$ est faux, on sort. Mémoire : $\boxed{0,\ 1,\ 4,\ 9}$, chaque valeur sur deux octets.
:::

:::exo-question{label="4." cours="t-c-while"}
```c
char s[4] = "abc";
int i = 0;
while (s[i] != 0) {
    s[i] = s[i] + 1;
    i++;
}
```

::tableau-memoire
---
titre: Après la boucle
cases:
  - variable: s[0]
    adresse: Octet 1
    attendu: ["'b'", 'b', '98']
  - variable: s[1]
    adresse: Octet 2
    attendu: ["'c'", 'c', '99']
  - variable: s[2]
    adresse: Octet 3
    attendu: ["'d'", 'd', '100']
  - variable: s[3]
    adresse: Octet 4
    attendu: '0'
  - variable: i
    adresse: Octet 5
    octets: 2
    attendu: '3'
---
::

#indice
Tiens un tableau : à chaque test, que vaut `s[i]` ? La boucle s'arrête **avant** de toucher au zéro final.

#solution
| Test | `s[i]` | Action | `i` après |
|---|---|---|---|
| `i = 0` | `'a'` ≠ 0 | `s[0]` devient `'b'` | 1 |
| `i = 1` | `'b'` ≠ 0 | `s[1]` devient `'c'` | 2 |
| `i = 2` | `'c'` ≠ 0 | `s[2]` devient `'d'` | 3 |
| `i = 3` | $0$ | on sort | 3 |

Le zéro final n'est pas modifié, et `i` vaut la longueur de la chaîne. Mémoire : $\boxed{98,\ 99,\ 100,\ 0}$ et `i` $= \boxed{3}$.
:::

::::exercice{titre="Palier 2 — Ce qu'affiche le programme" theme="Sommes, boucles imbriquées, %s et zéro final, point-virgule mal placé" badge="★★☆☆☆" icone="i-lucide-terminal" entete="introduction"}
Pour chaque programme, déroule les boucles sur une feuille, **tour par tour**, avant de taper la sortie.

:::exo-question{label="5." cours="t-c-for"}
```c
int s = 0;
for (int i = 1; i <= 5; i++) {
    s += i;
}
printf("%d\n", s);
```

::champs-reponse
---
champs:
  - libelle: Ligne affichée
    attendu: '15'
---
::

#indice
Quelles valeurs prend `i` ? `<=` inclut la borne.

#solution
`i` vaut $1, 2, 3, 4, 5$ ; `s` passe par $1, 3, 6, 10, 15$. Le programme affiche **`15`**.
:::

:::exo-question{label="6." cours="t-c-printf-chaines"}
```c
char m[8] = "bonjour";
m[3] = 0;
printf("%s|%c\n", m, m[4]);
```

::champs-reponse
---
champs:
  - libelle: Ligne affichée
    attendu: 'bon|o'
---
::

#indice
`%s` s'arrête au premier zéro. Mais `m[4]` a-t-il été effacé ?

#solution
`m[3] = 0` coupe la chaîne après `bon` : `%s` affiche `bon`. Les octets suivants sont intacts : `m[4]` contient toujours `'o'`, affiché par `%c`. Sortie : **`bon|o`**.
:::

:::exo-question{label="7." cours="t-c-for"}
```c
for (int i = 0; i < 3; i++) {
    for (int j = 0; j <= i; j++) {
        printf("*");
    }
    printf("\n");
}
```

::champs-reponse
---
champs:
  - libelle: Ligne 1
    attendu: '*'
  - libelle: Ligne 2
    attendu: '**'
  - libelle: Ligne 3
    attendu: '***'
---
::

#indice
Pour chaque valeur de `i`, combien de tours fait la boucle sur `j` ? Le saut de ligne est **après** la boucle intérieure.

#solution
| `i` | valeurs de `j` | étoiles |
|---|---|---|
| 0 | 0 | `*` |
| 1 | 0, 1 | `**` |
| 2 | 0, 1, 2 | `***` |

Un triangle : **`*`**, **`**`**, **`***`**.
:::

:::exo-question{label="8." cours="t-c-portee"}
```c
int i;
for (i = 0; i < 10; i += 3);
printf("%d\n", i);
```

::champs-reponse
---
champs:
  - libelle: Ligne affichée
    attendu: '12'
---
::

#indice
Le `;` juste après la parenthèse fermante du `for` est un corps de boucle **vide**. Quelle est la première valeur de `i` qui rend la condition fausse ?

#solution
La boucle ne fait rien d'autre que faire avancer `i` : $0, 3, 6, 9$, puis $12$, et $12 < 10$ est faux. Comme `i` est déclaré **avant** le `for`, il existe encore après : le programme affiche **`12`**.

Ce `;` est souvent une faute de frappe : `for (…);` suivi d'un bloc `{ … }` exécute le bloc **une seule fois**, après la boucle.
:::

:::exo-question{label="9." cours="t-c-while"}
```c
char s[] = "Bonjour";
int n = 0;
for (int i = 0; s[i] != 0; i++) {
    if (s[i] == 'o') {
        n++;
    }
}
printf("%d\n", n);
```

::champs-reponse
---
champs:
  - libelle: Ligne affichée
    attendu: '2'
---
::

#indice
`char s[] = "Bonjour";` laisse le compilateur compter la taille. La boucle parcourt les lettres jusqu'au zéro : combien sont des `o` minuscules ?

#solution
`B`, `o`, `n`, `j`, `o`, `u`, `r` : deux `o`. Le programme affiche **`2`**.

`char s[] = "…"` réserve exactement la place qu'il faut, zéro final compris : ici 8 octets.
:::

::::exercice{titre="Palier 3 — Le débordement" theme="Repérer l'écriture hors du tableau, et la corriger" badge="★★★☆☆" icone="i-lucide-shield-alert" entete="introduction"}
Le C ne vérifie jamais les bornes : c'est à toi de le faire. Devant chaque boucle qui écrit dans un tableau, la question à se poser : **quel est le plus grand indice atteint, et existe-t-il ?**

:::exo-question{label="10." cours="t-c-overflow" bonne="b"}
Laquelle de ces boucles écrit **hors** du tableau `int t[5];` ?

#a
`for (int i = 0; i < 5; i++) t[i] = 0;`

#b
`for (int i = 0; i <= 5; i++) t[i] = 0;`

#c
`for (int i = 4; i >= 0; i--) t[i] = 0;`

#d
`for (int i = 1; i < 5; i++) t[i] = 0;`

#indice
Pour chaque boucle, trouve le plus grand et le plus petit indice écrit, et compare à $0$ et $4$.

#solution
Avec `i <= 5`, le dernier tour écrit `t[5]` : la case **après** le tableau. Réponse **b**.

**Les autres :** **a** va de $0$ à $4$, le parcours type ; **c** va de $4$ à $0$ ; **d** oublie `t[0]`, ce qui est un défaut, mais n'écrit rien hors du tableau.

`<=` dans une boucle sur un tableau doit toujours alerter.
:::

:::exo-question{label="11." cours="t-c-overflow" bonne="d"}
```c
char code[4] = "123";
char nom[8];
scanf("%s", nom);
```

Rangé dans cet ordre, `nom` occupe les octets 5 à 12 et rien ne le suit. L'utilisateur tape `Maximilien` (10 lettres). Que se passe-t-il ?

#a
`scanf` refuse la saisie, trop longue.

#b
`code` est écrasé, puisqu'il est à côté de `nom`.

#c
`nom` contient `Maximili`, le reste est perdu.

#d
`scanf` écrit 11 octets à partir de l'octet 5 : 3 octets débordent **après** `nom`, sur ce qui suit en mémoire.

#indice
`scanf` écrit **à partir du début** de `nom`, vers les adresses croissantes. Combien d'octets en tout, zéro compris ?

#solution
10 lettres + le zéro final = 11 octets, écrits des octets 5 à 15 : **les octets 13 à 15 débordent** après `nom`. `code`, placé **avant**, n'est pas touché ici — mais le cours rappelle que d'autres informations vivent en mémoire (adresse de retour, contexte…), et que le compilateur range les variables comme il veut : rien ne garantit que ce qui suit est inoffensif. Réponse **d**.

**Les autres :** **a** et **c** prêtent à `scanf` des vérifications qu'il ne fait pas ; **b** oublie le sens de l'écriture.

La protection : `scanf("%7s", nom);` limite la lecture à 7 lettres (+ le zéro).
:::

::::exercice{titre="Palier 4 — Écrire une boucle" theme="Longueur, maximum, retournement et passage en majuscules" badge="★★★★☆" icone="i-lucide-code-xml" entete="introduction"}
Chaque question demande un **morceau de programme**. Place-le dans un `main` avec ses déclarations, **compile et teste** sur un exemple dont tu connais le résultat — et sur un cas limite (chaîne vide, tableau d'un seul élément) — avant de comparer.

:::exo-question{label="12." cours="t-c-while" code="c"}
`char s[100];` contient une chaîne lue par `scanf`. Écrire une boucle qui calcule sa longueur dans `int n`, **sans** utiliser `strlen`.

#indice
On compte les cases jusqu'au zéro final, exactement comme l'exemple `while` du cours.

#solution
```c
int n = 0;
while (s[n] != 0) {
    n++;
}
```

À la sortie, `s[n]` est le zéro final : `n` est l'indice du zéro, donc le nombre de lettres. Pour `"Bonjour"`, `n` vaut $7$ ; pour la chaîne vide, la boucle ne tourne pas et `n` vaut $0$.

On peut aussi écrire `while (s[n]) n++;` : une condition non nulle est vraie.
:::

:::exo-question{label="13." cours="t-c-for" code="c"}
`int t[10];` a été rempli. Écrire une boucle qui met le plus grand élément dans `int max`.

#indice
On part d'un candidat qui existe vraiment — le premier élément —, puis on le remplace dès qu'on trouve plus grand.

#solution
```c
int max = t[0];
for (int i = 1; i < 10; i++) {
    if (t[i] > max) {
        max = t[i];
    }
}
```

Partir de `max = 0` serait faux pour un tableau de négatifs : le maximum de $\{-5, -2, -9\}$ est $-2$, pas $0$. Avec `{4, -2, 9, 9, 1, …}`, on trouve $9$.
:::

:::exo-question{label="14." cours="t-c-chaines" code="c"}
Écrire un morceau de programme qui **retourne** une chaîne `s` sur place : `"Bonjour"` devient `"ruojnoB"`.

#indice
Calcule d'abord la longueur `n`. Puis échange la première et la dernière lettre, la deuxième et l'avant-dernière… avec deux indices qui se rapprochent. Pour échanger deux cases, il faut une variable temporaire.

#solution
```c
int n = 0;
while (s[n] != 0) {
    n++;
}
int g = 0;
int d = n - 1;
while (g < d) {
    char tmp = s[g];
    s[g] = s[d];
    s[d] = tmp;
    g++;
    d--;
}
```

- `d` part de `n - 1`, la dernière **lettre** : `s[n]` est le zéro final, qu'il ne faut surtout pas déplacer au début — la chaîne deviendrait vide ;
- la boucle s'arrête quand les indices se croisent ; avec une longueur impaire, la lettre du milieu reste en place.
:::

:::exo-question{label="15." cours="t-c-chaines" code="c"}
Écrire une boucle qui met en **majuscules** toutes les minuscules d'une chaîne `s`, sans toucher aux autres caractères : `"Bonjour !"` devient `"BONJOUR !"`.

#indice
Parcours jusqu'au zéro final. Une lettre est minuscule si elle est entre `'a'` et `'z'` ; sa majuscule est à la même distance de `'A'`.

#solution
```c
for (int i = 0; s[i] != 0; i++) {
    if (s[i] >= 'a' && s[i] <= 'z') {
        s[i] = s[i] - 'a' + 'A';
    }
}
```

Sans le test, l'espace et le `!` seraient décalés eux aussi et deviendraient d'autres caractères — l'espace pourrait même devenir la valeur $0$ et couper la chaîne.
:::

::extrait-cours{id="t-c-tableaux" titre="Les tableaux" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_1-les-tableaux"}
`type nom[N];` réserve $N$ cases **consécutives** du type. Les indices vont de $0$ à $N - 1$. Une case jamais écrite contient `??`.
::

::extrait-cours{id="t-c-chaines" titre="Les chaînes de caractères" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_2-les-chaînes-de-caractères"}
Une chaîne est un tableau de `char` **terminé par la valeur $0$** (`'\0'`, pas `'0'`). Toujours réserver un octet de plus que le nombre de lettres. Une chaîne qui initialise un tableau plus grand laisse les cases restantes à $0$ ; `char s[] = "…"` réserve juste ce qu'il faut.
::

::extrait-cours{id="t-c-printf-chaines" titre="%s dans printf et scanf" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_3-les-chaînes-avec-printf-et-scanf"}
`printf("%s", tab)` affiche jusqu'au premier octet nul — les octets suivants restent en mémoire. `scanf("%s", tab)` lit un mot, ajoute le zéro final, **sans `&`**.
::

::extrait-cours{id="t-c-while" titre="La boucle while" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_4-la-boucle-while"}
`while (condition) { code }` : condition testée **avant chaque tour**. Parcours type d'une chaîne : `int i = 0; while (s[i] != 0) { … i++; }` — à la sortie, `i` est la longueur.
::

::extrait-cours{id="t-c-for" titre="La boucle for" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_5-la-boucle-for"}
`for (depart; condition; instruction) { code }` : `depart` une fois ; puis tant que `condition` est vraie, `code` **puis** `instruction`. Parcours type d'un tableau de $N$ cases : `for (int i = 0; i < N; i++)`.
::

::extrait-cours{id="t-c-portee" titre="La durée de validité d'une variable" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_6-durée-de-validité-dune-variable"}
Une variable n'existe qu'entre les accolades où elle est déclarée ; celle d'un `for`, que dans ce `for`. Pour garder un compteur après la boucle, le déclarer avant. Un `;` juste après `for (…)` est un corps vide.
::

::extrait-cours{id="t-c-overflow" titre="Le dépassement de tampon" source="/cours/a1/mise-a-niveau-c/tableaux-et-boucles/cours#_7-le-dépassement-de-tampon"}
Écrire hors d'un tableau ne fait aucune erreur : on écrase la mémoire voisine, **vers les adresses croissantes** à partir du début du tableau. `scanf("%s")` ne vérifie pas la taille (`%7s` la limite). Le plus grand indice d'un tableau de $N$ cases est $N - 1$ : se méfier de `<=`.
::
